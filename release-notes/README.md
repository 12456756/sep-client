# 版本更新说明

每次发布前，在此目录新增与 `package.json` 版本号一致的文件，例如 `0.5.5.md`。
正文直接写面向用户的更新内容，每行一项，推荐使用简短列表：

```markdown
- 新增某项功能。
- 优化某项使用体验。
- 修复某个问题。
```

不要写版本标题、构建日志、链接或内部路径。客户端按纯文本列表展示，最多显示 20 项，每项 300 字，总计读取前 8000 个字符。

运行 `npm run release:notes:check` 检查当前版本的说明。
GitHub Actions 在打包前执行该检查，缺少文件、内容为空、编码错误或超过 64 KiB 都会失败。
发布准备脚本按产物版本号读取文件，将同一份正文写入 `latest.yml` 和 `latest-mac.yml` 的 `releaseNotes` 字段，随更新清单一起发布。

以往版本的文件保留作为历史记录；更新版本号时需要同时新增说明文件。
