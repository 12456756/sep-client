# 会话与编排测试提示词

日期：2026-10-29

用途：SEP 桌面客户端手工测试，共 21 个案例。以下为待执行的提示词与验收标准，不代表已通过真实平台测试。

## 使用方法

- **会话**：进入「安排工作 → 会话」，选择具备对应能力且已授权的员工。纯文本可用通用助手；员工名称不代表一定具备媒体工具。
- **自动编排**：进入「安排工作 → 编排 → 自动」，粘贴目标，检查计划后启动。关注员工匹配、依赖、交付物及执行结果。
- **手动编排**：进入「编排 → 手动」，分别配置步骤，见 A06。
- 每个独立案例选择一个空工作目录；只有标注“同一会话”或“恢复原工作”的案例复用原任务。提示词中的路径均相对于本次工作目录。
- 媒体规格以当前工具能力为准。普通案例允许说明后采用接近规格；R02 专门测试严格规格不支持时的处理。每次只生成指定数量，真实生成可能消耗算力。
- 图片和视频必须有真实、可打开的文件；只有描述、脚本、提交成功或任务 ID 均不能判定生成完成。目标格式不受支持时应说明限制，不能只修改扩展名。
- 当前自动规划规则不设置节点间人工确认。A03 应按依赖自动衔接；工具是否弹出授权按当次权限配置判断。
- Office、知识库及恢复操作依赖实际客户端版本和账号能力。前置条件不满足时记录“阻塞/不适用”及原因，不能直接记为通过。

### 建议先跑的 6 个案例

| 编号 | 场景 | 主要验证点 |
| --- | --- | --- |
| C01 | 会话多轮文本 | 上下文、流式回复、完成状态 |
| C02 | 会话生图 | 真实图片生成与交付 |
| C03 | 会话文生视频 | 无参考图的视频生成 |
| A01 | 编排文生视频 | 媒体意图、执行与交付 |
| A02 | 编排生图 | 单节点媒体计划与文件落地 |
| A03 | 编排先图后视频 | 跨节点资产引用、依赖顺序 |

## 一、会话测试

### C01｜纯文本与多轮上下文

第一轮：

```text
我们准备推广一款无品牌的米白色陶瓷马克杯。已确认的信息只有：容量 350mL、售价 49 元、目标人群是办公室用户。
请写一段 80 字以内的商品介绍，并列出这 3 项已确认信息。不要添加保温、防漏、耐摔等未经确认的卖点，不需要生成文件或图片。
```

同一会话第二轮：

```text
把刚才的介绍改得更口语化，限制在 50 字以内。容量、价格和目标人群保持不变，只给修改后的正文。
```

检查：第二轮保留 350mL、49 元及办公室用户的定位；没有混入内部 JSON、重复气泡或丢失回复；两轮结束后均退出运行状态，仍可继续发送消息。

### C02｜会话文生图

```text
请实际生成 1 张商品主图，不要只给我绘图提示词。
主体是一只无品牌的米白色陶瓷马克杯，放在木质桌面上，窗边自然暖光，简洁背景，杯子完整清晰，无人物、无文字、无水印。
优先使用正方形和当前支持的标准清晰度；如果规格不支持，请说明并使用最接近的可用规格。
把真实图片保存为 deliverables/c02-mug.png。若实际输出不是 PNG，请保留真实格式并说明实际路径。只生成 1 个版本。
```

检查：实际发起生图、图片可查看、文件能打开；数量为 1；画面主体符合要求；实际文件路径与回复一致。

### C03｜会话文生视频

```text
请直接使用文生视频能力，实际生成 1 条商品展示短片，不需要先生成图片，也不要只输出脚本。
内容是一只米白色陶瓷马克杯放在木质桌面上，窗边暖光，镜头缓慢向前推进，杯口有轻微热气，无人物、无文字、无水印。
优先横向 16:9、约 5 秒；如果当前工具不支持，请说明并采用最接近的可用比例和时长。
把真实视频保存为 deliverables/c03-mug.mp4。若实际输出格式不同，请保留真实格式并说明。只生成 1 条。
```

检查：执行的是文生视频；生成期间有真实状态反馈；最终文件可播放；若账号没有文生视频能力，应明确说明，不能伪称成功或自行换成图生视频。

### C04｜上传图片后图生视频

前置：上传一张主体清晰的马克杯图片，确认附件导入完成。

```text
请使用本轮上传的马克杯图片做图生视频，实际生成 1 条短片。
保持原图中杯子的颜色、形状和背景基本一致，只加入缓慢的镜头推进和轻微热气，不要重新生成另一张商品图作为输入。
优先约 5 秒，比例尽量保持原图；规格以当前工具支持为准。
保存真实视频到 deliverables/c04-reference-video.mp4，若原生输出格式不同请保留真实格式并说明实际路径。只生成 1 条。
```

检查：使用本轮真实附件，无需手工填写内部资产 ID；工具执行为图生视频；结果可播放，商品外观与输入保持合理一致。

### C05｜上传图片后编辑

前置：上传一张杯子照片；与 C04 独立开会话，避免引用错图。

```text
请实际编辑我上传的这张杯子照片，只把背景换成浅灰色摄影棚背景。
保留杯子的形状、颜色、把手方向和原有图案，不增加文字、其他商品或人物。只生成 1 张编辑结果，不要用一张无关的新图代替原图编辑。
保存到 deliverables/c05-edited.png；若实际输出格式不同请保留真实格式并说明。不要覆盖原附件。
```

检查：执行图片编辑并引用正确附件；原附件不变；编辑结果可打开，主体特征保留。

### C06｜生图后继续修改同一张图

前置：C02 完成后，在原会话继续发送。

```text
请编辑刚才在这个会话中实际生成的那张马克杯图片，把背景改成深蓝色，杯子本身保持米白色，其他构图尽量不变。
只生成 1 张修改版，保存到 deliverables/c06-mug-v2.png；若实际输出格式不同请说明实际路径。保留原图，不要让我重新上传，也不要重新做一个无关的杯子。
```

检查：能找到本会话上一轮的真实图片；修改版与原图分别保存；不会引用其他会话的资产；不重复生成多份。

### C07｜附件读取、数值计算与文件交付

前置：把以下内容保存为 UTF-8 的 `sales.csv` 后上传，确认附件可用。

```csv
商品,销量,单价
马克杯,12,49
帆布袋,8,29
笔记本,10,19
```

```text
请读取本轮上传的 sales.csv，按“销量 × 单价”计算各商品销售额和总销售额，按销售额从高到低排序。
输出逐项计算过程，并把结果保存为 deliverables/c07-sales-summary.md。只使用附件数据，不估算、不添加记录。
```

检查：马克杯 588 元、帆布袋 232 元、笔记本 190 元，总额 **1010 元**；文件包含同样结果；不是只根据文件名猜测内容。

### C08｜会话知识库：关闭、自动与手动引用

前置：准备专用测试知识库，放入一份可检索的《测试报销制度》，内容为：“市内交通费单次上限 80 元，提交截止为次月 5 日，需提供发票。”确认处理完成并有访问权限。以下三种模式分别新建会话，避免前一轮上下文带入答案。

模式一：选择“不使用知识库”。

```text
请依据公司《测试报销制度》，告诉我市内交通费单次上限、提交截止日期，以及是否需要发票。如果你没有读取到制度，请直接说明无法确认，不要猜测。
```

模式二：选择该测试库，启用自动检索，发送同一提示词；再发送：

```text
请把“下午好”翻译成英文，只给译文。
```

模式三：新建会话，启用手动检索，检索“市内交通费报销”，选中制度片段并引用到本次提问，再发送：

```text
请只依据我本次引用的制度片段，说明报销上限、提交截止日期和票据要求，并标明来源。片段中没有的信息请说明未提供。
```

检查：关闭时不查询也不编造制度；自动模式能回答 **80 元、次月 5 日、需发票**，普通翻译不触发无关检索；手动模式使用选中来源。检索次数与范围需结合可见活动或脱敏诊断记录判断，不能仅凭回答推断。

## 二、编排测试

### A01｜自动编排文生视频

```text
请安排具备实际文生视频能力且已授权的员工，为一款米白色陶瓷马克杯制作 1 条商品展示短片。
这是实际视频制作任务，不是写视频方案或分镜脚本。只需要一个视频制作步骤，不要额外安排生图、市场调研或发布。
画面是木质桌面、窗边暖光，镜头缓慢推进，杯口有轻微热气，无人物、无文字。
优先横向 16:9、约 5 秒，规格不支持时说明并选择接近的可用规格。
最终交付真实可播放视频，保存到 deliverables/a01-mug.mp4；若原生输出格式不同，按真实格式交付并说明实际路径。只制作 1 条。
如果没有具备文生视频能力的可用员工或工具，请明确提示缺口，不要把脚本当成视频交付。
```

检查：计划识别为文生视频且无多余生图节点；最终文件可播放；生成、保存完成后工作才标记完成。

### A02｜自动编排生图

```text
请安排具备实际生图能力且已授权的员工，完成 1 张无品牌米白色陶瓷马克杯商品主图。
只需要一个图片制作步骤，直接生成真实图片，不需要额外策划文档或视频。
要求：木质桌面、自然暖光、简洁背景、主体完整清晰，无人物、无文字、无水印。优先正方形，规格以当前可用能力为准。
最终图片保存到 deliverables/a02-mug-main.png；若原生格式不同，请保留真实格式并说明实际路径。只生成 1 张。
```

检查：计划是实际媒体生成而非需求单；无多余节点；图片关联到正确步骤并交付到工作目录。

### A03｜自动编排先生图，再图生视频

```text
请安排两个有先后依赖的步骤，为一款无品牌米白色陶瓷马克杯制作 1 张商品图和 1 条视频。
第一步：由具备生图能力的员工，实际生成一张木质桌面、窗边暖光、无人物无文字的马克杯商品图。优先横向，比例以可用能力为准。保存为 deliverables/a03-mug-main.png，若原生格式不同则保留真实格式。
第二步：由具备图生视频能力的员工，必须使用第一步实际生成并保存的图片作为输入，生成约 5 秒的缓慢推进短片，保持杯子外观及背景一致。保存为 deliverables/a03-mug-video.mp4，若原生格式不同则保留真实格式。
第二步依赖第一步图片成功保存，不能提前提交，不能自行换成文生视频，不要重新生成第二张参考图。
两个步骤按依赖连续完成，不插入中间人工确认。最终分别给出真实图片与视频路径，每种产物只生成 1 个版本。
```

检查：先图后视频；上游资产无需手工下载再上传；第二步使用正确图片；两份文件都能打开；任何一步失败时不应整项显示成功。视频预览与文件落地分别检查。

### A04｜并行分支与结果汇总

```text
请安排三个步骤，为“350mL、49 元、面向办公室用户的米白色陶瓷马克杯”制作文案：
第一步独立写 3 条商品标题，每条不超过 15 字，保存为 deliverables/a04-titles.md。
第二步独立写 2 段商品介绍，每段不超过 80 字，保存为 deliverables/a04-descriptions.md。
前两步互不依赖，可以并行。第三步必须等待前两步都完成，读取两份真实交付文件，从中选择一个标题和一段介绍，说明选择理由，保存为 deliverables/a04-final.md。
不要新增商品性能、促销、销量或评价，不生成图片和视频。
```

检查：计划中前两步无相互依赖，汇总依赖两步；汇总内容来自真实前置成果。是否实际同时运行受并发设置影响，串行调度本身不等于依赖错误。

### A05｜数据分析 → Word 报告 → PPT 汇报

前置：上传 C07 的 `sales.csv`；需要员工具备可用的 Office 文件工具。

```text
请依据本次上传的 sales.csv，安排三个前后依赖的步骤完成销售复盘：
第一步读取附件，计算各商品销售额、总销售额和排序，保存为 deliverables/a05-analysis.md。
第二步读取第一步结果，制作一份真实 Word 报告 deliverables/a05-report.docx，包含数据表、计算口径和简短结论，不新增销售数据。
第三步读取第二步报告，制作一份 3 页的真实 PowerPoint 文件 deliverables/a05-review.pptx，分别为汇总、商品对比和结论。
后续步骤必须沿用上游已核对的数据，不要重新编造。保存文件后再结束；如果缺少创建 DOCX 或 PPTX 的能力，请明确说明，不要将 Markdown 改扩展名交付。
```

检查：三个步骤正确串联；总额始终为 **1010 元**；DOCX、PPTX 能由对应应用打开，PPT 为 3 页；内容及表格数据一致。

### A06｜手动编排两步，验证顺序与上下文传递

操作：添加两位具有文本及文件写入能力的员工，按以下顺序设置；总目标填写“先出商品标题，再依据标题写介绍”。

第一步指令：

```text
为一款米白色陶瓷马克杯写 3 个商品标题。已知容量 350mL、售价 49 元、面向办公室用户。每条不超过 15 字。
将三条标题编号 1、2、3，保存到 deliverables/a06-titles.md。不要添加其他未经确认的功能。
```

第二步指令：

```text
读取前一步交付的 deliverables/a06-titles.md，使用其中第 2 个标题，写一段 80 字以内的商品介绍。
在结果中原样列出选用的标题，容量 350mL、售价 49 元、面向办公室用户的定位保持不变。保存为 deliverables/a06-description.md。
如果读取不到前置文件，请说明失败，不要自行重新生成三个标题。
```

检查：第二步在第一步完成后开始；标题与上游第 2 项逐字一致；两份文件存在；手动调整步骤顺序后，界面中的顺序与依赖保持一致，恢复正确顺序再执行。

### A07｜知识库检索与下游复用

前置：使用 C08 的测试知识库，在编排级选择该库并启用自动检索。若实际界面尚无该入口，记录版本和阻塞原因。

```text
请安排两个步骤，制作一份市内交通费报销指引。
第一步仅依据我选择的知识库中的《测试报销制度》，核对单次上限、提交截止日期和票据要求，注明资料来源，保存为 deliverables/a07-policy.md。检索不到时如实说明，不要猜测。
第二步必须读取第一步交付物，把已确认制度整理成给新员工看的简短操作清单，保存为 deliverables/a07-checklist.md。第二步只复用前置材料，无需再次检索，不新增制度条款。
不要查询未选择的知识库，不需要图片或视频。
```

检查：第一步检索范围仅为选定库；结果为 **80 元、次月 5 日、需发票**且有来源；第二步依赖前置文件。若版本支持节点知识库覆盖，可把第二步设为“不使用”后验证仍能读取上游成果。

## 三、异常、取消与恢复测试

### R01｜缺少附件时不能虚构输入

前置：新建空会话，不上传任何附件。

```text
请把我这轮上传的产品照片做成一条约 5 秒的图生视频，保持原商品外观。如果没有收到可用图片，请先告诉我缺少附件，等我上传后再生成；不要自行生图代替。
```

检查：提示缺少图片，不虚构附件、资产 ID 或已生成结果，也不提交付费视频任务。

### R02｜不支持的严格规格

前置：先查看当前能力，选一组确认不支持的规格。下面以“7 秒、11:7”为例；若已支持，替换后再测。会话和自动编排各跑一次。

```text
请实际生成 1 条米白色马克杯展示视频，时长必须恰好 7 秒，画面比例必须为 11:7，这两项都不接受替代。
提交前先核对当前工具能力；任一规格不支持就说明不支持项并停止，不要改成其他时长或比例，也不要裁剪、补帧或先生成再处理。
```

检查：不能满足时在提交生成前说明；不悄悄降级；不循环重试；不把失败解释为已完成。

### R03｜执行中终止

前置：使用 C03 或 A03 的提示词发起新任务，运行中点击客户端的终止操作；编排优先在上游图片仍在生成时终止。

检查：客户端及时结束本地执行并显示实际终止状态；不再启动新的下游步骤；再次打开历史时状态一致；已完成文件不丢失。

已提交到供应商的生成未必能远程取消，应记录终止时是否已提交及已有任务 ID，分别核对本地终止与远端生成/账务状态，不能把“客户端已终止”直接视为“供应商已取消、未扣费”。

### R04｜已提交媒体任务的恢复

前置：用 C03 或 A03 发起新任务，在确认媒体任务已经提交且可记录原任务 ID 后，正常退出并重新打开客户端；回到原工作，使用实际提供的恢复或继续入口。

如果需要在原会话发送继续指令：

```text
请检查这个会话里上一轮已经提交的媒体生成任务，优先恢复查询和保存已有结果。如果已经生成成功但没有保存，请只完成下载和交付。
不要新建第二个生成任务。如果无法确定原任务状态或无法恢复，请明确说明，等待我处理。
```

检查：恢复原媒体任务而非创建新任务；已有结果能继续保存；编排不会重做已成功节点；最终交付和状态一致。没有恢复入口时如实记录限制；不能通过新建工作代替原任务恢复。是否重复提交/扣费需核对原任务 ID、服务端请求和账务记录，不能只凭相似画面判断。

### R05｜工具授权拒绝与超时

前置：在会话模式关闭自动放行，使用需要人工确认的权限配置，再发送 C02。确认实际出现授权请求后，分别测试主动拒绝与等待超时；每次使用独立任务。

检查：拒绝或超时后不执行对应生成；界面给出真实原因；不自动换工具绕过授权，不反复弹出同一请求，不出现虚假的成功文件。

自动编排的媒体授权路径可能与会话不同，本例以实际会弹出确认的会话为主；若配置下没有人工授权请求，记录配置与实际路径，不能记为已覆盖拒绝分支。

### R06｜交付文件同名冲突

前置：在独立测试目录中创建 `deliverables/r06-result.md`，内容写“原文件，不允许覆盖”，保留一份对照。

```text
请写一段 50 字以内的马克杯介绍，尝试交付到 deliverables/r06-result.md。
如果该路径已经有文件，必须保留原文件不变，将新内容另存为 deliverables/r06-result-new.md，并明确告诉我实际交付路径。不要覆盖、删除原文件。
```

检查：原文件内容不变，新文件正确保存；界面和回复显示真实路径；不因目标已存在而声称交付到原路径。
