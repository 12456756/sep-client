## 现状分析

### 当前布局结构

```
┌─────────────────────────────────────────────────────────────┐
│ [Logo + 企业名]          标题区                  操作按钮区 │ ← 顶栏
├──────────┬──────────────────────────────────────────────────┤
│          │                                                  │
│  主导航  │                                                  │
│   首页   │                                                  │
│ 硅基员工 │              主内容区                            │
│ 安排工作 │                                                  │
│ 工作记录 │                                                  │
│ 技能库   │                                                  │
│          │                                                  │
│          ├──────────────────────────────────────────────────┤
│          │ [当前对话员工卡片 - 可折叠]                      │
└──────────┴──────────────────────────────────────────────────┘
```

**尺寸分配**（1200x800 标准窗口）：
- 左侧边栏宽度：`240px` 固定
- 顶部栏高度：`64px` 固定
- 主内容区：`960x736px`（宽度受限）
- 底部员工卡片：`240px` 高（展开时）

### 存在的问题

#### 1. **水平空间浪费严重**
- 左侧导航固定占用 `240px`，主内容区仅剩 `960px`
- 在 1200x800 标准窗口下，内容区宽度利用率仅 **80%**
- 员工卡片列表、工作记录表格经常需要横向滚动

#### 2. **视觉层级不清晰**
- 顶部有一层操作栏（首页、组织架构、通知）
- 左侧又有一层主导航（首页、硅基员工、安排工作...）
- 两个"首页"按钮同时存在，造成认知负担

#### 3. **垂直空间未充分利用**
- 桌面应用窗口是横向矩形（16:10 或 16:9）
- 垂直空间相对充裕，顶部只有 64px
- 左侧垂直导航在 5 个菜单项时已显得拥挤

#### 4. **扩展性受限**
- 如果未来增加新的一级导航（如"数据分析"、"设置"），左侧空间不足
- 二级菜单（如硅基员工下的"已分配"/"全部"）只能内嵌在页面内，无法在导航层级体现

#### 5. **与桌面应用惯例不符**
- 主流桌面应用（VS Code、Figma、Notion Desktop、Linear）都采用顶部导航
- 用户在桌面环境的操作习惯是"横向浏览"而非"纵向浏览"

---

## 设计目标

### 核心目标

1. **最大化内容区宽度** — 主内容区宽度从 960px 提升至 1140px+（提升 18%+）
2. **建立清晰的信息层级** — 一级导航、二级过滤、页面标题、操作按钮层级分明
3. **符合桌面应用惯例** — 对齐 VS Code、Figma、Notion 等主流桌面应用的交互模式
4. **保留快速员工切换** — 当前对话的员工卡片仍需一键可达
5. **支持未来扩展** — 为新增一级导航和二级菜单预留空间

### 非目标

- ❌ 改变页面内部的功能逻辑
- ❌ 调整路由结构和数据流
- ❌ 重新设计底层组件库

## 竞品调研

### 桌面应用顶部导航案例分析

#### 1. **VS Code** — 经典顶部导航 + 侧边工具栏

```
┌─────────────────────────────────────────────────────────────┐

├──┬──────────────────────────────────────────────────────────┤
│🔍│  main.ts > function initApp()                           │
│📁│  1  export function initApp() {                         │

│🐛│  3    // ...                                            │
│  │                                                          │
└──┴──────────────────────────────────────────────────────────┘
```

**特点**：
- 顶部：全局菜单栏（文件、编辑...）
- 左侧：窄工具栏（搜索、文件树、调试...），宽度仅 48px
- 内容区：占据绝大部分空间

**适用场景**：工具类应用，侧边栏是"工具切换"而非"页面导航"

#### 2. **Figma Desktop** — 浮动顶部栏 + 画布中心

```
┌─────────────────────────────────────────────────────────────┐

│                      [画布区域]                              │
│                                                             │
│                                                             │

```

**特点**：
- 顶部：主工具栏 + 工作区切换
- 无侧边栏，全屏画布
- 右侧抽屉式面板（按需弹出）

**适用场景**：创作类应用，最大化画布空间

#### 3. **Notion Desktop** — 侧边栏 + 顶部面包屑

```

│        工作区 / 项目 / 设计文档              [分享] [评论]   │

**特点**：
- 保留左侧导航（但可折叠）
- 顶部显示当前位置（面包屑）+ 页面级操作
- 导航项图标化，减少文字占用

**适用场景**：内容管理应用，强调层级导航

#### 4. **Linear** — 水平标签页导航

```
┌─────────────────────────────────────────────────────────────┐
│ [Linear Logo]  问题  视图  项目  路线图  设置    [🔍] [头像]  │

│  └──────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**特点**：
- 顶部：扁平的一级导航（问题、视图、项目...）
- 二级过滤器紧贴内容区顶部（所有问题、我的问题...）
- 无侧边栏，全宽度内容

**适用场景**：任务管理应用，强调横向浏览

### 竞品对比总结

| 应用 | 导航模式 | 侧边栏宽度 | 内容区占比 | 适用场景 |
|------|---------|----------|----------|---------|
| **VS Code** | 顶部菜单栏 + 窄工具栏 | 48px | ~95% | 代码编辑器 |
| **Figma** | 顶部工具栏 + 无侧边栏 | 0px | 100% | 设计工具 |
| **Notion** | 侧边导航 + 顶部面包屑 | 240px (可折叠) | 80-100% | 文档管理 |
| **Linear** | 顶部水平导航 | 0px | 100% | 项目管理 |
| **SEP (当前)** | 侧边导航 + 顶部操作 | 240px | 80% | AI 员工管理 |

**结论**：
- **Linear 模式最适合 SEP**：任务管理类应用，强调横向浏览，一级导航项不超过 8 个
- **参考 Notion 的可折叠侧边栏**：如果用户需要快速预览员工列表，可保留一个窄侧边栏（可选）

```

**布局规格**：
- **顶部导航栏高度**: `56px`
  - Logo + 企业名：120px
  - 导航项：每项 80-100px（5 个导航项：首页、硅基员工、安排工作、工作记录、技能库）
  - 右侧操作区：200px（搜索 + 通知 + 头像，组织架构入口在首页 tab 内）
- **主内容区**：`1200x744px`（宽度利用率 **100%**）
- **当前对话指示器**：右上角浮动卡片（240x48px）

**导航项设计**：
```css
.nav-item {
  height: 56px;
  padding: 0 20px;
  font-size: 15px;
  font-weight: 500;
  color: var(--ent-ink-dim);
  transition: all 0.2s;
}

.nav-item:hover {
  color: var(--ent-ink);
  background: rgba(196, 97, 47, 0.08);
}

.nav-item.active {
  color: var(--ent-brand-solid);
  border-bottom: 2px solid var(--ent-brand-solid);
}
```

**优点**：
- ✅ 内容区宽度最大化（1200px → 100%）
- ✅ 符合桌面应用主流惯例
- ✅ 视觉层级清晰（一层导航 + 页面内过滤器）
- ✅ 易于扩展（顶部可容纳 8-10 个导航项）

**缺点**：
- ⚠️ 失去"快速浏览员工列表"的能力（当前左侧底部员工卡片）
- ⚠️ 需要重新设计"当前对话"的入口

## 各页面详细布局设计

按照审美原则重新设计每个页面：单列居中布局、衬线标题配搭无衬线正文、温暖的陶土色系、真实摄影图片、充分的留白、柔和的圆角与阴影。

### 设计原则

**视觉语言**：
- **字体层级**：标题用 Fraunces 衬线（500 weight，紧字距），斜体强调关键词并着色 terracotta；正文用 Inter 300-500
- **配色**：奶油白背景 `#F7F4EF`，白色卡片 `#FFFFFF`，terracotta 主色 `#C4612F`（悬停 `#A94E22`），温暖灰边框 `#E7E1D7`
- **圆角**：按钮 `999px` 胶囊型，卡片 `8-12px`，小组件 `6px`
- **间距**：基础 `8px` 网格，组件间距 `16-24px`，页面内边距 `24-32px`
- **摄影**：每个页面的关键区域嵌入一张真实照片（Unsplash），而非纯色块或抽象渐变
- **密度变化**：首屏信息密度低（大标题+大图），往下滚动密度逐渐增加（卡片墙、列表）

**布局约束**：
- 标准窗口 `1200x800px`，内容区宽度 `1200px`（100% 利用）
- 顶部导航 `56px` 高，二级过滤栏/tab 栏 `48px` 高（按需显示）
- 主内容区滚动，其余固定

---

### 1. 首页 (HomePage) — 员工概览与组织架构

**核心改动**：

- 间距：16-20px

- 悬停：上浮 1-2px + 阴影加深

**按钮规范**：
- 主按钮：terracotta 填充，白色文字，圆角 `999px`（胶囊），高度 40-48px

- 页面顶部到英雄区：`32px`

- 区块之间：`32-40px`
- 卡片之间：`16-20px`

### 7.2 排版系统

**字体家族**：
- Display: `Fraunces` - 标题、品牌文字（Regular 400 weight）
- Body/UI: `Inter` - 正文、界面（300-500 weight range）

**字阶（Type Scale）**：
- Headline XL: 28px / 1.2 / -0.02em (首页标题)
- Headline L: 24px / 1.3 / -0.01em (页面标题)
- Headline M: 20px / 1.4 / 0 (卡片标题)
- Body L: 16px / 1.5 / 0 (正文、表单)
- Body M: 15px / 1.5 / 0 (说明、统计)
- Body S: 14px / 1.4 / 0 (辅助文字)
- Caption: 12px / 1.3 / +0.05em (眉标、标签)

**强调方式**：
- 关键词斜体 + terracotta 颜色（标题中使用）
- 500 weight（重要信息）
- 全大写 + 字距（眉标 EYEBROW）

### 7.3 圆角系统

- XL: `16px` - 大型容器、模态框
- L: `12px` - 卡片、区块
- M: `8px` - 小卡片、输入框
- S: `6px` - 徽章、标签
- Pill: `999px` - 按钮、胶囊型元素

## 九、设计决策记录

### 为什么选择顶部导航？

1. **空间利用**：释放 240px 侧边栏宽度 → 内容区增加 25%
2. **现代趋势**：Slack、Linear、Notion 等现代 SaaS 产品都采用顶部导航
3. **扩展性**：顶部导航更容易容纳 5+ 个一级页面，不会显得拥挤
4. **视觉聚焦**：用户视线从左上往下扫，顶部导航在第一视觉焦点

### 为什么首页要做 tab 而不是独立页面？

1. **降低层级**：组织架构不是高频操作，不值得占据一级导航位
2. **上下文连贯**：员工概览和组织架构都是"看人"，放在一起更合理
3. **减少跳转**：用户在看员工时想切换视角（列表 vs 层级），不用离开首页

### 为什么安排工作页改成会话式？

1. **降低认知负担**：三张卡片选模式 → 用户要先理解差异再选择，门槛高
2. **统一交互范式**：全对话式 = 用户只需"说话"，系统引导后续流程
3. **贴近产品定位**：SEP = AI 员工平台，会话是与 AI 交互的自然方式

### 为什么技能库要左侧导航？

1. **分类清晰**：Skills / Prompts / Agents 三类性质不同，需要明确分隔
2. **扩展性**：未来可能增加更多分类（Tools、Workflows...），左侧导航容易扩展
3. **减少切换成本**：左侧固定可见，不需要点下拉菜单

### 为什么卡片要简化（去掉描述）？

1. **提升扫视效率**：12 项技能 → 一屏看完所有名称，不需要逐个读描述
2. **详情页承载**：点进去看完整信息，列表只需要"识别 + 选择"
3. **视觉呼吸感**：描述文字占据 50% 卡片高度，删掉后卡片更干净

## 风险与应对

### 用户体验风险

#### 1. **习惯断层**

**风险描述**：用户习惯了左侧导航，突然改为顶部导航可能产生迷失感

**应对措施**：
- **渐进式迁移**：提供"经典布局"开关，允许用户暂时切换回旧版（保留 2 周）
- **引导提示**：首次进入新布局时显示交互引导（高亮导航位置）
- **快捷键保留**：保留原有键盘快捷键，增加新的导航快捷键
  ```
  Cmd + 1  →  首页
  Cmd + 2  →  硅基员工
  Cmd + 3  →  安排工作
  Cmd + 4  →  工作记录
  Cmd + 5  →  员工技能
  ```

#### 2. **"当前对话"入口不明显**

**风险描述**：原左侧底部员工卡片移除后，用户可能找不到当前对话

**应对措施**：
- **视觉突出**：右上角浮动指示器使用品牌色背景 + 动画
- **快捷键**：`Cmd + Shift + C` 快速打开对话面板
- **全局可见**：在任何页面都显示当前对话状态

```tsx
// 当前对话指示器
<div className="current-conversation-indicator">
  <div className="pulse-dot" /> {/* 动画脉冲点 */}
  <Avatar src={employee.avatar} size="sm" />
  <span className="employee-name">{employee.name}</span>
  <span className="status">对话中</span>
</div>
```

#### 3. **二级过滤器与页面标题冲突**

**风险描述**：页面标题、二级过滤器、操作按钮可能在一行挤不下

**应对措施**：
- **优先级排序**：过滤器优先，标题文字自动截断
- **响应式折叠**：窗口宽度 < 1200px 时，过滤器换行
- **下拉菜单备选**：过滤器过多时自动折叠为下拉菜单

### 技术风险

#### 1. **路由状态管理复杂度**

**风险描述**：顶部导航需要精确同步路由状态，嵌套路由可能导致激活态判断错误

**应对措施**：
```tsx
// 使用 React Router 的 matchPath 精确匹配
import { useLocation, matchPath } from 'react-router-dom';

const isActive = (path: string, currentPath: string) => {
  return matchPath({ path, end: false }, currentPath) !== null;
};
```

#### 2. **动画性能**

**风险描述**：过多动画可能导致低端设备卡顿

**应对措施**：
- 使用 CSS `transform` 和 `opacity`（GPU 加速）
- 避免 `width`、`height`、`margin` 等触发重排的属性
- 监听 `prefers-reduced-motion`，自动禁用非必要动画

```css
@media (prefers-reduced-motion: reduce) {
  .nav-item,
  .page-content,
  .filter-bar {
    animation: none !important;
    transition: none !important;
  }
}
```

#### 3. **Electron 窗口拖拽区域**

**风险描述**：顶部导航覆盖了 macOS 的窗口拖拽区域（`-webkit-app-region: drag`）

**应对措施**：
```css
.top-nav {
  -webkit-app-region: drag; /* 整个导航栏可拖拽 */
}

.top-nav button,
.top-nav input,
.top-nav a {
  -webkit-app-region: no-drag; /* 交互元素排除拖拽 */
}
```

1. **采用方案 A（纯顶部导航）**，内容区宽度利用率从 80% 提升至 100%
