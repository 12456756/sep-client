## Phase 0: PoC 验证 ✅

**时间**: 2026-07-30（1 天）  
**状态**: 已完成

### 目标

验证 Electron + pi-coding-agent SDK 的技术可行性，确认关键 API 行为。

### 完成内容

| PoC | 验证目标 | 状态 | 脚本 |
|-----|---------|------|------|
| ① | SDK import + `createAgentSession` 能正常初始化 | ✅ | `poc/01-sdk-import.ts` |
| ② | `before_provider_headers` 事件能动态注入 token | ✅ | `poc/02-provider.ts` |
| ③ | `tool_call` async handler 能 await GUI 决策 | ✅ | `poc/03-tool-call-async.ts` |
| ④ | 401 错误能冒泡（不被静默吞掉） | ✅ | `poc/04-failure.ts` |

### 关键发现

发现原交接文档在 3 处与实际 API 不符，已修正到 `CLAUDE.md` 和 `docs/对接/开发交接文档.md`：

1. `createAgentSession` 返回 `{ session, extensionsResult }` — 需解构
2. `DefaultResourceLoader` 必须传 `cwd`/`agentDir` 且调用 `reload()`
3. `session.on()` 不存在 → 用 `session.subscribe(listener)`

## Phase 1: 核心 UI 🔄

**时间**: 2026-07-31 ~ 2026-08-06（1 周）  
**状态**: 待开始  
**负责人**: TBD

### 目标

实现最小可用客户端：用户能登录、发送消息、看到 AI 回复、审批工具调用。

### 任务清单

#### 1.1 登录流程（2 天）

**优先级**: P0（阻塞后续所有功能）

- [ ] **OAuth 集成**
  - [ ] 注册 `sep-client://` custom protocol handler
  - [ ] 启动系统浏览器跳转 SEP OAuth 页面
  - [ ] 接收 authorization code 回调
  - [ ] 用 code 换取 `access_token` + `refresh_token`
  
- [ ] **Token 存储**
  - [ ] `refresh_token` 存入 safeStorage（加密）
  - [ ] `access_token` 存内存，带过期时间
  - [ ] 实现 `getAccessToken()` — 过期自动刷新
  
- [ ] **登录 UI**
  - [ ] 登录按钮
  - [ ] 登录中状态提示
  - [ ] 登录失败错误提示
  - [ ] 已登录状态：显示用户信息 + 退出登录

**验收标准**:
- 用户点击登录 → 浏览器打开 → 授权后回到客户端 → 显示"已登录"
- 应用重启后，refresh token 仍在，自动刷新 access token

#### 1.2 会话界面（2 天）

**优先级**: P0

- [ ] **启动 pi session**
  - [ ] "开始对话" 按钮 → `window.electronAPI.startSession()`
  - [ ] 主进程创建 `PiHost` 实例
  - [ ] 注册 SEP Gateway provider
  - [ ] 加载 SEP extensions（guard + provider）
  - [ ] `await resourceLoader.reload()`
  - [ ] `createAgentSession()` 解构 `{ session }`
  - [ ] `session.subscribe()` 订阅事件

- [ ] **消息输入与发送**
  - [ ] 输入框 + 发送按钮
  - [ ] 发送 → `window.electronAPI.sendPrompt(text)`
  - [ ] 主进程 → `session.prompt(text)`

- [ ] **流式输出显示**
  - [ ] 监听 `onPiEvent()` 回调
  - [ ] `message_start` → 创建消息气泡
  - [ ] `message_update` → 逐字追加内容（react-markdown 渲染）
  - [ ] `message_end` → 标记消息完成
  - [ ] `agent_settled` → 解除输入框禁用

- [ ] **会话控制**
  - [ ] "停止对话" 按钮 → `stopSession()`
  - [ ] 停止后禁用输入框
  - [ ] 可以重新 "开始对话"

**验收标准**:
- 用户输入 "hello" → AI 流式回复 → 输入框恢复可用
- 多轮对话正常（历史上下文保持）

#### 1.3 工具审批弹窗（1 天）

**优先级**: P0（安全必需）

- [ ] **审批请求接收**
  - [ ] 监听 `onToolApprovalRequest()` 回调
  - [ ] 解析工具名称和入参

- [ ] **审批弹窗 UI**
  - [ ] Modal 组件（Radix UI Dialog）
  - [ ] 显示工具名称（bash / write / edit）
  - [ ] 显示工具入参（JSON 格式化或纯文本）
  - [ ] "允许" / "拒绝" 按钮

- [ ] **审批响应**
  - [ ] 用户点击 → `sendToolApprovalResponse({ approved: true/false })`
  - [ ] 主进程 extension handler 返回 `{ block: !approved }`
  - [ ] 超时 60 秒自动拒绝

**验收标准**:
- AI 请求执行 `bash ls` → 弹窗显示命令 → 用户点击允许 → 命令执行 → 结果显示
- 用户点击拒绝 → AI 收到拒绝原因，继续对话

#### 1.4 基础 UI 优化（1 天）

**优先级**: P1（体验改善）

- [ ] **消息列表滚动**
  - [ ] 新消息自动滚动到底部
  - [ ] 用户手动滚动时不自动滚动

- [ ] **加载状态**
  - [ ] "AI 正在思考..." 占位符
  - [ ] 工具执行中显示 spinner

- [ ] **错误提示**
  - [ ] 网络错误 toast 提示
  - [ ] session 启动失败提示

**验收标准**:
- 长对话时滚动体验流畅
- 网络断开时有明确提示

### Phase 1 交付物

- [ ] 可运行的桌面应用（`npm run dev`）
- [ ] 用户能完成：登录 → 开始对话 → 发送消息 → 看到 AI 回复 → 审批工具 → 看到执行结果
- [ ] 应用重启后 token 仍有效，自动刷新

## Phase 2: 完善体验 ⏳

**时间**: 2026-08-07 ~ 2026-08-13（1 周）  
**状态**: 待开始

### 目标

提升用户体验，处理边界情况，增加必要设置。

### 任务清单

#### 2.1 多轮对话历史（2 天）

- [ ] **历史消息持久化**
  - [ ] pi session 自动保存到 SessionManager
  - [ ] 应用重启后恢复上次 session

- [ ] **历史消息加载**
  - [ ] 启动时加载历史（最近 50 条）
  - [ ] 下拉加载更多

- [ ] **会话列表**
  - [ ] 侧边栏显示历史会话列表
  - [ ] 切换会话
  - [ ] 新建会话 / 删除会话

**验收标准**:
- 用户与 AI 对话 10 轮 → 关闭应用 → 重新打开 → 历史仍在

#### 2.2 错误处理与重连（2 天）

- [ ] **401 自动刷新**
  - [ ] 拦截 `agent_end` 事件，检查 error 类型
  - [ ] 如果是 401 → 自动调用 `getAccessToken()` 刷新
  - [ ] 重试当前 prompt

- [ ] **网络断线重连**
  - [ ] 检测 `auto_retry_start` / `auto_retry_end` 事件
  - [ ] UI 显示 "正在重试..."
  - [ ] 重试失败后提示用户

- [ ] **错误日志**
  - [ ] 所有错误写入本地日志文件（electron-log）
  - [ ] 设置页可导出日志

**验收标准**:
- access token 过期 → 自动刷新 → 用户无感知
- 网络断开 → 提示重试 → 网络恢复后继续

#### 2.3 设置页（1 天）

- [ ] **连接设置**
  - [ ] 配置 SEP Gateway URL
  - [ ] 测试连接按钮（ping /health）
  - [ ] 显示连接状态

- [ ] **账户设置**
  - [ ] 显示当前登录用户
  - [ ] 退出登录按钮（清除 token）

- [ ] **其他设置**
  - [ ] 主题切换（亮色 / 暗色）
  - [ ] 字体大小调节

**验收标准**:
- 用户能切换 Gateway URL → 保存 → 重启后仍生效

#### 2.4 性能优化（1 天）

- [ ] **懒加载 pi session**
  - [ ] 不在应用启动时创建 session
  - [ ] 首次发送 prompt 时再启动

- [ ] **事件节流**
  - [ ] `message_update` 高频事件合并（每 100ms 最多转发 1 次）

- [ ] **历史消息分页**
  - [ ] 长对话只加载最近 N 条，按需加载更多

**验收标准**:
- 应用启动速度 < 2 秒
- 100 轮对话后仍流畅

### Phase 2 交付物

- [ ] 支持多会话切换
- [ ] Token 过期自动刷新
- [ ] 网络错误友好提示
- [ ] 设置页可配置 Gateway URL
