### 发布安全要求

- 安装包按版本不可变，禁止同版本不同内容覆盖；最终发布前验证完整 macOS 双架构及 Windows x64 目录。
- 安装包、blockmap 等关联资源必须先上传并核验；不能只上传安装器主文件。
- 清单最后提交，使用目标存储支持的原子替换/条件写入和发布锁；两个平台清单不是天然跨文件原子操作，部分失败需恢复旧清单并核验，不能宣称绝无短暂不一致。
- 上传前备份旧清单；上传失败时旧清单保持有效；记录恢复结果、产物哈希和完整脱敏发布日志。
- 复用 `test-update-feed.mjs` 验证匿名 HTTP 状态、版本、大小与 SHA-512，发布记录绑定本次批准版本及哈希，不能只验证“某个清单能下载”。
- 回滚只恢复清单并处理缓存，不删除/覆盖旧安装包，也不强迫已升级客户端降级；已经升级的用户通过更高版本修复。
- 本地 fixture、mock 和 dry-run 不产生正式验收通过记录；正式发布必须核对阶段 3 证据、签名身份和目标源授权。
- 本地每 channel lock 在 crash 后不会自动抢占；人工确认持锁进程退出后才处理残留锁，再显式 recover。目录须为用户自有安全 fixture，非恶意并发沙箱，无 power-loss durability 承诺；不得删除记录绕过版本尝试（含失败）不可复用要求。
