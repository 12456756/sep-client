# SEP 工作模块与对话优先界面设计方案

> 状态：已实施的设计基线。详细实现、自动化验证和剩余视觉验收见 [工作空间与图标导航开发文档](./工作空间与图标导航开发文档.md)。
>
> 范围：应用导航、统一工作入口、新建工作、工作列表、工作对话及按需展开的详情。
>
> 依据：用户提供的三张截图、当前 renderer 实现、`PRODUCT.md` 与 `DESIGN.md`。
>
> 布局：采用图 1 的“列表与对话同屏”结构，窄窗口可收起列表；本文的“当前实现”分析为实施前的基线记录。

## 1. 设计结论

将客户端的日常工作路径收敛为：**从「工作」进入，在同一个空间里新建、查找和继续工作；发送消息后，以对话内容为页面主体。**

三个核心变化：

1. 全局侧边栏默认只显示图标。鼠标悬停或键盘聚焦时，显示名称与轻量动效，点击后进入对应板块。
2. 「安排工作」与「工作记录」合并为「工作」。新建是该板块内的操作，历史和进行中的工作是同一份列表；状态使用符号标记与符号筛选，会话／编排使用独立的小标签。
3. 「产出结果」「工作过程」「工作信息」默认收起，通过对话标题栏的明确入口展开。等待确认和执行失败仍在对话区直接提示。

本次调整聚焦工作体验和外壳结构。员工、技能、知识库、算力、企业组织保留原有业务能力，适配统一导航。沿用 SEP 红色品牌、员工身份与真实状态体系。

企业身份仅以顶部 Logo 图标展示，不常驻公司名或公司简称；悬停或键盘聚焦时预览完整企业名称。企业组织与有权限的管理操作从企业图标点击后的菜单进入，不能在压缩导航后消失。个人／企业上下文切换本期保持已有语义，不新增一套组织管理流程。

「工作」是唯一一级入口。「新建工作」是操作，「会话／编排」是工作类型，「已完成」是状态，三个概念保持独立。

## 5. 全局图标导航

### 5.1 布局与图标

导航轨道固定宽 64px。顶部为企业 Logo 图标，中间为主入口，底部为账号头像；使用现有 Lucide 图标体系。导航按钮命中区为 40×40px，图标约 20px，按钮纵向间距 8px。

**居中明确为两个层级：** 每个按钮在 64px 轨道内水平居中，即左右各留 12px，SVG 在按钮内水平和垂直居中；首页、工作、员工等主导航组成一组，在企业图标与账号区之间的剩余高度中垂直居中。不是把图标贴着左侧排布，也不是把公司图标、导航和账号作为一组整体居中。

建议侧栏按「顶部固定区／可伸缩导航区／底部固定区」布局。中间区域 `min-height: 0`，导航组通过自动上下外边距居中；高度不足以完整放下导航时，自动回退为从上排列并允许中区滚动，避免首尾图标被居中裁切。企业图标与底部账号始终保留，窗口控制／拖拽区单独预留。

| 入口 | 建议图标 | 选中与提醒 |
| --- | --- | --- |
| 首页 | `LayoutGrid` | 淡品牌色底、品牌色图标 |
| 工作 | `MessageSquareText` | 选中底色；存在待处理工作时显示角标 |
| 硅基员工 | `Users` | 员工详情同属该入口 |
| 员工技能 | `GraduationCap` | 保持已有能力入口 |
| 知识库 | `BookOpen` | 保持已有能力入口 |
| 算力中心 | `Gauge` | 保持已有能力入口 |

默认不显示整列文字，也不在悬停时展开整条侧栏。这样页面宽度始终稳定。账号与企业图标点击后打开菜单，悬停只预览名称。导航角标采用绝对定位，不能因为出现数量把图标推离中心。

### 5.2 悬停与聚焦反馈

- 指针停留约 250ms 后，在图标右侧出现文字提示；键盘聚焦同样可见。
- 提示包括入口名称，工作有待处理事项时可显示「工作 · 3 项待处理」。数量来自真实数据。
- 提示以透明度和 4px 位移在 150ms 内出现，离开后约 100ms 隐藏；支持移入提示本身，Esc 可关闭。
- 按钮背景与图标颜色在 140ms 内变化；悬停时 SVG 以自身中心轻微放大到 `1.08`，160ms 完成；按下时短暂缩小到 `0.96`，80ms 完成，松开后回到悬停或默认状态。
- 图标缩放发生在固定命中区内，不改变布局，不旋转、不弹跳、不左右移动；选中图标保持品牌色和浅色底，不能仅在悬停时才看出当前页面。
- 使用 portal 避免被导航容器裁剪；提示不挡住相邻按钮。
- 减少动态效果模式下取消图标缩放与提示位移，以静态底色、图标颜色和焦点框反馈状态。
- 选中、悬停、键盘焦点各自可辨；每个图标按钮必须有可访问名称及 `aria-current`。

工作角标只统计待处理事项，计数大于 99 时显示 `99+`；不能把所有历史工作数量当作红色提醒。图标名称提示在无鼠标场景仍可通过焦点访问。

### 5.3 企业图标与名称预览

- 顶部仅放一个居中的企业图标按钮：外层 40×40px，Logo 约 30–32px，保持原始比例，不拉伸。
- 有可用企业 Logo 时展示真实 Logo；缺失或加载失败时展示中性的 `Building2` 图标，不使用完整公司名、公司简称或首字作为常驻替代内容。
- 悬停／键盘聚焦显示真实的完整公司名，例如「常州数易网络科技有限公司」。示意稿使用「示例企业」，不能将演示名接入正式界面。
- 名称提示默认出现在图标右侧，长名可换行；建议最大宽 280px。不能因长企业名扩宽轨道或把主内容推开。
- 点击打开企业菜单，菜单中可以显示公司名、企业组织与当前有权限的管理入口；提示本身不包含菜单操作。
- 企业按钮提供完整可访问名称、菜单展开状态与明确焦点。保留 Electron 拖拽区，但企业按钮及菜单必须处于 `no-drag` 区，保证悬停、点击和键盘交互有效。

## 6. 统一工作空间

### 6.1 默认布局

```text
┌──────┬─────────────────────────┬──────────────────────────────────────────┐
│  ◆   │ 工作             ＋新建 │ ◯ 当前工作标题  [会话]                    │
│      │ 搜索工作或员工          │ 参与员工                 [结果 2][过程][⋯]│
│      │                         ├──────────────────────────────────────────┤
│      │ ▦ 60  ◌ 8  ! 3  ✓ 42  │                                          │
│  ○   │ ⊘ 7                    │ 用户消息                                 │
│  ◉   │ [集合][气泡][节点]      │                                          │
│  ○   ├─────────────────────────┤ 员工回复                                 │
│  ○   │ ! 工作标题              │ Markdown、附件、必要的结果摘要             │
│  ○   │ [会话]           时间   │                                          │
│  ○   │ 当前摘要／下一步        │                                          │
│      │─────────────────────────│                                          │
│      │ ✓ 工作标题              ├──────────────────────────────────────────┤
│      │ [编排]           时间   │ 正在整理资料…                            │
│      │ 最新消息摘要            │ [附件] 输入消息                  [发送]  │
│  ●   │                         │ 当前员工 · 执行设置                       │
└──────┴─────────────────────────┴──────────────────────────────────────────┘
```

左侧轨道中 ◆ 表示企业 Logo 槽位，○／◉ 表示居中的导航图标槽位及选中项，底部 ● 表示账号头像；正式图标见第 5 节和独立 HTML 示意。工作状态用符号示意，方括号表示独立的小标签，计数仅为布局示例，不代表互斥分组或真实数量。正式界面中完成用绿色勾选圆、待处理用琥珀色感叹号圆、进行中用蓝色缺口圆环，不显示常驻的状态文字。图中的感叹号、气泡、节点与类型文字仅为排版代称，正式使用统一 SVG 图标。工作列表默认宽 304px，可在 280–360px 内调整。对话主区占剩余空间，正文与输入框对齐，正文阅读宽度上限约 800px。

工作空间占满可用高度。列表、对话消息和展开的详情各有独立滚动区；消息增长时，输入框保持可见。避免外层页面、聊天卡片、聊天内容三层同时滚动。

进入「工作」时，同一次应用会话内恢复上次选中的工作和筛选；首次进入显示新建界面。选择历史工作在右侧切换内容，左侧保留。提供「收起工作列表」按钮供用户专注阅读。

### 6.2 工作列表

列表顶端固定为「工作 + 新建」、搜索、状态符号筛选与类型标签筛选。状态按钮仅显示「图标 + 数量」，例如缺口圆环 8、感叹号圆 3、勾选圆 42，不常驻「工作中／待处理／已完成」文字；悬停或键盘聚焦显示完整名称和数量。五个按钮优先一行排布，空间不足时换行，不能靠横向滚动才能发现已完成筛选。类型标签单独一行，默认以集合、消息气泡、流程节点三个图标小标签表示全部类型、会话、编排；悬停或聚焦显示名称。

单条工作建议高 96–116px，结构为：

1. 标题前固定放状态符号，标题最多两行；时间作为次要信息。
2. 类型用独立图标标签：消息气泡表示会话、流程节点表示编排，始终可见，悬停或聚焦预览名称；员工身份作为简洁的头像或名称。状态不再占用一枚文字标签。
3. 一行摘要：优先当前待处理事项，其次失败原因，再次最新消息或交付摘要。

条目不重复展示相同的标题和目标，不常驻「查看结果／查看过程／删除记录」按钮排。点击条目打开对话；条目的更多菜单提供低频操作。删除与终止保留现有确认和真实影响说明。

默认按最近更新时间排序，复用现有规则。为避免实时流式更新导致列表持续跳动：选中项不因每个 token 重排，排序在切换工作、筛选或一轮状态稳定更新时应用。筛选改变导致当前工作不匹配时，右侧继续保留该对话，并提示「当前工作不在筛选结果中」，提供清除筛选入口。

### 6.3 状态、类型与计数

| 状态筛选（说明名称，默认不常驻） | 沿用的数据口径 | 条目表达 |
| --- | --- | --- |
| ▦ 全部 | 所有工作 | 各自真实状态符号 |
| 缺口圆环：进行中 | `isActive === true`，含由本轮执行持有的排队工作 | 蓝色缺口圆环／时钟／待处理感叹号，以实际状态为准 |
| 感叹号圆：待我处理 | `waiting-user` 或存在 `nextUserAction` | 琥珀色感叹号及具体待办摘要；失败但无待办的记录不自动算入 |
| ✓ 已完成 | `completed` | 绿色勾选；不意味着必定有文件交付 |
| ⊘ 未完成 | `failed` 或 `paused` | 条目使用失败叉号／终止方块，保留区别 |

未启动的 `arranging` 工作在「全部」使用时钟标记，悬停说明「待开始」，不能仅因创建过就算进行中。排队中的工作同样使用时钟，悬停说明「排队中」。

筛选集合可以重叠，例如一个仍由运行持有、等待用户的工作，同时符合「进行中」与「待我处理」。各状态数量不承诺相加等于总数，不能改造成互斥状态机。

类型使用权威的 `workType` 读取结果：`conversation → 会话`，`arrangement → 编排`。`kind: flow` 是现有前端结构字段，不作为权威分类依据。类型加载中或读取失败时显示明确文案，保留在「全部类型」内，提供重读入口，不能默认显示为会话。

筛选关系为「状态 AND 类型 AND 搜索」。状态计数应用类型与搜索条件，类型计数应用状态与搜索条件，沿用现有函数。数量为 0 的筛选仍可点击，展示对应空态。

类型采用中性背景／细描边的图标小标签：`MessageSquare` 表示会话，`Workflow` 表示编排。默认不常驻文字，悬停或聚焦展示「会话」「编排」。类型图标放在小标签容器内，状态图标直接放在标题前，两者通过位置、形状和容器区分。筛选标签可点击；条目与标题栏标签只说明类型，点击不会改变已有工作的类型。新建时的模式选择保留文字，帮助用户明确将采用哪种执行方式。

### 6.4 状态图标：调研后的推荐方案

用户的 ✅／🔴／⭕️ 是符号化表达的举例，并非锁定的图标和配色。上一版将其写成指定方案不准确，本节按调研结果修订。

**推荐：语义图标 + 克制的状态色 + 悬停／聚焦文字。** 默认只显示图标，重要待办和失败原因依然在主区直接说明。以下是 SEP 的设计建议，不声称已有用户测试证明其识别率。

| 用户举例 | 评估 | 推荐调整 |
| --- | --- | --- |
| ✅ 已完成 | 勾选适合表达完成，可沿用语义；彩色 emoji 的形态与应用图标不统一 | 绿色 `CircleCheck`，同一描边体系 |
| 🔴 待处理 | 点只能表达有事发生，无法区分未读、失败、等待确认；红色还会提升普通确认的紧迫感 | 琥珀色 `CircleAlert` 表示需要介入；红色 `CircleX` 单独表达失败 |
| ⭕️ 工作中 | 普通空心圆容易与未开始、未选中混淆；红色工作中也会与异常竞争注意 | 蓝色 `LoaderCircle` 缺口圆环表示处理中；待开始使用灰色虚线圆 |

完整状态映射：

| 含义 | 推荐图标 | 配色与行为 | 提示示例 |
| --- | --- | --- | --- |
| 工作中 | `LoaderCircle` | 蓝色，默认静态缺口圆环；不持续旋转 | 工作中 · 正在整理参考资料 |
| 已完成 | `CircleCheck` | 绿色勾选圆 | 已完成 · 2 个结果 |
| 待处理／待确认 | `CircleAlert` | 琥珀色感叹号圆 | 待你确认 · 请选择宣传图方向 |
| 失败／需要重试 | `CircleX` | 红色叉号圆 | 执行失败 · 下载未完成 |
| 已终止 | `Square` | 中性灰方块 | 已终止 · 已保留先前结果 |
| 待开始 | `CircleDashed` | 中性灰虚线圆 | 待开始 |
| 排队中 | `Clock3` | 中性灰时钟 | 排队中 · 等待执行 |
| 全部／未完成集合 | `Layers`／`Ban` | 中性图标，只用于筛选 | 全部工作 · 60 项／未完成 · 7 项 |

色彩沿用完成 `#1a7f52`、待处理 `#8a6410`、失败 `#bf3149`；进行中建议增加专用状态蓝 `#315f9b`，与品牌红的选中／主操作职责分开。新颜色仍需在真实浅／深色主题验证，不直接复用为整个应用的新品牌色。

不使用半圆填充比例表达普通“工作中”，避免被理解为 50% 进度；只在存在真实可量化进度时显示比例。缺口圆环在列表中保持静态，网络提交的短暂加载指示与工作的生命周期状态分开。

若执行状态不是 `waiting-user`，但存在真实 `nextUserAction`，保留原执行状态，并补充琥珀色感叹号提醒；提示同时说明执行状态与待办。不能为了待办标记而抹去失败或完成事实。新消息提示使用独立的小角标位置，不代替工作状态，也不与员工头像的可用性标记共用位置。

### 6.5 相似设计的调研与取舍

本节区分官方规范事实与 SEP 的设计判断。调研范围为企业工具、任务管理和图标交互的官方文档，不以营销截图或第三方仿制稿推断产品行为。

| 官方参考 | 可确认的做法 | 对 SEP 的借鉴与边界 |
| --- | --- | --- |
| IBM Carbon：Status indicators | 通过图形、符号、颜色区分状态；区分生命周期标记与更新角标；纯图标需要满足可辨识和对比度要求 | 借鉴语义区分，不把未读圆点直接等同待确认；图标优先可用，但需补充可访问名称和说明 |
| Microsoft Fluent 2：Badge | 徽标放在其描述的内容附近；纯图标信息要有可访问名称；有悬停交互时考虑焦点 | 类型图标标签紧邻工作标题，数量角标紧邻结果入口；隐藏文字时保留辅助说明 |
| GitHub Primer：Tooltip | 悬停或键盘聚焦显示图标按钮含义；文案简短，具备可访问名称 | 状态筛选、结果、过程和类型筛选采用清晰的命名，不使用一长段 Tooltip 承载业务决策 |
| Linear：Issue properties | 工作状态、优先级与分类标签是不同属性；状态覆盖未开始、进行、完成和取消等阶段 | SEP 的执行状态、类型和是否需要用户介入分别表达；不把会话／编排当作执行状态 |
| W3C WCAG 2.2：Content on Hover or Focus | 自定义悬停内容需要可关闭、可移入、持续可读 | 提示能用 Esc 关闭，鼠标移入提示不会立即消失；仅鼠标悬停不可作为唯一访问方式 |

三种可以采用的图形方向：

| 方向 | 视觉特征 | 优点 | 主要代价 | 本次判断 |
| --- | --- | --- | --- | --- |
| 纯色点 | 所有状态都用小圆点，靠颜色变化 | 极简，密集列表占地小 | 颜色依赖强，未读与待办容易混淆 | 不作为主要状态体系 |
| 生命周期圆形 | 虚线／空心／实心／勾选的圆形家族 | 视觉统一，适合稳定的阶段流转 | 待确认、失败仍需额外符号；半填充可能被误读为百分比 | 可作备选，必须补齐异常语义 |
| 语义图标 | 缺口环、感叹号、勾选、叉号、时钟 | 各状态有不同轮廓或内部符号，适合隐藏常驻文字 | 比纯点占地略大，需要统一尺寸和图例 | **推荐** |

这三种是为 SEP 归纳的方案，不宣称与某个参考产品的全部像素或交互完全一致。独立交互示意见 `outputs/work-status-icons-preview.html`，为演示数据，不连接真实工作。

### 6.6 悬停预览与可访问性

- 状态图形建议 14–16px，使用统一的 24px 绘制网格和描边风格；外层固定槽位使标题对齐。
- 状态筛选、类型筛选、结果和过程的图标按钮，命中区至少 32×32px。文字不常驻，但必须有完整的可访问名称与明确选中状态。
- 建议悬停约 250ms 后出现短提示，键盘聚焦立即显示。说明以「名称」或「名称 · 简短当前事实」为主，不把 Tooltip 写成小报表。
- Esc 可以关闭；鼠标可以移入提示；指针和焦点仍在触发区或提示内时不自动消失。提示跟随实际状态更新，不覆盖相邻主要操作。
- 工作行采用一个主焦点入口，读屏名称包含标题、状态与类型。鼠标悬停行内小图标可见对应说明；键盘聚焦行时提供相同含义的行级提示或可见辅助说明，不让类型和状态成为仅鼠标可发现的信息。
- 单独提供状态详情交互时，使用明确的按钮语义；静态标记不伪装成可点击按钮。不能随意给每个无语义的 `span` 添加 Tooltip 后就认为完成无障碍支持。
- 勾选、感叹号、缺口环、叉号、方块在灰度下仍需可分辨；状态图形与相邻背景对比度目标至少 3:1。
- 提示只说明名称和简短事实。完整失败原因、授权范围、确认内容与按钮放在主区或点击打开的面板，不能要求用户一直悬停才能决定是否授权。
- 菜单和新建模式选择可保留文字，特别是删除、终止和收费动作；“尽量图标化”优先作用于高频固定入口，而非删除所有文字。
- 可提供「显示图例」的轻量入口帮助首次使用者学习，默认不展开常驻说明。

### 6.7 可继续图标化的入口

| 元素 | 推荐图标／形式 | 悬停文字 | 保留的信息 |
| --- | --- | --- | --- |

## 7. 新建工作与发送后的连续体验

### 7.1 新建会话

点击「新建工作」，右侧显示轻量起始界面：一句「安排一项工作」、会话／编排切换、员工选择、输入框和附件入口。默认进入会话，优先复用用户当前选择的可用员工；没有有效选择时要求先选员工。

执行设置收在输入框下方的入口内，保留模型、工作目录、权限等真实配置，不在首屏展开所有参数。员工详情里的「安排工作」直接进入此界面并带入员工。

发送后：

1. 保留用户输入的消息与附件，右侧原位进入对话状态。
2. 创建成功后，把真实工作加入左侧列表并选中，保留真实工作 ID。
3. 创建失败时保留草稿与附件，原位说明原因，避免出现空白的“成功记录”。
4. 流式回复直接进入消息区，不自动打开结果或过程面板，不跳转到报表页。

### 7.2 新建编排

新建入口仍只有「会话／编排」两类；编排内部保留自动与手动方式、模板、预检查、步骤依赖、附件与运行设置。

自动编排先填写目标，再审阅计划并启动；手动编排进入工作区内的完整画布编辑态。画布编辑时可临时收起工作列表以获得空间，启动后回到同一工作的对话主视图。

编排运行后的对话区显示已有沟通内容、真实步骤摘要及最终总结，消息注明对应员工或步骤。详细 DAG、逐步输入输出和执行记录放入「过程」面板。对话中不展开整张流程图，也不把每条工具事件变成一条员工消息。

编排的「补充说明」「确认继续」「重试」仍调用对应的现有命令。自由文本输入若当前执行阶段不支持继续，显示明确原因和可用操作；不能仅因统一视觉就把普通会话的继续命令直接用于所有编排状态。

### 7.3 工作切换与草稿

每项工作保留独立输入草稿、附件导入会话、消息滚动位置。切换工作不会把上一项的文字或附件带到下一项。新建草稿与已有工作的追问草稿分开管理。

退出新建或切换模式时保留可兼容的输入；涉及无法保留的编排编辑时明确提示。草稿优先保存在当前应用会话内，不在本次设计中承诺新增跨重启持久化。

## 8. 对话主区

### 8.1 标题栏

标题栏按「状态图标 + 工作标题 + 类型图标标签」排列；例如蓝色缺口圆环、宣传图制作标题、消息气泡标签。保留参与员工，以及结果、过程、更多三个图标入口，名称通过悬停或聚焦呈现。不再显示 `[进行中]`、`[已完成]` 等文字状态标签。标题建议 18–20px，最多一到两行，长目标不再以超大标题占据首屏。

开始时间、耗时、工作目录、完整参与者、分享等放入工作信息或更多菜单。运行中的简短阶段说明放在输入框上方或消息末尾。没有可计算的真实进度时显示阶段文字，不显示推算百分比。

### 8.2 消息与输入框

- 用户消息可用浅灰气泡右对齐；员工回复以头像、姓名和开放式正文左对齐，减少大块背景。
- 员工正文建议 15px、行高 1.65–1.75；表格和代码块在自身内部横向滚动。
- 时间按消息组展示；复制操作在悬停与键盘聚焦时出现。
- 输入框固定在对话主区底部，初始约两行，随内容增长到限定高度后内部滚动。
- 保留附件、粘贴上传、语音、员工选择及既有发送快捷键；中文输入法组词时按 Enter 不触发发送。
- 执行中保留真实停止操作；输入与发送是否可用由运行能力决定，不把禁用按钮伪装为可提交。
- 用户位于底部时跟随新消息；向上阅读时保留位置，并显示「有新内容，回到底部」。
- 打开或关闭详情面板时，保持消息阅读锚点和输入草稿。

消息仍通过现有安全 Markdown 渲染，不执行原始 HTML、不自动加载任意远程图片。媒体预览通过已有受控资产接口读取。

### 8.3 结果出现在对话中的方式

有新结果时，在消息流中提供简短结果摘要和「查看结果」入口，可显示真实资产的小缩略图或文件名。正文继续承担说明，完整文件操作进入结果面板。

摘要按结果或交付事件稳定更新，不能每次轮询都插入一条新消息。完成后可显示 `✓ · 2 个结果`，悬停说明本轮已完成；不自动拉开面板或遮住正在阅读的回复。

## 9. 详情按需展开

### 9.1 入口与容器

标题栏提供文件图标及数量（结果）、时间线图标（过程）两个固定入口，默认不常驻文字；悬停或聚焦分别显示「产出结果 · 2 个文件」「工作过程」。低频信息放在更多菜单中的「工作信息」，也可由信息图标进入。使用与含义匹配的图标，不用同一个齿轮图标代指不同面板。

点击入口打开右侧统一详情面板，一次只显示一个面板。结果与过程可在面板顶部切换，工作信息按同一容器展示。再次点击当前入口或点击关闭按钮收起；打开面板只改变查看方式，不触发生成、重试或收费动作。

```text
默认：     [图标导航] [工作列表] [          对话          ]
宽屏展开： [图标导航] [工作列表] [      对话      ] [详情面板]
中屏展开： [图标导航]            [      对话      ] [详情面板]
窄屏展开： [图标导航]            [ 对话背景 ][覆盖式详情面板]
```

宽屏内嵌面板不锁定全页焦点。窄屏覆盖式面板使用 dialog 语义与焦点管理，关闭后恢复到触发入口。Esc 优先关闭最上层预览或菜单，再关闭面板。切换工作时默认收起详情，避免把上一项的结果误认为当前结果。

### 9.2 结果面板

面板内依次展示：

1. **已交付结果**：文档、图片、视频及其他可用文件，显示名称、类型、来源员工／步骤和可用操作。
2. **生成任务**：真实的生成、下载、保存或失败状态，保留恢复、停止跟踪、重新生成等现有能力。
3. **创作与参考素材**：导入参考图、参数与主动创作入口，默认折叠，按工作实际能力出现。

已有预览、复制路径、导出等操作继续可用。完整本地路径、任务 ID、供应商耗时和账务细节放入任务详情，不占据结果列表主体。

**结果计数的一致性要求：** 图 3 同时出现「产出结果 0」和「媒体已保存到本地」。新设计中，结果入口必须同时覆盖普通交付物与可读取的媒体资产，不能只统计 `work.deliverables.length`。

- 同一资产同时出现在媒体任务和交付记录中时，只计一次；优先使用稳定的交付物／资产关联 ID，不能仅按文件名猜测。
- 供应商生成成功但尚未保存或读取不可用时，归入生成任务，不能提前当作已交付结果。
- 缺少可靠关联时，分组显示「文件 N／媒体 M」，暂不报合并总数，避免重复计数。
- 数量未知或加载失败时显示「结果」与加载／失败反馈，不临时显示 0。
- 无文件交付但有文本回答时，说明「本轮结果已在对话中说明，暂无文件交付」，避免暗示工作毫无产出。

打开结果入口不能自动重做媒体。停止本地跟踪与取消供应商任务继续区分；重新生成的收费提示保留在具体动作附近。

### 9.3 过程面板

显示当前阶段、时间线、工具活动以及编排步骤。默认先看业务摘要，例如「正在读取参考资料」「等待你确认第 2 步」；逐条工具参数、日志和错误详情继续折叠。

编排可切换步骤列表与流程图，保留节点状态、依赖关系、输入输出和失败定位。打开失败定位入口时直接选中对应节点或事件。

### 9.4 工作信息

包括创建／开始／结束时间、本轮耗时、工作目录、参与员工、运行配置和终止原因。工作目录可复制，路径过长截断但可访问完整内容。这里只展示配置与事实，修改运行条件仍走现有明确操作。

## 10. 必须直接可见的待办与异常

隐藏次要详情后，用户依然要知道工作是否在等待自己。

| 情况 | 主区直接展示 | 进一步操作 |
| --- | --- | --- |
| 等待步骤确认 | 对话内的紧凑行动条：需要确认的内容、步骤与原因 | 查看相关结果；按现有语义确认或补充说明 |
| 工具授权 | 沿用现有授权确认界面与权限策略 | 确认／拒绝，超时按现有规则拒绝 |
| 启动失败 | 显示「未启动」及原因 | 查看原因后重试，不能继续显示运行百分比 |
| 执行中断 | 保留已收到内容，显示中断摘要 | 重试或打开过程定位 |
| 媒体仍在生成／保存 | 简短阶段提示与结果入口状态 | 查看任务；不能提前称为已交付 |
| 生成或保存失败 | 对话区出现可感知的失败提示 | 打开对应任务详情处理 |
| 已完成 | 绿色勾选标记，保留追问入口 | 支持继续的工作可以追问；其他工作展示既有可用动作 |

涉及多个步骤确认时，列明将确认的范围，不用一个含糊的「继续」按钮代替。查看面板本身不等于确认。隐藏、关闭或卸载面板不改变授权、任务生命周期与账务状态。

## 11. 尺寸、视觉与动效

### 11.1 窗口适配

现有 Electron 窗口最小尺寸为 960×640，本期以桌面为验收范围。

| 窗口宽度 | 默认结构 | 打开详情 |
| --- | --- | --- |
| ≥1440px | 64px 图标轨道 + 304px 列表 + 对话 | 对话保持至少约 640px 时内嵌 360–400px 面板，否则自动收起列表 |
| 1200–1439px | 图标轨道 + 列表 + 对话 | 临时收起列表后显示内嵌面板；关闭时恢复先前列表状态 |
| 960–1199px | 图标轨道 + 对话；列表通过标题栏按钮打开 | 详情使用 360–400px 覆盖式面板，列表与详情不同时覆盖 |

最终以内容可用宽度判断内嵌条件，不只依赖窗口断点。窄窗口打开工作列表使用覆盖式列表，选择后收起。标题栏入口和发送按钮在 960×640 及系统缩放下可达，输入区不能挤出窗口。

### 11.2 视觉语言

保留品牌红 `#ae383d` 与既有语义令牌。内容区以白色或现有深色表面为主体，列表与导航用轻微中性色差分区。工作空间取消影响阅读的大面积渐变和水印。

| 元素 | 建议规格 |
| --- | --- |
| 导航按钮 | 40×40px，圆角 10–12px，图标约 20px；轨道内水平居中，导航组在中区垂直居中 |
| 企业图标 | 30–32px Logo，40×40px 居中按钮；无图时使用 `Building2`，名称仅在提示／菜单内展示 |
| 列表标题 | 14px，600 字重 |
| 列表摘要／辅助信息 | 12–13px，保持对比度 |
| 工作状态符号 | 14–16px，固定槽位；使用形状 + 语义颜色，默认不附状态文字 |
| 会话／编排标签 | 视觉高 22–26px，图标 13–15px，中性轻底或细描边；筛选命中区至少 32px |
| 对话标题 | 18–20px，600 字重 |
| 对话正文 | 15px，约 1.7 行高 |
| 筛选与常规按钮 | 32–36px 高；键盘焦点清晰 |
| 输入框 | 圆角 16px，稳定边界，聚焦时增加品牌色焦点环 |
| 详情面板 | 白／深色实体表面，用一条边界或克制阴影分隔 |

减少嵌套卡片与多重边框，以对齐、留白和分隔线建立层次。只给选中导航、主操作及必要状态分配强调色。结果数量使用中性标记，新结果可用小点提醒，不制造持续闪烁。

### 11.3 动效规则

详情面板用 180–220ms 的轻量位移和淡入；布局只发生一次切换，避免逐帧压缩消息宽度导致文本反复重排。新消息不逐条弹跳，结果到达不抢焦点。减少动态效果模式下取消位移与布局动画。

深色模式同步设计导航选中、提示浮层、筛选、消息、面板和状态对比度，不直接反转浅色截图。正文与背景对比度目标至少 4.5:1，焦点与控件边界至少 3:1；状态依靠可区分图形与颜色，并提供悬停／焦点文字和可访问名称。

## 12. 加载、空态与边界

| 场景 | 行为／文案 |
| --- | --- |
| 没有历史工作 | 左侧「还没有工作」；右侧展示可直接操作的新建界面 |
| 没有可用员工 | 「当前没有可安排工作的员工」，提供已有员工授权或目录入口 |
| 筛选无结果 | 「没有符合条件的工作」，提供清除筛选，不误报没有历史 |
| 加载历史 | 列表骨架；已有对话不清空，不把加载中当成 0 条 |
| 对话读取失败 | 原位提示与重试，保留列表和输入草稿 |
| 工作已删除／无权访问 | 明确原因，允许返回列表，不显示上一项缓存内容 |
| 结果读取失败 | 面板内重试；对话继续可用，计数显示未知 |
| 文件已移动／不可读 | 保留结果记录并显示不可用原因；只提供实际支持的恢复动作 |
| 长员工名／长标题 | 合理截断，聚焦或提示可读取全称；不覆盖结果和过程入口 |
| 多员工编排 | 标题栏显示主身份与参与人数，完整名单在详情中，消息标明发言者 |
| 大量历史与长消息 | 列表按需渲染／加载；消息更新不重绘整份历史，不新增无必要依赖 |
| 新工作不符合当前筛选 | 创建成功后仍打开该工作；提示当前筛选不含它，不静默改写筛选条件 |

## 13. 实现边界与建议顺序

### 第一阶段：统一入口和工作外壳

把全局「安排工作／工作记录」入口合为「工作」，实现图标导航、悬停提示、列表／主区结构和响应式。先保留 `arrange`、`records`、`work` 作为内部路由状态，统一挂在工作外壳下，不强制重写路由系统。

旧的通知、命令入口、首页工作卡片与员工详情入口继续可用，统一落到工作空间的创建态或选中态。返回列表时恢复筛选与位置。对旧入口的兼容必须与新导航一起完成。

### 第二阶段：对话成为默认主体

复用 `WorkConversation`，压缩详情标题，移除常驻右栏，把结果、过程、工作信息放进统一面板。会话与编排均采用对话主视图，保留各自真实执行操作。

同步把媒体的查询和必要状态跟踪移至不会随面板卸载而消失的数据层，展示内容仍按需渲染。不能简单用条件渲染隐藏 `MediaArtifactsPanel`，导致后台状态和失败通知中断。

### 第三阶段：结果汇总与完整边界

统一文件／媒体的可用结果展示与计数，补齐待办提示、失败定位、草稿隔离、滚动保持、窄窗口、键盘和减少动态效果。必要时在 renderer 增加结果展示投影；若现有契约缺少可靠关联，先采用分组计数，另行明确最小契约变更。

建议组件边界如下，均为拟议命名：

| 责任 | 建议组件／文件 | 复用或调整 |
| --- | --- | --- |
| 全局导航 | `AppSideNav.tsx` | 改为默认图标轨道，沿用菜单与权限 |
| 工作空间组合 | `WorkHubPage.tsx` | 组织列表、新建、对话、详情及响应式 |
| 工作列表 | `WorkListPane.tsx` | 提取现有筛选与记录展示逻辑 |
| 工作创建 | `ArrangeWorkPage.tsx` 及现有 arrange 组件 | 作为工作空间的创建态 |
| 对话主区 | `WorkDetailPage.tsx`、`WorkTalkDrawer.tsx` | 提取可直接嵌入的内容，移除报表优先与重复抬头 |
| 按需详情 | `WorkInspector.tsx` | 结果／过程／信息共用一个容器 |
| 展示样式 | `enterprise.css`、`conversation.css`、相关工作样式 | 复用令牌，避免全局选择器影响其他页面 |

Renderer 继续通过既有 workspace、preload 与 IPC 工作。此次设计不改变后端运行状态机、授权策略、SDK 版本、文件访问与媒体计费语义。

## 14. 验收标准

1. 默认侧边栏只有图标：按钮水平居中，主导航组在企业与账号之间垂直居中，低高度下不裁切。顶部仅显示企业 Logo／图标，悬停和键盘聚焦可看到完整公司名。导航图标具有第 5.2 节的悬停／按下反馈；减少动态效果时取消缩放。所有提示和角标均不推动布局，企业按钮可点击且不受窗口拖拽区拦截。
2. 一级导航只出现一个「工作」入口，可以完成新建会话、新建自动／手动编排、查看历史和继续工作。
3. 五类状态均以「图标 + 数量」筛选，会话／编排以图标小标签展示与筛选；列表及标题栏不常驻状态或类型文字。悬停、键盘与读屏可获知完整含义，计数、重叠状态与类型未知场景符合第 6 节口径。
4. 发送消息后原位显示对话，默认不展示完整结果、过程或媒体侧栏；编排启动后也进入同一主视图。
5. 「结果」「过程」各一次点击可达；关闭后不丢失草稿、滚动位置或任务状态。
6. 待确认、授权请求、启动失败和媒体失败不会因详情关闭而不可感知；查看结果不等于确认或重新生成。
7. 真实已保存且可读取的媒体结果可以从结果入口找到；加载或读取失败时不会误显示结果为 0。
8. 切换工作时文字草稿、附件、结果与过程不会串项；流式回复时向上阅读不会被强制拉回底部。
9. 在 960×640、1280×800、1440×900、1920×1080 验证；浅／深色、键盘、中文输入法、减少动态效果均可用。
10. 通知、首页、员工详情、旧记录入口和返回行为全部连通；权限不足与已删除工作有明确反馈。

实施时运行 `npm run typecheck`、`npm run lint`、`npm run test:renderer` 与 `npm run build`；路由／层次边界受影响时运行 `npm run check:boundaries`。针对筛选计数、工作切换、详情面板、关闭面板后的媒体跟踪和待确认可见性补充行为回归覆盖。

视觉验收必须观察实际渲染的窗口与交互，包括悬停、焦点、展开、长文本和低高度窗口。本次交付只有文档，尚未进行改造后的运行或视觉验收。

## 15. 评审时需明确的两项

- **列表与对话的关系：** 本文推荐同屏，窄窗口按需打开列表；如果选择独立列表页，筛选和对话内部规范仍可沿用，需调整第 6、11 节及返回交互。
- **统一名称：** 本文使用「工作」，新建按钮使用「新建工作」，待处理符号的提示与可访问名称使用「待我处理」；实施前统一首页、通知、命令入口和空态中的相关文案。
