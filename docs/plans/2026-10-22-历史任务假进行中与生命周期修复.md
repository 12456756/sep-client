# 历史任务假进行中与生命周期修复

## 当前实施状态

第一阶段已落地：没有活动 run 的 `pending` / 陈旧运行快照不再计入进行中，详情页不再用 `createdAt` 伪造执行时长；任务快照已支持排队时间、当前/最近 run 起止时间和启动失败事实。首次执行、任务重试和自动编排启动失败会保存脱敏原因，重试准入后清除旧失败标记；等待审批后恢复运行保留同一 run 的开始时间。跨重启恢复会结束活跃 run，并清理暂停与 run 清理之间崩溃留下的旧准入，同时保留用户暂停状态。旧 run 的迟到列表或事件不能覆盖更新 run 或重试准备状态；新一轮重试可凭 run ID 和排队/真实开始时间重新进入活动态。

已验证：任务存储与恢复、普通/自动编排启动失败记录、并发不变量、前端状态投影/筛选/计时和旧事件保护回归测试通过。当前启动失败事实使用健康状态、时间和脱敏错误文本记录，尚未引入独立启动错误码或启动尝试 ID。后续仍需单独实施只读巡检、失联判定和灰度自动收敛；不会因本阶段修改而自动重跑或改写没有执行证据的历史任务。

## 问题

部分旧任务长期显示“执行中”，但没有实际 run、事件或产出；页面还把创建后的全部时间显示成执行时长。用户手动终止后，迟到 heartbeat 或旧事件不能再次激活任务。

## 已确认根因

- `src/features/enterprise/work-mapping.ts` 把所有 `pending` 映射为 `arranging`。
- 进行中筛选和首页数量只看这个映射，没有确认 `activeRunId`、队列登记或 worker 归属。
- `WorkDetailPage` 在缺少真实 `startedAt` 时用 `createdAt` 计算时长。
- 创建成功、准入成功、worker 启动成功和 run 持久化没有分开记录。
- 收尾跨多个异步写入，部分错误可能留下未收敛的任务状态。

## 目标方案

1. 将生命周期投影拆成：未开始、排队、启动中、运行中、等待审批、等待媒体、收尾、启动失败、失联、已暂停、已终止、已完成。
2. 用 `activeRunId + expectedRunId + stateRevision/generation` 判断当前执行归属。
3. 创建和启动分开记录；启动失败持久化 `startFailureCode`、脱敏原因和时间。
4. 无执行证据的旧 `pending` 只显示“尚未启动”，不自动启动、不强改为失败。
5. 已完成 run 但顶层 task 未更新时，只依据匹配的顶层 run、checkpoint 和交付证据修复。
6. 用户终止、归档、删除、新 run 和 scope 切换优先级高于迟到事件。
7. 排队时间、真实运行时间、暂停时间和媒体等待时间分开统计；没有 `startedAt` 时执行时长显示未知。

## 主要改动

- 新增 `electron/domain/task-lifecycle.ts` 纯分类与修复策略。
- 修改 `electron/runtime/task-manager.ts`、`task-runtime.ts`、`conversation-executor.ts`、`run-queue.ts`、`run-workers.ts`。
- 修改 `electron/data/task-store.ts`、`task-run-store.ts`，兼容旧数据。
- 修改 `electron/service/arrangement-service.ts`、`task-service.ts`、`task-creation-gate.ts`。
- 修改 `src/features/enterprise/work-mapping.ts`、`work-record-filters.ts`、`work-process.ts`、`WorkDetailPage.tsx`。

## 实施顺序

1. 用脱敏 fixture 复现无 run 的历史 `pending`，先实现只读分类。
2. 增加 start attempt、启动失败和准入 CAS。
3. 补齐 queue、worker、run、event drain、task settle 的幂等收尾。
4. 增加有界巡检和只读审计，确认失联后再灰度自动收敛。
5. 修正进行中筛选、状态文案和真实计时。

## 验收

- 旧任务不再显示执行动画，也不计入进行中。
- 创建七天但没有 `startedAt` 的任务不显示“已运行七天”。
- 真实排队、运行、审批和媒体等待仍能正确显示。
- 用户终止任务不被旧事件复活。
- 状态修复产生 0 次模型、工具和媒体提交。
