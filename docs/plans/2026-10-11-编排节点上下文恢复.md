# 编排失败节点上下文恢复

重试继续原逻辑节点，并通过 Pi SDK 0.83.0 的 SessionManager.open 加载该节点的 JSONL 会话。每次尝试仍创建独立 run 用于事件和监控归属；会话 ID、原任务目标及已保存的工具结果沿用历史记录。上游已完成节点及其输出保持在检查点中。

## 持久化关联

- ArrangementNodeCheckpoint.sessionRunId：最后成功登记会话的节点尝试。重试、暂停和恢复均保留该字段。
- TaskRunRecord.arrangementNodeId：所属逻辑节点。
- TaskRunRecord.resumedFromRunId：本次恢复来源的尝试。
- TaskRunRecord.sessionId / sessionFile：实际 Pi 会话标识及 JSONL 文件。多次尝试可以指向同一会话文件。

会话登记先保存 run 记录，再更新节点检查点。授权或准备阶段失败不会覆盖已有会话指针。旧检查点没有指针时，从父运行的编排节点事件定位历史节点 run；不按任务中最新 run 猜测会话。

## 恢复行为

1. 检查任务和节点状态、计划哈希，保护重试准入；授权失败保留原失败检查点，入队失败恢复检查点与任务状态。
2. 根据节点会话指针定位历史 run，核对员工、模型、工作目录及任务归属。
3. 验证会话文件真实路径位于当前任务目录内，JSONL 可解析、会话 ID 一致且记录链完整。
4. 打开历史会话，追加简短的继续指令。原目标与已完成工具结果从历史加载，不重新注入整份初始任务指令。
5. 完成后保存节点结果并释放下游节点。新父运行发送最小节点状态快照，使界面保留已完成进度。

如果之前没有创建会话，可正常开始该节点；如果已知历史会话缺失或损坏，则明确失败，不静默降级为空会话。存在已开始但未保存工具结果的副作用操作时，阻止直接重试，要求先核实操作结果；当前没有提供自动判断外部写入是否完成的能力。

## 流式失败与边界

缺少 finish_reason 的流仍视为失败，不把部分输出伪装成完成。手动重试恢复已经持久化的上下文，但不能恢复服务端尚未完成的生成状态或从某个 token 精确续传。未完成的模型回答需要在同一节点中重新生成，模型仍可能主动复查资料。

网关请求将 SDK 的 max_completion_tokens 映射为 max_tokens，避免输出预算被过滤；已有 max_tokens 优先。自动重试限制针对连续失败，成功的 SDK 轮次重置计数，既有重复工具循环保护继续生效。

生产日志中的约 30 秒连续中断需平台结合原始 SSE、网关超时和上游日志确认。参数映射修复并不能证明该超时已经解决。

## 验证重点

- 串行 A→B：A 完成一次，B 连续失败后恢复同一会话，A 不重跑。
- 真实 Pi SDK 配合本地模拟网关：两次中断后原目标只出现一次，两个成功工具结果均进入最终请求，会话 ID 一致。
- 旧记录恢复、会话缺失/损坏/跨任务路径、未确定副作用结果、授权及准入拒绝。
- 成功轮次重置自动重试预算，连续失败仍受限制，新运行界面保持已完成节点状态。
