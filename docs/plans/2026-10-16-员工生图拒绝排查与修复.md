# 员工生图拒绝排查与修复

## 实际原因

2026-10-16，UI 设计师任务 `2257cc60-c6ab-4172-bb76-84e5ddd1733e` 已调用图片能力查询，并尝试两次生成，不是系统提示词直接禁止调用。

1. 第一次指定 `quality=high`，但当前 Profile 没有向客户端声明质量选项，本地能力校验返回 `INVALID_ARGUMENT`。
2. 第二次省略质量参数后，报价请求缺少 `Origin` / `Referer`。生产 CSRF 防护返回 403，被客户端映射为 `PERMISSION_DENIED`；模型随后描述为权限拒绝并改交 HTML。
3. 员工职责提示词另有歧义：强调工具不能扩大职责，但未明确本职工作可以使用资料未逐项列出的通用工具。

## 修复

- `electron/data/sep-real-media-gateway.ts`：复用来源头 helper，默认使用 `config.SEP_WEB_ORIGIN`，为报价、提交、参考上传及恢复等请求带上可信 Web 来源。支持独立注入 Web origin，兼容 API 与 Web 分域；不关闭服务端 CSRF。
- `electron/pi/sdk/employee-system-prompt.ts`：按业务目标与交付物判断职责，明确本职工作可以使用获授权的图像生成、编辑等通用手段，不要求资料逐项写明或额外安装指定 Skill；职责外限制、费用和审批不变。
- `electron/pi/sdk/pi-coding-agent-adapter.ts`：工具说明要求先查能力，只使用已声明的参数，未声明质量选项时省略 `quality`。
- `electron/service/media-service.ts`：不支持的参数返回可操作的输入错误说明，避免误解为员工没有生图权限。
- 上述四处对应测试覆盖来源头、错误路径和职责规则；Pi 组装测试覆盖默认及自定义系统提示词下的媒体工具保留。

## 继续复测：启动前技能检查被限流

2026-10-16 用户再次反馈，安排工作页显示“操作过于频繁，请稍后重试”。此次错误发生在图片工具调用之前。

- 生产日志显示，10:32:05 至 10:32:14 集中出现约 196 次员工技能读取；10:32:39 起技能读取出现 429。10:33:13 和 10:33:15，当前员工的 runtime 请求均成功，但后续技能读取被 429 拒绝。
- 根因是工作区挂载和窗口重新聚焦会加载整批员工技能；技能库每次加载又会查询所有订阅的技能，累计耗尽技能接口每分钟 300 次额度。开发模式的过期 effect 还可能在失效后继续发出请求。
- 这不是图片执行被关闭，也不是员工职责提示词拒绝。没有调整生产限流或绕过任务启动前的员工技能授权检查。
