# 会话与编排知识库选择及按需检索开发文档

状态：已实施，真实平台联调待验收
创建：2026-10-29
范围：桌面客户端会话、编排、知识库详情页，以及现有知识库检索调用链

## 最新交互修订（2026-10-29）

根据最新确认，共用知识库选择器简化为知识库列表，以下规则覆盖本文后续的旧版三模式交互：

- 去掉“不使用 / 自动检索 / 手动检索”按钮，以及手动检索词、片段选择和引用表单。
- 新会话和新编排默认不选择任何知识库；选中一个或多个后，在所选范围内按需检索。
- 再次点击可取消选择；取消最后一个知识库即停止使用，不自动扩大检索范围。
- 按钮未选择时显示“知识库”，选择后显示“知识库 · N”；弹层保留列表筛选、分页和加载错误重试。
- 已保存的旧手动选择在选择器中转为普通知识库选择，去掉旧查询和片段引用。
- IPC 与运行时保留旧契约兼容；新的选择器仅输出空选择 `none` 或选中范围 `auto`，不向用户展示模式。

## 1. 背景与结论

当前知识库已经由平台统一托管，桌面端负责上传、权限范围内的资料管理和运行时检索。上传页面已经可以直接选择文件，但知识库检索入口仍以独立的“检索”页签呈现，普通会话也会在每轮默认调用检索。

本次调整把知识库使用入口移动到用户真正发起工作的地方：会话输入区和编排配置区。用户可以明确选择一个或多个自己有权限访问的知识库，也可以选择不使用；系统在自动模式下根据提示词判断是否需要检索，用户也可以手动发起检索并把结果引用到当前工作中。

桌面端知识库详情页中的“检索”页签应移除。它与新的会话/编排使用入口重复，且检索结果页不能生成回答，容易让用户误以为这里是正式使用入口。平台搜索接口、主进程搜索能力和 Web 管理员的检索验证页继续保留。

## 2. 产品目标

1. 用户在会话或编排中能看到清晰的“知识库”入口，不必先进入知识库详情页才能决定是否使用资料。
2. 用户可以选择一个知识库、多个知识库，或明确选择“不使用知识库”。
3. 自动模式只在提示词表现出知识需求时检索，避免当前普通会话每轮无条件请求造成的延迟和无关上下文。
4. 手动模式允许用户输入检索问题、查看命中片段，并将选中的结果引用到当前会话或编排节点。
5. 检索范围始终受平台权限控制；客户端不能因为用户选择失败或权限变化而扩大到其他知识库。
6. 知识库详情页聚焦文档上传、处理状态、版本和成员授权，保持页面简单。

## 3. 目标交互

### 3.1 会话输入区

知识库按钮放在会话输入框底部工具栏，位于员工/助手选择器之后、模型选择器之前，对应用户于 2026-10-29 提供的截图箭头位置。工具栏从左到右为：附件 → 员工/助手 → 知识库 → 模型 → 弹性空白 → 语音/发送。窄窗口下执行配置区可以换行，避免挤压发送按钮或溢出窗口。

按钮使用书本或资料图标，采用和员工、模型选择器一致的紧凑胶囊样式，不单独占一行，也不放进知识库管理页才能看到。未选择时显示“知识库”或“不使用”；有选择时显示数量和模式，例如“知识库 · 1 个”“知识库 · 3 个”。按钮旁不直接展示长名称，长名称在弹层中展示。

点击按钮打开向上对齐的轻量弹层，弹层锚定在按钮上方或工具栏上方，不能遮挡正在输入的文本。会话发送后保留本次选择，创建新会话时默认恢复为“不使用”，避免把上一个会话的资料范围误带到下一次工作。

按钮显示当前状态：

- `不使用`：本轮不调用知识库。
- `自动 · 1 个`：自动模式，限定到一个选中的知识库。
- `自动 · 多个`：自动模式，限定到多个选中的知识库。
- `手动 · 1 个`：手动检索模式，点击后输入检索问题。

点击按钮打开轻量弹层，内容包括：

1. 模式选择：`不使用`、`自动检索`、`手动检索`。
2. 当前账号可访问知识库列表，支持单选和多选。
3. 自动模式下显示说明：“仅在问题涉及企业资料、制度、流程或内部数据时检索”。
4. 手动模式下显示检索词输入框和“检索”按钮。
5. 手动结果展示文档名、知识库名、版本、位置和片段；用户可选择“引用到本次提问”。

弹层关闭后只保留按钮摘要，不在输入框中插入结构化标记。用户发送消息时，选择策略随请求进入主进程；知识库名称和检索结果不拼接到用户可编辑的原始提示词中。

第一阶段不把“未选择知识库”解释为“搜索全部可访问知识库”。未选择就是不调用，避免权限范围和调用成本不透明。后续如果需要全部范围，可增加明确的“全部可访问知识库”选项。

发送消息时只保存选择策略和知识库 ID，不把检索原文写入任务设置。手动引用的片段作为本轮不可信参考资料注入运行时，并在日志中脱敏。

### 3.2 编排配置区

会话和编排共用同一套选择器组件。编排的“会话”模式在底部输入工具栏使用相同位置；“自动编排”模式在目标输入框底部的执行配置区域使用相同样式，放在工作目录、权限和模型等运行设置附近。不要把知识库选择埋在节点列表末尾。

在编排草稿顶部增加默认知识库选择器，复用会话输入区的选择组件。默认策略会被所有节点继承，用户可以在节点详情中覆盖：

- `继承编排设置`：使用编排级模式和知识库范围。
- `不使用`：该节点不检索。
- `自动检索`：规划器根据节点目标生成可选的 `knowledgeQuery`，只有生成有效查询时执行搜索。
- `手动检索`：用户为节点填写检索问题，执行该节点前搜索并注入结果。

规划器必须知道用户选择的知识库名称和 ID，但只能把 ID 作为检索范围传给执行器。规划器不得因为没有内部知识需求而强行生成查询。

### 3.3 知识库详情页

桌面端详情页保留：

- 文档上传、替换、删除、失败重试；
- 文档处理状态、版本和解析预览；
- 成员授权（仅有权限的管理员显示）。

移除桌面端“检索”页签和 `KnowledgeSearch` 的页面入口。保留以下能力：

- `KnowledgeClient` 的 `search` action；
- 主进程 `KnowledgeService`/`KnowledgeApi` 的搜索实现；
- 会话和编排运行时调用；
- Web 端管理员检索验证页面及平台 `test-search` 兼容接口。

如后续需要桌面端管理员诊断，可新增独立的“管理员诊断”入口，不再把它放在普通知识库详情页的主流程中。

## 4. 行为模型

### 4.1 共享选择策略

建议新增共享类型：

```ts
type KnowledgeUseMode = 'none' | 'auto' | 'manual'

interface KnowledgeSelection {
  mode: KnowledgeUseMode
  knowledgeBaseIds: string[]
  manualQuery?: string
  sources?: Array<{ knowledgeBaseId: string; sourceId: string }>
}
```

约束：

- `mode === 'none'` 时 `knowledgeBaseIds` 必须为空，不能执行搜索；
- `mode === 'auto'` 或 `mode === 'manual'` 时至少选择一个知识库；
- ID 去重，最多 100 个，沿用现有平台契约；
- `manualQuery` 最多 1000 字符；
- 手动引用最多 20 个，仅保存知识库与来源 ID，主进程发送前重新读取来源正文及版本；
- 客户端只保存 ID，名称仅用于当前界面展示；
- 登出、切换账号、切换企业或权限刷新后清理失效选择。

现有平台搜索接口已经支持 `knowledgeBaseIds`，不需要新增一套检索 API。主进程搜索端口应将选择范围传给现有 `POST /knowledge-bases/search`。

### 4.2 自动模式的判断

自动模式不是“选了知识库就每轮检索”。选中的知识库表示允许检索范围，是否发起检索由轻量 knowledge gate 决定。

第一阶段 gate 使用确定性规则，至少覆盖：

- 用户明确提到“知识库、公司制度、内部资料、企业规定、员工手册、按照文档”等词；
- 用户明确要求查询、核对、依据、参考内部资料；
- 用户在提示词中提到当前选中的知识库名称；
- 用户要求回答企业内部流程、政策、历史记录或业务数据。

不命中 gate 时不调用平台搜索，模型直接处理用户问题。gate 不改变用户原始提示词，也不把知识库名称或规则写进系统提示词。

如果用户在提示词中提到一个当前未选择或已失效的知识库，客户端不能自动扩大范围。应提示用户先在“知识库”选择器中选择该库；如果用户没有权限，显示无权访问，不透露该库的额外内容。

后续可以把 gate 替换为低成本分类器，但必须保留“用户明确选择不使用”这一硬性开关。

### 4.3 手动模式

手动模式由用户显式点击“检索”触发：

1. 客户端提交 `manualQuery + knowledgeBaseIds`；
2. 展示检索状态、命中片段和来源信息；
3. 用户选择一个或多个片段后点击“引用到本次提问”；
4. 发送时把选中片段包装成不可信知识上下文，注入本轮 worker prompt；
5. 未点击引用时，检索结果只停留在弹层中，不自动影响回答。

手动检索失败、无权限、未就绪和无匹配必须分别展示，不能把服务错误当成“没有资料”。

### 4.4 会话运行时

当前 [conversation-executor.ts](/Users/yao/LLM/sep-client/electron/runtime/conversation-executor.ts:233) 对非 `general` 会话每轮自动搜索。本次改造后流程为：

```text
读取本轮 KnowledgeSelection
→ mode=none：直接运行 worker
→ mode=manual：使用用户已引用的片段，不再次自动搜索
→ mode=auto：运行 knowledge gate
    → 未命中：直接运行 worker
    → 命中：用当前问题 + knowledgeBaseIds 搜索
→ 将结果作为不可信参考资料注入 worker prompt
```

通用助手（`general`）与员工会话均支持知识库选择，并遵守同一套选择范围和按需检索规则。当前代码对 `general` 的搜索跳过逻辑需要改为按知识库策略判断；不能只增加按钮而继续无条件跳过。此调整只增加资料参考能力，不开启通用助手的员工技能或其他员工专属工具。知识库搜索应发生在 Pi worker 执行前，由 Electron 主进程完成；模型不能自行扩大知识库范围。

### 4.5 编排运行时

当前 [arrangement-executor.ts](/Users/yao/LLM/sep-client/electron/runtime/arrangement-executor.ts:489) 只要节点有 `knowledgeQuery` 就搜索，且规划校验目前要求节点查询非空。本次改造后：

- 节点 `mode=none`：不搜索；
- 节点 `mode=manual`：使用用户填写的查询搜索；
- 节点 `mode=auto`：规划器可生成查询，也可以返回空查询；空查询时不搜索；
- 节点没有局部设置时继承编排级策略；
- 执行器始终把 `knowledgeBaseIds` 传给搜索端口；
- 重试或恢复只按原节点策略重新执行，不回退到全部可访问知识库。

规划器提示词需要从“每个节点必须有 knowledgeQuery”改为“只有确实需要企业知识时填写 knowledgeQuery”。`knowledgeQuery` 保留 1000 字符上限。

## 5. 数据和接口改造

### 5.1 桌面共享契约

在 `src/shared/types.ts` 和 `electron/domain/arrangement-plan.ts` 中增加 `KnowledgeSelection` 或等价的稳定类型，并加入：

- 会话草稿/工作计划；
- 编排草稿；
- 编排节点局部覆盖；
- 运行时 `QueuedRun`/`WorkPlan`。

旧任务没有该字段时按 `mode=none` 兼容，不能因为历史任务缺字段而触发全量检索。

### 5.2 搜索端口

把当前 `KnowledgeSearchPort` 从只接收字符串扩展为：

```ts
interface KnowledgeSearchRequest {
  query: string
  knowledgeBaseIds: string[]
  topK?: number
  sources?: Array<{ knowledgeBaseId: string; sourceId: string }>
}
```

迁移期间可以保留适配器，避免一次性修改所有测试和调用点。最终所有正式运行时调用都必须显式传知识库范围。

### 5.3 IPC 和平台权限

现有知识库 IPC 已支持 `knowledgeBaseIds`，本次主要补齐调用方和状态传递。服务端仍是权限最终判定者：

- 选择已失效的知识库 ID 时，客户端刷新列表并清理该选择；
- 收到 404/403 时不得静默改为搜索其他知识库；
- Token、检索原文、命中片段和手动查询不得进入日志；
- 登出和账号切换时取消未完成的搜索请求。

## 7. 验收标准

### 会话

- 选择“不使用”时，发送任意消息，知识库搜索调用次数为 0；
- 自动模式下，普通闲聊不会搜索；明确要求企业制度或内部资料时搜索一次；
- 自动模式只搜索用户选择的知识库；多选时请求包含全部选中 ID；
- 手动模式只有点击“检索”才发起搜索，未引用结果不会进入 worker prompt；
- 通用助手和员工会话均能按选择策略检索；通用助手未选择知识库时调用次数为 0，选择后涉及资料的问题可以检索，且不会因此加载员工技能；
- 搜索失败不泄露 query、token 或资料原文到日志。

### 编排

- 编排级选择能够被所有节点继承；节点可以覆盖为不使用、自动或手动；
- 自动节点可以没有 `knowledgeQuery`，此时不搜索；
- 手动节点使用用户填写的 query 和选定知识库；
- 重试、恢复和并发节点不会丢失知识库范围；
- 计划和运行时快照中的知识库 ID 与权限变化可被重新校验。

### 知识库详情页

- 桌面端不再显示“检索”页签；
- 文档上传、状态、版本、预览和授权功能不受影响；
- 运行时会话和编排仍能调用同一个搜索服务；
- Web 管理员检索验证仍可用；
- 删除页签不会删除平台搜索接口或客户端内部搜索 action。

### 回归与联调

- 运行 renderer/typecheck/lint/build；
- 运行会话、编排、知识库契约和边界测试；
- 增加“无检索意图查询为 0 次”的回归测试；
- 使用真实授权测试账号验证单选、多选、撤权、切换账号和失效 ID；
- 联合验收上传完成、自动检索、手动检索、来源展示和平台 403/404 行为。

## 8. 分阶段实施

1. **契约和状态**：新增选择策略，接入会话/编排草稿和运行时快照，保持旧任务按“不使用”兼容。
2. **选择器和手动检索**：完成会话输入区、编排配置区、单选/多选、不使用和手动结果引用。
3. **自动 gate**：替换普通会话每轮无条件检索，增加明确的规则 gate 和取消/失败降级。
4. **编排按节点检索**：放宽 `knowledgeQuery` 必填约束，支持继承和节点覆盖。
5. **移除桌面检索页签**：删除普通入口，保留内部搜索服务和 Web 管理员验证。
6. **真实平台联调**：验证权限、失效选择、Origin/Referer、版本切换、撤权和恢复场景。

## 9. 风险与取舍

- 自动 gate 可能漏掉隐含知识需求，因此必须保留手动检索入口；后续可用低成本分类器提升召回。
- 选中多个知识库会扩大上下文和延迟，首版应限制最多 10 个用于 UI 选择，并沿用平台最多 100 个的接口上限。
- 撤权或知识库删除后，历史任务中的 ID 可能失效；运行时应明确提示并停止本次检索，不能扩大范围补偿。
- 手动引用内容仍是不可信资料，不能作为系统指令；继续使用现有上下文标记和日志脱敏。
- Web 管理员测试检索与客户端正式成员检索的权限语义不同，不能用 Web 测试替代桌面端真实验收。



## 10. 实施记录（2026-10-29）

已完成桌面会话与编排的共用选择器：不使用、自动、手动；会话按钮位于员工/助手之后、模型之前。知识库列表支持搜索与分页，手动检索支持来源片段选择和明确引用。切换范围或检索词会使旧结果失效；会话之间独立保存选择，成功发送后消费手动引用，避免带入下一轮。

自动编排在规划输入中获得经主进程校验的库 ID 与名称；模型只生成可选的 `knowledgeQuery`，不能改写用户的知识库选择。节点可继承全局、单独覆盖或关闭；手动节点可只填写查询，执行前检索。自动节点缺查询时不检索。手动编排也支持相同设置。

主进程显式传递检索范围并校验返回来源，权限失败不扩大范围。手动引用通过现有来源接口重新读取，保留来源、版本和历史版本标记。运行快照保存选择策略，支持续聊和重试。通用助手支持同样的知识参考能力，并继续使用原有工具与技能边界。

桌面知识库详情只保留文档、版本预览与授权管理入口；平台 Web 和管理员诊断接口没有修改。原 `KnowledgeSearch` 组件暂保留为内部候选实现，已无普通页面入口。

验证记录：类型检查、生产构建、边界检查、针对修改文件的 ESLint 和四项 SDK POC 均通过。后端全套 2319 项通过、1 项跳过；前端 494 项通过；运行时不变式 202 项通过、1 项跳过；Chromium 选择器/知识库管理页面 11 项通过（含按钮顺序与窄屏截图检查）。全仓 ESLint 受既有生成产物与历史脚本问题影响，未扩大本次改动范围处理。
