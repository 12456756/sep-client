# 电商图片客户端与 SEP 联调记录

> 日期：2026-10-12。范围：SEP 当前源码合同、客户端协议消费、非收费测试。
> 状态：runtime 配置合同已对齐；真实 SEP 在线执行链路与真实模型验收未完成。

## 1. 已确认的服务端实现

- SEP 的 runtime 路由为 `GET /api/client/subscriptions/:subscriptionId/runtime`，使用普通 access token。
- 媒体配置扩展通过 `?mediaProtocolVersion=1` 协商。旧响应没有媒体字段时，普通对话继续工作。
- 权威字段位于 `SEP/backend/src/shared/media.dto.ts`；配置阶段提供 `executionAvailable`、`defaultProfileId` 和 Profile 的参考图/数量/尺寸约束。
- 当前 `media-config.service.ts` 固定返回 `executionAvailable: false`、`tools: []`。Profile 配置不代表生成已经开放，不能推断取消或恢复能力。
- SEP 当前只有媒体配置接口，没有可调用的参考上传、报价、生成提交、回执查询、内容下载及取消 Controller；协作合同也将这些执行接口标为草案。
- 只读探测时 `localhost:3001` 没有监听，健康、runtime 和配置请求均连接失败（HTTP 000 / ECONNREFUSED），不能记为真实服务通过或权限拒绝。
- 电商员工 seed 不等于实际图片 Skill 已批准发布；尚无在线订阅、Skill 分发和图片执行授权的验收证据。

## 2. 本次客户端修正

- `platform-api.ts` 请求增加正式媒体版本 query，严格校验真实 SEP 配置片段。格式不兼容、含私密额外字段或尚不支持的执行声明会被省略；不阻断普通聊天，不输出原始响应。
- 新增 `sep-media-runtime-contract.ts`，按 SEP 当前配置 schema 校验，不将本地 mock 的执行字段假装成 HTTP 合同。
- `media-contract.ts` 接受合法配置阶段响应，但转换为空执行能力；配置 Profile 不会启用工具、报价或生成。
- 图片面板的服务投影明确区分“SEP 图片执行接口尚未接通”与“员工无可用图片能力”。没有媒体网关时，读取历史不发起授权或生成。
- 复制 SEP 的脱敏 `media-runtime-v1.json` 到客户端 fixtures，逐字比较一致。未来字段变更须先同步权威 schema/fixtures，再改客户端。
- 新增真实 loopback HTTP 传输的 fixture 测试，覆盖路径、query、Bearer、两种配置响应、旧响应及 401。此服务器只返回静态数据，不是实际 SEP 或模型。
