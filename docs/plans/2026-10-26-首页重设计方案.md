# SEP 首页重设计方案

日期：2026-10-26  
状态：方案草案，供评审；本轮已撤回上一版主页实现，不继续开发新方案。  
范围：桌面客户端个人首页。  
关联文件：`src/pages/enterprise/HomePageRedesign.tsx`、`src/styles/home-v2.css`。

## 1. 结论与方向

首页承担三个任务：**开始一项工作、继续已有工作、找到协作员工**。

推荐采用「一个新建入口 + 一个工作摘要区 + 一行员工入口」的结构。首屏只有一个主要内容区；工作状态通过切换视图查看，员工在下方作为次要入口。所有工作共用一个列表，不再同时展示两份内容重叠的工作列表。

这是待评审的新建议，不代表已经确认的视觉稿。上一轮设想的三栏布局、独立统计卡、快捷入口卡片组，不再作为下一轮实现依据。

## 2. 上一版为什么显得乱

依据用户提供的客户端截图，可以确认这些问题：

| 问题 | 截图表现 | 新方案要求 |
| --- | --- | --- |
| 页面边界失控 | 工作列表底部与“快速入口”标题接近或重叠，员工区被挤到页面下方 | 模块按文档流排列，数量有上限，不用绝对定位拼接页面 |
| 滚动方向过多 | 工作区出现内部纵向滚动和横向滚动 | 首页摘要不设内部滚动，不出现横向滚动条 |
| 信息重复 | 同一项工作出现在“需要处理”和“最近工作”两处 | 用一个列表切换不同范围 |
| 入口重复 | 顶部新建、底部对话/编排、模板条和自动安排分别占位 | 首页只保留一个明确的新建入口，具体方式在已有工作空间选择 |
| 重点不清 | 问候、统计卡、工作列表、快捷入口、员工都在争取注意力 | 工作内容优先，员工其次，统计退为筛选数量 |
| 摘要缺少行动提示 | 失败和等待处理的行突出显示 0% 或 50% | 提示真实下一步；无法可靠计量时不展示百分比 |

这些是渲染结果与信息结构上的问题。具体 CSS 冲突需要下一轮实现时检查共享样式、容器高度和网格收缩行为，不能只靠调整间距修复。

## 3. 首屏结构

以下是结构线框，用于确认内容位置与优先级，不是最终配色或视觉稿。

```text
现有图标侧栏 │ 现有应用顶栏：个人 / 企业、命令入口、主题、通知
─────────────┼─────────────────────────────────────────────────
             │
             │  今天，想让团队做点什么？             [＋ 新建工作]
             │  选择员工开始对话，或安排一项多人协作工作。
             │
             │  继续工作                              全部工作 →
             │  [最近] [工作中图标 15] [待处理图标 6] [完成图标 1]
             │  ──────────────────────────────────────────────
             │  状态图标  工作标题                 类型标签   时间
             │            当前员工 · 下一步 / 最近进展
             │  ──────────────────────────────────────────────
             │  状态图标  工作标题                 类型标签   时间
             │            当前员工 · 下一步 / 最近进展
             │  ──────────────────────────────────────────────
             │  ……按可用高度展示 3～5 项，其余进入全部工作
             │
             │  我的员工                              全部员工 →
             │  头像 姓名/职责    头像 姓名/职责    头像 姓名/职责
             │
```

### 3.1 开始工作

- 标题控制在一句，作为任务邀请，不拼接“姓名 + 问候 + 页面介绍”的长句。
- 只保留一个品牌色主按钮：`新建工作`。
- 点击进入已有的安排入口 `{ name: 'arrange', mode: 'pick' }`。
- 对话、自动编排、手动编排、模板和已保存流程继续在现有工作空间中选择。开发前确认这些入口均可到达；如某项目前不可到达，应在工作空间补齐承接方案，不能在首页做一个名称相似但去往其他功能的按钮。
- 第一版不新增首页消息输入框，避免与正式工作区形成两套草稿和发送逻辑。

### 3.2 继续工作

- 首页的主体，使用一个摘要列表。
- 默认查看“最近”，按真实 `updatedAt` 倒序展示。
- 顶部切换范围：最近、工作中、待处理、已完成。
- “最近”保留短文字；其余使用状态图标和数量，鼠标悬停或键盘聚焦时显示名称与数量。
- 切换只改变当前列表内容，不产生第二个面板，不改变应用路由。
- “全部工作”进入与当前范围对应的完整工作列表。那里负责搜索、完整筛选、置顶、重命名和删除操作。
- 首页不新增一套工作右键菜单；需要管理记录时进入已有工作空间。

每行只展示这些信息：

| 位置 | 内容 | 规则 |
| --- | --- | --- |
| 行首 | 状态图标 | 使用已有状态组件，提供完整状态提示 |
| 第一行 | 工作标题、会话/编排标签、更新时间 | 标题优先占宽；类型来自权威分类；时间不换行 |
| 第二行 | 当前员工、下一步或最近进展 | 使用真实内容；没有可靠摘要时只显示员工 |

行高建议 68～76px。标题默认单行截断，悬停和聚焦可查看完整标题。主标题不缩小到难以阅读以换取更多条目。

点击整行进入 `{ name: 'work', workId }`，发送消息后继续使用现有以对话为主的工作页面。工作过程、产出结果、工作信息沿用现有浮层，不在首页展开。

### 3.3 我的员工

- 作为新对话入口，放在工作摘要下方。
- 最多显示 4 位；紧凑窗口显示 3 位。其他员工通过“全部员工”查看。
- 员工以头像、姓名和一行职责展示，不加卡片外框，不展示推测的空闲/忙碌百分比。
- 默认优先展示近期参与过用户工作的员工，其余保持原有目录顺序；关联依据为工作参与者或当前员工 ID。
- 来源为当前用户已获授权的真实员工，不混入企业未分配员工。
- 点击进入 `{ name: 'arrange', mode: 'chat', employeeId }`。
- 不可用或需要授权的员工必须显示真实原因，并进入已有员工详情处理；不能当成可直接开工的员工。
- 没有头像时使用现有姓名首字或头像组件，不显示破损图片。

## 4. 状态图标与标签

延续用户希望的“以图标显示，悬停预览文字”。不使用 emoji 建立第二套状态语言。

| 状态 | 图形语义 | 颜色角色 | 悬停 / 聚焦提示 |
| --- | --- | --- | --- |
| 工作中 | 现有工作中圆环图标 | 蓝色 | 工作中，员工正在处理 |
| 待处理 | 圆内叹号 | 琥珀色 | 待处理；有真实下一步时同时显示 |
| 已完成 | 圆内勾 | 绿色 | 已完成 |
| 失败 | 现有失败图标 | 红色 | 工作失败，打开查看原因 |
| 已暂停 / 用户终止 | 现有暂停或停止图形 | 中性色 | 根据真实状态说明 |
| 安排中，尚未运行 | 现有准备状态图形 | 中性色 | 安排中，尚未开始执行 |

实现必须优先复用 `WorkStatusIcon`、`WorkTypeTag`、`workStatusLabel`、`IconHint`。表格描述图形意图，不要求再造一套相似图标。

- 状态区不反复打印“已完成 / 工作中”等字样，完整名称通过提示与可访问名称提供。
- 会话、编排保留小标签，使用图标和短文字，布局样式与工作列表一致。
- 类型加载中、类型不可用必须保持未知状态，不能根据旧 `kind` 字段猜测后显示为“会话”。
- 图标形状也要区分状态，保证灰度下仍可辨识。
- 提示约 200ms 出现，支持键盘聚焦；不能只给不可聚焦图标加原生 `title`。
- 提示浮层不能被列表或页面容器裁掉。

## 5. 数据与筛选口径

首页与完整工作列表使用同一套业务口径。

| 首页范围 | 数据规则 | 查看全部目标 |
| --- | --- | --- |
| 最近 | 全部工作，按更新时间倒序 | `records / all` |
| 工作中 | `isActive === true` | `records / active` |
| 待处理 | `status === 'waiting-user'` 或存在 `nextUserAction` | `records / mine` |
| 已完成 | `status === 'completed'` | `records / done` |

- 复用 `work-record-filters.ts`，避免首页和工作页出现两个“待处理”定义。
- 失败和暂停保留在“最近”中并显示实际状态；仅当存在下一步动作时进入“待处理”。不把所有失败、暂停自动并为待处理。
- 尚未启动的编排不能仅因 `status === 'arranging'` 计入工作中。
- 数量取完整筛选结果，之后再裁剪首页条目；不能对 `slice(0, 5)` 的结果计数。
- 首页不显示“今日完成”，避免把历史工作更新误算为今天交付。
- 不展示虚构进度。特别是会话、异步媒体生成、等待用户和失败状态，不能用 0% 暗示可靠的执行进度。
- 列表更新保持当前筛选，不因流式消息强制切换视图或抢走键盘焦点。

## 6. 视觉规格

目标是清晰的桌面工作界面，色彩用于行动、状态和选中反馈。

- 页面使用安静的浅色或深色表面。首页范围内不再叠加装饰渐变和额外模糊层。
- 工作摘要可以有一个统一表面；内部各行使用留白和细分隔线，不每行再套一层卡片。
- 主按钮使用品牌红；工作中蓝、待处理琥珀、完成绿、失败红。
- 图标选中态使用语义浅底，未选中态更轻。整块背景不随工作状态大面积变色。
- 深色模式使用项目语义变量与专用状态对比色，不能只把白色背景反转。
- 标题约 22px，模块标题 15px，工作标题 14px，正文与辅助内容 12～13px。正文不使用 9～10px 以塞入更多信息。
- 数量和时间使用等宽数字特性，避免实时更新时宽度跳动。
- 间距基于 8px；模块之间 24～32px，同一条记录内部 4～8px。
- 页面内容宽度建议上限 1200px，宽屏居中；不随窗口无限拉长标题和行间距离。
- 仅 hover/focus/按下和切换视图有短反馈，约 140～180ms。不做循环旋转、脉冲、依次入场。
- `prefers-reduced-motion` 下关闭非必要位移与切换动效。

## 7. 尺寸与溢出策略

先计算应用内容区尺寸，再选择布局。不能只按照窗口总宽度判断，因为侧栏、窗口栏和顶部栏也会占空间。

| 场景 | 工作摘要上限 | 员工上限 | 布局行为 |
| --- | --- | --- | --- |
| 常规桌面，例如 1440 × 900 | 5 项 | 4 位 | 单一主列表，完整展示三个层级 |
| 较矮窗口，例如 1280 × 720 | 3 项 | 3 位 | 减少摘要数量和模块间距，不压缩行内容 |
| 最小桌面窗口，例如 960 × 640 | 3 项 | 3 位 | 标题简化，员工职责按空间截断，核心入口可见 |
| 更小尺寸或系统文字放大 | 按上述紧凑上限 | 最多 3 位 | 允许唯一的页面纵向滚动，保证内容可达 |

统一规则：

1. 首页列表和员工区域不设独立滚动，不引入横向轮播。
2. 通过展示上限和“全部工作 / 全部员工”承接更多数据，不能用裁切隐藏模块。
3. 文本容器有 `min-width: 0`，网格列可收缩，长标题不会挤出横向滚动条。
4. 不用负 margin、固定定位或 transform 将下方模块叠到列表上。
5. 不用 `overflow: hidden` 掩盖无法放下的内容；高度不足时优先减条目，仍不足就允许页面滚动。
6. 返回首页或切换筛选后从摘要顶部展示，不恢复到列表中间造成首行半截可见。

## 8. 空状态、加载与错误

| 场景 | 表达 | 可执行动作 |
| --- | --- | --- |
| 没有任何工作 | “还没有工作，从第一项开始。” | 新建工作 |
| 当前筛选为空 | 与筛选相符，例如“暂时没有待处理工作。” | 切回最近 |
| 没有员工 | “暂时没有分配给你的员工。” | 查看员工目录或现有授权说明 |
| 工作仍在读取 | 适量骨架行 | 不提前宣布“没有工作”或显示伪造的 0 |
| 工作读取失败 | “工作记录暂时无法读取。” | 调用已有重试能力；无能力时先明确接口缺口 |
| 类型读取失败 | 保留工作，类型标记为未知 | 复用现有分类重试 |
| 员工头像失败 | 姓名首字回退 | 不影响员工入口 |
| 员工不可用 | 显示具体可用状态 | 进入详情查看原因 |

当前 `EnterpriseWorkspace` 没有独立的工作列表加载/错误字段。下一轮若实现工作读取骨架和重试，必须先梳理已有初始任务查询的状态；不能拿全局 `busy` 当作列表加载状态，也不能在首页静默吞掉读取错误。

## 9. 开发边界

本轮只做回滚和本文档。后续实现应限制在首页、首页摘要的数据投影与必要的样式文件。

保留已完成的产品交互：

- 主导航继续使用居中图标、企业图标、悬停名称和已有动效。
- 工作列表与对话的现有布局不变。
- 工作过程、产出结果和工作信息继续按需打开浮层。
- 不恢复分享功能，不引入归档操作。
- 不修改 Electron 运行时、IPC、安全配置或依赖版本。

实现注意：

- 新首页类名使用统一专属前缀，避免 `.section-header`、`.count` 等通用选择器污染其他界面。
- 对状态、类型和时间的表达复用已有组件与工具。
- 先完成工作摘要和尺寸适配，再加入员工入口；每一阶段都在真实客户端查看。
- 未确认的新方案不写成 `DESIGN.md` 的既定系统规范。

## 11. 评审重点

下一轮首先确认以下三点，再进入视觉稿与开发：

1. 首页采用单一工作摘要，状态通过切换查看，不同时铺开多栏。
2. 保留一个新建入口，具体工作方式在已有工作空间选择。
3. 员工区保留为一行轻量入口，不再占据主体位置。

确认结构后，应先给出一张实际尺寸的静态视觉稿，并包含一组有待处理、有运行中、有完成工作的内容示例。视觉稿里的示例必须标为示意数据，不进入正式业务数据。
