# 龙硅客户端「企业组织」横向组织关系图设计与开发方案

> 状态：横向树状图 Phase 1 已开发，折叠体验已补齐，待视觉验收；Phase 2 / Phase 3 待继续收口  
> 日期：2026-09-27  
> 适用范围：Electron 客户端「企业」视角 / 组织架构页  
> 关联代码：`src/pages/enterprise/OrganizationPage.tsx`、`src/features/enterprise/organization-map-model.ts`、`src/styles/enterprise.css`  
> 设计约束：只读展示；不增加组织管理权限、不新增后端接口；保留 SEP 返回的真实组织成员和授权关系，不从本地订阅员工推造组织数据。

---

## 1. 最终布局方向

本页不采用传统的“从上到下”组织树，也不采用部门卡片网格。

页面采用适合横向桌面屏幕的 **四列横向树状组织关系图**：

```text
公司  →  部门  →  子部门/碳基员工  →  硅基员工
```

四列从左到右固定排列：

1. **公司列**：展示企业名称和企业总成员数。
2. **部门列**：展示企业下的部门，以及未归属部门分组。
3. **碳基员工列**：展示该部门下真实的企业成员。
4. **硅基员工列**：展示当前碳基员工实际被授权 / 可使用的硅基员工。

它保留传统组织树的父子连接关系，只把树旋转为从左到右：公司节点连接多个部门，部门节点连接成员，成员节点连接其真实授权的硅基员工。用户可以同时看到完整关系，而不是依赖点击后才切换右侧列表：

> 我所在的企业 → 我所在的部门 → 我是谁 → 我可以使用哪些硅基员工。

## 3. 四列设计细则

### 3.1 第一列：公司

- 位于组织图最左侧。
- 公司节点在视口中保持稳定，不被右侧内容遮挡。
- 展示企业名称、企业类型、企业成员总数。
- 使用品牌红浅色边框和企业图标作为视觉锚点。
- 不把公司节点伪装成部门或普通人员卡片。

示意：

```text
┌──────────────┐
│  企业         │
│  龙硅科技      │
│  42 位成员     │
└──────────────┘
```

### 3.2 第二列：部门

- 部门按纵向列表排列，但整体属于横向关系图的第二列。
- 每个部门展示：部门名、成员数量、展开 / 收起状态。
- 子部门仍然位于部门关系列中，但使用真实的横向嵌套分支与连接线表达父子关系；子部门节点位于父部门右侧，不把不同层级的部门平铺成上下并列项。
- “未归属部门”作为真实数据关系下的独立分组。
- 不根据成员职位、订阅关系或本地数据猜测部门归属。

示意：

```text
部门
├── 研发部       12 位成员
├── 产品部        8 位成员
├── 市场部        6 位成员
└── 未归属部门    2 位成员
```

### 3.3 第三列：碳基员工

- 只展示 SEP 返回的真实碳基企业成员。
- 成员按左侧当前部门分组排列。
- 展示头像 / 姓名首字占位、姓名、职位。
- 当前登录用户显示轻量“我”标记。
- 点击成员后，第四列展示该成员真实的硅基员工授权关系，同时打开现有详情抽屉。
- 成员很多时，第三列内部使用纵向滚动或“展开更多”，不能把页面高度无限撑开。

示意：

```text
碳基员工
├── 张三       工程师       我
├── 李四       产品架构师
├── 王五       工程师
└── 展开更多（还有 18 人）
```

### 3.4 第四列：硅基员工

- 展示当前选中碳基员工实际拥有的 `employeeIds` 对应硅基员工。
- 只显示真实授权关系，不展示全部本地订阅员工。
- 展示硅基员工头像、名称、能力 / 状态和可用入口。
- 如果该成员没有授权硅基员工，显示：

```text
暂未配置可用的硅基员工
```

- 没有选中碳基员工时，显示轻量提示：

```text
选择左侧成员，查看其可使用的硅基员工
```

- 选中硅基员工后仍使用现有员工详情导航和权限规则。

## 4. 连接关系与视觉层级

### 4.1 连接线

使用从左向右的关系线表达四列关系：

```text
公司节点 ─────▶ 部门节点 ─────▶ 子部门/碳基员工 ─────▶ 硅基员工
```

- 连接线使用低对比度企业中性色。
- 当前选中的关系链使用品牌红或品牌红浅色高亮。
- 未选中的关系线保持安静，不制造视觉噪音。
- 连接线是辅助信息，节点文本必须本身可读。
- 不使用动态粒子、流动光线或持续动画。

### 4.2 四列视觉权重

| 列 | 视觉权重 | 主要目的 |
|---|---:|---|
| 公司 | 最高 | 明确当前企业范围 |
| 部门 | 中高 | 明确组织归属 |
| 碳基员工 | 最高 | 用户识别和选择真实成员 |
| 硅基员工 | 中 | 展示授权结果和下一步操作 |

### 4.3 选中状态

选中某个部门时：

- 部门节点红色浅底 / 边框高亮。
- 对应碳基成员列自动定位到该部门成员。
- 硅基员工列显示空状态或部门级提示，不伪造授权数据。

选中某个碳基员工时：

- 员工节点红色描边。
- 当前部门和公司节点保持弱高亮，帮助用户理解路径。
- 硅基员工列刷新为该成员的真实授权列表。
- 右侧详情抽屉展示成员信息。

## 5. 查找与交互

### 5.1 保留轻量搜索

当前全局命令入口只支持页面 / 操作，不支持企业成员定位，因此保留一个轻量搜索入口：

- 支持搜索公司、部门、碳基员工姓名、职位。
- 搜索部门时，定位到部门列并展示该部门成员。
- 搜索碳基员工时，自动选中其公司 → 部门 → 成员路径。
- 搜索硅基员工时，仅在当前真实授权关系中匹配，不搜索本地未授权员工。
- 搜索入口不与缩放、筛选、适应屏幕按钮混排。

### 5.2 不提供的操作

- 不提供放大 / 缩小。
- 不提供缩放比例。
- 不提供自由拖动画布。
- 不提供部门管理、成员编辑、权限编辑。
- 不提供从本地订阅员工反推组织关系的快捷操作。

### 5.3 成员详情

沿用现有详情抽屉：

- 成员姓名、职位、所属部门。
- 当前成员标记。
- 平台真实返回的硅基员工授权关系。
- `assignedToMe`、availability 等现有权限和状态规则不改变。
- `Escape` 关闭抽屉，关闭后保留当前四列选中关系。

## 6. 横向屏幕布局规范

### 6.1 桌面端

四列使用稳定的最小宽度，优先保障横向关系清晰：

```text
公司列       部门列          碳基员工列             硅基员工列
180px        220px           280px                  300px+
```

- `1440 × 900`：四列完整可见，常用关系链无需横向滚动。
- `1280 × 800`：四列保持可读，硅基员工列可在内容区内滚动。
- `1100 × 720`：公司列和部门列固定，右侧两列允许横向查看。
- `960 × 640`：保持四列顺序不变，组织图内部横向滚动；不压缩文字。

### 6.2 滚动行为

- 页面整体不出现无意义的横向滚动。
- 组织关系区域可以横向滚动，但四列顺序不改变。
- 公司列固定在左侧，向右查看成员和硅基员工时仍能识别企业范围。
- 每一列成员列表可以独立纵向滚动，避免页面高度被单列长列表撑爆。
- 不通过缩小节点来“强行塞进一屏”。

### 6.3 macOS / Windows

- 不修改全局标题栏、窗口控制按钮和拖拽区。
- 组织图从应用内容安全区开始，避免覆盖 macOS 左上角按钮。
- 滚动条出现或隐藏不能造成四列跳动。
- 鼠标滚轮、触控板横向滚动和键盘操作均可浏览关系。
- Windows 和 macOS 下节点最小宽度、字体和连接线保持一致。

## 7. 数据与架构边界

- 公司、部门、碳基员工均来自 SEP 返回的 `OrganizationCarbonEmployee` 关系。
- 部门归属只使用平台返回的 `parentId` 或明确关系，不根据职位文字猜测。
- 硅基员工只使用当前碳基员工的真实 `employeeIds` 授权关系。
- 不将 `workspace.employees` 的全部订阅员工展示到第四列。
- 不从硅基员工的 availability 推断碳基员工状态。
- 负责人字段缺失时显示“负责人信息暂未提供”，不把第一个成员当负责人。
- 异常 parentId、空关系和环形关系应防御性展示，不能让整个页面白屏。

## 8. 分阶段开发计划

### Phase 1：四列横向关系结构

- 移除当前部门卡片网格作为主布局。
- 建立公司、部门、碳基员工、硅基员工四列。
- 实现从左到右的关系连接线和当前关系高亮。
- 实现部门 → 碳基员工 → 硅基员工的真实数据联动。
- 保留 loading / empty / error / retry 状态。

**验收标准：**

- 页面第一眼就是四列：公司 → 部门 → 碳基员工 → 硅基员工。
- 公司名称在最左侧，不位于页面顶部居中。
- 不再出现部门卡片网格，也不再把组织关系从上到下堆叠。
- 选中碳基员工后，右侧展示其真实硅基员工授权关系。
- 没有授权关系时有明确空状态。
- 不从本地订阅员工推造任何企业组织数据。

### Phase 1.1：一屏优先的折叠体验

- 默认只展开当前用户所在部门；没有当前用户时展开第一个部门。
- 其他部门保留部门节点与成员数量摘要，点击节点或摘要即可展开。
- 默认只展开当前用户的硅基员工关系，其他碳基员工保留授权数量摘要。
- 搜索时自动展开匹配路径，避免搜索结果被折叠隐藏。
- 折叠摘要保留横向连接线，仍能直观看到公司 → 部门 → 成员 → 硅基员工的关系。
- 大组织继续保留容器滚动作为兜底，但默认视图减少垂直占用，优先在一屏展示主干。

### Phase 2：关系交互与人物表达

- 完善部门 / 碳基员工 / 硅基员工节点的头像、姓名和职位层级。
- 完善选中链路高亮、轻量搜索和详情抽屉联动。
- 完善键盘焦点、读屏文本和暗色主题。
- 对大部门增加局部滚动或展开更多。

### Phase 3：规模与跨平台收口

- 使用 1 / 6 / 20 / 50+ 部门和成员 fixture 检查四列关系。
- 检查多个硅基员工授权、无授权、超长名称和同名人员。
- 检查 960、1100、1280、1440 宽度下的横向浏览。
- 检查 macOS / Windows 标题栏、滚动条和详情抽屉。
- 删除不再使用的旧树画布和部门网格样式。
- 运行 `npm run test:renderer`、`npm run typecheck`、`npm run lint`、`npm run build`。
