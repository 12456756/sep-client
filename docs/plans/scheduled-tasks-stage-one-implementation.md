# 本地定时任务阶段一实现记录

更新：2026-10-20。本文件记录实际实现，不将后续阶段或原始专家建议作为已交付能力。

## 当前范围调整

定时任务现在是左侧栏的独立模块，位于“安排工作”与“工作记录”之间。工作记录不承载定时任务管理界面，只展示实际工作结果，并提供“定时触发”来源链接。此前撤下的入口没有恢复到工作记录中；本次为独立模块重新接通经过校验的 IPC。

## 本次闭环

1. 从左侧“定时任务”新建任务，选择一名已授权员工、模型、工作目录、权限、执行时间和时区。
2. 保存任务定义后，调用既有 PiTaskWorker 分析员工职责和需求，生成单员工工作指令及文件交付合同。规划禁用工具，不执行用户任务。
3. 用户只读查看合同并确认启用。不能编辑计划节点；修改需求会清除旧合同。修改时间、名称、目录和权限保留合同，但必须重新确认。
4. 到期生成唯一执行记录，在独立成果子目录通过原有 TaskRuntime、ArrangementExecutor 和 PiTaskWorker 执行。
5. 使用原有真实文件交付校验。聊天回复不是完成依据；校验失败只在当前会话修正，最多五次，不新建任务重跑。
6. 独立模块分别展示任务列表、创建/编辑表单，以及详情中的“执行记录”和“任务配置”。每个时间点可查看状态、启动尝试、错误、配置快照；成果链接到既有工作详情并可返回原任务。任务修改始终更新原定义 ID，历史执行保留自己的配置快照。

本阶段仅支持单员工、指定时间执行一次。周期、Cron、自动编排快照复用、可配置重叠策略和执行进程隔离属于后续纵向闭环，尚未实现。

## 数据与去重

- 按现有企业和用户作用域，保存 `scheduled/state.json`。聚合文件版本为 1，包含任务定义、执行记录和尝试；升级后在首次操作时创建，无旧记录迁移。
- 同作用域写链串行化。写临时文件、同步文件、同目录 rename 替换；不先删除主文件。调度记录不自动从旧备份回滚，避免恢复未消费的触发点。
- 定义包含 revision、输入配置、只读合同、启用状态和 nextRunAt。修改和确认必须携带预期 revision。
- 执行 ID 为任务定义 ID 与原计划 UTC 时间的哈希，与配置版本无关。
- 生成执行记录与消费 nextRunAt 是一次聚合写入，成功后才能尝试启动。
- 每次执行先固定普通任务 ID，并在普通任务首次持久化时绑定来源；重试准备工作复用该 ID。
- 启动前先持久化 launching；普通任务准入时永久保存 scheduledAdmission。已有凭据的任务不能再次准入。普通任务的执行、重试以及对话追加/换员工接口拒绝定时来源，防止在准入前从其他入口抢跑；工作摘要只读。
- Electron 单实例限制避免两个客户端同时领取同一份文件。该方案不是跨设备协调协议，不支持多进程直接修改同一存储。

## 定时与生命周期

- 单个动态定时器，配置新增、修改、确认、暂停、删除后立即请求扫描；重复请求合并，不同时运行两个扫描。
- 有待执行任务时，最迟 60 秒校准一次系统时间；执行中约 2 秒检查状态。没有待处理工作时不保留调度计时器。
- 登录成功后恢复；休眠唤醒后请求扫描；注销、认证失效、退出和安装更新前停止调度。安装失败时恢复。
- 已启用任务在离线或休眠期间错过时间：24 小时内仅补执行该次，超过窗口生成 missed 记录。
- 暂停或尚未确认的任务不能启用过去时间，必须修改为未来时间，避免把主动暂停当作离线漏跑。
- 暂停只取消未来触发，不取消已经生成的执行实例；停止本次执行是独立动作。删除采用软删除，执行历史保留，非终态执行未处理前拒绝删除。
- 启动等待最多 1 小时，且不超过原定时间后的 24 小时。单次执行包括排队最多 1 小时；取消等待最多 15 秒。

## 异常处理与界面

| 情况 | 后端处理 | 前端 |
| --- | --- | --- |
| 规划合同不合法 | 参照自动编排员工运行时的分步校验反馈：区分回复未完成、JSON 和字段错误，只反馈实际失败步骤并保留已知需求；不设固定修正次数，超时、取消或服务报错时停止，不启用 | 保留草稿或创建进度，显示失败，可重新生成或继续创建 |
| 超出职责、缺少必要输入 | 规划时阻止启用；执行时返回 blocked 协议后将本次标记失败并保留 INPUT_REQUIRED，不自动重跑 | 展示具体原因、已有成果和工作详情 |
| 身份过期 | 复用原刷新流程；前置鉴权无法完成则 waiting_auth | 等待登录或重新检查，不伪装运行中 |
| 明确撤权、模型/技能/目录不可用 | blocked，不循环重试 | 显示配置或授权原因，允许重新检查 |
| 启动前网络错误、临时服务错误、429 | 指数退避和抖动，最多首次加三次重试；尊重 Retry-After，不提前调用 | 展示尝试和下次重试时间 |
| 达到重试上限或启动等待期限 | 本次 failed，不创建替代 Run | 展示最终原因和尝试记录 |
| 正在运行或等待审批 | 沿用既有运行时和审批；无人值守不等于批准 | 展示运行/待审批及既有审批 UI |
| 文件未通过验收 | 原会话最多五次校验后失败 | 不标记成功，已有成果保留 |
| 运行异常、断流 | 保留既有会话、事件、检查点；不做调度层整任务重放 | 失败或待核查，进入工作详情排查 |
| preparing 时重启 | 未准入，允许重新准备同一普通任务 ID | 同一次执行记录继续启动检查 |
| launching 时重启 | 只有可核验的完成凭据才确认成功；否则 review | 提示核查已有文件和外部操作 |
| 运行中断、未闭合副作用 | review，禁止自动重放；普通重新检查不能关闭 review；单独的确认核查接口必须携带 confirmed=true，仍运行/排队/待审批则拒绝关闭 | 先查看工作与文件，再二次确认“已核查，关闭记录”，不提供整任务重试 |
| 取消/超时无法确认停止 | review，保留资源占用判断 | 明确状态不确定，不伪装已安全取消 |
| 调度文件损坏、扫描基础设施异常 | 停止调度，不用旧备份重跑 | 显示读取失败或调度停止，检查后手动恢复 |

阶段一同一时间最多一个定时执行，手动任务仍复用原队列与锁。待核查任务保留工作目录冲突约束；受限目录下互不重叠的其他定时任务可以继续。任一方使用 full-local 时无法证明资源独立，保守等待核查。

## 页面一致性

- 任务是否启用与最近执行结果分开显示，失败不会被误解为“任务已暂停”，一次性安排到期后不会继续显示仍有下次执行。
- 创建请求使用固定 requestId 去重；配置编辑保留原 ID 和进入表单时的 revision，冲突不会静默覆盖。
- 保存结果先写入页面缓存，再刷新列表；刷新失败保留已创建任务 ID。较早的列表响应不会覆盖新状态；普通轮询不会抹掉操作错误提示。
- 页面轮询仅用于同步展示，离开页面释放监听器和计时器，隐藏时停止读取；本地调度完全由主进程负责。
- 表单复用已有运行目录、权限和模型组件；仅在定时任务中排除无法生成文件的只读权限，不改变手动任务选项。没有技能替换入口。
- 执行日期按所选时区解析。夏令时不存在或重复的当地时间拒绝保存并提示另选时间。

## 限制与后续验证

- 尚未使用 utilityProcess。Agent 仍在现有运行进程中，不能声称解决 CPU 密集任务阻塞主进程的问题。
- 本阶段不提供周期/Cron、自动编排创建、手动立即触发和自定义补偿/并发策略；后续按纵向闭环扩展，页面不展示这些未实现入口。
- 无法仅凭本地文件证明外部 API、邮件、支付等副作用恰好一次。状态不确定时宁可等待核查，不保证无人介入后仍全部执行。
- 未通过真实云端账号做无人值守端到端验证，未在真实操作系统休眠、硬断电、磁盘故障下做破坏性测试；当前覆盖的是确定性模拟和既有 SDK 本地网关测试。
- 文件锁作用于单客户端进程。不同设备不会协同去重，不应将同一 userData 作为多进程共享调度库。
- JSON 历史暂不自动归档。周期任务、大量长期执行记录、运行时错误结构化分类透传、进程隔离和资源限额应各自作为后续闭环开发。
- 保存工作计划后员工职责变更，执行时仍按现有员工身份约束判断；不自动改写原合同。
