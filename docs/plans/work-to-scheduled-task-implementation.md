# 工作编排加入定时任务

## 已实现

- 使用工作列表原有的“加入定时任务”入口，仅已识别的编排工作可用；不复制对话或规划草稿。
- 弹窗仅包含标题和时间设置。标题默认当前工作标题；默认一次性执行，时间为打开弹窗时的本地明天同一时刻，精确到分钟。
- 复用已有每天、每周、每小时和自然语言自定义时间组件。夏令时不存在或有歧义的时间不会被静默移动。
- 后端读取当前用户作用域内的已确认 WorkPlan，不接受前端提供员工、模型、权限、目录或计划。
- 复制节点、依赖、交付约定、媒体要求、知识库配置、已确认输入和完整权限策略；不重新规划。
- 已确认附件复制为独立快照。原工作计划及附件删除后，定时任务不依赖原记录。
- 不复制会话、执行检查点、进度、审批决定和成果；员工技能在每次执行时重新授权装配。
- 创建完成后一次性持久化为已启用，通知动态定时器重新扫描。
- 每个周期走原有 Dispatcher、Runner 和 Agent Runtime，保留每个时间点的执行记录及工作详情入口。
- 从工作复制的任务使用同一个简化弹窗编辑，仅修改标题和时间，更新同一记录并保留计划副本。

## 持久化及幂等

- 原有 `scheduled/state.json` 保持 version 1；编排计划新增可选 `source` 引用，兼容原记录。
- 独立计划保存于用户作用域下 `scheduled/templates/<templateId>.json`，包含版本、完整计划及内容校验值。
- 附件复用 AttachmentStore 的独立快照存储，使用保留的 templateId，无新增工作列表记录。
- 前端只持有必要的来源摘要；模板路径、附件复制及完整权限策略均由主进程控制。
- 注册前先建立调度状态事务文件，再持久化模板和附件，最后原子提交启用状态。失败不会出现已启用的半成品。
- requestId 派生稳定 definitionId；同一请求重试返回已有记录，不重复创建，也不重新启用已被用户暂停的任务。
- 同一个请求 ID 的不同参数返回冲突；计划在弹窗打开后变化时返回版本冲突。
- 当前客户端会话内，回复丢失时保留原请求，关闭、重开弹窗仍核对同一请求；不自动生成新请求 ID。
- 编辑使用 revision 检查。已有未完成执行时拒绝修改；历史已生成时间点不能重复使用。
- 同一周期的领取、启动收据及恢复逻辑沿用现有调度模块；不能承诺外部操作的通用 exactly-once。

## 异常行为

- 计划缺失、交付约定不完整、输入引用失效：创建失败，弹窗显示原因，不启用。
- 登录、员工或模型授权失效：创建失败；运行前发现失效时进入现有等待登录或阻塞状态，不启动业务。
- 全部节点通过执行前授权检查后才准备实际工作；多员工中任意员工不可用，不先运行其他节点。
- 附件复制中断：允许核对相同目标字节后重试；目标内容不符时拒绝覆盖。
- 模板损坏或丢失：拒绝执行，不从原工作重建，不从旧备份擅自恢复。
- 网络临时失败：沿用现有启动前有限退避；业务已经被接纳或状态不确定时不自动重跑。
- 来源准备跨越退出登录、切换账号或服务停止：丢弃过期结果，不提交启用状态。
- 自定义时间解析同样拒绝 null、undefined、false 的授权结果，不先调用模型。
- 日志包含工作复制并启用、标题/时间更新及原有逐周期领取、授权、运行和交付事件。

## 主要文件

- `electron/service/scheduled-work-source.ts`：加载权威计划、独立复制、读取模板、复制输入。
- `electron/domain/scheduled-work-source.ts`：来源契约及可安全复用条件校验。
- `electron/service/scheduled-task-service.ts`：来源上下文、原子创建启用、仅标题/时间编辑。
- `electron/service/scheduled-task-runner.ts`：从完整模板创建新工作，复用原执行器。
- `electron/data/scheduled-task-store.ts`、`electron/data/attachment-store.ts`：模板校验及附件重试安全。
- `electron/bootstrap/build-backend.ts`、`electron/controller/routes/scheduled.ts`、`electron/preload.ts`、`src/shared/ipc.ts`：依赖装配及严格 IPC 契约。
- `src/components/enterprise/scheduled/WorkScheduleDialog.tsx`、`src/features/enterprise/work-schedule-pending.ts`：简化弹窗与结果未知时的请求保留。
- `src/pages/enterprise/WorkListActions.tsx`、`WorkHubPage.tsx`、`ScheduledTasksPage.tsx`：原入口及来源任务编辑路由。
- `src/features/enterprise/scheduled-time-form.ts`：按日历计算明天默认时间；其他时间控件继续复用。

## 验证与限制

- 定时任务后端及工作重跑定向回归：116 项通过；另有附件重复复制/损坏检查测试通过。
- 前端回归：616 项通过；并发与执行器回归：211 项通过。
- Playwright：1440、1280、760、390 宽度下的创建、丢失回复核对、重新打开、编辑、无重复记录和布局检查通过；已检查桌面及窄屏截图。
- 类型检查、相关文件 ESLint、架构边界检查、electron-vite 生产构建执行通过。
- 全量后端尝试不是通过状态：2588 项通过、27 项失败、5 项跳过；包含 Windows 符号链接权限、长路径、Office 子进程，以及未修改的编排交付测试失败。挂起的测试子进程已终止。
- 单独复查中，媒体 E2E 通过；编排交付的 waiting-user/completed 断言及 Node 测试子进程序列化问题仍复现，未在此功能中修改。
- 无新增第三方依赖或数据库；未验证真实云端无人值守执行。
- 暂不支持只读权限的来源工作、没有文件交付契约的旧计划、直接引用旧执行媒体 artifactId 的计划；不会静默扩大权限或丢弃引用。
- 只复制已确认附件，不复制整个原工作目录。原计划中的固定日期、固定路径及业务要求不由此功能重新解释。
- 中断创建产生的孤立模板/附件保守保留，暂未增加自动清理；结果未知请求的前端保留只覆盖当前客户端会话。
