## 1. 这次首页要解决什么

当前首页已经具备“个人工作台”的基本模块，但首屏的信息层级仍然偏散：顶部标题、内容标题、统计卡和工作区标题重复表达；两个空状态区域占据了较大高度；已订阅员工在窗口较矮时容易被推到首屏之外。

本次不重新设计业务模型，不新增接口，不把首页做成数据大屏。首页只回答普通用户最关心的三个问题：

1. **现在有没有事情需要我处理？**
2. **硅基员工正在帮我做什么？**
3. **我可以马上使用哪些已订阅员工？**

首页的产品定位：

> **一个低噪音、可恢复、以行动为中心的个人工作台。**

它不是宣传页，也不是管理员后台；它应该让用户登录后在 5 秒内知道下一步做什么。

## 2. 调研结论：借鉴成熟产品的工作台方法

本次参考的是成熟产品的信息组织方式，不照搬它们的品牌视觉或复杂功能。

| 产品 | 可复用的设计思路 | 不适合直接照搬的部分 | 龙硅采用方式 |
|---|---|---|---|
| Asana | 首页先给出任务、目标和项目概览；“My tasks”集中呈现个人下一步；Inbox 只保留与用户相关的更新 | Asana 的项目、目标、报表层级很重，普通用户不需要看到完整项目管理体系 | 首屏优先“待我处理”和“进行中”，将员工作为可直接进入的工作入口；通知只呈现需要关注的工作更新 |
| Slack | 工作区身份稳定放在侧栏；导航、通知和工作内容保持分层；相关工作集中在同一个工作空间 | Slack 的频道树和消息流会制造持续信息噪声，不适合龙硅的任务执行场景 | 保留稳定侧栏和右上角通知，将“个人 / 企业”作为工作视角切换，不把通知变成消息流 |
| Notion | 页面标题、内容层级和模块化区块清晰；首页可作为进入不同工作内容的索引 | 无限文档树和自由画布会增加用户理解成本 | 使用有限数量的固定模块，标题、说明、内容三层即可；不引入无限嵌套 |
| Linear | 强调当前工作、状态和下一步动作；列表信息密度高，状态表达明确 | Issue / Project 体系过于专业，不能让普通用户先理解内部对象模型 | 工作卡只保留状态、标题、下一步、执行员工、更新时间五类信息 |
| VS Code / Figma | 应用外壳稳定，导航区、标题区、工作区边界明确；浮层不破坏主内容 | IDE 的暗色高密度视觉不适合企业普通用户 | 保留桌面应用的稳定骨架，使用龙硅红色作为少量行动强调色 |

### 2.1 调研提炼出的共同规律

- **先展示用户自己的工作，再展示系统能力。** 首页不能从“我们有什么功能”开始，而要从“你现在要处理什么”开始。
- **导航是稳定的，内容是变化的。** 侧栏负责定位，首页负责决策；不要把大量入口塞进首页卡片。
- **通知与任务分开。** 通知告诉用户“有变化”，任务区告诉用户“需要行动”。
- **空状态不是空白。** 没有数据时要说明当前状态、原因和下一步，但不能用大面积插画或长篇解释占满页面。
- **摘要卡只做跳转。** 首页统计数字不是报表，点击后进入完整列表；统计卡需要紧凑、可扫描、可键盘操作。

## 3. 首页的产品结构

### 3.1 页面层级

```text
客户端外壳
├── 左侧主导航
│   ├── 企业标识
│   ├── 首页
│   ├── 硅基员工
│   ├── 安排工作
│   ├── 工作记录
│   └── 员工技能
│
├── 顶部应用栏
│   ├── 当前页面标题
│   ├── [个人] [企业] 视角切换
│   ├── 主题切换
│   └── 通知
│
└── 个人工作台首页
    ├── 首页问候 / 主行动
    ├── 工作概览
    ├── 待我处理
    ├── 进行中
    └── 我的硅基员工
```

### 3.2 首页模块优先级

| 优先级 | 模块 | 目的 | 首屏要求 |
|---|---|---|---|
| P0 | 待我处理 | 告诉用户是否需要立即行动 | 有数据时置于最醒目区域；无数据时压缩为空状态条 |
| P0 | 进行中 | 让用户知道系统没有“丢失”工作 | 与待我处理同级，显示关键进度和执行员工 |
| P0 | 已订阅员工 | 让用户快速找到可用员工 | 首屏至少露出 3 张卡；人数多时横向滚动 |
| P1 | 工作概览 | 快速判断工作量 | 仅保留 3 个紧凑数字，不做大面积统计面板 |
| P1 | 安排工作 | 提供明确的创建入口 | 只保留一个主按钮，不在首页重复铺多个快捷入口 |
| P2 | 企业组织 | 查看组织关系 | 通过顶部“企业”进入，不与个人工作台混排 |

### 4.3 布局决策

1. **不再重复显示多个“工作台”标题。** 顶部栏负责页面身份；内容区只保留一次“今天，从这里开始”。
2. **主按钮放在问候标题右侧。** “安排工作”是首页唯一主行动，和用户进入首页后的下一步直接关联。
3. **统计区从大卡改为紧凑摘要条。** 数字用于判断和跳转，不应抢过待处理工作。
4. **待我处理与进行中并列。** 两者都是核心工作状态，避免纵向连续堆叠导致页面过长。
5. **员工区固定为全宽横向墙。** 员工是龙硅区别于普通任务工具的核心入口，不能因为空状态而被推到首屏之外。
6. **没有数据时用短空状态。** 空状态最多两行说明，避免用大插画或大块虚线框浪费垂直空间。

## 5. 模块交互设计

### 5.1 首页问候区

内容：

- 小标签：`个人工作台`
- 主标题：`今天，从这里开始`
- 说明：`先处理需要你的事项，再查看正在推进的工作。`
- 主按钮：`安排工作`

规则：

- 页面标题和说明不根据时间频繁变化，避免用户每次进入都产生不稳定感。
- 主按钮始终可用；没有员工时进入安排工作页后显示明确的不可用原因，而不是无响应。
- 960 宽度下按钮保留图标和短文本，不换成只显示图标。

### 5.2 工作概览

三个指标固定为：

```text
待我处理    进行中    已订阅员工
```

规则：

- 数字使用等宽数字或 `font-variant-numeric: tabular-nums`，防止刷新时布局跳动。
- 待我处理使用轻微红色强调；进行中使用品牌红的深色文字；已订阅使用中性强调色。
- 数字为 0 时仍然可点击，进入对应列表的空状态页。
- 不显示“企业共 N 位员工”作为单独大文本；该信息可放入企业视角或员工列表页。

### 5.3 待我处理

有数据时，每张卡只表达：

```text
状态 + 更新时间
工作标题
下一步动作
当前执行员工 + 进入详情
```

交互：

- 点击整卡进入工作详情。
- `Enter` / `Space` 与点击行为一致。
- 键盘焦点完整可见，不能只靠颜色表达选中状态。
- 最多首屏展示 3 张；更多进入工作记录页，不在首页无限增长。

无数据时：

```text
✓ 目前没有需要你处理的工作
新的确认事项和交付结果会优先出现在这里。
```

空状态不提供“立即安排工作”第二个按钮，避免和页面主按钮重复；用户可直接使用顶部主按钮。

### 5.4 进行中

有数据时：

- 显示当前状态、标题、执行员工、最近更新时间。
- 若已有进度字段，显示细进度条；没有真实进度时不伪造百分比。
- 使用“实时更新”或更新时间说明状态，但不使用持续闪烁动画。

无数据时：

```text
目前没有进行中的工作
安排一项工作后，它会在这里持续显示进展。
```

### 5.5 我的硅基员工

员工墙继续保留横向滚动，但交互收敛为“可见卡片 + 两侧控制 + 触控板滚动”：

- 3～5 位员工且一屏能放下：不显示左右箭头，不制造无意义的轮播感。
- 超出一屏：显示左右箭头，按钮位于员工墙边缘中线；支持鼠标滚轮横向滚动和 Shift + 滚轮。
- 不自动无限轮播；员工是工作入口，不是广告 Banner。
- 每张卡保留：头像、员工名、状态、当前工作摘要、进入员工详情。
- 卡片最小宽度建议 `176px`，最大宽度建议 `208px`；避免长员工名挤压状态标签。
- 头像加载失败必须有首字母或统一占位，不出现破图。
- 卡片焦点和 hover 状态一致，点击打开员工工作抽屉。

没有订阅员工时：

```text
企业还没有给你分配硅基员工
企业管理员分配之后，你的员工会出现在这里。
```

这是权限 / 数据状态，不是网络错误；不得显示“加载失败”。

## 6. 状态设计规范

首页必须区分下列状态，不允许用“空数组”统一代替：

| 状态 | 用户看到什么 | 可执行动作 |
|---|---|---|
| 加载中 | 保留模块骨架，显示 2～3 行轻量 skeleton | 不可点击或保持当前数据 |
| 正常有数据 | 工作卡 / 员工卡 | 点击进入详情或列表 |
| 正常为空 | 简短说明 + 未来数据来源 | 必要时通过页面主按钮继续 |
| 无权限 / 未分配 | 说明“尚未分配”或“暂无权限” | 仅在确实有申请 / 联系入口时提供按钮 |
| 网络失败 | 模块级错误条，说明可重试 | “重新加载” |
| 服务端限流 | 明确说明暂时无法获取，不显示 0 | “稍后重试”或自动重试倒计时 |
| 会话过期 | 全局错误提示并回到登录页 | 重新登录 |

### 6.1 禁止的状态表达

- 用“0 个员工”掩盖员工接口失败。
- 用紫色 loading、发光粒子或持续动画表达“AI 正在工作”。
- 在空状态里展示复杂的营销文案。
- 在首页显示用户没有权限执行的管理动作。
- 让错误只出现在开发者控制台，界面没有解释。

## 7. 视觉与尺寸标准

### 7.1 视觉方向

本页沿用已确定的龙硅红色品牌体系：

- 主色：品牌红，用于主按钮、当前视角、关键状态和焦点环。
- 背景：暖白 / 浅灰白，避免冷紫色和大面积渐变。
- 内容卡：白色或轻微偏暖的面板，使用细边框和极轻阴影。
- 状态色：红色只强调“需要行动”；进行中、完成、失败使用可读的语义色，不能所有状态都变成红色。
- 装饰：只允许小面积、静态、低对比的品牌细节；首页不使用粒子流、轨道、复杂 AI 图标。

### 7.2 尺寸令牌

| 项目 | 标准值 | 说明 |
|---|---:|---|
| 顶部应用栏 | 44px | 兼容 Electron titleBarOverlay 和拖拽区域 |
| 左侧导航 | 216px | 1440 宽度下；最小可缩至 200px，不覆盖内容 |
| 内容最大宽度 | 1180px | 居中或靠左，避免超宽空白 |
| 内容左右内边距 | 32px / 24px / 16px | 大 / 中 / 最小窗口 |
| 首页模块间距 | 16px | 主垂直节奏统一 |
| 卡片内部间距 | 14～16px | 工作卡不低于 12px |
| 主按钮高度 | 36～40px | 首页主按钮 40px，普通按钮 34px |
| 统计条高度 | 64～72px | 不使用 120px 以上大统计卡 |
| 卡片圆角 | 10～12px | 不使用夸张圆角 |
| 输入 / 按钮圆角 | 8px | 与其他页面统一 |
| 员工卡最小宽度 | 176px | 长名称可读 |
| 员工卡最大宽度 | 208px | 避免卡片变成大块空面板 |
| 触控 / 点击目标 | ≥ 32px | 图标按钮建议 34～36px |
| 正文 | 13～14px | 保证桌面端密度与可读性 |
| 标题 | 22～28px | 页面主标题不超过 28px |

### 7.3 字体与内容

- 中文优先使用系统 UI 字体栈，保证 macOS 与 Windows 都有合理 fallback。
- 标题最多两行；员工名和工作标题溢出使用省略号，并通过 `title` 或详情页提供完整文本。
- 不用英文状态文案装饰界面；状态应该直接使用中文表达。
- 所有数字和时间格式保持现有词汇表统一，避免同一页面出现“刚刚 / 刚才 / 实时”等多套表达。

## 8. 跨平台窗口与响应式要求

### 8.1 macOS

- 原生红黄绿按钮区域必须与企业 Logo / 公司名保持独立安全区，不能在同一坐标层重叠。
- 左上角品牌区应与 `titleBarStyle: hidden` 的窗口配置配套，保留明确的 `padding-left` 和 `padding-top`。
- `.electron-drag-region` 只用于空白拖拽区；按钮、链接、输入框、下拉菜单、员工卡都必须明确 `-webkit-app-region: no-drag`。
- 长企业名应截断，不允许顶到窗口控制按钮或遮住页面标题。

### 8.2 Windows

- `titleBarOverlay` 的系统按钮通常位于右上角，顶部操作组必须预留右侧安全区。
- 主题、通知、个人 / 企业切换不能被窗口按钮覆盖。
- 窗口按钮区域的背景色必须与顶栏一致，避免出现明显色块断层。

### 8.3 窗口尺寸行为

| 窗口 | 行为 |
|---|---|
| 1440×900 及以上 | 待我处理 / 进行中并列；员工墙展示 5 张左右 |
| 1280×800 | 保持并列；员工墙展示 4 张左右；说明文案可缩短 |
| 1100×720 | 工作卡缩为 2 列；员工墙展示 3 张左右 |
| 960×640 | 工作模块纵向排列或使用紧凑布局；员工墙仍需露出 2 张卡 |
| 低于 960 宽或 640 高 | 由 Electron 最小窗口限制阻止；不得依靠横向溢出解决 |

所有断点都需要检查：

- 长企业名
- 长员工名
- 工作标题超过两行
- 待处理数字达到两位数
- 0 数据、加载、错误三种状态
- 深色主题下的边框、文字和焦点环

---

## 9. 推荐的组件拆分

首页实现不引入新的状态管理或依赖，优先在现有组件上做小步重构：

```text
HomePage
├── HomeHeader
├── HomeSummary
├── HomeWorkGrid
│   ├── HomeWorkSection: 待我处理
│   └── HomeWorkSection: 进行中
└── HomeEmployeeSection
    └── EmployeeWall
```

建议职责：

- `HomePage`：数据筛选、路由跳转、状态组合。
- `HomeHeader`：标题、说明、安排工作按钮。
- `HomeSummary`：三个统计入口，不处理业务数据。
- `HomeWorkSection`：统一工作区标题、数量、空状态、错误状态。
- `HomeEmployeeSection`：员工墙标题、查看全部、横向滚动。
- `EmployeeWall`：只负责卡片布局和滚动，不承担员工业务逻辑。

不建议：

- 为首页单独复制一套员工卡样式。
- 在 CSS 中继续叠加多个互相覆盖的 `.ent-home-*` 规则。
- 通过修改 API 返回结构来适配视觉布局。
- 为了首页视觉效果新增动画库或图表库。

## 10. 分阶段开发计划

### Phase 1：结构收敛

目标：不改接口，只调整首页信息层级。

- 去掉重复的页面标题表达。
- 将统计卡改为紧凑摘要条。
- 将待我处理 / 进行中改为同级工作区。
- 保留员工横向滚动，保证首屏可见。
- 删除首页中没有真实业务价值的装饰性状态文案。

验收：

- 1440×900 首屏能同时看到工作区和至少 3 张员工卡。
- 960×640 不出现横向页面溢出。
- 没有工作数据时，两个空状态都不占据大面积空白。

### Phase 2：状态和交互打磨

目标：让首页在真实数据和异常数据下都可解释。

- 加载 skeleton。
- 模块级错误和重试。
- 区分空数据、未分配、限流和网络错误。
- 统一卡片键盘交互和焦点样式。
- 员工墙支持箭头、触控板滚动和 reduced motion。

验收：

- 模拟接口失败时不会显示“0 个员工”。
- Tab 可以访问统计、工作卡、员工卡和操作按钮。
- `prefers-reduced-motion: reduce` 下没有持续移动动画。

### Phase 3：跨平台与视觉收口

目标：保证 macOS / Windows 和主题切换的一致性。

- 检查标题栏安全区和拖拽区。
- 检查 960 / 1100 / 1280 / 1440 四档窗口。
- 检查浅色、深色主题。
- 清理重复 CSS 和失效样式。
- 使用真实长文本和真实员工数量做手工验收。

验收：

- macOS 红黄绿按钮不与品牌区重叠。
- Windows 右上角操作组不与窗口按钮重叠。
- 红色主题在首页、员工、工作记录和工作详情中保持一致。

## 11. 开发验收清单

### 结构

- [ ] 首页只保留一个主标题和一个主行动按钮。

- [ ] 首页没有粒子、轨道、复杂 AI 装饰。

## 12. 本次结论

首页不再继续增加模块，而是做三件事：

1. **把待我处理放到第一优先级。**
2. **把已订阅员工提前并稳定地展示出来。**
3. **把空状态、错误状态和跨平台窗口状态做正确。**

实现顺序按 `Phase 1 → Phase 2 → Phase 3` 执行；每个阶段完成后先运行针对性检查并手工验收，再进入下一阶段。
