## 问题与优先级

| 优先级 | 问题 | 交付文档 | 主要结论 |
|---|---|---|---|
| P0 | 视频/图片生成已提交，但页面长时间停在生成中 | 媒体生成长等待与交付优化 | 主进程 tracker 与模型轮询重复等待，生成、下载、保存和交付没有统一收尾 |
| P0 | 历史任务一直显示执行中 | 历史任务假进行中与生命周期修复 | `pending` 被前端直接映射为进行中，且用 `createdAt` 伪造执行时长 |
| P1 | 普通会话每轮响应很慢 | 普通会话耗时优化 | 知识库无条件查询、共享上下文增长、恢复拼接全部历史 |
| P1 | 图片/视频调用次数很多但没有对应消费 | 请求次数、耗时观测与计费口径修正 | 模型回合、工具调用、媒体提交、媒体轮询和重试混在一个计数里 |

## 依赖关系

1. 先做媒体状态查询和阶段计时，确认供应商生成、客户端发现、下载保存、交付各自耗时。
2. 并行修复生命周期投影和真实计时；这部分不依赖供应商状态接口。
3. 完成普通会话知识库门控和上下文预算。
4. 最后统一请求分类、指标和 UI 展示，避免继续把模型回合当作媒体调用次数。

## 统一验收

- 同一个媒体幂等键最多一次实际生成提交，恢复和刷新不重复扣费。
- 无 `activeRunId`、`startedAt`、run 或事件证据的历史 `pending` 显示“尚未开始”，不计入进行中。
- 任务排队、真实运行、审批、媒体等待、暂停和终态分别计时。
- 普通会话无检索意图时不触发知识库查询；恢复不拼接全部历史。
- UI/API 分开显示 model request、tool call、media submission、media polling、retry 和 billing event。
- 所有状态修复不触发模型、工具或媒体生成。

## 发布顺序

P0 媒体诊断与跟踪 → P0 生命周期投影与计时 → P1 普通会话门控和上下文预算 → 统一观测和请求分类 → 灰度开启自动状态收敛。
