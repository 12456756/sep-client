# 员工技能紧凑列表与独立详情页开发文档

- 日期：2026-10-28。
- 状态：前端已实施，自动化与浏览器回归已完成；真实 Electron 与平台联调尚未执行，详见第 16 节。
- 产品决策：采用「紧凑列表 + 独立详情」，提供员工筛选、版本筛选、排序和浏览状态恢复；列表直接切换使用版本；详情负责阅读、个人修改和版本记录。
- 明确约束：**本期不调整后端版本切换逻辑，不新增按员工单独切换版本。员工筛选仅影响展示；切换仍调用现有接口，作用于该技能的全部关联员工绑定。**
- 实现范围：React renderer、前端路由与状态、技能样式及对应测试。复用现有接口与依赖，不升级 Pi SDK，不修改 Electron service/data/runtime、持久化格式或审批策略。

## 1. 目标与验收结果

用户应能快速找到某位员工的技能，在列表直接切换使用版本，进入简洁的详情阅读和编辑内容。

本期交付：

1. 替换大型卡片的紧凑列表，保持较高的信息密度和可读性。
2. 技能与员工联合搜索、员工单选筛选、当前使用版本来源筛选、三种稳定排序。
3. 独立详情页：默认 Markdown 阅读，原文按需查看，显式进入编辑。
4. 在列表通过版本下拉直接切换全部关联员工的版本；详情版本记录可按需查看各员工使用情况。
5. 保存后继续查看和启用个人版本，保留本地可用、上传、审核的原有语义。
6. 返回来源、筛选与滚动位置恢复，以及账号和企业隔离。
7. 完整的加载、失败、无结果、无版本、版本不可用与未保存编辑处理。

## 3. 本期业务边界

### 3.1 保留的版本行为

现有 `selectSkillVersion({ capabilityId, versionId })` 契约不增加参数，不发送 employeeId/subscriptionId。

- 切换仍作用于该技能全部关联员工绑定，包括被当前员工筛选隐藏的员工。
- 按现有规则在下一次技能加载时生效，不替换正在执行中的技能内容。
- 保存个人版本不自动切换使用版本；只有用户主动执行切换才调用选择接口。
- 企业/平台原文保持只读，修改生成新的个人版本。
- 个人版本继续保存本机并按现有流程上传送审；本地可用性不以远端审核通过为前提。
- 可选版本继续由 `usableVersionIds` 判断，不能根据状态文案自行放宽权限。
- 原有本地保存、幂等、上传重试、身份检查和错误返回继续沿用。

### 3.2 展示员工范围与切换范围

员工筛选是查找工具，不是写操作的作用域。列表表头标明「使用版本 · 全部关联员工」，下拉的可访问名称包含全部关联员工数量；切换成功反馈该次变更的完整人数。

切换人数按全部 bindings 的唯一 subscriptionId 计数，不按当前筛选结果计算。保留下一次技能加载生效的后端行为；员工使用名单在详情版本记录中按需展开，不在正文上方重复铺设使用设置。

不提供员工勾选框、单行员工切换或重复确认弹窗；列表下拉选择可用版本即执行现有全部绑定切换。

## 4. 信息架构与入口

```text
员工技能列表
  ├─ 搜索 / 员工筛选 / 版本筛选 / 排序
  ├─ 使用版本下拉 → 切换全部关联员工的版本
  └─ 查看详情 → 技能详情
                  ├─ 技能说明：阅读 / 原文 / 创建个人版本
                  └─ 版本记录：查看某版本 / 使用情况 / 上传状态 / 重试上传

员工详情
  ├─ 查看全部技能 → 技能列表，预选该员工
  └─ 查看某个技能 → 技能详情，保留员工来源与上下文
```

保留 `skills` 独立详情路由，不改抽屉，不在列表中嵌入完整编辑器。

与同日《硅基员工列表与精简详情页重构开发文档》配合：员工详情继续只展示已有技能摘要，版本切换放在技能列表，阅读和个人修改放在技能详情。该文档中「沿用已有技能详情」的入口细节以本文为本期更新，不扩大员工详情的正文范围。

## 5. 紧凑列表规格

### 5.1 页头与工具栏

```text
[搜索技能或员工…] [全部员工 ▾] [全部版本 ▾] [名称排序 ▾] [刷新]

找到 8 / 39 个技能                                     清除筛选

技能 / 简介                  关联员工         使用版本          操作
用户需求挖掘                 爆品机会评估师   平台版 1.0.0      查看详情 >
商品机会评分                 爆品机会评估师   企业版 1.0.1      查看详情 >
电商任务规划                 员工A、员工B     多个版本          查看详情 >
```

- 首次默认：空搜索、全部员工、全部版本、名称排序。
- 内容区直接显示工具栏，不再重复展示「员工技能」标题和标题旁数字；数量集中在工具栏下方展示。
- 保留输入技能名称、技能描述或员工名称的联合搜索，去除首尾空格并忽略拉丁字母大小写。
- 搜索、员工、版本条件取交集；排序在筛选后执行，不改变原始 workspace 数据。
- 没有有效筛选时展示「共 Y 个技能」；有搜索/员工/版本条件时展示「找到 X / Y 个技能」。排序改变不算筛选。
- Y 是当前账号、企业下成功加载且去重的技能数，X 是筛选匹配数；首次加载和无缓存失败时不展示虚假 0。
- 「清除筛选」清空搜索并恢复全部员工、全部版本，保留排序；没有筛选时不显示该入口。
- 刷新沿用现有加载和限流逻辑，不重置筛选或排序。

### 5.2 员工筛选

- 第一期开单选，默认「全部员工」。
- 选项只来自当前技能库真实 bindings，按 subscriptionId 与 `workspace.employees.id` 关联；不按员工名称或平台 employeeId 模糊连接。
- 展示头像、员工名、关联技能数。每个员工的计数按 capabilityId 去重，以完整技能集合为基数，不随其他条件变化。
- 选项按员工名称排序，同名使用 subscriptionId 稳定排序；名字不唯一时保留身份区分提示。
- 缺少员工映射但存在绑定时使用「员工信息暂不可用」及可区分的订阅标识，不生成头像身份或业务介绍。
- 点击技能行中的员工标签可设置员工筛选；该操作不打开员工详情，也不触发版本切换。
- 用户主动选择一个新员工时清空搜索词，保留版本筛选和排序；之后输入搜索继续与员工条件相交。这样从搜索结果点击员工后能看到该员工的全部匹配技能。
- 从员工详情进入列表时预选该 subscriptionId，清空旧搜索和版本筛选，保留排序偏好。
- 已选员工在成功刷新后不再有绑定时，回退到全部员工并给一次轻提示；加载中或刷新失败时保留原条件。

### 5.3 版本筛选

选项为「全部版本」「个人」「企业」「平台」，按全部关联员工**当前正在使用**的版本来源筛选，与列表「使用版本」列保持一致。通过 `bindings[].selectedVersionId` 解析来源；本地版本 key 与上传副本 ID 均归入个人，其余根据对应版本的 PERSONAL / ENTERPRISE / PLATFORM 来源判断。

仅存在历史版本、保存了尚未启用的个人版本，均不会改变分类；上传与审核状态也不改变当前使用来源。多名员工使用不同来源版本时，技能可同时出现在对应分类中，行摘要仍显示「多个版本」。所有绑定均未选择或无法解析时，只出现在「全部版本」。员工筛选不缩小此处的使用范围，与行摘要继续基于全部绑定的规则一致。

### 5.4 排序

| 选项 | 主排序规则 | 次排序与缺失值 |
| --- | --- | --- |
| 名称排序（默认） | 技能名称，使用 `Intl.Collator('zh-CN', { numeric: true, sensitivity: 'base' })` 升序 | 名称相同按 capabilityId 升序，空名称排后 |
| 关联员工最多 | 唯一 subscriptionId 数量降序，始终统计该技能全部绑定 | 同值按名称与 capabilityId |
| 最近个人修改 | 当前可见个人记录的最大有效 createdAt 降序，合并 localVersions 与 PERSONAL versions | 缺少有效日期排后；同值按名称与 capabilityId |

「最近个人修改」只表示个人版本创建时间，不能用企业发布时间、审核更新时间或当前刷新时间代替。没有个人记录的技能仍显示在末尾，不自动过滤。

不提供使用频次、热度、推荐度或综合评分排序：当前没有对应的可靠技能统计数据。

### 5.5 行内容与操作

| 区域 | 展示规则 |
| --- | --- |
| 技能 | 名称 + 最多一行真实描述；无描述省略；名称可聚焦并打开详情 |
| 关联员工 | 最多两名员工标签，超过显示 `+N`；通过可点击展开及键盘操作查看完整名单 |
| 使用版本 | 下拉直接显示全部绑定的统一版本；不一致显示「多个版本」，全为空显示「未选择版本」，失效时显示「已选版本不可用」；选择可用项即切换 |
| 个人版本 | 有记录时加小型「有个人版本」标记；不重复展示整段审核说明 |
| 操作 | 「查看详情」，使用次要文本样式；不放整行红色主按钮 |

使用版本摘要始终基于该技能全部 bindings，不能在员工筛选后把多个版本误报为单一版本。展开信息可以说明具体员工的使用版本。

列表移除每项重复的「企业可用技能」、发布版本专栏、大图标区域和底部规则长文。使用版本列保留紧凑下拉；发布和审核信息按需查看版本记录。

名称和查看按钮均可打开详情，不通过整行 click 嵌套员工按钮；避免点击员工筛选时意外进入详情。

## 6. 独立详情页规格

### 6.1 页面结构

```text
← 返回技能列表 / 返回员工详情

用户需求挖掘

[技能说明] [版本记录]

企业版 1.0.1                     [阅读 / 原文] [创建个人版本]
───────────────────────────────────────────────────────
技能正文
```

- 标题保留技能名称，移除重复简介、来源小字、使用设置、影响范围长文、字符统计及常驻规则说明。
- 正文开头与页面同名的一级标题只显示一次；完整原文不变。
- 首次进入默认「技能说明」与阅读模式，不默认进入编辑。
- 读取、保存和上传失败时才展示对应错误与恢复操作；不为正常阅读放置重复提示。

### 6.2 查看版本与使用版本

详情只维护 `viewingVersionId`，列表的实际使用版本从最新 `skill.bindings[].selectedVersionId` 派生。查看版本记录与正文不触发版本切换，详情不再维护待切换候选。

初次查看按以下顺序选择：所有绑定统一使用且可预览的版本 → 来源员工正在使用且可预览的版本 → 可见的绑定 currentVersion → 可见远端版本 → 本地记录。多个候选使用创建时间降序、ID 次排序；无版本时显示空态，不发出空 ID 预览请求。

### 6.3 列表直接切换

- 使用版本列的原生下拉列出可见版本，本地和上传副本合为一项；不可用项禁用。
- 当前统一版本作为选中项；多版本、未选择或失效时显示对应占位。
- 选择不同可用项即调用 `workspace.selectSkillVersion(capabilityId, versionId)`，不增加候选和确认按钮。
- 正在切换时禁用版本下拉、刷新及详情入口，防止重复提交；异步结果受身份隔离保护。
- 成功后按现有 hook 更新全部关联绑定，显示一次简短结果；分类随实际使用来源更新。
- 失败显示错误，并提供「重试切换」「刷新使用情况」。不伪造成功，不假设后端原子回滚。
- 没有关联绑定、没有可用版本或重复选择当前统一版本时不发送请求。

### 6.4 默认阅读与原文

- 复用已安装 `react-markdown`、`remark-gfm` 和现有渲染模式，不新增依赖。
- 默认渲染技能正文；提供「阅读 / 原文」切换，原文保持只读，编辑入口明确。
- 阅读模式不展示 frontmatter 和元数据控件；与页面名称相同的开头一级标题只显示一次。只在展示层识别明确闭合的头部 `---` 区块，不改写、补齐或序列化内容；未闭合时按普通正文处理。
- 保存始终使用完整原文，保留 frontmatter、换行、Markdown 和未知字段，不把渲染结果作为保存源。
- 不启用原始 HTML，不执行脚本、不加载远程图片；第一期正文链接作为不可点击文字展示，沿用现有文档预览的处理方式，不引入新的外链打开通道。
- 代码块与宽表格在局部横向滚动，不撑宽页面；原文区域独立处理长行。
- 加载、读取失败、有效但为空的正文和无可见版本分别展示，失败时保留所选版本并允许重新读取。

### 6.5 创建个人版本、保存与继续使用

- 「创建个人版本」进入完整原文编辑，使用 textarea，保留现有内容上限；来源不存在、读取失败、忙碌中不可编辑。
- 编辑页明确显示来源版本。已有个人版本也可继续修改，但每次仍生成新的个人记录，不覆盖原记录。
- 编辑后显示「取消修改」「保存为个人版本」，只有真实变更、内容非空且存在有效 parentVersionId 时可保存。
- 当前本地记录的 parentVersionId 回退沿用现有逻辑，不重设计服务端版本继承关系。
- 保留保存弹窗的名称/修改说明输入，以及现有幂等 key 复用逻辑，避免一次失败重试生成重复提交。
- 保存成功后退出编辑，留在详情查看新个人版本，提供「返回列表切换」动作，返回后焦点定位该技能的版本下拉。
- 用户在列表选择新版本后才调用切换；保存本身不自动应用。
- 上传成功简短提示「个人版本已保存，已上传送审。」；上传未成功提示「个人版本已保存到本机，上传未成功。」；具体状态和重试入口在版本记录。
- 保存成功但后续列表刷新失败时，保留 hook 已接收的本地记录和刚保存原文，继续允许选择本地版本，不把刷新失败误报为保存失败。
- 保存接口返回失败时保留编辑内容与当前幂等尝试，显示实际错误，不自行断言已上传或已保存。

### 6.6 未保存编辑与忙碌状态

保留 beforeunload 保护，并统一覆盖返回、全局侧栏跳转、历史返回、切换正文版本、刷新导致当前版本替换、取消修改等会丢失草稿的路径。仅阅读/原文视图切换不丢内容；有草稿时版本记录标签先禁用，保留保存和取消操作。

离开保护采用现有确认能力或统一的前端导航守卫，不只保护详情内的返回按钮。允许放弃后再导航；拒绝放弃则路由、草稿和光标保持。账号退出或企业切换立即隔离旧内容，不把旧草稿迁入新身份，不为保留草稿阻止身份隔离。

保存、上传重试、切换分别标明操作状态，不用「重新读取」处理所有错误：读取失败提供重读，保存失败提供重试保存，上传失败提供重试上传，切换失败提供重试切换。

## 7. 版本记录

- 版本记录放在独立标签页，列出名称、来源、创建时间、本地可用性、上传/审核状态及操作。
- 默认创建时间降序，日期缺失排后，ID 稳定排序；未知状态显示可理解的兜底文字并保留原状态作为补充，不映射成已通过。
- 「正在查看」与「使用中」分别显示；使用中标明「全部 N 名员工使用」或「N / M 名员工使用」，可展开员工名单。
- 本地可用、是否上传、远端审核是三个维度。远端待审/驳回不能把对应本地记录禁用。
- 本地记录与其 `uploadedVersion.id` 对应的远端记录合为一条展示，审核状态优先使用最新 `versions` 中相同 ID 的记录；本地原文和本地选择标识保留，不删除持久化记录。
- 合并行保留本地 idempotencyKey 和远端 ID 的别名关系：任一 ID 被查看或使用都能正确标注；切换本地内容时仍使用本地 key，不误用尚不可启用的远端 ID。
- 未上传的本地记录提供「重试上传」；上传成功后更新原行，保持正在查看的本地内容与实际使用标识。
- 「查看内容」只更新查看状态，不切换使用。没有可见版本时显示明确空态。
- 「刷新状态」继续调用 `refreshSkills()`，遵循已有去重、焦点刷新冷却和 429 倒计时，不新增轮询。

## 8. 路由、返回与状态恢复

### 8.1 前端路由建议

只扩展 renderer `AppRoute`，保留现有 `{ name: 'skills', skillId? }` 兼容性。建议增加可选 `employeeFilterId`、`sourceEmployeeId` 和返回来源：

```ts
type SkillEntrySource =
  | { name: 'skill-list' }
  | { name: 'employee'; employeeId: string };

// 合并进现有 AppRoute，而非创建第二套路由系统。
{ name: 'skills'; skillId?: string; employeeFilterId?: string;
  sourceEmployeeId?: string; returnTo?: SkillEntrySource }
```

`employeeFilterId` 与 `sourceEmployeeId` 均使用 subscriptionId：前者决定列表展示，后者只提供详情来源和默认查看参考；二者都不进入切换 IPC。

- 从列表打开详情，记录来源为技能列表，返回恢复列表快照。
- 从员工详情打开某技能，返回该员工详情；提供次要「全部技能」入口，避免返回目标与文案不符。
- 从员工详情打开技能列表，预选该员工；从该列表继续打开技能后，应返回列表而非跨过列表回员工详情。
- 不带来源的详情默认返回技能列表；来源员工失效时回到技能列表并给轻提示，不进入失效页循环。

### 8.2 状态所有权与隔离

- 列表快照放在不会随列表/详情切换卸载的 workspace 上层或专用 hook，由 `attachmentScopeKey` 隔离；不在模块级全局变量缓存。
- 快照包含搜索、employeeFilterId、版本筛选、排序、滚动锚点/偏移和打开详情的触发元素身份。
- 本期只要求当前会话内恢复，不新增后端偏好存储，也不把技能原文或编辑草稿存入 localStorage。
- 账号/企业变化立即清空列表快照、查看缓存、错误、切换反馈与草稿；异步响应不能写回新 scope。
- 筛选或排序主动变化时列表回到起始位置；从详情返回时恢复，后台刷新时尽量维持原锚点。
- `ClientAppPage` 的统一置顶与技能恢复由单一入口协调；不能先恢复后又被另一个 effect 清零，也不能改变工作页等其他页面的滚动行为。
- 恢复等待有效列表完成渲染，失败有缓存时可恢复缓存；数据变化时定位原技能，原技能不再存在则将偏移限制在有效范围。
- 返回后恢复键盘焦点到原技能入口；来自员工页时恢复对应技能入口。鼠标用户不强制产生额外跳动。
- 详情 ID 不存在时：加载中等待；加载失败显示失败与重试；成功确认无此技能才显示「该技能不在当前授权列表中」及返回入口。

## 11. 加载与异常状态

| 场景 | 行为 |
| --- | --- |
| 首次加载、无缓存 | 紧凑行骨架和加载文字，不展示零结果或无授权结论 |
| 后台刷新、有缓存 | 列表继续可用，保留条件、行锚点和原数据，显示轻量刷新状态 |
| 无缓存加载失败 | 错误与重试，不显示「没有技能」 |
| 有缓存刷新失败 | 标明保留上次加载数据，不清空列表或当前个人版本 |
| 429 | 沿用倒计时，到期才允许重试；不新增自动请求循环 |
| 部分记录被跳过 | 保留现有 warning，数量仅统计有效记录 |
| 成功加载但技能为空 | 「当前账号还没有已授权的员工技能」 |
| 有筛选但无匹配 | 「没有匹配的技能」和清除筛选，不覆盖加载错误 |
| 技能存在但没有版本 | 详情显示名称和无版本空态；禁用编辑，列表禁用切换，不调用空 ID 预览 |
| 查看版本刷新后消失 | 无未保存修改时提示并选择有效回退；有草稿时保留已读来源与草稿，禁止无有效 parent 的保存/切换，不静默替换正文 |
| 切换失败 | 保留原显示并提供重试切换与刷新使用情况入口；不假设后端原子回滚 |
| 保存成功、上传未成功 | 本地记录继续可查看、可选择，提供重试上传 |
| 保存成功、刷新失败 | 保留本地记录及正文，分别提示保存结果和刷新失败 |
| 账号或企业切换 | 立即隔离旧正文、员工信息、草稿与切换反馈，忽略旧异步返回 |
