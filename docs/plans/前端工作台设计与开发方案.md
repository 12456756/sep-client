# SEP Client 前端工作台设计与开发方案

## 1. 文档目的

本文档用于指导 SEP Client 前端工作台的重构开发。目标是把客户端从“选择一个员工并操作工具”调整为“老板安排工作、硅基员工接单并完成交付”的工作台体验。

本次前端重构的核心目标：

1. 登录后直接进入工作台，不再进入独立的员工选择页。
2. 点击“新建任务”后，先选择“新建对话任务”或“任务中心任务”。
3. 对话任务突出员工身份，支持在同一个对话上下文中切换员工。
4. 任务中心突出多人编排、工作步骤、员工交接和最终交付。
5. 对话生成过程可见、可追踪、可恢复，页面关闭或重启后能够回到最后记录。
6. 保持 Electron 主进程与 React 渲染进程边界，渲染进程不直接接触 Node/Electron API。

参考素材位于 `front_picture/`。参考图只用于借鉴布局密度、输入框工具栏、侧栏层级、账户入口和窗口控制细节，不直接复制素材或页面视觉。

## 2. 范围与非目标

### 2.1 本期范围

- 工作台外壳和左侧导航重构。
- 登录后直接进入工作台。
- 新建任务二选一页面。
- 对话任务页面重构。
- 对话顶部员工切换区域。
- 对话底部模型、技能、工作目录和权限设置。
- 原生目录选择和已选目录展示。
- 对话自动滚动和历史末尾定位。
- 对话成果侧栏。
- 任务中心创建页和执行过程展示页。
- 账户菜单和退出登录入口。
- 收起侧栏、窄窗口和窗口控制区域适配。
- 流式输出、工具执行、等待授权、失败、重试、空状态和加载状态。

### 2.2 非目标

- 本期不升级 `@earendil-works/pi-coding-agent` 或 `@earendil-works/pi-ai`。
- 本期不让渲染进程直接调用 Pi SDK。
- 本期不实现完整的任意 DAG 编排编辑器；任务中心第一版采用线性步骤，数据结构预留依赖字段。
- 本期不在前端猜测 Token 或额度；额度必须由 SEP 提供安全接口。
- 本期不引入新的 UI 框架，优先复用现有 Radix、Lucide、Tailwind 和本地组件。

## 3. 用户心智模型

用户是“老板”，员工是“硅基员工”。用户的主要动作不是“调用模型”，而是：

```text
提出目标 -> 选择负责员工 -> 交代工作 -> 查看员工工作 -> 授权必要操作 -> 接收成果
```

页面文案和状态应围绕这条流程：

- `安排工作`：创建任务或启动编排。
- `员工已接单`：任务已经进入运行队列。
- `正在工作`：员工正在生成内容或执行工具。
- `等待你的确认`：需要用户批准工具操作。
- `已完成交付`：任务已经产生最终结果。
- `交接给下一位员工`：任务中心步骤切换。

避免使用过度技术化的主文案，例如“调用模型”“发送请求”“启动 Runtime”。技术细节可在成果侧栏和运行详情中展示。

## 4. 总体页面结构

### 4.1 应用壳层

```text
AppShell
├── ElectronTitlebarSpacer
├── WorkspaceSidebar
│   ├── NewTaskButton
│   ├── NavigationItems
│   ├── RecentConversationList
│   └── AccountMenuTrigger
└── WorkspaceMain
    ├── WorkspaceHeader
    └── WorkspaceRoute
```

登录完成后直接渲染 `AppShell`。员工实例列表由 `auth:get-instances` 获取并传入工作台状态，不再渲染独立的实例选择路由。

### 4.3 新建任务选择页

点击“新建任务”后进入选择页，不立即调用 `task:create`：

```text
┌─────────────────────────────────────────────────────────┐
│ 新建任务                                                │
│ 选择你要安排的工作方式                                    │
│                                                         │

│ │ 新建对话任务             │  │ 任务中心                 │ │
│ │ 与硅基员工持续交流       │  │ 编排多个员工完成工作      │ │
│ │ 适合分析、讨论和修改      │  │ 适合明确步骤和交付物      │ │
│ │ [开始对话]               │  │ [开始编排]               │ │
│ └────────────────────────┘  └────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

选择页要求：

- 两个选项左右排列，最小宽度不足时上下排列。
- 卡片是独立可点击区域，圆角不超过 8px。
- 悬停只做轻微上移、边框强调和图标颜色变化。
- 支持 Tab 聚焦和 Enter 确认。
- 提供返回按钮，但返回不创建空任务。
- 对话任务卡排在左侧，任务中心卡排在右侧。

## 5. 路由与页面状态

前端可继续使用现有 `WorkspaceView`，但需要将状态扩展为：

```ts
type WorkspaceView =
  | 'new-task'
  | 'conversation-list'
  | 'conversation'
  | 'task-center-list'
  | 'task-center-create'
  | 'task-center-run'
  | 'employees'
  | 'skills'
  | 'status'
```

页面状态必须显式区分：

```ts
type LoadingState = 'idle' | 'loading' | 'ready' | 'error'
type RunPresentationState =
  | 'draft'
  | 'queued'
  | 'running'
  | 'waiting-approval'
  | 'completed'
  | 'failed'
  | 'paused'
  | 'interrupted'
```

不允许通过“有没有文本”推断任务是否运行。状态优先读取后端任务和运行事件。

## 6. 对话任务设计

### 6.1 页面布局

```text
┌───────────────┬────────────────────────────────┬─────────────────┐
│ 工作台侧栏     │ 对话主区                         │ 成果侧栏          │
│               │                                │                 │
│ 对话           │ 当前员工栏                       │ 成果              │
│ 任务中心       │ [头像] 员工 A  ▼                 │ 文件              │
│ 硅基员工       │ 已参与：员工 A · 员工 B           │ 报告              │
│ 技能资源       │                                │ 运行记录          │
│               │ 消息列表                         │ 员工交付状态       │
│ 账户           │                                │                 │
│               │ 输入框                           │                 │
└───────────────┴────────────────────────────────┴─────────────────┘
```

桌面端默认使用 `grid-template-columns: minmax(220px, 280px) minmax(0, 1fr) minmax(240px, 320px)`。成果侧栏可收起；收起后主区占用剩余空间。

### 6.2 对话顶部员工栏

组件：`ConversationParticipantBar`。

内容：

- 当前负责员工头像、名称、职责摘要。
- 工作状态点：空闲、正在工作、等待授权、已交付、失败。
- 员工切换下拉菜单。
- 已参与员工列表。
- “添加员工”入口。

员工切换行为：

1. 保留同一个任务和消息历史。
2. 记录新的 `activeEmployeeInstanceId`。
3. 后续消息由新的员工运行时处理。
4. 消息和运行记录标注实际员工。
5. 切换期间显示“正在交接给……”状态，避免用户误以为旧员工仍在生成。

当前后端任务只有单一 `employeeInstanceId`，要实现该交互需要增加参与员工和当前员工字段。前端组件应先按可扩展的数据结构编写，不把员工 ID 写死在页面状态中。

### 6.3 消息列表

组件：

- `ConversationTimeline`
- `ConversationMessage`
- `EmployeeMessageHeader`
- `ToolActivityMessage`
- `ConversationScrollAnchor`
- `ScrollToLatestButton`

消息样式：

- 员工消息靠左，显示员工头像和名称。
- 用户消息靠右，显示用户名称或“我”。
- 消息宽度使用 `min(720px, 82%)`，长文本正常换行。
- 不使用大面积气泡包裹整个页面；消息本身使用轻量背景和边框。
- Markdown、代码块、文件链接和错误信息需要独立排版。

### 6.4 自动滚动规则

```ts
const FOLLOW_THRESHOLD = 96
```

实现规则：

- 初次打开历史消息后执行一次 `scrollTo({ top: scrollHeight })`。
- 每次 `text_delta` 到达时，如果距离底部小于 `FOLLOW_THRESHOLD`，自动滚到底部。
- 用户滚动到历史区域时，停止自动跟随。
- 停止跟随后有新消息，显示“回到底部”按钮。
- 点击“回到底部”后恢复跟随状态。
- 切换任务时重置滚动状态并定位到末尾。

必须使用 `useLayoutEffect` 或等价的渲染后测量，避免内容尚未布局时定位失败。

### 6.5 输入框

组件：`ConversationComposer`。

布局：

```text
┌─────────────────────────────────────────────────────────┐
│ 输入你想交代的工作……                                      │
│                                                         │
│ ＋   技能：代码审查   模型：GPT-5.2   [选择工作目录]      │
│                                           [发送 ↑]       │
└─────────────────────────────────────────────────────────┘
```

工具栏固定在输入框底部，设置项不放在页面顶部：

- 添加附件按钮。
- 技能选择菜单。
- 模型选择菜单。
- 工作目录选择按钮。
- 目录权限菜单：只读 / 读写。
- 发送按钮。

发送按钮必须有禁用、发送中和失败重试状态。输入框支持 Enter 发送、Shift+Enter 换行；正在运行时禁止重复提交。

### 6.6 工作目录选择

通过 `window.electronAPI.selectDirectory()` 打开系统目录选择器。

选择后显示：

- 目录名称。
- 只读或读写状态。
- 悬停显示完整路径。
- 清除目录按钮。
- 打开目录按钮（如后端后续提供安全的打开目录 IPC）。

渲染进程不得直接调用 `fs`、`shell` 或 Electron 模块。

## 7. 成果侧栏

组件：`ConversationArtifactsPanel`。

分区：

1. `交付结果`：最终文本摘要、生成的文件、报告。
2. `文件变更`：新增、修改、删除的文件。
3. `工作记录`：工具执行和运行时间线。
4. `本次配置`：实际员工、模型、技能和工作目录。

状态显示：

- `准备工作`：任务还未执行。
- `员工正在工作`：流式生成或工具执行。
- `等待你的确认`：存在权限请求。
- `已交付`：运行成功并产生结果。
- `需要重试`：运行失败。

侧栏在 960px 以上显示为固定列；低于该宽度时改为抽屉，通过图标按钮打开。抽屉打开时不覆盖输入框的发送按钮。

## 8. 任务中心设计

### 8.1 创建页

组件：

- `TaskCenterCreatePage`
- `TaskGoalEditor`
- `EmployeePlanBuilder`
- `EmployeePlanStep`
- `PlanPreview`
- `WorkspacePermissionField`

页面流程：

```text
填写工作目标
  -> 选择多个员工
  -> 为员工分配职责
  -> 调整执行顺序
  -> 设置工作目录和权限
  -> 预览工作计划
  -> 开始安排工作
```

第一版只支持线性步骤：步骤 2 默认依赖步骤 1，步骤可以拖动排序。数据结构保留 `dependsOn`，不在本期实现任意连线编辑器。

### 8.2 执行页

组件：

- `TaskCenterRunPage`
- `TaskPlanTimeline`
- `TaskPlanStepCard`
- `EmployeeHandoffBanner`
- `TaskDeliverySummary`

执行视觉：

```text
老板安排目标
  ↓
内容员工 · 已接单
  ↓
内容员工 · 正在工作
  ↓
内容员工 · 已交付，交接给审核员工
  ↓
审核员工 · 正在工作
  ↓
任务已完成
```

每个步骤显示员工头像、职责、状态、输入、输出、耗时和操作。等待授权时步骤卡高亮并显示确认入口；失败时只突出当前失败步骤，不让整条时间线失去上下文。

### 8.3 推荐数据结构

前端类型建议：

```ts
interface TaskPlanStep {
  id: string
  employeeInstanceId: string
  instruction: string
  order: number
  dependsOn: string[]
  status: RunPresentationState
  startedAt: number | null
  completedAt: number | null
  outputSummary: string | null
  artifactIds: string[]
}

interface TaskPlanDraft {
  goal: string
  steps: TaskPlanStep[]
  workspace: LocalWorkspaceBinding
  continueOnFailure: boolean
}
```

后端对应的任务计划接口需要在后续阶段设计，前端先使用适配器隔离模拟数据和真实 IPC。

## 9. 员工资源页

组件：`EmployeeResourcePage`、`EmployeeResourceRow`。

员工资源页使用真实实例列表驱动，不使用前端写死的员工数组。每行显示：

- 员工头像和名称。
- 员工职责和部门。
- 当前状态。
- 可用模型数量。
- 可用工具数量（如后端提供）。
- “开始对话”或“加入任务”操作。

员工卡片不应堆叠在卡片中。页面使用全宽列表和紧凑行，便于比较多个员工。

## 10. 账户菜单

组件：`AccountMenu`。

左下角触发器显示：

```text
[头像] 用户名称
      所属企业
```

菜单内容：

- 用户名称、邮箱和企业。
- 剩余额度 / Token（来自后端安全接口）。
- 检查更新。
- 设置。
- 退出登录。

退出登录放在菜单末尾并需要二次确认。任何 token 原文、refresh token 或 Authorization header 都不能进入 React 状态、日志或 IPC payload。

## 11. 窗口与标题栏

- 关闭、最小化、最大化交给 Electron 标题栏。
- 页面内容不再放业务层面的窗口控制按钮。
- `electron-drag-region` 只保留窄的顶部拖拽区域。
- 拖拽区域不得覆盖员工切换、页面操作或账户菜单。
- 最小窗口尺寸按现有 `960x640` 约束验证。
- 低于 1120px 时成果栏收起；低于 960px 时不允许产生横向滚动。

## 12. 状态与 IPC 适配

### 12.1 现有接口复用

当前前端可直接复用：

- `auth:get-instances`
- `task:create`
- `task:execute`
- `task:continue`
- `task:get-messages`
- `task:get-all`
- `task:get-stats`
- `task:list-runs`
- `task:get-timeline`
- `util:select-directory`
- `pi:event`
- `pi:tool-approval-request`

### 12.2 需要后续扩展的接口

多员工对话需要：

```text
task:get-participants
task:set-active-employee
task:add-participant
task:continue（携带 activeEmployeeInstanceId）
```

任务中心需要：

```text
task-plan:create
task-plan:get
task-plan:execute
task-plan:pause
task-plan:retry-step
task-plan:get-timeline
```

账户额度需要：

```text
account:get-usage
```

以上接口在后端完成前，前端应通过 `WorkspaceDataPort` 适配器提供临时数据，不要在组件内直接写 `window.electronAPI` 以外的模拟逻辑。

### 12.3 事件映射

前端统一将后端事件映射为展示状态：

| 后端事件 | 前端表现 |
| --- | --- |
| `text_delta` | 员工消息流式追加，自动滚动 |
| `tool_execution_start` | 工作记录新增“正在执行工具” |
| `tool_execution_end` | 工作记录标记成功或失败 |
| `agent_end` | 员工步骤完成或交接 |
| `session_error` | 当前运行失败，显示重试 |
| `pi:tool-approval-request` | 弹出权限确认，任务状态变为等待确认 |
| `task:updated` | 更新任务状态、成果和进度 |

组件边界要求：

- Pi SDK 相关类型只在主进程和共享序列化边界出现，不能进入渲染进程。

## 14. 状态管理设计

推荐使用 Zustand 管理工作台状态，按领域拆分：

```ts
interface WorkspaceStore {
  view: WorkspaceView
  sidebarExpanded: boolean
  selectedTaskId: string | null
  newTaskMode: 'conversation' | 'task-center' | null
  instances: EmployeeInstanceSnapshot[]
  tasks: Task[]
  activeTask: Task | null
  error: string | null
}
```

注意事项：

- 不把 access token、refresh token 写入 Zustand。
- 不把完整 Pi SDK session 放入渲染进程状态。
- 流式文本使用按任务和运行 ID 分组的临时缓冲，任务完成后以持久化消息为准。
- 任务切换时保留缓存，但必须重新读取最后消息和运行状态。
- 组件订阅尽量选择细粒度 selector，避免单个 `text_delta` 触发整页重渲染。

## 15. 动画规范

动画服务于状态理解，不作为装饰。

| 场景 | 动画 | 时长 |
| --- | --- | --- |
| 页面切换 | `opacity 0 -> 1` + `translateY(8px) -> 0` | 250-350ms |
| 卡片悬停 | `translateY(0) -> -2px` + 边框强调 | 150-200ms |
| 按钮按下 | `scale(1) -> .97` | 100-150ms |
| 侧栏收起 | 宽度和内容透明度过渡 | 200-250ms |
| 员工切换 | 头像淡出、名称替换、状态点切换 | 250ms |
| 流式生成 | 光标闪烁或轻量三点 | 800-1200ms 循环 |
| 员工工作 | 头像轻微呼吸 | 1600ms 循环 |
| 时间线交接 | 当前节点高亮并向下一节点移动 | 300-450ms |
| 任务完成 | 状态点和成果摘要淡入 | 300ms |
| 抽屉打开 | `translateX(16px) -> 0` + 淡入 | 250ms |

实现要求：

- 支持 `prefers-reduced-motion: reduce`，减少或关闭非必要动画。
- 不使用大面积闪烁、无限旋转或会影响阅读的背景动画。
- 运行中状态必须有非动画的文字或颜色语义，不能只依赖动画。

## 16. 视觉规范

### 16.1 颜色

使用语义变量，不在组件内散落硬编码颜色：

```css
:root {
  --background: oklch(0.985 0.008 70);
  --surface: oklch(1 0 0);
  --surface-muted: oklch(0.965 0.012 70);
  --foreground: oklch(0.22 0.02 35);
  --muted-foreground: oklch(0.52 0.025 35);
  --border: oklch(0.89 0.02 70);
  --brand: oklch(0.58 0.18 28);
  --success: oklch(0.58 0.15 150);
  --warning: oklch(0.72 0.16 75);
  --danger: oklch(0.58 0.18 25);
  --radius-sm: 4px;
  --radius-md: 8px;
}
```

品牌色用于主要按钮、当前员工状态和关键节点，不要让整页变成单一红色或单一蓝色。

### 16.2 字体与间距

- 优先使用现有系统字体栈，确保中文和英文回退正常。
- 正文建议 14-15px，页面标题 24-32px，侧栏文字 13-14px。
- 使用 4px 基础间距单位。
- 页面分区使用留白和分隔线，不使用多层嵌套卡片。
- 卡片只用于员工、任务步骤、成果文件等独立重复项。

## 17. 响应式与窄窗口

窗口约束：

- 960px：最低可用窗口宽度。
- 1120px 以下：成果侧栏默认收起。
- 960-1120px：侧栏可展开，但主区必须保持输入框可用。
- 低于 960px：不允许横向滚动，员工设置改为抽屉或底部工具菜单。

布局规则：

```css
.workspace-layout {
  display: grid;
  grid-template-columns: var(--sidebar-width) minmax(0, 1fr);
}

.conversation-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) var(--artifacts-width);
}
```

所有长文本、路径、员工名称和任务标题必须允许换行或截断，并通过 tooltip 展示完整内容。固定格式的按钮、工具栏、时间线节点使用稳定尺寸，不能因为文字变化导致布局跳动。

## 18. 可访问性

- 导航使用 `nav`，主要内容使用 `main`，消息列表使用语义化区域。
- 所有图标按钮提供 `aria-label` 和 tooltip。
- 员工切换、模型选择、技能选择使用键盘可操作的菜单。
- 当前导航项使用 `aria-current`。
- 权限弹窗打开时将焦点移动到主要操作按钮。
- 颜色不能作为唯一状态表达，必须同时有文字或图标。
- 正文和控件满足至少 4.5:1 对比度。

## 21. 技术决策总结

1. 前端页面以工作台为中心，不再以实例选择为中心。
2. “新建任务”先选择任务类型，真正提交时才创建后端任务。
3. 对话共享的是消息上下文，不是多个员工之间的 Pi session 对象。
4. 任务中心第一版使用线性步骤，数据结构预留依赖字段。
5. 展示组件不直接调用 Electron，所有 IPC 通过 feature hook 或 adapter 管理。
6. 动画只用于解释状态，不用于装饰页面。
7. 先完成前端壳层和单员工对话体验，再接入多员工后端能力，降低一次性改动风险。
