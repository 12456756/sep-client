# 客户端统一使用 stable 渠道

2026-10-29 起，客户端仅构建和发布 stable 渠道。此前文档中的 beta 构建命令已废弃；历史校验工具仍可读取 beta 数据，便于审计旧产物。

- 默认运行配置、发布说明和打包入口使用 stable。
- `config/release.stable.json` 指向生产 API 与网关；仍可通过环境变量覆盖业务地址。
- 删除 npm 中的 beta 打包和配置生成入口。直接运行配置生成脚本并指定 beta 会失败，避免误生成测试渠道安装包。
- 现有 `0.2.4` stable 安装包已使用正确渠道，本次无需覆盖同版本产物。

## 发布位置

渠道根目录：`https://download.longdaosep.cn/sep-client/stable/`。

macOS 清单为 `latest-mac.yml`，Windows 清单为 `latest.yml`。安装包及 blockmap 放在 `<version>/` 下；先上传并核验全部产物，最后更新两个根清单。

服务器目录：`/opt/longdao/deploy/production/conf.d/downloads/sep-client/stable/`。

旧 `/sep-client/beta/*` 地址仅用于兼容，临时重定向到相同相对路径的 stable 地址，响应禁止缓存；不再向 beta 目录发布文件。保留历史 beta 文件用于审计，不让其继续作为独立更新源。

## 构建命令

```bash
npm run package:local:stable
# 正式签名凭据齐备时才使用 npm run package:stable
```

macOS 继续使用 ad-hoc 签名和浏览器下载安装流程，Windows 继续使用浏览器下载安装流程。版本提升、安装包内部版本和更新清单版本必须一致。
