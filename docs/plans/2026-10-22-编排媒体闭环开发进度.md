## 1. 已实现内容

### 1.1 计划和交付协议

- 节点新增可选 mediaRequirements，描述生成、编辑、图生视频、文生视频以及输入来源和规格偏好。
- 交付物新增可选 artifact 描述；结束 JSON 新增可选 mediaDeliverables，提交交付物 ID 与资产 ID 的映射。
- 最终文件记录新增可选 sourceArtifact，记录图片或视频源资产及哈希。
- 旧计划、旧文件提交和旧交付快照继续兼容，不要求补齐媒体字段。
- 前序来源必须是当前节点的直接依赖；指定的交付物必须存在，显式声明的类型必须匹配。
- 重复媒体需求 ID 在 domain 与 IPC 字段校验中都会被拒绝；不设置固定的媒体需求数量上限。
- 比例、分辨率和输出格式使用可扩展字符串；时长、帧率和数量不写死供应商能力范围。实际可用范围仍需后续实时能力协商。
- 规划提示和节点提示已具备新契约描述；重新规划保留已有媒体需求。这不代表新路径已经启用。

主要文件：electron/domain/arrangement-plan.ts、arrangement-delivery.ts、arrangement-planner.ts、src/shared/types.ts 及相关测试。

### 1.2 任务内媒体关联索引

新增 electron/domain/arrangement-media.ts、electron/data/arrangement-media-link-store.ts 及其测试；electron/data/scope-path.ts 增加任务内索引路径。

- 索引记录 owner、task、编排 run、节点 run、attempt、订阅、job、输入、输出和物化关系。
- 在任务作用域内以 kind + jobId 定位，不以节点 ID 覆盖同节点的其他 job。
- 同一路径的多 store 实例写入串行化；重复内容写入保持幂等。
- 禁止重绑原始归属、修改既有哈希、删除既有输出或以较旧更新时间覆盖记录。
- 区分不存在与损坏：损坏索引不能被当作空列表覆盖，保留损坏证据，可读取有效备份。

当前接口：

~~~ts
list(scope, taskId): Promise<ArrangementMediaLink[]>
get(scope, taskId, kind, jobId): Promise<ArrangementMediaLink | null>
upsert(scope, link): Promise<ArrangementMediaLink>
~~~

当前为任务内 JSON 数组存储，list 读取全部。分页、服务层资产授权、运行时 job 关联和从权威媒体存储重建索引尚未接入。

### 1.3 图片 output 派生 reference

electron/domain/media.ts 与 electron/data/media-store.ts 新增 deriveReferenceFromOutput(scope, taskId, assetId, signal, validate?)。

- 读取任务内已保存图片输出，核对实际字节、哈希、MIME、尺寸及原始 job/output 关系。
- 原 output 保留；派生 task-local reference，不原地改变资产类型。
- 相同哈希复用现有 reference，保留已有身份和元数据；新建 reference 记录首次派生来源。
- 复用现有原子保存、取消与授权回调防护机制。
- 覆盖跨 owner/task 拒绝、取消、重复派生、导入引用复用及源文件损坏测试。

这只是数据能力；编排执行器和视频服务尚未自动调用它，用户仍不能依靠本次改动直接完成跨节点图片转视频。

### 1.4 分阶段保护和恢复兼容

- 在尚未实现媒体物化与专用类型验收前，新的带类型媒体交付节点及声明 inputFrom 的节点会在准备工具和创建 worker 前明确停止，避免先产生付费任务再发现无法交付。
- 普通工作区文件验收拒绝媒体映射和声明为图片/视频的交付物，防止把一个扩展名或资产 ID 当作媒体验收成功。
- 旧文件工作流和既有媒体工具生命周期不因缺少新字段被禁用；本保护不是新的媒体权限开关。
- 从已验收记录恢复结束 JSON 时保留媒体映射，不丢弃 sourceArtifact。
- 媒体源哈希、最终文件哈希和已记录快照必须一致；恢复时不能以改变后的工作区字节替换媒体来源证据。

主要文件：electron/runtime/arrangement-executor.ts、electron/domain/arrangement-delivery.ts、electron/data/arrangement-delivery-files.ts 及对应测试。

## 2. 阶段状态
