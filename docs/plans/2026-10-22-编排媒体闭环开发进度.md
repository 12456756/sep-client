# 编排媒体闭环开发进度

- 更新日期：2026-10-22。
- 实施依据：[编排生图生视频闭环详细开发方案](./2026-10-22-编排生图生视频闭环详细开发方案.md)。方案中的“当前缺口”描述的是实施前基线，本进度文档记录实施后的状态。
- 当前状态：三个主要连接及显式确认已接入，后端 mock 端到端测试通过。尚未完成 Electron 界面操作、真实网关、真实账务验收，不能据此认定所有规划功能已上线。
- 本文只记录编排媒体闭环。另一会话的品牌视觉、登录页和 macOS 签名打包改动保留，本轮不提交或推送 Git。

## 1. 已实现的三个连接

### 1.1 编排节点与原媒体任务连接

新增 ArrangementMediaService，通过 ArrangementMediaPort 接入 ArrangementExecutor，由 build-backend 组装现有图片、视频服务和作用域存储。

- 按 owner、task、计划哈希、节点、员工订阅和真实节点 run 核验归属；模型只能查询和提交当前节点关联的媒体资产。
- 图片和视频在付费提交前持久化节点与 job 关联。关联写入失败时停止提交，不产生未关联的已发送请求。
- 视频 job 记录不可变 runId；恢复时只接入当前节点的原 job，不把同任务其他员工的 job 当成当前节点输出。
- 恢复优先查询原 job，沿用冻结的请求与原资产；不因节点重试而自动重新报价、提交同一操作。
- 已发送 job 的关联证据缺失时明确停止，禁止把缺失索引当成没有生成过。自动重建索引仍未实现。
- Pi 视频工具结果保留可交付的资产 ID、哈希和保存状态，继续过滤本地路径、令牌及其他非白名单字段。

主要文件：electron/service/arrangement-media-service.ts、electron/domain/arrangement-media-runtime.ts、electron/service/media-service.ts、video-run-service.ts、mock-video-host-service.ts、video-service.ts、electron/pi/sdk/pi-coding-agent-adapter.ts。

### 1.2 生图输出与后续图生视频连接

- 执行器解析计划声明的 inputFrom，只接受当前任务中已完成且已确认的直接前置节点交付物。
- 对照前置文件记录、源资产哈希和节点关联索引，定位明确的图片输出；多个候选无法唯一定位时提示补充来源，不默认取第一张。
- 通过 deriveReferenceFromOutput 验证原图字节、哈希、MIME、尺寸和 job/output 关系，派生任务内 reference；保留原 output。
- 同哈希 reference 幂等复用。后续员工获得安全的 localAssetId，由现有视频服务上传和执行图生视频。
- 声明的引用进入节点提示和工具参数；跨任务、跨 owner 或未声明的引用在请求生成前被拒绝。
- 文生视频不要求参考图片，沿用现有 profile、授权、报价和审批链。

主要文件：electron/service/arrangement-media-service.ts、electron/data/arrangement-media-assets.ts、electron/data/media-store.ts、electron/runtime/arrangement-executor.ts。

### 1.3 已保存媒体与工作区最终交付连接

- 模型通过 mediaDeliverables 提交“交付物 ID → 资产 ID”。主进程从当前节点已保存输出获取可信字节，自动写入计划中的工作区相对路径。
- 图片检查实际格式；视频按流复制、计算哈希并检查 MP4/WebM 文件标识。该检查不等同于视频全量解码、视觉质量或播放效果验收。
- 源资产、最终文件与任务内冻结快照保持同一哈希。下游使用校验后的快照路径，不能以被修改的工作区文件替代已确认版本。
- 相同路径、相同哈希可幂等恢复；已有不同内容时报冲突，保留原文件，不静默覆盖。
- 校验路径、符号链接、硬链接、大小、哈希及复制期间文件变化；有界读取、流式写入、短写处理、取消检查和临时文件清理已接入。
- 已声明快照缺失、损坏或缺少任务目录时明确失败，不回退工作区文件。
- 物化前持久化 pendingSubmission。退出或本地文件冲突后，恢复只补做原输出的物化与验收，不再创建模型 worker 或重新生成。
- 模型提交错误资产映射时返回纠正提示，可用原已保存资产修正；真正的本地落盘失败保留待恢复清单。

主要文件：electron/data/arrangement-media-files.ts、arrangement-media-assets.ts、arrangement-delivery-files.ts、electron/domain/arrangement-delivery.ts、electron/runtime/arrangement-executor.ts。

## 2. 显式确认与兼容性

- 默认生成完成并验收后自动继续。仅计划显式设置 requiresUserConfirmation 时，节点以 completed + pendingConfirmation 持久化，编排进入 waiting-user。
- 等待确认的节点不能释放下游；通用重试不能绕过确认。
- 新增 arrange:confirm-nodes IPC，从 preload、TaskService 到 TaskRuntime 调用专用确认方法。输入校验、安全 ID、重复点击互斥、计划/检查点复核及授权检查均已接入。
- 确认后的调度准入失败会恢复原检查点；末节点确认可直接结束任务，不重新运行生成 worker。
- 修复编排暂停结束后检查点 activeRunId 未清空的问题，否则真实确认入口会被旧运行标记阻塞。
- renderer 区分“等待用户确认”与“节点失败等待重试”，从持久化快照或事件投影恢复 pendingConfirmation；确认动作使用专用 IPC。
- 旧计划、旧文档交付和旧媒体工具继续兼容；不增加独立媒体权限开关，沿用员工授权和既有审批。
- 原生工作区媒体文件（artifact.source=workspace）的专用验收尚未实现，当前在创建 worker 和调用生成工具前明确提示；已接通的是媒体库已保存输出的自动交付。

主要文件：electron/domain/arrangement-execution.ts、electron/data/arrangement-checkpoint-store.ts、electron/runtime/task-runtime.ts、electron/controller/routes/arrangement.ts、electron/preload.ts、src/features/enterprise/work-mapping.ts、useEnterpriseWorkspace.ts。

## 4. 端到端测试与结果

### 4.1 测试真实性边界

electron/runtime/arrangement-media-e2e.test.ts 使用真实 TaskRuntime、TaskManager、计划/检查点/节点 run/媒体索引持久化、MediaService、VideoRunService、媒体协调器与文件物化；经过真实 Pi 工具定义和结果白名单。模型 worker、SDK 扩展注册宿主和外部图片/视频网关采用 mock，不连接真实供应商，不产生真实费用。

这证明的是后端跨模块闭环及重建服务后的恢复，不是完整 Electron 点击流程或真实供应商验收。renderer 的状态映射和 IPC 路由另有自动化测试。

### 4.2 21 个后端 E2E 场景

1. 跨员工生图→图生视频，输入字节/哈希一致，最终文件与快照自动生成。
2. 图片提交后暂停、重建运行时，继续原 job。
3. 视频提交后暂停、重建运行时，继续原 job。
4. 无参考图的文生视频。
5. 工作区同名异内容冲突，重启后只恢复本地交付，不新增 worker、报价或生成提交。
6. 图片提交响应丢失，恢复原请求。
7. 视频提交响应丢失，恢复冻结原请求。
8. 视频下载损坏，不能标记交付成功。
9. 视频输出过期，不能标记交付成功。
10. 视频生成失败，不能标记交付成功。
11. 跨任务参考图在媒体请求前拒绝。
12. 无关资产映射不能发布到当前节点。
13. 模型修正错误映射，继续使用已有输出。
14. 审批拒绝，不提交生成。
15. 审批后关联写入失败，不发送生成。
16. 已发送图片 job 关联丢失，不允许再次生成。
17. 员工缺少视频工具，在视频报价或上传前停止。
18. 中间确认阻塞下游；重试不能绕过；并发重复确认仅一次有效。
19. 最终确认结束任务，不增加 worker。
20. 确认授权失败，保留等待状态，之后可恢复。
21. 确认后调度准入失败，回滚并允许之后恢复。
