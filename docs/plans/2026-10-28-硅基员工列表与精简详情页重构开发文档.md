# 硅基员工列表与精简详情页重构开发文档

- 日期：2026-10-28
- 状态：前端已实施；数据与页面回归、浏览器夹具验收通过。完整语音回归通过；真实平台账号验收仍待完成。
- 范围：硅基员工列表页、员工详情页、相关数据映射、返回状态和回归验证。
- 产品决策（按最新反馈更新）：列表负责快速找员工并开始工作；**员工详情使用右侧模态抽屉**，正文只包含「员工简介、已有技能、最近工作」。移除列表左上角标题和说明，取消可见「查看详情」按钮，整卡／整行点击打开抽屉。
- 实现约束：复用现有 React、TypeScript、CSS、员工订阅、组织目录、技能库和工作数据，不新增依赖，不升级 Pi SDK，不改动任务执行与审批策略。

## 1. 目标与验收结果

用户在列表页能快速判断谁适合当前工作，直接开始对话；需要了解更多时打开右侧详情抽屉，查看真实技能和最近工作。返回后继续原来的浏览位置。

本期必须交付：

1. 紧凑、响应式的员工卡片与列表两种视图。
2. 员工名称、介绍、已授权可见技能名称的联合搜索。
3. 数据来源正确的「分配给我的 / 企业全部员工」范围切换。
4. 「员工简介、已有技能、最近工作」组成的右侧详情抽屉。
5. 列表筛选和滚动位置恢复、账号与企业隔离、完整加载与错误状态。

页面精简不依赖补齐不存在的业务接口。缺少介绍、能力画像或技能说明时，按本文收起或显示明确状态，不生成未经配置的业务能力。

## 3. 页面信息架构

```text
硅基员工列表
  ├─ 开始对话 → 现有对话创建页，预选该员工
  └─ 点击卡片／列表行 → 右侧员工详情抽屉
                  ├─ 开始对话 → 同一对话创建页
                  ├─ 查看技能 → 对应技能详情
                  └─ 最近工作 → 对应工作页面
```

路由继续使用现有 `employees`、`employee`、`arrange`、`skills`、`work`。employee 仅作为内部抽屉导航状态，当前来源页面保持挂载，不再渲染独立详情页。抽屉不提供第二套输入、语音或任务提交逻辑。

## 4. 列表页规格

### 4.1 页头与筛选

```text
[分配给我的] [企业全部员工]   [搜索员工或技能…] [全部状态] [卡片 / 列表]

[员工卡片]   [员工卡片]   [员工卡片]
[员工卡片]   [员工卡片]   [员工卡片]
```

- 移除内容区左上角「硅基员工」标题及「找到合适的员工，把工作交给它完成」说明；工具栏直接作为页面顶部。保留共享顶栏与侧栏。
- 无搜索和状态条件时显示当前范围总数；有条件时显示「找到 X / Y 名员工」，X 为匹配数量，Y 为当前范围总数。
- 首次默认「分配给我的」及卡片视图；有已保存视图偏好时使用偏好。
- 保留范围切换、状态筛选和视图切换，不增加职能、部门、评分或绩效筛选。
- 搜索提示改为「搜索员工或技能…」，匹配名称、非空介绍、真实绑定技能名称；去除首尾空格并忽略拉丁字母大小写。
- 不用 `goodAt`、模板名或岗位名称猜测技能；不请求用户无权查看的技能正文。
- 状态筛选保留真实支持的「可用、工作中、暂时不可用」；本期员工页不提供由前端权限开关推导的「需要授权」选项。
- 搜索、范围和状态相交；切换视图不重置条件。没有匹配时提供「清除筛选」。

### 4.2 卡片

```text
[头像] 爆品机会评估师                     可用

真实配置的一句话介绍，最多展示两行。
[真实技能名称] [真实技能名称] [+N]

最近使用：昨天
[开始对话]                    （整卡点击查看）
```

| 元素 | 规则 |
| --- | --- |
| 头像与名称 | 复用 `EmployeeFace`；名称最多两行，完整名称可通过悬浮或焦点提示读取 |
| 状态 | 保留文字与语义色；未分配关系另用文字表达，不用整卡置灰导致内容难读 |
| 介绍 | 非空时展示，最多两行；为空则收起，不保留空段落 |
| 技能 | 按当前订阅绑定展示，去重后最多两项；更多显示 `+N`；本区作为摘要，不额外增加第三个跳转入口 |
| 最近使用 | 使用现有本机工作记录计算的 `lastWorkedAt`；为空则整行收起 |
| 开始对话 | 主按钮，进入 `{ name: 'arrange', mode: 'chat', employeeId }`；不点击即创建任务 |
| 详情入口 | 取消可见「查看详情」按钮；整张卡片覆盖原生按钮，名称为「查看员工名详情」，支持 Enter／Space。与独立的开始对话按钮保持平级，避免嵌套和误触 |

删除授权计数、无记录提示、无内容的星星图标和占位标签。介绍与技能同时缺失时，允许卡片自然变短。

卡片内部以正常文档流排版，不用大段空白把操作推到底部。同一网格行可等高，但不通过固定高度遮挡文字。

### 4.3 紧凑列表

每行包含「头像与名称、简短介绍或技能摘要、状态、最近使用、开始对话」。整行点击打开详情抽屉，开始对话独立执行。摘要采用介绍优先、真实技能名称兜底的规则；都缺失则省略。

空间不足时依次收起最近使用和摘要，保留员工身份、状态与操作。不能把员工名称挤到无法识别，也不能产生页面水平滚动。

### 4.4 布局与视觉

尺寸均为 CSS 像素，以**员工内容容器宽度**为响应式依据，避免受侧栏展开、缩放和高分屏截图比例影响。

| 内容容器宽度 | 网格 | 排版 |
| --- | --- | --- |
| ≥ 1000px | 三列 | 筛选工具栏优先同排 |
| 640–999px | 两列 | 工具栏按需换行，搜索框可占独立一行 |
| < 640px | 单列 | 搜索框整行；筛选和视图切换自然换行 |

- 宽屏内容阅读宽度控制在约 1180–1280px，与 `DESIGN.md` 保持一致。
- 页面内边距 24px，窄窗口 16px；卡片间距 16px，卡片内边距 16px。
- 圆角、字体、按钮、分隔线、焦点与深色模式复用现有设计变量；员工名称约 15px，正文约 13px，元信息约 11–12px。
- 使用安静的中性背景，减少员工内容区的大面积粉色渐变和装饰阴影；品牌红用于选中状态、焦点及主操作。
- 样式限制在员工列表和详情的专用类名下，避免改变首页共用的 `EmployeeCard` 布局。共享入口文案若调整，应同步检查所有调用方。

## 5. 精简详情抽屉规格

`employee` 继续作为内部导航状态，界面为右侧模态抽屉，原页面保持挂载。使用原生 dialog 管理焦点与背景不可交互；宽度最多 640px，窄窗口占满可用宽度，正文独立滚动。支持右上角关闭、Esc 和点击遮罩关闭，关闭后恢复触发卡片焦点，列表筛选与滚动不变。正文只放以下三部分，不增加分组标签页。

```text
员工详情                         [关闭 ×]

[头像] 爆品机会评估师                    [开始对话]
       真实配置的一句话介绍 · 可用

已有技能
技能名称               一句话说明          查看技能 >
技能名称               一句话说明          查看技能 >

最近工作
商品机会评估           已完成              昨天 >
品类市场分析           进行中              今天 >
```

### 5.1 员工简介

- 展示头像、完整名称、真实介绍、状态和唯一主按钮「开始对话」。
- 介绍为空时省略，不写通用能力承诺，也不留空白卡片。
- 未分配给我时，在简介下显示「这位员工尚未分配给你，需要使用请联系企业管理员」，主按钮不可用。
- 名称必须在正文展示，不能依赖旧代码中「名字已在顶栏」的假设。
- 不展示模板版本、部门、职能标签、授权计数或个人偏好编辑器。

### 5.2 已有技能

- 按当前员工订阅绑定筛选技能，每项只显示技能名称、描述和「查看技能」。
- 有描述时展示一行摘要；无描述时收起说明，不重复展示名称。
- 点击进入 `{ name: 'skills', skillId: capability.id }`，不得跳到不带定位的全部技能页。
- 企业版本、个人版本、编辑、切换和上传继续留在已有技能详情中，本页不复制这些功能。
- 加载、失败、无绑定和无权查看必须分开：只有成功加载且确实没有绑定时，才显示「这位员工暂未配置可查看的技能」。
- 企业目录中的未分配员工若缺少可见技能数据，说明「当前账号暂无可查看的技能信息」，不将其解释为员工没有能力。

### 5.3 最近工作

- 只使用当前账号、当前企业下 `workspace.works` 中该员工参与的工作。
- 关联规则为 `participants.includes(employee.id)` 或 `currentEmployeeId === employee.id`；采用订阅 ID，不按名称、模板 ID 或平台员工 ID 模糊匹配。
- 按工作 ID 去重，按 `updatedAt` 降序，取前 3 条；同一时间使用工作 ID 做稳定排序。
- 每条显示工作名称、现有工作状态和更新时间，点击进入 `{ name: 'work', workId }`。
- 复用现有工作状态呈现，不从旧 `kind` 字段推断会话或编排类型。
- 不显示不存在的统计、绩效或完成率；仅展示本机当前可见的记录，不称为企业完整历史。
- 成功加载后没有记录时整块收起；工作列表尚未加载或加载失败时，不将其误报为没有记录。
- 不新增「查看全部」入口，避免为本期扩展员工维度工作筛选路由。

### 5.4 移出的内容

| 内容 | 本期处理 |
| --- | --- |
| 详情输入框、语音按钮、发送按钮 | 删除详情中的挂载，统一使用现有对话创建页 |
| 「能做什么 / 不做这些」 | 不展示当前为空的画像字段；已有真实技能承担能力说明 |
| 本机权限面板 | 从员工详情移除；保留后端现有审批机制，本期不新增权限设置入口 |
| 模板版本 | 不进入本期精简详情页 |
| 「管理我的版本」和全局技能按钮 | 由具体技能的详情入口承接 |

权限设置只有在真实执行策略、作用范围和持久化接通之后，才考虑独立入口。本期不展示无可用内容的设置按钮，也不把删除前端开关视为放宽执行权限。

## 6. 数据与状态处理

### 6.1 两种员工范围

- 我的员工：继续来自 `workspace.employees`，其订阅来源保持不变。
- 企业全部员工：使用 `workspace.organizationEmployees` 的组织目录；以订阅 ID 合并我的员工信息。
- 同 ID 员工的真实可用状态、技能绑定和最近使用优先复用个人订阅侧信息；头像与描述仅在对应字段缺失时使用另一来源兜底。
- 企业目录里尚未同步出现的个人有效订阅可补入去重集合。企业目录读取失败时，只能显示带错误说明的已知缓存或明确标为不完整的结果，不能将个人数量标成企业总数。
- 企业目录与我的订阅可用权限不一致时，采取保守策略禁用开始对话，并通过既有刷新恢复；不能仅凭目录展示关系授予执行权限。
- 详情查找使用同一员工集合，保证从企业目录打开未分配员工不会立即显示「找不到员工」。不改变全局 `workspace.employees` 的原有含义，以免影响首页、对话和组织页。
- 详情在所属数据源加载中时显示加载状态；成功读取后确实不存在才显示找不到及返回入口。

### 6.2 技能与搜索

- 扩展 `needsSkillLibrary()`，让 `employees` 与 `employee` 路由共用 `useSkillLibrary`。
- 继续复用现有并发请求复用、焦点刷新冷却、429 重试倒计时与账号企业隔离，不为每张卡片发请求。
- 按 `binding.subscriptionId` 建立技能名称索引；不把一个技能的全部绑定或全部员工技能混入当前员工。
- 技能初次加载中，名称与介绍搜索仍可用，同时提示「技能加载中，搜索结果暂不完整」。加载失败时保留已成功取得的技能缓存，给出错误与可用的重试入口。
- 没有缓存且技能加载失败时，说明「技能暂不可用，当前仅搜索员工名称和介绍」，不显示「暂无技能」的业务结论。
- 重试通过既有 `refreshSkills()` 执行，并遵守 429 冷却；技能加载不阻塞合法的开始对话入口。

### 6.3 状态与开始对话

员工是否可用必须依据订阅和平台状态，并叠加真实工作活动，不再依据 `permissions.some(item => item.enabled)`。

| 条件 | 员工页行为 |
| --- | --- |
| 已分配且订阅有效，状态可用 | 开始对话可点击，预选该员工 |
| 已分配且工作中 | 沿用现有入口及后端并发规则；展示「工作中」，不承诺一定排队或立即执行 |
| 未分配、订阅无效或明确不可用 | 禁用开始对话，并展示原因；查看详情仍可用 |
| 状态加载失败 | 保留已知状态并标注未更新；缺少权威信息时不能宣称可用，提供重试 |

前端禁用是交互提示，真正的订阅、授权、模型与任务执行检查继续由现有后端执行。界面不得绕过检查，也不替后端实现新的权限系统。

实现时审查 `EMPLOYEE_AVAILABILITY` 中现有提示：「可以排队」「需要开启本机权限」不能直接作为本期页面承诺。优先提供员工页专用呈现或最小更新共享词汇并检查其他消费者，不盲目修改全局枚举。

### 6.4 返回与状态隔离

- 保存范围、搜索词、状态筛选、视图类型、列表滚动位置及进入详情的触发元素标识。
- 抽屉打开时背景页面保持挂载；列表状态仍由稳定的 workspace / App owner 持有，以支持技能／工作跳转返回。不能使用跨账号共享的模块级单例。
- 搜索、筛选、滚动和焦点只需会话内保留；视图偏好可按企业 ID + 用户 ID 存入已有本地偏好存储。存储不可用时退回默认值，不阻断页面。
- 关闭详情抽屉时保留列表状态、滚动并恢复卡片焦点；从技能或工作返回详情时不重复创建导航记录。
- 从首页带显式 `scope` 进入时，以该 scope 为准，并重置本次搜索、状态筛选和滚动；保留视图偏好。普通导航无显式 scope 时恢复当前会话的列表状态，首次为 mine。
- 从首页等非列表入口进入详情时，在原来源页面上方打开，关闭后回到原来源；无来源时以员工列表为背景。不要始终跳转到一个全新的「全部员工」页面。
- 修改 `ClientAppPage` 的统一置顶行为时，将抽屉视为原背景路由，打开／关闭不触发滚动重置；从其他页面回到员工列表时使用已保存位置，其他页面继续原有行为。数据和布局就绪后恢复，避免先置顶再明显跳动。
- 切换账号、企业、退出登录时清理会话状态，不恢复另一个作用域的员工 ID、搜索、工作记录或技能缓存。

## 7. 加载、空状态与无障碍

| 场景 | 展示与操作 |
| --- | --- |
| 个人订阅首次加载 | 员工骨架与加载说明；不提前显示 0 名 |
| 个人订阅加载失败 | 错误与重试，有缓存则保留；不显示「没有员工」 |
| 企业目录加载或失败 | 在企业范围单独呈现；我的员工范围仍可使用 |
| 当前范围确实无员工 | 「暂未分配员工」或「企业暂无可见员工」，使用与范围一致的说明 |
| 搜索或状态筛选无匹配 | 「没有符合条件的员工」及清除筛选 |
| 技能或工作局部失败 | 只影响对应区域，保留员工简介与合法操作 |
| 详情对象已失效 | 说明无法查看并提供返回，不自动跳转或保留可操作的过期对象 |

范围控制优先采用语义明确的按钮组及 `aria-pressed`；若保留 tab 结构，必须补齐方向键、roving tabindex 和对应面板。视图按钮提供选中状态与名称。

所有操作支持 Tab、Enter / Space 和可见焦点；卡片的覆盖按钮与开始对话按钮必须平级；开始对话独立接收点击，不触发打开抽屉。禁用原因不能只放在禁用按钮的 tooltip 中，应有可读说明。结果数量使用克制的 `aria-live`，状态不只依赖颜色。长名称、200% 缩放、深色模式和窄窗口均须可读。
