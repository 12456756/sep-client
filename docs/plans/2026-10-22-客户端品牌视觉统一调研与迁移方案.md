# 客户端品牌视觉统一调研与迁移方案

> 日期：2026-10-22  
> 状态：设计方案，待实施  
> 范围：登录后 Electron 客户端的浅色主题、品牌背景、水印和主要页面视觉  
> 依据：当前 `src/` 实现与新版登录页样式；不改变业务流程、信息架构或 Electron 窗口行为

## 1. 目标与设计结论

登录页已经形成一套用户认可的品牌表达：低饱和玫瑰灰到冷灰的连续渐变、深红色品牌强调、深灰文字，以及由品牌图形构成的低透明度水印。客户端应沿用这些识别特征，但不能把登录页的整屏渐变、居中品牌内容和大面积装饰直接复制到工作界面。

设计结论：

- **同一品牌，不同浓度。** 登录页负责建立品牌氛围；工作台保持更克制，背景渐变只承担外壳底色和空间过渡。
- **先统一令牌，再整理页面。** 主色、背景、文字、边框、表面、焦点态和阴影使用企业客户端语义变量；页面不各自保存一套接近但不相同的颜色。
- **渐变属于工作区外壳，内容表面负责可读性。** 主画布使用浅玫瑰到冷灰的低对比背景，顶栏、输入区、弹窗和需要连续阅读的内容使用清晰的表面色。
- **水印属于应用品牌，不属于企业品牌。** 当前侧栏显示的是用户所在企业的 Logo/名称，不能把产品水印放进企业标识位置。
- **浅色和深色主题分别设计。** 登录渐变不直接套进深色主题；深色模式维持现有暗色层级，仅调整品牌强调色和对应的装饰水印。
- **不以装饰替代信息层级。** 不增加工作台大幅欢迎海报、模糊光斑、粒子或重复的品牌卡片；员工、任务、状态和操作仍是第一视觉层。

## 2. 当前实现调研

### 2.1 应用结构

当前登录后页面以 `ClientAppPage` 作为外壳，结构为：

```text
.ent-shell
├── AppSideNav       企业标识、主导航、账号菜单
└── .ent-shell-main
    ├── AppTopBar    页面标题、个人/企业切换、命令入口、主题、通知
    ├── 错误提示
    └── .ent-scroll  当前工作页面
```

浅色/深色模式由 `.ent-shell.dark` 和 `data-theme` 驱动；侧栏折叠状态由 `.sidebar-collapsed` 驱动。页面包含首页、组织、员工列表与详情、安排工作、工作记录、技能、知识库、算力中心及工作详情。安排工作有独立的全高工作区和滚动规则，视觉调整不能改变该布局。

主要入口文件：

| 用途 | 文件 |
|---|---|
| 页面外壳、主题状态、页面路由 | `src/pages/ClientAppPage.tsx` |
| 企业侧栏 | `src/components/enterprise/AppSideNav.tsx` |
| 顶部栏 | `src/components/enterprise/AppTopBar.tsx` |
| 客户端语义令牌、通用控件、外壳 | `src/styles/enterprise.css` |
| 当前首页 | `src/pages/enterprise/HomePageRedesign.tsx`、`src/styles/home-v2.css` |
| 安排工作 | `src/pages/enterprise/ArrangeWorkPage.tsx`、`src/styles/arrange.css` |
| 登录页品牌图与水印 | `src/pages/LoginPage.tsx`、`src/index.css` |

### 2.2 已有视觉基础

`src/styles/enterprise.css` 已经有一套较完整的 `--ent-*` 语义变量，很多共用控件、侧栏导航、表单、弹窗和安排工作页面都依赖这些变量。因此，大部分页面可以先通过令牌校准整体色彩，再按页面修整硬编码颜色，不需要重写组件。

当前浅色令牌以米色画布、白色面板、棕色正文和橙红色主色为主；登录页则使用玫瑰灰/冷灰渐变、`#AE383D` 强调色和灰紫文字，两者目前不是同一组视觉变量。深色变量已有独立覆盖，应保留为独立主题。

### 2.3 需要处理的具体断层

1. **颜色变量已分叉。** 登录页的 `--login-*` 与客户端 `--ent-*` 是两套命名及取值。客户端 CSS 注释还描述“米色底色 / 棕色系”，和用户认可的新登录页方向不一致。
2. **首页样式存在旧变量引用。** `src/styles/home-v2.css` 的 `.ent-home-v2` 引用 `var(--ent-bg)`，全仓没有找到该变量的定义；迁移时应改用明确的画布语义令牌，避免依赖失效值。
3. **首页存在独立颜色。** 统计图标仍有紫色与灰色渐变，部分页面/状态色直接写在页面 CSS 中。品牌色迁移不能覆盖语义状态色，但需要识别哪些是装饰色并收敛。
4. **装饰浓度不一致。** 通用 `--ent-*` 变量与 `home-v2.css`、`arrange.css` 中的 `--arr-*` 变量并存；边框、输入底色和阴影可能各自偏冷、偏暖。
5. **首页头部较像独立卡片。** 当前 `.home-banner` 用完整白底边框包住欢迎语和统计；建议把欢迎语与摘要指标从整块框中释放，改为在统一画布上形成轻量信息行，保留需要交互的统计组件边界。
6. **平台窗口区不能被主题破坏。** `.ent-top` 是 Electron 拖拽区，Windows 右侧需要避让窗口按钮，macOS/Windows 的窗口主题还由主进程同步。任何透明顶栏调整都必须保留可拖拽与按钮点击区域。
7. **页面滚动行为有明确约束。** `ent-scroll-arrange` 是固定工作区；首页和组织页使用特殊 overflow；工作详情和员工墙也有专门宽度/滚动规则。背景装饰不可通过修改这些滚动容器行为来实现。

### 2.4 登录页水印实现事实

登录页从 `src/assets/logo.png` 导入同一个透明品牌图，分别用于清晰的主 Logo 和装饰水印。水印是单独的 `<img>`，通过绝对定位、放大、旋转、低透明度、`pointer-events: none` 及父容器裁切，获得图形嵌入底色的效果。它不是烘焙在渐变图片里的像素，也不参与内容排版。

客户端复用时应继续使用产品品牌图片，而不是把图片写进背景截图。装饰层必须是无障碍隐藏的、不可点击的，并始终位于交互控件后面。

## 3. 视觉规范建议

### 3.1 颜色方向

以下是迁移的建议起点，渐变和表面最终需要通过真实 Electron 窗口截图校准。主色以用户已认可的登录页为准，语义状态色保留可识别性。

| 用途 | 建议值 / 方向 | 使用规则 |
|---|---|---|
| 品牌深红 | `#AE383D` | 主操作、当前导航、焦点环、需要强调的品牌状态 |
| 品牌 hover | 比主色略深的同色阶 | 仅用于交互反馈，不做大块背景 |
| 画布起点 | `#EAD5DC` | 渐变左侧极淡起始色，不直接作为文字底 |
| 画布过渡 | `#F2DCD6`、`#F0E6E5` | 低饱和过渡色，避免出现明显分栏 |
| 画布终点 | `#EEF0F4` 至 `#F5F6F8` | 内容区右侧/下侧的冷灰收束 |
| 正文 | `#302E34` | 标题和正文；确保普通文字对比度 |
| 次级文字 | `#716A72` | 辅助说明、面包屑、未选中导航 |
| 面板表面 | 接近白色的轻暖灰白 | 表单、弹窗、输入区、连续阅读面板 |
| 分隔线 | 玫瑰灰/冷灰的低对比色 | 采用细边线代替层层阴影 |
| 语义状态 | 沿用成功绿、提醒琥珀、错误红 | 颜色仍配合图标和文字，不因品牌统一而全部染红 |

应用浅色渐变建议比登录页更淡一档：画布的主要面积观感应接近浅灰，而不是粉色页面。不要给每张卡片加渐变；渐变只用于连续背景、少量品牌强调和需要强调的主动作。

### 3.2 表面层级

统一成四层，避免“渐变底上叠很多白卡”：

1. **应用画布**：低对比玫瑰灰至冷灰的柔和渐变。
2. **导航与顶栏**：低不透明度浅表面或纯浅色表面，细分隔线与画布连接；须满足文字清晰和窗口拖拽区可见。
3. **交互面板**：表单、输入区、弹窗、菜单使用稳定的不透明表面，保证读写体验。
4. **信息项**：员工卡、任务行等采用现有边框和间距组织；只有悬停、选中、错误等状态才升高视觉权重。

优先使用颜色和边界区分层级；阴影仅用于弹出菜单、抽屉和浮层，不用作每个普通卡片的默认装饰。

### 3.3 水印方案

建议将产品水印放在 `.ent-shell-main` 的背景层右下角，尺寸约为主内容高度的 35%–50%，最大边长约 360–440px，透明度初始值 1.5%–2.5%，略微移出边界并裁切。采用登录页同一透明 PNG，通过独立装饰元素承载，不复用企业 Logo。

约束：

- 装饰层 `aria-hidden`、不可交互，位于顶栏/页面内容/弹窗之下，不改变层叠和点击行为。
- 顶栏保持清晰表面；员工卡、表格、消息正文和知识文档等不透明面板遮住水印。水印主要在页面留白、边缘和空状态周边隐约可见。
- 首页可有更明显但仍低于 3% 的背景水印；其他页面保持外壳一致，不在每张卡片/每个页面重复放 Logo。
- 侧栏折叠时不改变水印；小窗口或高密度工作区可关闭水印，避免装饰挤占内容或降低对比度。
- 深色主题使用单独的低亮度/透明度设置，避免浅色 Logo 产生发光贴纸感；优先使用原始透明图，不为水印新增生成式素材。

## 4. 分阶段迁移

### Phase 0：建立视觉基线

- 记录当前浅色/深色模式，在首页、安排工作、工作记录、知识库、员工列表和算力中心各取一张窗口截图。
- 记录常见窗口尺寸、标题栏高度、侧栏展开/折叠和页面滚动状态。
- 通过 DevTools 检查 `--ent-*`、`--arr-*` 的最终计算值和无定义变量，尤其核实 `--ent-bg` 引用。
- 确认主进程窗口背景色与 renderer 顶部/侧栏交界，macOS 和 Windows 分别检查。

### Phase 1：统一语义令牌和应用外壳

修改重点：`src/styles/enterprise.css`、`src/pages/ClientAppPage.tsx`，必要时仅为装饰层增加极小的品牌图引用。

- 重新命名或校准浅色 `--ent-*` 颜色令牌，使画布、表面、文字、线条、品牌、交互态各有唯一语义来源。
- 将渐变作为 `.ent-shell`/主内容背景的一部分；为导航和顶栏制定协调的表面规则。
- 把 `--ent-bg` 替换为已定义的画布变量；清理与全局语义变量重复的旧色彩令牌时先核实引用，不做批量盲替换。
- 实现应用级产品水印层，并验证 z-index、裁切、窗口拖动区和点击行为。
- 保留 `.ent-shell.dark` 覆盖语义令牌，浅色渐变不得泄漏进暗色主题。

### Phase 2：首页验证品牌浓度

修改重点：`HomePageRedesign.tsx`、`home-v2.css`。

- 将欢迎语和统计调整为轻量、连贯的摘要区，减少整块白色横幅的“卡中卡”感。
- 员工工作区沿用清晰卡片和信息密度，移除仅为装饰的表情符号/高饱和紫色图标渐变，状态仍用语义色表达。
- 首页空状态、加载和错误状态统一表面、文字、按钮和边界。
- 对比有员工、无员工、多人/长名称等状态，确认品牌背景不和业务信息争夺注意力。

### Phase 3：逐类页面迁移

先迁移能复用语义变量的页面，再处理有独立视觉系统的页面；不改变业务交互：

- **安排工作**：保留固定工作台、底部输入区、模式切换和内部滚动；统一 `--arr-*` 与 `--ent-*` 的色彩，主流程按钮保持清晰。
- **工作记录/员工/技能**：优先统一页面画布、筛选器、列表行、标签、空状态和弹窗，不给高密度数据列表叠加渐变或水印。
- **知识库/工作详情/组织/算力中心**：保留各自图表、流程、媒体和文档的专有信息设计，只对齐通用背景、文字、边框、表面、按钮和主题响应。
- **通知、命令面板、设置、抽屉**：复核浮层表面、遮罩、焦点环、hover 和危险操作颜色；确保它们不受背景装饰影响。

### Phase 4：跨平台与主题验收

- 浅色与深色模式分别验收，不把浅色渐变截图作为暗色基准。
- macOS 与 Windows 检查标题栏高度、窗口按钮避让、拖动区域和 renderer 背景衔接。
- 检查侧栏展开/折叠、低高度窗口、窄窗口、内容滚动、对话输入和抽屉叠层。
- 用对比度检查确认正文/小字/控件边框/焦点环达到可读性；状态仍同时由文字或图标表示。
- 确认 `prefers-reduced-motion` 行为不因视觉迁移改变；不新增持续动画。

## 5. 文件改动范围建议

第一轮实现建议限制在下列文件，页面验证后再扩展：

| 文件 | 预期职责 |
|---|---|
| `src/styles/enterprise.css` | 浅/深色语义变量、主外壳、侧栏、顶栏及共用控件颜色 |
| `src/pages/ClientAppPage.tsx` | 如需，增加单个无障碍隐藏的应用水印层；保留主题状态和窗口布局 |
| `src/pages/enterprise/HomePageRedesign.tsx` | 首页摘要区结构和品牌装饰的归属 |
| `src/styles/home-v2.css` | 首页画布、摘要指标、员工卡、响应式样式和遗留色值 |
| `src/styles/arrange.css` | 第二轮对齐安排工作独立变量；保留工作台布局与交互 |
| `src/styles/notifications.css`、`updates.css`、`knowledge.css`、`compute-center.css` 等 | 后续依页面检查结果修改，不在第一轮无差别全量替换 |

不要改动登录鉴权、IPC、数据状态、Electron 窗口行为或新增依赖。不要把登录页的 CSS 变量直接提升成全局变量；登录页和客户端有不同的明暗主题与视觉责任，应共用色值决策但保留作用域语义。

## 6. 验收标准

### 视觉一致性

- 登录页与客户端主色、正文色和品牌情绪一致，浅色客户端背景能看出柔和的色彩过渡，但首屏不显得粉、空或像宣传页。
- 主内容、导航、顶栏在相邻边界处连续，不再呈现黑/白或米色/冷灰的突兀拼接。
- 水印只在留白处形成轻微品牌提示，正常阅读时不会先看到水印。
- 员工状态、工作状态、成功/提醒/错误语义不被品牌红统一覆盖。

### 交互与主题

- 导航选中、hover、焦点、键盘操作、按钮禁用、表单错误、通知和菜单状态均可辨认。
- 深色模式没有浅色水印或浅色渐变残留；窗口原生按钮、拖动区域和主题同步正常。
- 安排工作仍能在原窗口尺寸下使用，输入区位置、模式切换、内部滚动和结果滚动未回归。
- 页面滚动、侧栏折叠、低高度布局、空状态和弹出层均无重叠或裁切。

### 验证方式

- 自动检查：`npm run typecheck`、`npm run lint`、`npm run build`；如只改 CSS/页面结构，至少运行类型检查、相关测试和生产构建。
- 视觉检查：Electron 实机截图或 Playwright 截图，覆盖 1440×900、1200×800、960×640；浅色/深色、侧栏展开/折叠、首页/安排工作/高密度列表。
- 交互抽查：导航和键盘焦点、主题切换、滚动、输入区提交前状态、抽屉/命令面板/通知面板打开关闭。
- 对比基线截图，确认变化集中在品牌色与表面层次，没有改变业务信息、可用区域和窗口行为。

## 7. 决策记录

- **采用**：登录页的玫瑰灰—冷灰渐变、深红主色、克制水印和深灰文字作为产品品牌资产。
- **采用**：水印放在应用内容外壳背景层，不放进企业 Logo 区，也不重复贴在卡片上。
- **采用**：先调令牌和外壳，再用首页作为品牌浓度样板，之后逐类迁移其余页面。
- **不采用**：所有页面使用完整登录渐变、全白内容区或大面积深色/纯黑侧栏。
- **不采用**：一次性批量替换所有 CSS 颜色；状态色、图表色和媒体内容必须按语义分别判断。
- **范围限制**：本文是设计与实施建议，不代表迁移已完成；具体截图评审应在 Phase 1 和 Phase 2 完成后进行。
