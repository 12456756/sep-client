# 请求次数、耗时观测与计费口径修正

## 问题

界面显示“图片调用模型 12 次、视频调用 20 次”，但后台没有对应数量的媒体消费，用户无法判断时间和费用到底消耗在哪里。

## 已确认根因

当前计数混合了不同概念：

- 模型执行回合。
- 工具调用后继续生成。
- 交付校验或 JSON 修正回合。
- 网关重试和执行恢复。
- 媒体实际提交。
- 媒体状态轮询。
- 账务/receipt 事件。

因此“模型请求次数”不能推导“媒体生成次数”，`SETTLED` 也不能单独推导视频已经生成并保存。

## 目标方案

1. 统一阶段 telemetry：`queued`、`admission`、`lock`、`setup`、`provider`、`tool`、`knowledge`、`media`、`delivery`、`eventDrain`。
2. 请求分类至少包含 `modelRequest`、`toolCall`、`mediaSubmission`、`mediaPolling`、`retry`、`resume`、`billingEvent`。
3. 每条记录绑定 `taskId`、`runId`、`nodeRunId`、`stage`、`durationMs`、`attempt`、`reasonCode`。
4. UI 分开展示模型回合、媒体提交、媒体轮询和账务事件，不再使用“视频调用次数”统称。
5. 计费状态只作为账务事实展示；生成成功必须由供应商状态、下载保存和交付证据共同确认。

## 主要改动

- `electron/runtime/run-queue.ts`
- `electron/runtime/workspace-lock-manager.ts`
- `electron/runtime/run-events.ts`
- `electron/runtime/conversation-executor.ts`
- `electron/data/task-run-store.ts`
- `src/features/enterprise/work-mapping.ts`
- `src/pages/enterprise/WorkDetailPage.tsx`

## 实施顺序

1. 不改变执行行为，先补齐阶段计时和请求分类。
2. 对历史任务只做读取投影，缺失数据展示未知，不从模型回合数倒推媒体提交。
3. 增加聚合查询和 UI 展示，支持按 task/run/node 分解耗时。
4. 将指标接入告警：媒体提交重复、长时间无状态变化、收尾失败、事件 drain 超时。

## 验收

- 能回答每个任务时间消耗在队列、锁、模型、知识库、媒体、下载、交付还是收尾。
- 同一媒体 job 的提交数、轮询数和模型回合数可分别查询。
- 历史数据缺失时显示“未知”，不伪造费用或生成次数。
- 日志不包含完整 prompt、凭据、refresh token 或供应商敏感 URL。
