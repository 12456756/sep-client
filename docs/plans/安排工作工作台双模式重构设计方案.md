# 安排工作工作台双模式重构设计方案

> 日期：2026-09-28
> 状态：Phase 1–3 实现完成，Phase 4 验收中（待桌面窗口视觉验收）
> 目标：将当前“先选择三张模式卡片，再进入独立流程”的安排工作入口，重构为一个持续可用的工作台；用户在顶部切换「会话 / 编排」，页面主体随模式切换。借鉴 Codex 桌面端“固定工作区 + 底部组合操作区”的交互逻辑：运行设置全部收纳在窗口底部的输入/操作区中按需展开，不再从右侧滑出独立设置侧栏；同时保留 SEP 的员工协作、自动计划与手动流程能力，不照搬其品牌外观。

## 1. 产品判断

当前安排工作页先展示「对话式 / 自动 / 手动」三张等权大卡片。它让用户必须先理解三种工作流的区别，也把“和员工沟通”与“规划多人任务”表现成三个彼此独立的功能入口。

重构后把用户心智收敛成两个问题：

1. **我想直接和一位员工开始工作吗？** → 会话
2. **我想安排一项多人协作工作吗？** → 编排

「自动 / 手动」是编排内部的两种规划方式，不再与会话并列为三个首页大入口。第一次使用时默认进入会话；有模板、已保存流程或明确编排意图时，可以直接打开对应编排状态。

## 2. 信息架构与示意图

客户端已有全局左侧导航和全局顶部栏，安排工作页不再重复画一套应用导航。全局顶部的「个人 / 企业」切换仍只负责切换产品空间；下面的「会话 / 编排」是安排工作模块内的模式切换，两者视觉上分组明确。

│ 首页         │                                                           │
│ 硅基员工     │  安排工作                                                 │
│ 安排工作 ◀   │  安排工作工作台                     │
│ 工作记录     │                                                           │
│ 员工技能     │       ┌──────────────┬──────────────┐                     │
│              │       │   会话       │   编排       │  ← 顶部双模式切换  │
│              │       └──────────────┴──────────────┘                     │
│              │                                                           │
│              │  ┌───────────────────────────────────────────────────┐    │
│              │  │                                                   │    │
│              │  │           当前模式的主要工作区                    │    │
│              │  │                                                   │    │
│              │  │     会话：员工欢迎态 / 对话上下文                 │    │
│              │  │     编排：目标与协作计划 / 流程画布                │    │
│              │  │                                                   │    │
│              │  └───────────────────────────────────────────────────┘    │

工作区只有两种顶层模式。模式切换固定在安排工作内容顶部；会话与编排共用同一个底部输入容器规格，始终位于内容区底部中央。目录按钮位于输入框左上方，员工/自动方式、权限、模型和发送按钮位于输入框底部工具栏。点击更多设置后，面板从工具栏上方就地展开，不再出现页面级底部条或独立侧栏。

### 2.2 会话模式

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 安排工作                                            [ 会话 ● | 编排 ○ ] │
│                                                                         │
│                         ┌─────────────┐                                 │
│                         │ 员工头像    │                                 │
│                         └─────────────┘                                 │
│                                                                         │
│                                                                         │
│                                                                         │
│             [员工能力提示 / 常用目标建议，可选]                           │
│                                                                         │
│                                                                         │
│                         [选择目录]                                      │
│              ┌──────────────────────────────────────────────┐            │
│              │ 随心输入                                     │            │
│              │                                              │            │
│              │ [选择同事]       [访问权限] [模型]        ↑  │            │
│              └──────────────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────────────────────┘
```

- 员工选择收进输入区的首行，已从员工详情进入时自动预选，不再先经过独立员工步骤。
- 中央欢迎态只展示当前员工身份、简短能力说明及少量建议，不堆叠教程、指标卡和重复标题。
- 底部组合操作区作为主要操作点：描述目标、选择资料/目录，并在同一底部区域查看/修改工作目录、模型、权限和风险确认，再开始工作。
- 发送后沿用现有 `startConversation`，创建成功进入工作详情页；真正执行期间的多轮对话与记录仍在工作详情中，不在安排页伪造聊天历史。
- 没选员工时，发送按钮禁用并给出轻量的选择提示；从员工详情跳转时保留该员工。

### 2.3 编排模式

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 安排工作                                            [ 会话 ○ | 编排 ● ] │
│                                                                         │
│ 编排协作计划                                  [自动] [手动]               │
│ 说明目标，确认参与员工和分工后再启动                                    │
│                                                                         │
│ ┌─────────────────────────────────────────────────────────────────────┐ │
│ │ 自动：                                                                │ │
│ │ 目标输入 → 生成中/可编辑计划 → 员工步骤与交接 → 运行前检查            │ │
│ │                                                                     │ │
│ │ 手动：                                                                │ │
│ │ 左：顺序流程画布 / 员工步骤       右：当前步骤或工作资料配置          │ │
│ └─────────────────────────────────────────────────────────────────────┘ │
│                                                                         │
│ ┌─────────────────────────────────────────────────────────────────────┐ │
│ ┌─────────────────────────────────────────────────────────────────────┐ │
│ │ [目录] [模型] [权限]                                  窗口底部条 │ │
│ ├─────────────────────────────────────────────────────────────────────┤ │
│ │ 补充工作目标 / 资料                              [生成计划 / 开始]  │ │
│ └─────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────┘
```

- 编排内提供轻量子切换「自动 / 手动」，仅在选择编排后出现；这是编排方法，不是安排工作工作台的第三种顶层模式。
- 自动保留现有草稿生成、检查、编辑和确认启动能力。生成前主操作为「生成计划」，生成后主操作变为「确认并开始工作」。未确认前不能开始执行。
- 手动保留现有流程画布、添加员工、调整顺序、步骤配置、保存常用工作和启动能力。
- 从企业模板、常用工作或复制流程进入时自动选择「编排 / 手动」并带入草稿，不先跳回空白欢迎页。

## 3. 页面组成与视觉层级

### 3.1 安排工作局部页头

- 全局 AppTopBar 标题固定为「安排工作」，不随模式显示「对话式安排 / 自动 / 手动」等易让人误认为是不同页面的标题。
- 模式切换放在页面内容顶部，采用一个有清晰选中态的双段控件：`会话`、`编排`。切换范围限于模块内部，不替代全局的「个人 / 企业」控件。
- 安排工作页不显示全局副标题；仅保留全局标题「安排工作」和页面内的模式切换，避免重复说明。

### 3.2 工作区

- 工作区使用页面可用高度，主体内容保持适度最大宽度，欢迎态和空状态居中。
- 会话模式不出现执行设置右侧抽屉或侧栏。员工能力信息按需展示；工作目录、模型、权限与风险确认集中在窗口底部的组合操作区，默认显示紧凑摘要，点击后在输入区上方/底部区域内展开设置面板，不遮挡主工作区且不改变页面横向布局。
- 编排模式中的手动设计可以是唯一保留双栏的场景：左侧流程，右侧当前步骤配置。自动生成不强行并排放三个卡片。
- 输入区贴近工作区底部但不遮挡内容；窗口较小时允许工作区内部滚动，底部操作区保持可达。运行设置折叠时显示目录、模型、权限的当前摘要；展开时在底部操作区内向上增加一层设置区域，不覆盖输入框、不改变主工作区宽度。

### 3.3 视觉规范

- 沿用客户端当前品牌红、浅灰工作区、白色内容面板及既有圆角/边框/阴影 token，不重新引入一套颜色。
- 模式切换为低高度、紧凑分段控件，不做大型彩色卡片。
- 当前模式用清晰的文字、底色和 `aria-pressed`/tab 语义表达；非当前模式保持可读，不靠颜色作为唯一信息。
- 动效只用于模式内容轻微淡入/横向过渡（约 160–220ms），遵守 `prefers-reduced-motion`；模式切换不触发长时间加载或假进度。

## 4. 交互和状态规则

1. 首次通过左侧「安排工作」进入：默认会话模式；若无可用员工，显示现有明确空状态和返回员工页的路径。
2. 在会话与编排之间切换：不应静默清空已填写的目标、所选员工、草稿步骤或已生成计划。至少分别保留两种模式的未提交状态；无法保留时必须在离开前明确提示。
3. 会话中若已选员工，切换到编排不把此员工自动伪装成已确认的流程步骤；可提供“将此员工作为第一步”的明确快捷动作，但必须由用户触发。
4. 编排的自动/手动子模式互切时保留可兼容的目标和资料；自动计划与手动流程属于不同结构，转换必须明确告知且不能静默覆盖。
5. 模板、常用工作、复制流程、员工详情的现有深链入口均继续工作；选中的模式从入口参数推导。
6. 工作记录、工作详情和真实执行逻辑不因安排工作 UI 重构而改变。
7. 主按钮需体现当前动作，避免所有状态都显示“开始”：会话「开始工作」/「发送」，自动编排「生成计划」/「确认并开始工作」，手动编排「保存流程」与「开始工作」按当前草稿状态呈现。

## 5. 现有能力迁移映射

| 当前入口/组件 | 新工作台位置 | 必须保留的行为 |
| --- | --- | --- |
| 三张 `ModeCards` 卡片 | 移除；由顶层「会话 / 编排」取代 | 不删除三种现有真实工作能力 |
| `ChatArrange` | 会话工作区 + 底部组合输入区 | 员工选择、目标校验、底部运行设置、`startConversation` |
| `AutoArrange` | 编排 → 自动生成 | 目标生成草稿、取消、修改草稿、运行前检查、确认后启动 |
| `ManualArrange` | 编排 → 手动设计 | 流程画布、员工步骤配置、重排、保存常用工作、启动 |
| `RunSettingsDrawer` | 移除独立侧栏呈现，迁移为窗口底部组合操作区内的可展开设置面板 | 工作目录、模型、权限及原有安全默认值；设置摘要始终可见，详细控件就地展开 |
| `templateId` / `arrangeSeed` | 默认进入编排 → 手动 | 模板与常用工作的步骤、资料和用户修改能力 |
| 员工详情「安排工作」 | 默认进入会话并预选员工 | 仍只对当前账号可操作的员工显示入口 |

## 6. 导航与实现边界

当前路由将 `pick / chat / auto / manual` 作为同一层的 ArrangeMode。设计目标是将其收敛为清楚的顶层模式和编排子模式，例如：

```text
顶层：会话 | 编排
编排子模式：自动 | 手动
入口来源：templateId / employeeId / arrangeSeed
```

具体路由编码在实现阶段先盘点所有调用方，再做兼容迁移；不要只改 ArrangeWorkPage 而遗留员工页、首页快捷入口、常用工作和复制流程的跳转错误。功能实现继续通过既有 `workspace` 方法与 IPC，不把执行、权限校验或平台数据搬到 renderer 新模块中。

## 7. 分阶段开发与验收

### Phase 0：状态和入口盘点

- 梳理所有安排工作路由、模式跳转、模板/保存流程预填充和执行设置行为。
- 定义顶层会话/编排与编排子模式的路由及本地草稿保留规则。
- 验收：现有入口全部有明确的新模式落点；无行为被误删。

### Phase 1：工作台骨架和模式切换

- 新建双模式布局、稳定页头、欢迎态和响应式工作区。
- 保留现有模式组件，通过适配层先完成正确切换，不重写业务调用。
- 验收：窗口宽度变化时无横向溢出；键盘可切换模式；模式有可访问名称和选中状态。

### Phase 2：会话模式输入体验

- 将员工选择与目标输入整合为一个 ChatGPT 风格但品牌一致的输入区。
- 移除多余的四步大向导呈现；运行设置固定归入窗口底部组合操作区，需要时在底部就地展开，禁止弹出右侧独立抽屉/侧栏。验收需覆盖设置折叠/展开、窗口较矮时的可达性及权限默认值保持。
- 验收：无员工、未输入目标、预选员工、切换员工、启动中、启动失败均有正确状态；启动后进入原工作详情。

### Phase 3：编排模式聚合

- 把自动和手动收进编排子切换，接入现有 AutoArrange、ManualArrange。
- 自动草稿、手动流程、模板和常用工作按各自状态正确呈现。
- 验收：未确认自动计划不可运行；手动步骤编辑、保存和启动行为保持一致。

### Phase 4：状态保留、视觉收尾与回归

- 完成跨模式草稿保留、动效、深色主题与小窗口处理。
- 覆盖所有旧入口的路由测试和安排工作端到端主路径。
- 验收：lint、typecheck、相关 renderer tests、build 通过；减少动画系统设置生效；无任务执行或权限回归。

## 8. 首屏布局验收示意

在常见桌面窗口（约 1280×800 可用内容区）内，模式切换、主要工作区和输入区都应同时可见；不得像当前三卡入口一样把首屏主要面积用于解释和选择功能。缩小窗口时优先压缩留白与辅助文案，不压缩输入控件和关键按钮。

```text
安排工作页可见区
┌───────────────────────────────────────────┐
│ 顶部：安排工作 / 会话、编排切换            │
├───────────────────────────────────────────┤
│                                           │
│             主要工作区                     │
│                                           │
├───────────────────────────────────────────┤
│ ┌─────────────────────────────────────────┐ │
│ │ [目录] [模型] [权限]                       │ │ ← 窗口底部摘要条
│ │ 展开后设置就地向上显示，不覆盖工作区      │ │
│ └─────────────────────────────────────────┘ │
└───────────────────────────────────────────┘
```

## 9. 明确不做的事

- 不把「会话、自动编排、自己编排」继续做成三张等权首屏大卡片。
- 不把「个人 / 企业」全局切换与「会话 / 编排」局部切换合并成一个控件。
- 不复制 ChatGPT/Codex 的品牌标识、颜色或导航结构；只借鉴固定工作区与底部组合操作区的交互原则。
- 不以右侧抽屉/侧栏承载运行设置；设置不得挤占工作区主体宽度，统一在窗口底部按需展开。
- 不在本次布局重构中改变后端编排协议、员工授权、风险操作确认、工作记录和执行详情模型。
- 不强迫普通用户理解 DAG、运行时、订阅 ID、模型 ID 等内部术语。
