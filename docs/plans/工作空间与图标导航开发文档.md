# 工作空间与图标导航开发文档

> 状态：renderer 已实施，自动化检查通过；实际窗口视觉与端到端验收尚未完成。
>
> 设计依据：[工作模块与对话优先界面设计方案](./工作模块与对话优先界面设计方案.md)。
>
> 范围：renderer 的导航、工作空间、对话、详情面板、展示状态与回归测试。不修改主进程执行协议、SDK、授权或计费规则，不增加依赖。

## 1. 交付目标

1. 64px 图标导航：企业仅显示 Logo／`Building2`，名称通过 Tooltip 查看；六个主入口居中排列，账号固定底部。
2. 安排工作、工作记录、工作详情合为一个「工作」空间：左侧紧凑列表，右侧新建或对话，筛选和选中工作独立。
3. 使用图标区分状态和类型；悬停及键盘焦点可读取完整含义，不能仅靠颜色。
4. 会话和编排运行后以对话为主体，结果、过程、工作信息按需查看，等待确认与错误直接可见。
5. 面板收起不停止媒体查询、不重新提交媒体请求；结果计数不把读取失败当成 0。
6. 保留附件、粘贴、语音、审批、停止、重试、文件预览、员工切换等真实能力。

## 3. 组件结构与所有权

```text
ClientAppPage
├─ AppSideNav
│  └─ IconHint（共享 Tooltip）
└─ WorkHubPage（arrange / records / work）
   ├─ WorkListPane
   │  ├─ 状态筛选：图标 + 数量
   │  ├─ 类型筛选：图标小标签
   │  └─ 工作条目：状态图标 + 标题 + 类型 + 摘要
   ├─ ArrangeWorkPage（新建态，复用自动／手动编排）
   └─ WorkDetailPage（选中态）
      ├─ 标题与结果／过程／信息入口
      ├─ 待办及失败行动条
      ├─ WorkConversation
      └─ Inspector（默认关闭，单实例）
         ├─ 结果：文件与媒体
         ├─ 过程：活动与编排步骤
         └─ 信息：时间、目录、参与员工
```

共享交互 `IconHint` 使用已安装的 Radix Tooltip，复用其 portal、键盘、Esc 与可移入能力；不自己实现全局鼠标监听体系。接口约定为 `label: string`、`children: ReactElement`、可选 `side`，触发器采用 `asChild`，避免嵌套按钮。禁用按钮如需说明，使用可聚焦的外层包装。

状态展示抽离为 `WorkStatusIcon`、`WorkTypeTag`。默认无常驻文字；提供可访问名称，Tooltip 不替代名称。工作条目只保留一个主按钮焦点入口，条目的完整可访问名称包含标题、状态和类型；不能在条目内嵌套按钮。

## 4. 路由与工作空间状态

### 4.1 保留现有路由契约

继续使用 `arrange`、`records`、`work`，不新增后端 work hub 对象，不迁移任务记录。

| 现有入口 | 目标 |
| --- | --- |
| `records` | 工作空间，应用该路由的筛选；恢复仍存在的选中工作，否则显示新建 |
| `work(workId)` | 工作空间选中该工作；保留先前列表筛选 |
| `arrange` | 工作空间新建态；保留员工、模板和模式参数 |
| 员工详情安排工作 | 同上，带入员工 |
| 首页工作、已读标记、通知 | 继续使用原 workId 与现有查阅行为 |
| 命令入口 | 文案改为新建工作／工作，旧关键词继续可搜索 |

工作空间在三种路由之间保持同一个 React 组件实例，不能在路由切换时用不同页面组件导致列表状态丢失。

### 4.2 状态拆分

- `filters`：状态桶、类型、搜索；首次从 records 路由初始化，records 外保留。
- `selectedWorkId`：当前查看的任务，切到新建时不删除旧任务。
- `listOpen`：用户是否打开列表；窄窗口默认为收起，提供稳定按钮。
- `inspector`：`results | process | info | null`，切换工作时重置。
- 输入草稿／附件会话／滚动位置：按 `attachmentScopeKey + workId` 隔离，只在当前登录工作空间生命周期内保存，不持久化到磁盘。`retainOwner()` 以生命周期代数和微任务延迟清理：StrictMode 的 cleanup/setup 回放不会取消仍使用的附件，真实退出仍取消开放会话。
- 新建组件尽量保持挂载，以保留尚未提交的输入；手动编排可临时收起列表获取空间。

创建成功通过 `onWorkCreated` 更新新建组件版本，清空已提交内容；失败返回 `false`，不更新版本。保持挂载不能导致下一次新建再次提交上一项工作的附件。

筛选不应改变当前对话。选中工作被筛选排除时，显示提示和清除筛选操作。删除成功后清理对应视图状态并回到列表／新建；切换账号或企业重建状态容器，禁止跨作用域复用。

### 4.3 排序与更新

复用最近更新时间排序。流式 token 更新不持续重排已显示条目；按工作状态、成员变化、列表增删、筛选变更或明确刷新更新排序快照。消息摘要仍显示实时数据。路由与顺序快照在 layout effect 中协调，render 阶段仅计算展示数据。数据不足时不虚构进度、耗时或工作类型。

## 5. 状态和类型映射

| 状态 | 图标 | 色彩 |
| --- | --- | --- |
| running | LoaderCircle，静态缺口环 | 状态蓝 |
| waiting-user | CircleAlert | 琥珀色 |
| completed | CircleCheck | 绿色 |
| failed | CircleX | 红色 |
| paused | Square | 中性灰 |
| arranging，未持有运行 | CircleDashed | 中性灰 |
| 排队／本轮待执行 | Clock3 | 中性灰 |

`isActive` 与业务状态分开处理：只有 `isActive === true` 属于进行中集合；`nextUserAction` 保留重叠待办语义。失败工作存在待办时，仍显示失败图标，并附待处理提醒。

类型只读取 `workType`。`resolved: conversation` 用消息图标，`resolved: arrangement` 用流程节点；loading 与 unavailable 分别使用加载／帮助图标，提供读取状态和重试入口。不能用旧 `kind` 猜测分类；详情在权威类型未解析时显示加载／重试态，暂不挂载类型专属操作。`kind` 仍可用于已解析类型下的兼容执行路径。

现有状态桶、类型桶和计数规则不改。相关既有回归测试必须继续通过。

## 6. 导航与 Tooltip 实施细节

- 固定 64px 轨道，按钮 40×40px，SVG 20px；企业 Logo 30–32px，账号头像同轴。
- 导航组在剩余高度中通过自动上下外边距居中；不足时自动从顶部开始滚动，顶部与底部固定区不被覆盖。
- 全部入口只显示图标，不保留“展开文字侧栏”的按钮；主导航工作入口覆盖 arrange、records、work 三类激活状态。
- 公司图标缺失／加载失败使用 Building2，不使用公司首字；完整名称通过 Tooltip 与菜单展示。
- 企业图标与菜单使用 no-drag；窗口拖拽区与系统按钮空间保留。
- 悬停 SVG 缩放 1.08，160ms；按下缩放 0.96，80ms；背景及颜色 140ms。
- 名称提示约 250ms 延迟，默认右侧，150ms 淡入；键盘可见、Esc 可关闭、可移入，不推动内容布局。
- 减少动态效果时取消缩放、位移及非必要动画。
- 企业和账号菜单有点击外部关闭、Esc、焦点恢复和正确的菜单语义；菜单内保留明确文字。

## 7. 对话、详情与媒体生命周期

### 7.1 对话

两类工作均优先展示消息。标题不再重复巨大的目标、全宽时间条和固定右栏。已有工作使用紧凑员工身份；每条员工消息保留实际发言者。编排不把底层工具日志伪装成员工回复。

复用现有输入法判断、附件、语音和流式跟随逻辑。向上阅读不被新消息拉回底部；切换工作后恢复各自滚动。执行中发送是否支持、编排确认和重试均由现有服务约束决定，不因统一 UI 改写继续命令语义。

### 7.2 Inspector

默认关闭，一次一个面板。结果、过程、信息入口有可访问名称，结果数量未知时不显示假 0。宽屏内嵌，空间不足先收起列表；窄屏采用模态覆盖，使用现有焦点管理或已安装 Dialog。打开关闭不能重建对话或清空输入。

待办、启动失败、执行中断、媒体交付失败留在主区。失败节点可在主区独立重试；“补充说明”直接聚焦消息输入框。终止在输入区提供原因与确认；删除放在工作信息面板，明确提示记录无法恢复、已有文件仍保留，确认后复用原 `deleteWork`，删除成功才清理视图。

### 7.3 媒体

图片和视频查询不能随 Inspector 关闭卸载。实现时允许把轻量查询组件保留挂载，并通过可见参数控制预览、表单和长列表等重内容；或提取稳定的数据 Hook。关键验收是关闭面板后仍持续获取状态、结果摘要及错误，且无重复提交。

结果入口至少提供可靠的分组计数：文件 N、图片 M、视频 K。只统计当前 taskId 的已保存 output，参考素材不计入结果。图片从顶层资产与 job.assets 聚合时按 localAssetId 去重；视频按现有输出稳定 ID 去重。跨文件／媒体缺少共同身份时不直接相加报告总数，避免双计。

附件恢复使用 `RetainedAttachmentState`，由当前登录工作空间持有真实的导入 session 与附件集合。重新挂载输入框时复用该 session 并重绑粘贴能力，不重新创建或只还原文件名；离开输入框时解除绑定。普通新建输入框仍在卸载时取消开放会话。任何卸载之后才返回的新建 session 都立即取消，不能遗留不可见会话；退出登录／切换作用域由持有者集中清理，成功发送后清空保留状态。

读取未完成、异常和不支持媒体能力分别处理。媒体生成成功与文件保存完成分开；取消本地跟踪不等同取消供应商任务；打开 Inspector 不触发生成或重做。

## 8. 响应式、视觉和性能

- 最小窗口 960×640；验证 1280×800、1440×900、1920×1080。
- 默认列表 304px，允许在 280–360px 范围调整；窄窗口默认收起，按钮可重新打开。
- 对话阅读宽度约 800px；输入区固定在主区底部，消息单独滚动。
- 不再用大卡片包住整个工作对话；取消工作区妨碍阅读的渐变／水印。
- 新增语义色只作用于状态，不更换 SEP 品牌色；浅／深色保持对比度。
- 关闭 Inspector 不加载图片预览字节，不播放隐藏视频，不重复挂载查询组件。
- 不为每条工作启动媒体轮询；只对当前选中工作保留媒体观察。
- 页面不得因长标题、路径、员工名或代码块产生横向溢出。

## 9. 开发顺序与回归门槛

1. 编写状态映射、选择／筛选保留、未知类型和结果去重的行为回归，保留现有测试。
2. 实现共享 Tooltip、图标导航及独立样式，更新导航调用方。
3. 实现 WorkHub 与紧凑列表，整合三类旧路由、新建模式和返回路径。
4. 实现对话默认视图及按需面板，处理草稿隔离和媒体生命周期。
5. 整合样式、命令文案、文档索引和实际设计令牌，检查所有入口。
6. 运行针对性测试及完整 renderer、typecheck、lint、build、boundaries；修复本次引入的问题。

独立并行模块按所有权分工：导航／Tooltip、详情／媒体各自负责文件；主代理负责工作空间、共享图标、路由整合、文档与最终验证。任何 agent 不得覆盖他人修改或扩大后端范围。
