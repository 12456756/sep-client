# 编排媒体预览、视频授权与交付冲突修复方案

- 日期：2026-10-22
- 状态：已实施，完成自动化验证
- 范围：编排任务中的图片/视频预览、视频调用授权弹窗、媒体交付路径冲突，以及相关额度失败提示
- 目标：让媒体生成能顺畅执行、产物可在客户端查看、交付冲突可恢复，同时保留平台授权、额度和文件保护边界。

## 1. 结论

最近几项现象分别发生在 UI、生成授权和文件物化三个环节，不是同一个底层故障：

1. 编排工作详情没有挂载已有的 `MediaArtifactsPanel`。当前组件只在对话工作类型下显示；编排工作有最终文件列表，但没有编排节点媒体任务的预览视图。
2. “视频是否允许”弹窗来自视频生成服务的报价授权链。视频工具本身在 Pi 工具守卫里已由可信 host 接管；真正触发弹窗的是生成前后的 `requestApproval`。因此只修改通用工具守卫不会消除该弹窗。生成审批与文件冲突也无关。
3. `MEDIA_DESTINATION_CONFLICT` 表示计划目标路径已存在不同内容。当前落盘采用 no-clobber 策略，保留旧文件并拒绝覆盖；最近任务中新图片与旧 `deliverables/mug-main.png` 冲突。
4. 每日额度不足是另一个独立失败原因。额度/预算校验可能在报价或提交阶段拒绝生成；不能把它显示成路径冲突，也不能靠绕过用户确认解决。

最近一次编排媒体详情 UI 调整是在 `29f63ae` 的通用样式改动之前。`29f63ae` 只改了样式和记录页小项，没有改动媒体详情挂载；媒体面板的历史挂载条件已限定为 `isConversation`。因此“预览消失”更准确地说是编排详情一直缺少这块连接，而非该样式提交覆盖了编排预览。

## 2. 当前调用链与证据

### 2.1 视频授权弹窗

编排执行器把当前节点授权回调传给 `VideoRunService`。视频服务通过报价/平台授权后调用回调；非自动授权模式会向渲染端发送 `ToolAuthorizationRequest`，由 `ToolApprovalDialog` 展示。`full-local + auto-approve` 时服务端会采用自动模式，但其他工作权限模式仍可能弹窗。

需要区分两类授权：

- 工具执行权限：是否允许员工调用 `video_generate` / `video_from_image`。当前由编排授权工具集合及 host 的实时能力检查控制。
- 生成和费用授权：确认当次报价、预算、员工订阅和用户的授权偏好。每日额度或预算不足时，SEP 报价/授权校验仍应拒绝。

用户要求视频工具默认不反复弹出允许窗口。建议将编排媒体生成改为“在有效平台授权和当次预算额度内自动放行”，费用风险通过平台额度/预算校验与明确的生成记录控制；提供可配置的自动/逐次确认偏好。不得把 `PERMISSION_DENIED`、无报价、预算不足、权限失效等情况转换成自动放行。

此方案不会自动允许 `bash`、`write`、`edit`、MCP 或未知工具。图片参考素材上传如平台要求用户同意数据传输，仍沿用独立的传输授权规则，避免把“视频默认放行”扩大为所有外部副作用操作。

### 2.2 预览

`WorkDetailPage` 已显示工作区最终交付文件，并为对话工作挂载 `MediaArtifactsPanel`。编排工作详情则展示步骤和最终文件，但没有按节点读取已保存媒体资产并渲染图片/视频预览的面板。

现有工作记录已包含编排执行快照及最终交付信息；媒体资产则通过 `ArrangementMediaService` 和媒体存储按任务、节点及员工权限关联。实现时应从主进程读取投影后的媒体摘要/预览数据，不把存储绝对路径、供应商临时 URL、令牌或内部路径送到 renderer。

### 2.3 目标文件冲突

`materializeArrangementMedia()` 会先验证安全路径、源文件哈希和类型，再通过不覆盖方式发布文件。若目标已存在且哈希不同，返回 `MEDIA_DESTINATION_CONFLICT`。相同内容可幂等成功；不同内容不会覆盖旧文件。

本次中断符合此路径：历史任务已在工作区写入 `deliverables/mug-main.png`，新任务生成了新的图片资产，提交时目标仍是同一相对路径。合理的修复是把冲突变成明确、可恢复的交付动作，不是静默覆盖或放宽路径安全检查。

## 3. 目标体验

- 编排详情按节点展示已保存的图片、视频及其生成/保存状态；媒体可在客户端直接预览，最终工作区文件仍可打开或复制路径。
- 常规编排下视频生成不再出现重复的通用“是否允许调用视频工具”弹窗；在平台授权有效、报价有效且额度允许时按默认授权偏好继续。
- 用户可以关闭自动放行，改回逐次确认；任何模式下都不能越过平台额度、授权、能力和安全校验。
- 目标文件路径冲突时旧文件保留，新媒体资产也保留；界面明确展示冲突，并允许使用不冲突的新文件名继续交付。替换旧文件必须是明确操作，并保留可恢复副本或经过主进程安全验证。
- 额度不足、视频授权失败、媒体服务不可用和路径冲突分别显示可理解的原因及各自能执行的后续操作。

## 4. 实施方案

### 阶段 A：视频授权默认策略

1. 梳理 `ArrangementExecutor -> VideoRunService -> MockVideoHostService -> ToolApprovals -> ToolApprovalDialog` 的完整回调，并把“工具许可”和“报价/费用审批”在类型与 UI 文案上分开。
2. 增加明确、可持久化的媒体生成授权偏好，支持自动放行与每次确认。默认按用户明确要求采用自动放行，但只作用于编排媒体生成，不影响通用高风险工具策略。
3. 自动放行的准入仍要求员工订阅/任务归属匹配、视频 runtime 和工具已授权、有效报价、SEP `authorized` 与 `budgetAuthorized` 均通过、授权版本未变、生成请求哈希匹配。
4. 自动模式仍记录报价摘要、生成请求、媒体 job ID、预算结果和授权模式，UI 可查阅；额度拒绝或授权失效直接返回可诊断错误，不弹出一个看似可由用户强行批准的普通工具窗。
5. 逐次确认模式保留报价确认 UI。弹窗文案明确这是“确认本次视频生成及报价”，展示员工、创意摘要、预计费用/额度信息（平台提供时），不再笼统写成“是否允许工具调用”。
6. 超时、取消、账号切换和任务恢复沿用现有 fail-closed 语义；恢复已有 job 不重新确认或重复提交付费请求。

### 阶段 B：编排媒体预览

1. 扩展已有媒体摘要查询能力，返回节点 ID、媒体类型、生成任务状态、已保存资产摘要和安全预览句柄；保持主进程拥有路径和数据读取权。
2. 经 IPC/Zod 边界校验 task ID、node ID、asset ID，并校验当前 owner、任务、计划哈希、节点 run 和资产状态。只允许读取当前编排可见的已保存产物。
3. 在编排工作详情挂载媒体区，按节点/交付物分组，展示图片缩略图/大图查看器与视频播放器、生成状态、失败原因和交付路径。复用现有媒体卡片/播放器风格，避免在 renderer 另造存储逻辑。
4. 支持加载中、无媒体、生成中、等待授权、额度不足、保存中、已保存、预览失效、任务归档和读取错误状态。非媒体任务不显示空面板。
5. 预览数据使用短期、任务绑定的安全句柄或受控 IPC 读取流；不暴露绝对路径、任意文件 URL 或供应商临时下载链接。视频文件需支持进度和暂停，图片按真实 MIME 渲染。
6. 预览加载失败不改变任务执行状态或交付验收状态；刷新详情后能重新加载，不重新发起生成。

### 阶段 C：交付路径冲突恢复

1. 保留 no-clobber、符号链接/硬链接防护、哈希验证和快照语义；不在常规自动运行中覆盖不同内容。
2. 将冲突变成可恢复的节点/交付状态，持久化源资产 ID、源哈希、原计划路径和冲突检测时间。任务重启后恢复该交付，不启动新 worker、不重新报价或生成。
3. 默认提供“保留两份并继续”：为新产物选择同目录下的可用名称（例如 `mug-main-2.png`），同时返回/持久化实际路径并在交付列表中展示计划名与最终名。命名策略应可配置或由用户编辑，避免把固定后缀格式变成产品硬限制。
4. 可选提供“替换已有文件”，但必须由用户明确触发；替换前验证原目标和新媒体文件，先保留旧版可恢复副本，再以原子操作更新目标。取消、失败或崩溃恢复不得丢失任何一版。
5. 如果路径冲突来自相同哈希，视为幂等成功，不增加副本、不提示用户。
6. 若实际路径发生变化，更新最终交付记录、节点结果和下游文件引用；不得继续让下游节点读取已经不匹配的原路径。

### 阶段 D：额度和错误反馈

1. 将每日额度不足/预算不足与 `MEDIA_DESTINATION_CONFLICT`、`PERMISSION_DENIED`、`AUTH_REQUIRED`、`UNAVAILABLE` 分开映射。
2. 额度不足显示来源（平台/员工/套餐/任务预算，以后端安全摘要实际提供为准）、剩余或重置时间（如 API 有提供）和可行操作。不得猜测重置时间，也不显示敏感账务明细。
3. 额度不足后不自动重试付费请求。用户恢复额度后可从原节点重试；如果服务端已有已提交 job，则恢复查询原 job。
4. 工具错误日志保留可关联的 task/run/node/job ID 和阶段，不记录 access token、临时 URL 或完整敏感 prompt。

## 5. 数据与兼容性

- 旧任务快照继续可读取；新字段采用可选字段和显式版本演进。
- 媒体自动授权偏好默认值需从用户设置/企业策略读取；服务端额度和员工授权始终是最终权威。
- 编排最终交付 path 记录实际落盘路径，保留计划路径以供审计；旧记录没有实际路径时按现有 `path` 解释。
- 旧媒体预览 API 或对话媒体面板继续工作；编排新增能力只读取任务内已保存资产。
- 不限制用户的图片比例、视频时长等业务参数；由当前 employee runtime、供应商能力、平台额度与本机资源策略协商。

## 6. 验收标准

### 授权

- 默认授权偏好下，编排节点调用可用的视频工具时不会弹出重复的通用允许窗口。
- SEP 报价无效、权限失效、员工未授权或额度不足时，视频不会提交，界面给出相应原因。
- 逐次确认偏好下能看到正确报价并确认/拒绝；拒绝后不提交生成。
- 自动放行视频不会让 `bash`、`write`、`edit`、未知工具或未授权 MCP 工具自动通过。
- 已提交 job 的任务恢复不会再次提交或重复扣费。

### 预览

- 编排详情可预览已保存图片和视频；多个节点的媒体不会串到其他任务/员工。
- 任务刷新/重开后预览可恢复；不存在或未保存的媒体给出状态而非空白画面。
- renderer/IPC 不暴露本地绝对路径、临时 URL、凭据；跨任务和伪造资产 ID 被拒绝。
- 普通对话的既有图片/视频面板无回归。

### 冲突与额度

- 同名不同内容时原文件字节和哈希保持不变；选择“保留两份”后新旧文件都能打开且交付路径正确。
- 用户明确选择替换时有可恢复的旧版，崩溃/取消测试不会造成丢失。
- 同哈希重试幂等成功，无重复文件。
- 冲突恢复不重新运行员工、不重新请求报价、不重复生成。
- 每日额度不足显示额度失败，不错误显示为路径冲突；恢复额度后能继续已有任务。

## 7. 测试计划

- 单元测试：授权模式判定、预算/报价失败分类、路径冲突命名、同哈希幂等和替换回滚。
- 服务测试：视频自动授权与逐次确认两条链、SEP 授权失败、额度不足、运行时权限版本变化、恢复原 job。
- IPC/数据边界测试：预览资产 owner/task/node 归属、归档任务、非法 ID、失效句柄和敏感字段投影。
- renderer 测试：编排媒体面板状态、图像/视频播放、额度错误、冲突动作、刷新恢复；确保会话面板不回归。
- 端到端 mock：生图 -> 编排预览 -> 图生视频 -> 视频预览/交付；同路径旧图冲突后选择保留两份并恢复；额度拒绝无生成提交。
- 客户端手工验收：使用新空目录生成图片和视频；验证预览、默认自动放行和额度不足提示；另用已有同名旧图复现冲突并确认两个产物都保留。
- 真实网关/账务只在用户主动选择可计费的手工验收时执行；自动化测试全部使用 mock，不产生真实费用。

## 8. 实施顺序与交付

1. 先补共享类型、错误映射和服务回归测试，确认自动放行没有越过平台额度授权。
2. 接通编排媒体预览数据与 IPC，再挂载详情 UI 并覆盖恢复/权限测试。
3. 加入持久化冲突状态及“保留两份”路径协商，最后实现可选的显式替换和回滚。
4. 执行 `npm run typecheck`、相关 renderer/tasks/invariants 测试、`npm run check:boundaries`、`npm run build`；如改动 `electron/pi/` 或 runtime loading，补跑四个 POC。
5. 已完成代码实现与自动化验证；客户端手工验收仍需在本地启动客户端后执行。

## 9. 实施记录

已落地的行为：

- 编排详情挂载 `ArrangementMediaPanel`，按节点展示已保存图片/视频，并通过受控 IPC 读取预览内容；普通对话继续使用原媒体面板。
- 编排媒体视频运行启用节点级自动授权，上传参考图和报价确认不再重复弹出通用授权窗口；运行版本、员工订阅、工具能力、报价和平台额度校验仍保留。普通对话仍按原审批策略运行。
- 视频终止性业务错误只通知一次，并在 worker 被中止后保留原始错误码，避免被“中断”或后续交付校验覆盖。
- 媒体目标路径采用不覆盖策略：同名不同内容自动选择同目录可用后缀路径（如 `movie-2.mp4`），旧文件保留，实际路径写入最终交付记录；同哈希重试保持幂等。
- 已保存的图片成果不会因为后续视频失败而从编排详情消失。

- `npm run typecheck`
