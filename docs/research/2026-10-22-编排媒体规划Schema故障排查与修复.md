# 编排媒体规划 Schema 故障排查与修复

日期：2026-10-22。范围：客户端自动编排中的媒体规划、校验、员工执行提示与媒体交付。

## 1. 结论

14:43 的失败不是“没有合适员工”，也不是生成图片或视频的供应商调用失败。规划模型已经返回两个员工及对应模型，但返回结果在工作契约校验阶段被整体拒绝。员工选择事件在校验成功后才发布，所以界面没有显示选中员工。

14:50 的再次尝试遇到了同类问题。问题既包含过窄的描述性字段，也包含提示词没有说明清楚的协议字段；不能通过关闭整个 Schema 校验解决。

本次采用：业务偏好开放扩展，含义明确的模型写法在解析入口兼容，内部协议及执行安全约束继续校验。修复已落入代码；两次原始响应的离线重放通过，结构等价的回归用例也覆盖到模拟媒体生成与最终文件保存。

## 3. 已实现的修复

### 3.1 补全规划说明和示例

`electron/domain/arrangement-planner.ts` 补充需求 ID、类型与操作枚举、输入对象形状、选择枚举、偏好类型和交付标记要求。增加文生图、图片编辑、图生视频、文生视频四种结构示例，并用测试验证示例符合实际 Schema。

原普通文档示例和待授权员工推荐结构继续保留，避免媒体示例改变普通任务的规划行为。

### 3.2 只在模型输出入口兼容常见写法

`electron/domain/arrangement-planner-media.ts` 在严格校验前正规化模型输出。

- 兼容有限、明确的操作别名，包括 `text-to-image`、`text_to_image`、`image-to-image`、`image-edit`、`image_to_video`、`text_to_video`。
- 缺少需求 ID 时补全；不会修改已经提供但无效的 ID，也不会忽略重复 ID。
- 缺少 kind 时，可从已知规范操作推导；明确给出的冲突 kind 继续拒绝。
- 单来源数组可展开；不截断多元素数组，不合并冲突来源，不补造资产 ID。
- `auto` 转为 `model`；其他不明确的选择值继续拒绝。
- 仅在同类型需求的操作唯一且文件格式明确时推导遗漏的媒体交付标记；显式的 `workspace`、`either` 不会被覆盖。

IPC、人工编辑及持久化计划继续使用规范值，不把所有入口改成接受任意别名。员工授权、执行模型允许列表、DAG、来源归属和安全路径校验继续执行。

### 3.3 放宽业务偏好，保留真实参数的类型

`preferred` 可扩展为任意合法 JSON 描述，支持字符串、数值、布尔、数组、嵌套对象和 null。风格、主体、场景、镜头、氛围等不再被一张封闭字段表限制。

已有标准字段继续验证：时长和帧率为正有限数，数量为安全正整数，audio 为布尔值，比例、分辨率和格式为字符串。没有新增常见比例列表、短时长上限、低数量上限或固定媒体需求条数限制。现有大范围用例包含时长 86400 秒、帧率 1000、数量 500 和超过 64 项需求。

这些值能被计划保存，不代表供应商支持。实际支持范围仍由能力清单与运行时预检决定。不会把偏好对象直接透传成工具参数。

### 3.4 将偏好传递给执行员工

`electron/runtime/arrangement-executor.ts` 在节点执行提示中加入完整 `mediaRequirements`，包括操作、来源和偏好。此前这些内容虽然保存在计划内，但未完整进入员工提示。

提示同时说明：先读取能力清单，再将偏好转为受支持的参数；使用后端提供的参考资产；来源未确定时说明缺少选择，不擅自选图，不重复生成前置成果。人工节点只要包含媒体需求，也进入结构化执行提示分支。

### 3.5 将确定会失败的情况提前报告

新生成的规划中，必需的图片编辑或图生视频缺少图片来源时，规划阶段即给出具体字段错误。

直接标记为 `media-output` 的交付物，其格式必须受现有媒体保存链路支持并与图片/视频类型一致。当前原文件保存支持 PNG、JPEG、WebP、MP4、WebM。该清单与文件物化代码共享，避免规划和保存各维护一份列表。MOV、GIF、AVIF 等仍可通过另行转换后的普通工作区文件交付，不因本次修改限制普通交付格式。

错误增加节点序号、字段路径和校验类型。日志中的路径只保留已知协议字段及数组索引，未知字段名不原样输出，也不记录失败字段值或整份模型回复。

## 4. 同类排查及剩余边界

| 项目 | 当前状态 | 说明 |
| --- | --- | --- |
| 合理描述偏好被拒绝 | 已修复 | 扩展字段接受合法 JSON，标准参数仍校验 |
| 提示词未给完整媒体协议 | 已修复 | 四类示例有契约测试 |
| 员工看不到结构化偏好 | 已修复 | 完整传入节点执行提示 |
| 漏交付标记后期保存失败 | 常见明确场景已修复 | 唯一操作可补全；有歧义时要求明确标记，不擅自决定 |
| 图生视频缺少必需来源 | 新规划提前报错 | 不伪造上游节点或用户资产 |
| 直接媒体交付格式不支持 | 新规划提前报错 | 不通过改扩展名假装格式转换 |
| `inputSelection` 多选策略 | 仍有能力边界 | 后端每项需求解析一个明确来源；`any/all/model/user` 尚无独立自动选图或交互选择引擎 |
| 只生成中间媒体、最终交付文档 | 允许 | 不强制每项媒体需求都有最终媒体文件，避免限制合理的中间素材工作流 |
| 偏好自动满足 | 不作保证 | 执行员工结合能力清单处理，未新增确定性的所有偏好参数映射器 |
| 已失败草稿自动恢复 | 未修改 | 没有回写历史草稿、自动重试或触发付费调用；客户端需重新发起规划 |

`inputSelection` 目前用于表达意图，不能当成已经完成的多图选择能力。多张明确输入可写成多个有明确来源的需求；需要从候选图中由人选择时，仍需后续完整的选择状态与交互设计。本次没有把暂未实现的策略伪装成自动成功。
