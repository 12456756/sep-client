# SEP Client 产品设计文档

**版本**: v2.0  
**更新时间**: 2026-07-30  
**设计理念**: AI 员工，而非 AI 助手

---

## 产品定位

SEP Client 是一个**桌面版 AI 员工管理客户端**。用户通过它管理和分配任务给企业部署的 AI 员工，AI 员工自主完成任务并汇报结果。

### 核心理念对比

| 维度 | 传统 AI 助手 | SEP AI 员工 |
|------|-------------|-----------|
| 工作方式 | 被动响应，一问一答 | 主动工作，自主完成任务 |
| 用户角色 | 提问者 | 管理者/同事 |
| 交互频率 | 持续对话 | 分配任务 → 查看结果 |
| 工作场景 | 用户盯着屏幕等回复 | AI 在后台工作，完成后通知 |
| 工具使用 | 每次都需审批（打断流程） | 预设权限，自主决策 |
| 输出形式 | 文本消息 | 文件、报告、执行结果 |

### 任务状态机

```

  ↓

  └─→ paused (已暂停) → running
```

### 2. 权限管理

#### 工作目录隔离

用户创建任务时可以指定工作目录：
- AI 员工**仅能在该目录内**自主创建、修改、删除文件
- 读取目录外的文件需要审批
- 跳出目录执行命令需要审批

#### 工具权限预设

```
实例配置（管理员在后端设置）:
  文案助手:
    自动允许:
      - read, grep, find (只读工具)
      - write, edit (限定在工作目录内)
    需要审批:
      - bash (执行命令)
      - fetch (网络请求)
    禁止:
      - rm -rf (危险命令)
      - sudo (提权操作)
```

#### 批量审批

当 AI 需要执行多个操作时：
```
┌─────────────────────────────────────────┐
│  任务需要执行以下操作                    │
├─────────────────────────────────────────┤
│  1. 创建文件: blog_post.md              │
│  2. 创建文件: outline.md                │
│  3. 运行命令: npm run format            │
│  4. 提交到 Git: git commit -m "..."    │
│                                         │
│  [全部允许] [逐个审批] [全部拒绝]        │
└─────────────────────────────────────────┘
```

## 技术架构

### Session 生命周期（关键变化）

**旧方案（聊天模式）**:
```
用户登录 → 选择实例 → 进入聊天页 → 创建 session → 发送消息
```

**新方案（任务板模式）**:
```
用户登录 → 选择实例 → 立即创建 session → 进入任务板页
                       ↓
                   session 后台运行
                       ↓
                   随时接收任务
```

### 任务执行流程

```
用户创建任务
  ↓
TaskManager.createTask(prompt, workDir)
  ↓
task.status = 'pending'
  ↓
PiHost.executeTask(taskId)
  ↓
session.prompt(task.prompt)
  ↓
pi-coding-agent 开始工作
  ↓
监听事件，更新任务状态:
  - agent_start → status = 'running'
  - tool_call → status = 'waiting_approval'
  - agent_settled → status = 'completed'
  - agent_end (error) → status = 'failed'
  ↓
通知用户（桌面通知 + 应用内通知）
```

### 工具审批流程

```
AI 调用工具 (bash/write/edit)
  ↓
pi-extension/guard.ts 拦截
  ↓
检查权限:
  ├─ 在工作目录内? → 自动允许
  ├─ 只读工具? → 自动允许
  └─ 高风险操作? → 需要审批
      ↓
  task.status = 'waiting_approval'
      ↓
  UI 显示审批卡片
      ↓
  用户批准/拒绝
      ↓
  task.status = 'running'
```

## 用户典型场景

### 场景 1: 内容创作

**角色**: 运营人员  
**任务**: 撰写产品推广文案

```
1. 用户打开 SEP Client，选择"运营部文案助手"
2. 点击 [+ 新建任务]
3. 输入:
   - 标题: "撰写产品推广文案"
   - 描述: "新产品上线，需要一篇 1500 字的推广文案..."
   - 工作目录: ~/Documents/营销项目/
4. 点击 [创建并开始]
5. AI 员工开始工作（用户可以关闭窗口）
6. 5 分钟后，用户收到通知: "任务已完成"
7. 用户打开应用，查看生成的文件
8. 文件保存在工作目录: product_promo.md
```

### 场景 2: 数据分析

**角色**: 产品经理  
**任务**: 分析用户反馈数据

```
1. 选择"数据分析助手"
2. 创建任务: "分析上月用户反馈，生成报告"
3. 工作目录: ~/Documents/用户反馈/
4. AI 开始工作:
   - 读取 CSV 文件
   - 统计分析
   - 生成可视化图表
   - ⚠️  需要审批: 运行 Python 脚本
5. 用户批准
6. AI 继续执行，生成报告: report.pdf
7. 用户收到通知，下载报告
```

### 场景 3: 代码生成

**角色**: 开发人员  
**任务**: 生成 API 接口代码

```
1. 选择"技术助手"
2. 创建任务: "根据设计文档生成 REST API"
3. 工作目录: ~/Projects/backend/
4. AI 开始工作:
   - 读取 API 设计文档
   - 生成代码文件
   - ⚠️  需要审批: 批量创建 5 个文件
5. 用户选择 [全部允许]
6. AI 创建文件:
   - routes/user.ts
   - controllers/user.ts
   - models/user.ts
   - ...
7. 用户收到通知，查看生成的代码
```

## 与传统聊天界面的对比

| 维度 | 传统聊天界面 | 任务板模式 |
|------|-------------|-----------|
| 任务管理 | 无，只有消息历史 | 有，清晰的任务列表 |
| 多任务 | 不支持，只能一个接一个 | 支持，多个任务并行 |
| 后台运行 | 不支持，必须保持窗口打开 | 支持，可以关闭窗口 |
| 进度可见 | 无，只知道"正在输入" | 有，百分比进度条 |
| 结果形式 | 文本消息 | 文件、报告、执行日志 |
| 工具审批 | 弹窗打断 | 任务状态变化，不打断 |
| 通知 | 无 | 桌面通知 + 应用内通知 |
