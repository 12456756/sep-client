# 客户端弹窗开发规范

- 确认日期：2026-10-26
- 状态：已确认的开发要求；登录模块、安排工作模块已接入，其余业务模块按迁移顺序开发。
- 适用范围：客户端登录页、工作台和各业务模块中的提醒、操作结果、报错、操作确认及工具授权弹窗。

本文是后续新增、修改和统一客户端弹窗时的开发与验收依据。本文记录要求，不代表现有界面已完成迁移。

## 1. 总体要求

1. 客户端反馈统一使用应用内弹窗，登录页与工作台共用组件、样式和交互规则。
2. 用户只需要知道简短的问题和必要的操作，不展示排查过程与技术细节。
3. 错误提示按“用户操作或网络问题”和“平台问题”两类处理，不为不同页面重复制定规则。
4. 后端负责判断错误并生成用户文案；前端负责展示，不得再次把具体原因改写成泛化提示。
5. 同一错误不得同时通过弹窗、提示条或浏览器原生提示重复通知。
6. 本规范不要求为每次点击增加成功提醒。已有或确有必要的成功反馈使用统一弹窗。

## 2. 用户文案

### 2.1 两类错误提示

| 类型 | 展示规则 | 示例 |
| --- | --- | --- |
| 用户操作问题 | 直接说明具体问题 | 账号或密码错误；请选择需要使用的员工 |
| 网络问题 | 直接说明网络问题及必要的处理方式 | 网络连接失败，请检查网络 |
| 平台问题 | 简短错误信息，追加“请联系平台管理员” | 员工列表加载失败，请联系平台管理员；任务提交失败，请联系平台管理员 |

用户操作问题与网络问题属于同一类展示规则。不得将网络失败、平台故障误报为账号密码错误，也不得将已知具体问题再次改成“操作未能完成”。

没有足够信息识别原因时，使用兜底文案：“操作失败，请联系平台管理员。”不得猜测失败原因。

### 2.2 展示限制

- 不展示错误码、HTTP 状态码、请求编号、内部路径、异常堆栈和原始接口响应。
- 不提供“查看详情”“复制诊断信息”等排查入口。
- 不直接展示平台原始错误字符串；先在主进程验证、分类并转换成符合本规范的文案。
- 不展示令牌、凭据或其他敏感信息。
- 错误弹窗通常直接展示一句话，不再重复添加“发生错误”“错误提示”等标题。
- 需要展示操作结果时，必须有事实依据。不能在结果不明确时声称任务未提交、数据未保存或平台任务已取消。

### 2.3 确认文案

确认弹窗只说明操作对象与必要后果，使用具体动作按钮。

| 场景 | 文案示例 | 按钮 |
| --- | --- | --- |
| 删除工作记录 | 确认删除这条工作记录？删除后无法恢复。 | 取消、删除 |
| 放弃未保存修改 | 确认放弃尚未保存的修改？ | 保留修改、放弃修改 |
| 停止本地跟踪 | 确认停止本地跟踪？平台任务可能仍在执行。 | 取消、停止跟踪 |

示例中的后果必须符合实际业务行为。停止本地跟踪和取消平台任务不得混用文案。

## 3. 后端开发要求

### 3.1 统一错误入口

- 在现有 `electron/errors/error-mapper.ts` 等统一错误入口扩展规则，避免各 IPC 路由重复拼接用户文案。
- 结合业务错误码、网络异常类型和当前操作识别原因，不能只按 HTTP 状态码判断。
- 登录时的 401 与登录后的 401 分别处理；403 根据实际权限或账号状态处理，不统一认定为密码错误或登录失效。
- IPC 返回展示所需的简短文案及必要的程序处理标识。已有内部错误标识可以继续用于程序判断，但不得在弹窗中显示。
- 平台响应与新增 IPC 字段必须在边界验证，保持现有架构和最小 preload API。

### 3.2 日志与诊断

- 具体异常及可用的请求关联信息，在主进程经过共享脱敏流程后记录到日志。
- 使用现有 `electron/common/logger.ts`，不添加裸 `console.*`。
- 不得为方便排查而把原始响应、凭据或技术堆栈发送到渲染进程。
- 同一故障的用户文案应与日志关联，便于平台管理员排查，但不要求用户查看或提供技术详情。

### 3.3 通知来源和会话

- 用户主动操作失败，通过该操作的响应返回；后台异常通过现有事件通道通知。
- 同一失败由一个入口负责触发用户弹窗，避免响应与事件分别通知一次。
- 后台自动重试不逐次弹窗，同一持续异常合并处理。
- 退出、重新登录或切换账号后，旧会话的延迟响应和后台事件不得触发新会话弹窗。
- 遵循现有 IPC 通道与 renderer bridge 边界，不从其他模块直接调用 `webContents.send`。

## 4. 前端视觉要求

### 4.1 样式

- 采用应用内居中弹窗，跟随客户端现有浅色、深色主题。
- 背景使用轻遮罩；弹窗正文左对齐，底部按钮右对齐。
- 圆角为 8px，内边距为 24px。
- 有标题时标题字号为 16px，正文字号为 14px，按钮文字为 14px。
- 内容前放置对应状态图标：成功绿色、提醒黄色、失败红色；确认弹窗根据操作性质使用对应图标。
- 使用现有 Lucide 图标，不用表情符号代替状态图标。
- 状态不能只靠颜色表达，必须同时有明确文字或图标语义。
- 复用当前项目已使用的 Radix 弹窗能力，不再为业务页面创建独立的反馈弹窗样式。

### 4.2 大小

| 项目 | 规格 |
| --- | --- |
| 常规宽度 | 400px |
| 窄窗口最大宽度 | 窗口宽度减 32px |
| 高度 | 随内容变化，通常约 160-220px，不强制固定高度 |
| 最大高度 | 窗口高度的 70% |
| 超长内容 | 正文区域滚动，操作按钮保持可见 |
| 按钮高度 | 36px |
| 按钮最小宽度 | 80px，随按钮文字必要扩展 |

文字必须正常换行，长内容不得撑出窗口、遮挡按钮或与其他内容重叠。尺寸不能因图标、按钮加载状态或悬停发生明显跳动。

## 5. 展示内容与停留时间

| 场景 | 内容示例 | 默认按钮 | 停留规则 |
| --- | --- | --- | --- |
| 操作成功 | 保存成功 | 关闭 | 显示后 2 秒自动关闭，也可手动关闭 |
| 用户操作错误 | 账号或密码错误 | 知道了 | 不自动关闭，等待用户关闭 |
| 网络问题 | 网络连接失败，请检查网络 | 知道了 | 不自动关闭，等待用户关闭 |
| 平台问题 | 员工列表加载失败，请联系平台管理员 | 知道了 | 不自动关闭，等待用户关闭 |
| 警告或重要提醒 | 对应的简短提醒内容 | 知道了 | 不自动关闭，等待用户关闭 |
| 操作确认 | 简短确认内容及必要后果 | 取消、具体动作 | 等待用户选择，不自动执行 |

成功提示的 2 秒从实际显示时开始计算，不从进入队列时计算。关闭、切换账号或组件卸载时必须清理计时器，旧计时器不得关闭下一条弹窗。

工具授权不套用普通提醒的停留规则，保留现有审批截止时间与超时自动拒绝机制，不因本次统一而增加、延长或重置授权期限。

## 6. 统一交互要求

### 6.1 关闭和取消

- 错误、提醒和确认弹窗点击遮罩不关闭。
- 普通错误或提醒按 Esc 等同于关闭；确认弹窗在执行前按 Esc 或关闭等同于取消，不执行实际操作。
- 点击“知道了”只关闭提醒，不触发自动重试、重新提交任务或跳转。
- 关闭反馈不代表取消已发出的业务请求；只有后端确实支持取消时，才能提供业务取消按钮。
- 危险操作默认聚焦取消或保留按钮，避免 Enter 意外执行危险动作。

### 6.2 操作执行期间

- 用户点击明确的确认按钮后，才执行对应业务操作。
- 执行期间防止重复提交，按钮显示“正在删除”等与操作对应的状态。
- 不允许通过 Esc、关闭按钮或遮罩将尚未完成的操作误判为已取消。
- 执行失败时在原弹框中切换为简短错误提示，保留原页面的数据和上下文，不再叠加一个错误弹框。
- 不为失败的写入、付费或任务提交操作进行隐式重试。

### 6.3 排队、去重和生命周期

- 由全局公共组件管理反馈弹框；同一时间只显示一个，不叠多层遮罩。
- 同一操作的同一错误只提示一次，后台持续异常及自动重试进行合并，避免连续打断用户。
- 业务表单或详情弹窗中发生错误时保留原上下文，协调弹窗状态，不叠加两套交互遮罩。
- 会话失效只处理一次；退出或切换账号时清理旧会话弹窗和排队项。
- 被清理的待确认操作按取消处理，不能留下永远等待的 Promise，也不能在新会话中继续执行。
- 工具授权必须绑定原请求身份和截止时间，排队不得延长授权期限；过期请求不得继续授权执行。
- 弹窗具备正确的对话框语义、焦点约束和可访问名称，关闭后将焦点恢复到合理位置。

## 7. 迁移顺序

1. 完善后端统一错误映射与必要的共享契约。
2. 建立前端公共弹窗和全局管理入口，实现计时、排队、去重与会话清理。
3. 接入登录、工作台加载、任务启动停止、图片视频与工具审批。
4. 替换知识库、技能、设置、更新等模块的现有反馈与浏览器原生确认框。
5. 对照本规范检查遗漏，移除重复提示入口，保持其他业务行为不变。

文件选择、保存位置选择等系统原生业务对话框不属于普通反馈弹窗，不因本次统一而替换。持续加载状态和任务进度继续使用相应状态展示，不对每次进度变化弹框。

## 8. 验收要求

- [ ] 用户操作或网络问题直接说明问题，平台问题包含“请联系平台管理员”。
- [ ] 已知错误不被再次泛化，未知错误不编造原因。
- [ ] 弹窗没有技术详情、诊断展开入口或敏感信息。
- [ ] 登录页与工作台使用同一套反馈组件和视觉规格。
- [ ] 成功提示实际显示 2 秒后关闭；错误、重要提醒和确认不自动关闭。
- [ ] 确认取消不会执行操作，重复点击不会重复提交，关闭反馈不会假装取消请求。
- [ ] 失败反馈保留用户输入和业务上下文，不重复弹框或叠加遮罩。
- [ ] 后台自动重试不连续弹框，会话失效不重复提示。
- [ ] 退出、同账号重新登录和切换账号后，旧响应、旧事件与旧计时器不影响新会话。
- [ ] 工具审批保留原有截止时间、拒绝及过期处理，统一外观不改变授权安全规则。
- [ ] 浅色和深色主题下内容清晰，小窗口及长文案不溢出，键盘与焦点行为正确。

实施时运行与改动范围对应的类型、边界与回归检查；本规范文档本身的新增不代表弹窗功能已开发完成。

## 9. 登录模块实施范围

- 登录表单校验、登录失败、历史账号读取、密码读取、历史账号移除确认及结果、退出失败、登录失效统一使用公共弹窗。
- 登录成功直接进入工作台，不增加成功弹窗；历史任务、图片和视频恢复继续在后台执行。
- 仅当登录接口返回 HTTP 401 且消息严格为已验证的“邮箱或密码错误”时，展示“账号或密码错误”；其他 401 展示“登录验证未通过”。
- 未知 403 不推断账号停用；平台或客户端内部错误使用简短说明并追加“请联系平台管理员”。
- 未增加登录超时计时器或自动重试；仅将实际传输超时分类为网络连接超时。
- 登录模块实施阶段未迁移工作台员工加载、任务、工具审批及其他业务模块的原有反馈。

## 10. 安排工作模块实施范围

- 会话、自动编排、手动编排中的创建、预检查、启动、保存、目录选择、附件操作及语音输入使用公共弹窗；员工列表和员工状态加载失败使用同一入口。
- 用户填写或选择错误、实际网络异常直接说明原因；平台内部问题追加“请联系平台管理员”。通用 HTTP 403 只说明请求被拒绝，不推断授权已到期或账号已停用。
- 预检查仅向页面返回安全的问题类别和短文案，不返回包含内部订阅 ID、节点 ID 的校验字符串。
- 自动编排根据已有校验原因区分模型响应异常、返回格式异常、输出上限、步骤不完整、员工或模型不可用、附件未分配、交付安排不完整等问题；未知原因保留操作级兜底文案。
- 自动编排响应与终态事件只提示一次；旧草稿版本、旧会话及已卸载页面的结果不得更新当前页面或触发弹窗。不增加任务超时或自动提交重试。
- 保存常用工作成功显示 2 秒；本机保存失败不标记为“已保存”。正常任务启动、取消编排和取消文件选择不增加成功弹窗。
- 语音应用授权改用公共确认弹窗；取消或离开页面不继续授权或录音。保留现有系统麦克风权限检查和录音时限。
- 删除已迁移的编排错误条、附件错误条、语音反馈组件、独立语音原生确认框及对应废弃样式。加载状态、任务进度和空状态继续留在页面。
- 工作记录、工作详情中的其他操作反馈属于后续迁移范围；共享附件和语音组件随本轮统一。
- 页面回归入口：`scripts/test-arrange-feedback-ui.mjs`；编排既有流程回归入口：`scripts/test-auto-arrange-ui.mjs`。

## 11. 模型运行失败提醒

- 对话和安排工作的最终运行失败统一使用公共弹窗，复用第 4、5 节的尺寸、样式和停留规则；点击“知道了”只关闭弹窗。
- 模型请求超时显示“模型请求超时，请稍后重试”；网络故障直接提示检查网络；平台故障使用已核实的简短原因并追加“请联系平台管理员”。不能确定原因时显示“工作运行失败，请联系平台管理员”。
- `Request timed out.` 按模型请求超时处理；不修改 SDK 请求时限和现有自动重试预算，不增加整项任务自动重跑。
- 自动重试过程、重试后成功、节点中间失败不弹窗。安排工作在本轮并行节点收尾后合并提示一次；仅等待用户确认且没有失败节点时不提示故障。
- 主动暂停、终止和退出引起的中断不作为模型故障提醒。对话失败后保留已收到内容及会话，可发送新消息继续；安排工作按现有入口重试失败节点，保留已完成节点。
- 运行错误先在主进程分类。任务状态、运行记录和运行事件仅保存安全文案；模型原始错误写入经过共享脱敏流程的主进程日志，不放进用户弹窗。
- 最终失败通过已有 Pi 事件通道的 `run_failure_notice` 事件通知，载荷仅包含归属身份和受控错误代码；前端按固定文案表展示，按任务和运行 ID 去重。监听器跟随登录工作台，页面切换不重复订阅，退出或账号切换后旧监听和迟到通知失效。
- 浏览器回归入口：`scripts/test-runtime-feedback-ui.mjs`；运行生命周期回归：`electron/runtime/runtime-failure.test.ts` 和 `electron/runtime/arrangement-executor.test.ts`。
