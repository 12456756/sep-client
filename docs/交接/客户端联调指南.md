## 环境准备

### 1. 后端服务启动

```bash
# 克隆仓库（如果还没有）
git clone <repository-url>
cd SEP

# 安装依赖
pnpm install

# 启动数据库
docker-compose up -d

# 初始化数据库
cd backend
npx prisma migrate deploy
npx prisma generate
npx prisma db seed

# 启动后端
npm run dev
```

**验证后端启动成功**:
```bash
curl http://localhost:3001/auth/login -X POST \
  -H "Content-Type: application/json" \
  -d '{"email":"<STAFF_EMAIL>","password":"<TEST_PASSWORD>"}'
```

预期返回：
```json
{
  "token": "eyJhbGc...",
  "user": {
    "id": "demo-user-acme-staff",
    "email": "<STAFF_EMAIL>",
    "name": "技术员",
    "role": "USER"
  },
  "enterprise": {
    "id": "demo-ent-acme",
    "name": "示例科技有限公司"
  },
  "roleInEnterprise": "MEMBER"
}
```

## 联调流程

### 第一步：登录获取令牌

**接口**: `POST /auth/login`

**请求**:
```json
{
  "email": "<STAFF_EMAIL>",
  "password": "<TEST_PASSWORD>"
}
```

**响应**:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": "...", "email": "...", "name": "..." },
  "enterprise": { "id": "demo-ent-acme", "name": "示例科技有限公司" },
  "roleInEnterprise": "MEMBER"
}
```

**客户端需要保存**:
- `token` → 存储到本地（用于后续请求的 `Authorization: Bearer <token>`）
- `user.id` → 当前用户 ID
- `enterprise.id` → 当前企业 ID

---

### 第二步：获取可用员工实例列表

**接口**: `GET /client/instances`

**请求头**:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**响应**:
```json
{
  "data": [
    {
      "id": "demo-inst-acme-writer",
      "name": "文案助手（技能包）",
      "avatar": "https://avatar.iran.liara.run/public/15",
      "description": "快速生成电商文案、广告语",
      "industry": "电商",
      "position": "内容运营",
      "employee": {
        "id": "demo-emp-writer-skill",
        "name": "文案助手（技能包）"
      }
    }
  ]
}
```

**客户端展示**:
- 在侧边栏或员工列表展示所有可用实例
- 用户可选择一个实例开始对话

---

### 第三步：创建会话

**接口**: `POST /client/conversations`

**请求**:
```json
{
  "instanceId": "demo-inst-acme-writer"
}
```

**响应**:
```json
{
  "data": {
    "id": "conv-abc123",
    "instanceId": "demo-inst-acme-writer",
    "createdAt": "2026-07-31T08:00:00Z"
  }
}
```

**客户端**:
- 保存 `conversationId`
- 打开聊天窗口

---

### 第四步：发送消息并接收流式响应

**接口**: `POST /gateway/chat`

**请求**:
```json
{
  "conversationId": "conv-abc123",
  "message": "帮我写一条母婴产品的种草文案"
}
```

**响应**: SSE 流式输出

```
data: {"type":"start"}

data: {"type":"text","content":"🎯 宝宝的第一口"}

data: {"type":"text","content":"辅食，选对了吗"}

data: {"type":"text","content":"？\n\n我家"}

data: {"type":"text","content":"宝宝6个月"}

...

data: {"type":"done","metadata":{"tokensUsed":150}}
```

**客户端处理**:
1. 使用 `EventSource` 或 `fetch` 接收 SSE 流
2. 逐块解析 `data:` 行
3. 根据 `type` 更新 UI:
   - `start` → 显示加载状态
   - `text` → 追加文本到消息气泡
   - `tool_call` → 显示"正在调用工具..."
   - `tool_result` → 显示工具返回结果
   - `done` → 完成，显示 token 消耗

---

### 第五步：获取会话历史

**接口**: `GET /client/conversations/:conversationId/messages`

**响应**:
```json
{
  "data": [
    {
      "id": "msg-1",
      "role": "user",
      "content": "帮我写一条母婴产品的种草文案",
      "createdAt": "2026-07-31T08:00:00Z"
    },
    {
      "id": "msg-2",
      "role": "assistant",
      "content": "🎯 宝宝的第一口辅食，选对了吗？...",
      "createdAt": "2026-07-31T08:00:05Z"
    }
  ]
}
```

**客户端**:
- 切换会话时加载历史消息
- 展示完整对话记录

## 常见问题

### Q1: 401 Unauthorized

**原因**:
- Token 过期（有效期 1 小时）
- Token 格式错误
- 未传 `Authorization` 头

**解决**:
```bash
# 重新登录获取新 token
curl -X POST http://localhost:3001/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"<STAFF_EMAIL>","password":"<TEST_PASSWORD>"}'
```

---

### Q2: 403 Forbidden - 无权访问员工实例

**原因**:
- 实例未授权给当前用户
- 用户所在部门未授权

**解决**:
1. 使用管理员账号登录 Web 前端（`http://localhost:3000`）
2. 进入「我的员工」→ 点击员工卡片 → 点击「授权」
3. 选择成员或部门，保存
4. 客户端重新获取实例列表

---

### Q3: 404 Not Found - 实例不存在

**原因**:
- `instanceId` 错误
- 实例已被删除

**解决**:
- 调用 `GET /client/instances` 获取最新列表
- 检查 `instanceId` 拼写

---

### Q4: SSE 流式响应中断

**原因**:
- 网络不稳定
- 代理服务器缓冲
- 超时设置过短

**解决**:
- 设置更长的超时时间（推荐 60s）
- 禁用代理缓冲
- 断线重连机制：
  ```javascript
  const eventSource = new EventSource(url);
  eventSource.onerror = () => {
    eventSource.close();
    // 3秒后重试
    setTimeout(() => reconnect(), 3000);
  };
  ```

---

### Q5: 消息发送后无响应

**排查步骤**:
1. 检查后端日志：`backend/logs/` 或控制台
2. 检查 sub2api 配置：`backend/.env` 中的 `SUB2API_API_KEY`
3. 测试 sub2api 连通性：
   ```bash
   curl https://longdaoai.cn/v1/models \
     -H "Authorization: Bearer sk-your-key"
   ```

---

### Q6: 算力不足

**错误信息**:
```json
{
  "error": "Insufficient compute balance",
  "code": "INSUFFICIENT_BALANCE"
}
```

**解决**:
1. 使用管理员账号登录 Web 前端
2. 进入「运营端」→「企业管理」
3. 找到测试企业，点击「充值」
4. 充值 1000 点算力

## 高级场景

### 场景 1: 切换员工实例

**流程**:
1. 用户点击侧边栏另一个员工
2. 调用 `POST /client/conversations` 创建新会话（使用新 `instanceId`）
3. 切换聊天窗口到新会话

**注意**:
- 每个实例的会话是独立的
- 切换实例 ≠ 切换会话

### 场景 2: 多轮对话

**流程**:
1. 发送第一条消息，获得回复
2. 继续使用相同 `conversationId` 发送后续消息
3. AI 会记住上下文

**示例**:
```bash
# 第一轮
POST /gateway/chat
{"conversationId": "conv-1", "message": "我是做母婴产品的"}

# 第二轮（AI 会记住前面说的）
POST /gateway/chat
{"conversationId": "conv-1", "message": "帮我写个文案"}
```

### 场景 3: 工具调用（网页搜索）

**员工**: 市场调研员  
**消息**: "搜索一下2024年母婴市场趋势"

**SSE 流**:
```
data: {"type":"tool_call","name":"web_search","args":{"query":"2024年母婴市场趋势"}}

data: {"type":"tool_result","name":"web_search","result":"[搜索结果...]"}

data: {"type":"text","content":"根据搜索结果..."}
```

**客户端展示**:
- 工具调用时显示"🔍 正在搜索..."
- 工具结果可折叠展示
- 最终答案正常显示

## 性能优化建议

### 1. 连接池复用

客户端维护 HTTP 连接池，避免每次请求都建立新连接。

### 2. Token 缓存

Token 有效期 1 小时，客户端应缓存并在过期前刷新。

### 3. 实例列表缓存

`/client/instances` 结果变化不频繁，可缓存 5 分钟。

### 4. 消息分页

历史消息超过 50 条时，使用分页：
```
GET /client/conversations/:id/messages?page=1&limit=20
```
