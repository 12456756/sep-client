# 模型运行日志

## 终端与文档分工

终端显示中文标题、分隔线、任务名称、当前阶段或节点、模型请求状态、耗时、用量和验收结果。模型输入、思考、输出、工具参数和结果正文不进入终端，包括 debug 与 trace 级别。结构化日志保留诊断标识，终端展示不铺开 UUID、订阅编号和指纹。

## 保存位置

日志位于 `<应用用户数据目录>/model-logs/`，与任务业务工作区、Pi 会话目录分离。使用应用可写的数据目录，避免从 Finder、快捷方式或只读安装目录启动时无法写入日志；开发环境也使用相同规则。以终端输出的绝对路径为准。

目录按企业、成员编码隔离，再按规划草稿 ID 或任务 ID 分组：

```text
model-logs/<企业编码>/<成员编码>/<草稿或任务 ID>/
  model-trace.md                 中文总览、时间线、明细链接
  runtime.md                     会话位置、工具、重试、压缩、业务验收与错误明细
  requests/<运行 ID>-<会话唯一标识>-<序号>.md   每个实际模型请求的完整明细
```

三个员工匹配阶段共用草稿目录；执行节点和对话归入各自任务目录。规划记录不因确认任务而搬迁。以终端输出的“详细日志已创建”绝对路径为准。仅记录接入后发生的运行，不追溯补造旧任务。

## 请求明细

- 输入采集于 provider 的最终 `onPayload`：调用方钩子和网关归一化之后，保留实际系统提示、角色、消息顺序、历史、工具返回、工具定义及请求配置。
- 每个请求独立文件，按首次执行、恢复执行、校验失败修正或工具续轮说明用途；重试和压缩另记请求类型。不新增请求、不改变提示词。
- 记录请求发送时间、响应头返回耗时、首个 SDK 流事件、首次思考、首次正文、结束时间、结束原因和用量。没有提供或没有观测到的字段明确标记，不根据字符数伪造 Token 用量。
- 首个 SDK 事件不等于网络首字节；各时刻均相对发送时间，不可简单相加为模型计算时间。总耗时不包含此前的授权和重试退避等待；等待过程单独记录。
- 流式内容采用约每秒一次的完整块快照，异步写入，不等待磁盘再向 Pi 转发事件。块结束时写入最终快照。中断保留已收到内容并标记不完整，不能当作成功交付。
- 运行总览是时间线，详细内容放在请求文件和运行明细，不会因并行节点互相穿插。

## 安全与行为约束

不沿用普通终端日志的 8192 字符截断；SDK 或工具在发送前已有的截断如实保留。共享脱敏实现去除可识别凭据、签名参数和内嵌二进制，文档不是 HTTP 请求的逐字节副本，也不会记录授权请求头。

文件可能含企业资料和模型返回的业务内容，仅用于本地排障，不通过 IPC 暴露。POSIX 文件创建使用限制权限，Windows 继承日志目录 ACL。日志目录不可写或磁盘异常时提示一次，不中止业务请求；该情况下应视记录为可能不完整。

Pi 原有 `.jsonl` 不变。日志改动不改变员工职责、审批、模型请求计数、重试策略或交付校验规则，不设置新的修正次数上限。
