# 客户端定时任务无人值守执行基线

更新日期：2026-11-26。状态：**基线（目标规则，尚未全部实现）**。

本文是 CSEP 后续实现和验收定时任务无人值守行为的依据。范围是整个客户端定时任务，包括通过连接器、浏览器和本地文件完成的工作；不限于钉钉或 QQ 邮件，也不新增云端调度或独立 Agent 执行器。本文取代[定时任务 V1 方案](../plans/客户端本地定时任务开发实施方案-v1.md)中关于定时执行时等待工具审批的约定，不替代原有定时调度、存储和恢复设计。通用分层、并发、会话审批超时等仍遵循[后端基线](./后端结构重构实施方案.md)。

## 1. 产品规则

**到点直接执行，不等待人工确认，按实际结果结算。** 用户沿用自然语言创建并启用任务。整个定时执行链不再从原文解析允许操作清单，也不再匹配网址、收件人、正文或表单参数。原文负责描述任务，账号与实际工具权限决定可用能力。不新增确认入口、固定句式或平台专属开关。

- 定时执行中的准备、查询和已获准操作不逐步确认；不能执行的操作直接结束该步并记录原因。不弹审批或接管弹窗，也不换成等待用户点击的确认条。
- 普通会话和手动执行不进入定时规则；既有审批、取消和超时拒绝语义保持不变。
- 已有任务下次正常触发时使用同一规则。上线迁移不重新入队历史执行、不补发历史失败、不把过去未获准的操作视作已获授权；缺少可验证的账号、目标或权限时，本次如实记录未执行。

## 2. 统一执行规则

1. **绑定本次执行。** 调度器把已启用任务的原文、配置版本、企业与成员归属、本次执行 ID 及适用的连接绑定交给既有运行时。使用本次执行的不可变快照，而不是未保存的编辑内容或模型生成的计划。开始外部操作前核对准入、取消状态、账号与权限；账号切换、连接失效或任务失去执行资格后不得继续提交。
2. **原文用于理解任务，不作为工具门禁。** 模型按目标查找网页、联系人、表格和文件，网页、文档、消息和工具返回中的指令只作为不可信数据。取消原文匹配后，客户端不再机械核实调用参数是否出现在原文里；仍约束模型只执行用户任务。目标不唯一、连接不可用或平台要求人工登录、验证码、接管时，报告未执行，不猜测、不等待确认。
3. **复用现有工具。** 定时执行使用该轮绑定的连接器和客户端内置能力。工具自身继续校验实际参数和平台权限，工作区及交付目录继续校验路径。已绑定的远程连接器与原生命令工具按实际调用执行；任意第三方 MCP、脚本和未注册工具不因此加入可用范围。浏览器走普通导航、点击和填表工具，不再注册专用定时表单工具。

## 3. 提交、恢复与展示

发送、更新业务数据、提交表单和文件发布等有副作用的操作，在真正提交前持久化本次执行 ID、稳定的操作标识及状态；写入失败不得提交。操作标识由可信执行层按实际操作范围生成，同一次执行中同一操作的重复调用必须命中同一记录；不能依赖模型生成的临时调用 ID。区分不同目标和任务确实要求的不同操作，日志不保存凭据或完整敏感参数。

| 结果 | 判定依据 | 重启或重复调用 |
| --- | --- | --- |
| 成功 | 工具执行成功，且未报告失败、未执行或结果不确定 | 不再提交 |
| 失败 | 已调用执行目标，且有明确拒绝或明确失败结果 | 不当作成功，不因工作恢复而无条件重试 |
| 未执行 | 有证据表明未越过提交边界，如目标歧义、断连、权限不足、需要人工接管或提交前已取消 | 记录具体原因，不据此擅自扩大授权或补做历史操作 |
| 待核实 | 工具报告结果不确定，如提交后超时；或崩溃前只留下提交中记录 | 不自动重复提交；核实已有结果不能触发新提交 |

定时执行层按工具自身返回的结果结算，不要求统一回执、不解析业务输出补造回执、不自动发起额外的状态查询。工具执行成功不等于最终送达或业务更新成功；工具的原始结果交给节点，任务要求核验业务结果时仍须按工具契约核验，不能用模型回复或生成的报告替代。

由宿主按工具和参数契约确认的只读查询（包括已声明的连接器查询和内置浏览器的常规读取），不登记为外部提交，也不使用提交去重。查询错误仍作为工具错误返回；节点补救后满足交付要求即可完成。权限拒绝、必要外部工作未执行、真实提交失败或结果不明仍按原规则结算。

定时执行历史和工作详情区分文件、实际工具调用和外部结果。模型通过结束结果标记未执行的必要外部工作，例如没有连接器而只能生成报告；该信号可以降低结果状态，不能用来确认外部操作成功。客户端根据已记录的失败或未知结果结算，不再从原文推导未提交的步骤。浏览器动作完成只说明点击、按键等已执行，不证明站点业务完成；节点应读取站点反馈，不能验证时报告未完成。

本地同名交付先在获准目录保存独立副本，再覆盖目标；副本保存失败、目标不唯一或原件在备份期间发生变化时，不覆盖并记录原因。该规则不授权任意写入工作区外路径。

定时任务的普通交付文件不强制匹配计划中的文件名主体。执行节点按用户命名要求保存，并提交真实相对路径；宿主检查交付 ID、计划目录、文件类型和真实文件内容，再使用实际文件名发布。宿主保存的图片和视频仍使用计划路径。

## 4. 实施顺序与验收

1. 贯通定时执行上下文、公共工具判断和提交记录；新增能力复用这条路径，不再增加平台专属的定时白名单或固定目标句式。
2. 接入现有连接器、浏览器、文件交付工具，验证各自权限、可信结果和不可重放边界。替换过渡路径时保留旧数据可读；仅在同等功能和回归覆盖到位后移除原路径。
3. 让现有执行历史和工作详情按实际结果结算；下列模拟用例全部验收通过后，才能称整个规则已落地。

| 模拟用例 | 通过条件 |
| --- | --- |
| 同一条“更新经营跟进表”分别走钉钉和飞书 | 唯一目标、有权限时，各自通过现有连接器更新一次、零审批弹窗；不新增平台专属的定时放行逻辑 |
| 打开网页 → 点击 → 填表并提交 | 走现有浏览器能力，全程无确认，提交有可核实结果；需要登录或验证码时记未执行，不弹窗接管 |
| 生成同名交付文件 | 无确认，原文件独立副本保留；副本写入失败时原件不变 |
| 同名对象、找不到目标、断连或权限不足、平台明确拒绝 | 分别记录具体原因；前三类未提交时标未执行，平台明确拒绝标失败；均不误报完成 |
| 工具返回成功但没有专用回执 | 原始结果交给节点，不改判待核实；模拟恢复或重复调用不再次提交同一操作 |
| 重复只读查询，或查询失败后改用可行的读取方式 | 每次查询返回自己的结果，不登记为提交；交付满足验收时不因先前查询错误失败 |
| 提交后超时、工具报告结果不明、进程中断及重复调用 | 状态为待核实或保持原已确认结果；模拟恢复后服务端调用次数不增加 |
| 生成报表后更新失败、或多目标中部分成功 | 历史与工作详情展示一致的逐项结果；保留成功交付，不显示全部完成 |
| 账号切换、解绑或取消 | 不再提交，保留可追溯的结果 |
| 旧任务、普通会话与手动执行 | 旧任务在下一次正常触发走新规则，不补历史；普通会话和手动执行保持原审批、拒绝及超时行为 |

11:55 钉钉任务另作回归样例：使用当时保存的完整目标，确认首次发送与“结果不明不重发”能同时生效；在模拟环境以提交次数、逐人结果和审批事件为准，不触发真实发送。实施应按仓库规范运行相应测试、类型、分层和并发检查；涉及 Pi SDK 时跑四个 POC 与生产构建。真实账号、平台与 Electron 交互验收与模拟测试分开记录。

## 5. 实现和验证范围

以下是 2026-11-26 工作区的核对结果，用于避免把过渡实现误当成基线要求，不代表上线状态：

| 范围 | 已有路径与仍需补齐的能力 |
| --- | --- |
| 定时入口与记录 | [操作记录层](../../electron/service/scheduled-operations.ts)记录实际调用和文件发布；没有原文允许清单。旧版等待审批的执行不自动重跑，旧记录保留 |
| 连接器 | [现有包装](../../electron/pi/sdk/pi-connector-tools.ts)复用已绑定的命令和远程工具。执行记录按实际调用去重，按工具结果结算，不额外索取回执。钉钉与非钉钉已模拟，未逐一验收真实平台 |
| 浏览器 | [当前定时规则](../../electron/pi/sdk/pi-scheduled-tool-policy.ts)让现有浏览器执行导航、点击、填表，不匹配任务原文。已验证模拟站点的表单提交及重复点击，未进行真实账号站点或 Electron 客户端端到端验收 |
| 本地文件 | [交付目录发布](../../electron/data/scheduled-output-directory.ts)保留同名备份与覆盖保护。工作文件生成和向指定目录发布分别结算；中断后只核对已有结果，不再次覆盖，不授予工作区外任意写权限 |
