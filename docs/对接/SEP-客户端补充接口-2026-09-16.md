# SEP 客户端补充接口

日期：2026-09-16。补充《SEP-客户端共享联调完整对接文档-v1.md》。下面路径均相对于 `https://sep-dev.longdaoSEP.cn/api`，使用 `Authorization: Bearer <accessToken>`，不是 employment token。部署与真实账号验收记录见本文末尾。

## 1. 组织架构与企业目录

### GET /enterprise/organization

所有企业成员可读本企业部门、成员基本资料和硅基员工目录。只从登录身份解析企业，不接收 enterpriseId。示例中的 ID 是占位符，目录和授权数组仅展示一项：

```json
{
  "enterprise": { "id": "enterprise_id", "name": "客户端联调企业", "logo": null },
  "permissions": {
    "grantVisibility": "ENTERPRISE",
    "departmentGrantInheritance": "DIRECT_DEPARTMENT_ONLY",
    "personalReportingSupported": false
  },
  "statistics": {
    "employeeCount": 2,
    "subscriptionCount": 2,
    "activeEmployeeCount": 2,
    "currentUserAvailableEmployeeCount": 2
  },
  "departments": [
    { "id": "department_id", "name": "研发部", "parentId": null, "leaderId": "member_id", "sortOrder": 0 }
  ],
  "members": [
    { "id": "member_id", "userId": "user_id", "name": "联调成员", "departmentId": "department_id", "position": "研发", "avatar": null }
  ],
  "employees": [
    {
      "employeeId": "employee_id", "subscriptionId": "subscription_id",
      "name": "需求分析员", "avatar": null, "position": "需求分析", "description": "整理需求与验收条件",
      "status": "ACTIVE", "employeeStatus": "APPROVED", "endDate": null,
      "active": true, "currentUserCanUse": true
    }
  ],
  "grants": [
    { "id": "grant_id", "subscriptionId": "subscription_id", "memberId": "member_id", "departmentId": null, "expiresAt": null }
  ]
}
```

- `leaderId` 引用 EnterpriseMember.id，即 `members[].id`，不是 userId。未设置的负责人为 null；当前没有个人直属上级模型，不能用部门树推造个人汇报线。
- 所有成员看到全企业组织基本字段，不含邮箱、模型密钥、systemPrompt 等。
- `ENTERPRISE_ADMIN` 的 `grantVisibility=ENTERPRISE`，可看本企业所有有效授权；`MEMBER` / `DEPT_MANAGER` 为 `SELF`，仅本人直接授权及本人所属部门授权。不能用普通成员响应重建其他人的完整授权关系。
- 部门授权只覆盖该部门直属成员，不继承给子部门。管理员使用员工也需要有效授权。
- `grants` 仅包含授权未过期、订阅 ACTIVE 且订阅未到期的记录。null 到期时间表示无限期；到期时间等于当前时间已失效。
- `employees` 按订阅列出，包含全部状态：ACTIVE、PAUSED、EXPIRED、TERMINATED。同一 employeeId 可以出现多条。
- `employeeCount` 按 employeeId 去重，含停用和过期；`subscriptionCount` 不去重；`activeEmployeeCount` 仅有效 ACTIVE 订阅对应的去重员工数；`currentUserAvailableEmployeeCount` 进一步要求本人有有效授权。
- `status` 是订阅状态，`employeeStatus` 是模板发布状态，不是 IDLE/WORKING。运行状态继续用 `/enterprise/employee-status` 及已有 WS。

### GET /enterprise/overview

与 organization 同权限、同计数口径，返回 `enterprise`、`permissions`、`statistics`、`employees`，省略 departments、members、grants。首页统计使用本接口；运行员工列表仍以 `/client/subscriptions` 为准。

## 2. 保存完整个人 Skill 并送审

### POST /enterprise/skill-versions

一次请求完成创建 PERSONAL 版本及进入审核队列，没有需要客户端补调的“提交审核”步骤。

```http
POST /enterprise/skill-versions
Authorization: Bearer <accessToken>
Idempotency-Key: 902a70ec-b23d-4ec0-82c8-73450fe778a9
Content-Type: application/json
```

```json
{
  "capabilityId": "capability_id",
  "parentVersionId": "platform_version_id",
  "content": "---\nname: requirement-analysis\ndescription: 分析需求\n---\n\n# 工作方法\n先明确验收条件。\n",
  "changeSummary": "增加验收条件"
}
```

`capabilityId`、`parentVersionId` 非空，最多 128 字符；content 为 1 至 500000 字符，完整保留 frontmatter、换行及尾部空白，不进行 Markdown 渲染或执行；changeSummary 可选，最多 2000 字符。ownerId、enterpriseId、status 不接受客户端指定。

来源版本须属于同一 capability，且是已发布平台版、当前企业已发布企业版或本人在当前企业的个人版。调用者必须有该 SKILL 对应的有效员工订阅与授权。

首次成功 `201`（节选）：

```json
{
  "id": "psv_<64位摘要>",
  "capabilityId": "capability_id",
  "parentVersionId": "platform_version_id",
  "enterpriseId": "enterprise_id",
  "ownerId": "user_id",
  "scope": "PERSONAL",
  "version": "0.0.0-personal.<64位摘要>",
  "status": "PENDING_ENTERPRISE_REVIEW",
  "submittedAt": "2026-09-16T09:00:00.000Z",
  "enterpriseReviewedAt": null,
  "rejectionReason": null,
  "content": "完整原文，与请求一致"
}
```

幂等及版本规则：

1. 每次用户点击保存生成一个 UUID 作为 Idempotency-Key，并与原请求一起保留到收到确定响应。键接受 16-128 位字母、数字、下划线和连字符。
2. 超时、断线、5xx 后重试同一保存，复用键和同一请求内容。服务端按“企业 + 用户 + 键”持久去重，返回同一 id，不重复创建版本或审核记录。
3. 同键不同内容、capabilityId、parentVersionId 或 changeSummary 返回 409。用户再次编辑保存必须换新键，创建新的待审核版本。
4. 原文在提交后固定，旧编辑/删除副本接口不能改写送审版。审核只改状态和审核元数据。
5. 审核完成后重试原保存，返回同一版本的**当前**状态，不会把它重新变成待审核。
6. 个人送审版本号由平台生成，属于独立不可变版本标识，不参与平台/企业的 1.x.x 序列。ID 按不透明字符串处理，不能假设所有版本 ID 都是 CUID；客户端不要按个人 version 排序，使用 createdAt。

## 3. 查询版本、审核结果与原文

### GET /enterprise/skill-versions?capabilityId=...

返回数组，包含该能力已发布平台版、当前企业已发布企业版、本人当前企业全部个人版。支持可选 status 过滤。每项包含 id、capabilityId、parentVersionId、scope、version、status、ownerId、submittedAt、enterpriseReviewedAt、rejectionReason、changeSummary、createdAt、updatedAt。正文通过 preview 单独读取。

不传 capabilityId 保持原 Web 企业版本列表契约，不用于查询个人审核结果。

### GET /enterprise/employees/:employeeId/skills

已有 `skills[].versions` 扩展包含本人个人版（含待审核、通过、驳回），并增加上述审核元数据。

- `currentVersion` 仍表示订阅公共选版：管理员选择的企业/平台版，其次员工模板默认平台版，再其次最新发布平台版；上传个人版不会自动改变它。
- `latestPublishedVersion` 表示该能力最新发布的**平台版**，没有则 null，以服务端 createdAt 降序认定；不是最新待审核个人版。
- `upgradeAvailable` 保持原含义：有 currentVersion 与最新平台版且两者 id 不同。企业定制版也可能得到 true，这是可选择回到平台最新版本的提示，不应触发静默替换。

客户端本地可选用的状态与作用域：

| scope | status | 客户端可使用范围 |
|---|---|---|
| PLATFORM | PLATFORM_APPROVED | 有该技能授权的用户 |
| ENTERPRISE | ENTERPRISE_APPROVED | 本企业有该技能授权的用户 |
| PERSONAL | ENTERPRISE_APPROVED | 该版本 ownerId 对应本人，且仍有技能授权 |
| PERSONAL | PENDING_ENTERPRISE_REVIEW / ENTERPRISE_REJECTED | 仅展示审核与原文，不安装执行 |
| PERSONAL | PERSONAL_ACTIVE | 历史 Web 即时副本，不属于客户端审核发布流程 |
| 任意 | DRAFT / ARCHIVED / 其他待审、驳回状态 | 不安装执行 |

个人审核通过后由客户端在本地选择安装，不修改 SubscriptionSkillVersion，不替换其他成员公共版本。原 Web 的“个人副本修改即生效”入口仍保留，客户端保存送审不要调用它。

### GET /enterprise/skill-versions/:versionId/preview

返回版本元数据、capability 摘要和 `content` 完整存储原文，不截断。本人可读自己的各审核状态个人版，仍须有效技能授权；同企业管理员可读取已送审个人版供审核，无须另给管理员员工使用授权；其他成员/其他企业不可读。

新保存送审版本的 content 精确保留原请求。历史版本在旧写入流程中已剥离的 frontmatter 无法凭空还原，该接口不会伪造原文；本次配置的联调发布版本包含完整 frontmatter，可直接用于编辑联调。

## 4. 企业管理员处理审核

### GET /enterprise/skill-version-reviews

仅 ENTERPRISE_ADMIN；DEPT_MANAGER 无此权限。查询参数：status 默认 PENDING_ENTERPRISE_REVIEW，可取 ENTERPRISE_APPROVED、ENTERPRISE_REJECTED；capabilityId 可选；page 默认 1；limit 默认 20，范围 1-100。

返回 `{ "total": 1, "page": 1, "limit": 20, "items": [版本元数据] }`。正文使用 preview 获取。队列仅包含当前企业的个人送审版本。

### POST /enterprise/skill-versions/:versionId/review

```json
{ "decision": "REJECT", "comment": "请补充验收标准" }
```

decision 为 APPROVE 或 REJECT，驳回时 comment 必填，最多 2000 字符。成功 `201`，返回最新版本元数据，状态为 ENTERPRISE_APPROVED 或 ENTERPRISE_REJECTED，设置 enterpriseReviewedAt，驳回时设置 rejectionReason。通过仅表示本人版本获准使用，不发布为企业公共版本。

版本仅能审核一次；并发审核只有一个成功，其余 409。响应丢失后重新查询版本状态；不要盲目重复审核。再次修改须由作者创建新版本。

## 5. 错误与联调验收

错误沿用 `{statusCode,message,requestId,timestamp,path}`。401 为无效/过期 accessToken；403 为无企业成员身份或非企业管理员；404 为资源不存在、无有效技能授权或不可见来源；400 为参数非法/父版本能力不匹配；409 为幂等键冲突、不可编辑送审版或重复审核。没有权限与不存在的资源均可能返回 404，客户端不要根据 ID 猜测资源存在。

验收顺序：登录 → subscriptions 和 employee-status 非空 → organization/overview 数量一致 → skills 获取发布版 → preview 取完整原文 → 带新幂等键保存 → 同键重试得到同 id → 改内容复用键得到 409 → 查询本人待审版 → 管理员审核 → 查询结果及原文 → 新保存创建新 id。普通成员读取他人个人版/审核队列必须被拒绝。

模型网关继续使用 employmentToken、`/gateway/v1/chat/completions` 和订阅 allowedModels。接口补充不改变客户端本地任务执行边界。
