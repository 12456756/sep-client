# 客户端 IPC 接口契约

最后更新：2026-08-18

> 本文档定义 **React Renderer ↔ Electron Main Process** 之间的 IPC 接口契约。
> Electron main 是客户端的后端，负责运行 pi-coding-agent SDK、管理任务状态、本地持久化和调用 SEP 平台。
> SEP 平台只负责登录认证和提供授权资源列表，详见 [`后端接口需求.md`](./后端接口需求.md)。

---

## 架构总览

```
┌──────────────────┐       IPC (contextBridge)       ┌──────────────────────┐       HTTP        ┌──────────────┐
│  React Renderer  │ ◄────────────────────────────► │  Electron Main       │ ◄──────────────► │  SEP Platform │
│  (前端 UI)        │                                 │  (客户端后端)          │                   │  (认证+资源)   │
│                  │                                 │                      │                   │              │
│  LoginPage       │                                 │  pi-coding-agent SDK │                   │  POST /client │
│  WorkspaceHome   │                                 │  TaskManager         │                   │    /auth/login│
│  ConversationView│                                 │  CredentialsManager  │                   │  GET  /client │
│  WorkflowView    │                                 │  WorkspaceManager    │                   │    /instances │
│  WorkspaceComposer│                                │  AuthSessionManager  │                   │              │
└──────────────────┘                                 └──────────────────────┘                   └──────────────┘
```

**核心原则**：
- Renderer 不直接访问 SEP 平台、不持有 token、不接触文件系统。
- 所有业务逻辑在 Electron main 中实现。
- 任务状态、消息历史由 Electron main 本地管理（可持久化到本地存储）。
- SEP 平台仅提供：登录认证、授权资源列表（员工/技能/工作流）、AI 网关。

## 一、认证域

### AUTH-CMD-001 登录

**IPC**: `auth:login`（`invoke`）

```
方向：renderer → main
```

请求：
```ts
interface LoginRequest {
  email: string
  password?: string              // 使用已保存密码时可为空
  rememberPassword: boolean
  useSavedPassword: boolean      // true 时密码由 main 从 safeStorage 读取
}
```

响应：
```ts
interface LoginResponse {
  success: boolean
  data?: {
    user: { id: string; email: string; name: string }
    enterprise: { id: string; name: string } | null
  }
  error?: {
    code: string                  // INVALID_CREDENTIALS | ACCOUNT_DISABLED | RATE_LIMITED | NETWORK_ERROR | SERVICE_UNAVAILABLE
    message: string
    statusCode: number
    retryable?: boolean
  }
}
```

**main 侧职责**：
1. 调用 SEP 平台 `POST /client/auth/login` 完成认证
2. 将 refreshToken 通过 `safeStorage` 加密存储
3. 如果 `rememberPassword` 为 true，加密存储密码
4. 更新本地账号历史记录
5. 如果 `useSavedPassword` 为 true，从 safeStorage 读取密码，不要求 renderer 传入

**renderer 侧职责**：
- 只接收 `user` 和 `enterprise` 信息
- 不接触 accessToken、refreshToken 或密码明文

## 二、资源域

### RES-QRY-001 查询授权资源

**IPC**: `resources:list`（`invoke`）

```
方向：renderer → main
```

响应：
```ts
interface ResourcesResponse {
  success: boolean
  data?: {
    employees: Array<{
      employeeId: string
      displayName: string
      description: string
      avatar?: string
      status: 'ACTIVE' | 'PAUSED' | 'REVOKED'
      modelOptions: Array<{
        modelId: string
        displayName: string
        providerName?: string
        description?: string
        isDefault: boolean
        supportsTools: boolean
        status: 'ACTIVE' | 'PAUSED' | 'REVOKED'
      }>
    }>
    skills: Array<{
      skillId: string
      name: string
      description: string
      version: string
      status: 'ACTIVE' | 'PAUSED' | 'REVOKED'
      installed: boolean          // 客户端本地是否已下载
      requiresTools?: boolean
    }>
    workflows: Array<{
      workflowId: string
      name: string
      description: string
      version: string
      status: 'ACTIVE' | 'PAUSED' | 'REVOKED'
      employeeIds: string[]
      requiresWorkspace: boolean
      inputs: Array<{
        id: string
        label: string
        type: 'text' | 'long-text' | 'number' | 'boolean' | 'enum' | 'path'
        required: boolean
        options?: string[]
        placeholder?: string
      }>
    }>
  }
  error?: { code: string; message: string; retryable?: boolean }
}
```

**main 侧职责**：
1. 调用 SEP 平台 `GET /client/instances` 获取授权实例列表
2. 将 instance 数据映射为 employee + modelOptions 结构
3. 技能和工作流如 SEP 平台暂不提供，由 main 从本地配置/预置数据构建
4. 合并本地技能安装状态（`installed` 字段）
5. 按当前用户授权过滤

**关于数据来源**：
- SEP 平台 `GET /client/instances` 返回的是 instance 列表，每个 instance 包含 `allowedModels`
- main 需要将其转换为 employee 结构（instanceId → employeeId, displayName 保持不变）
- 技能和工作流如 SEP 暂不提供，main 可以先用本地配置，但响应结构必须保持一致

## 三、任务域

### 产品规则

- 任务中心统一展示当前登录用户的个人任务，不按 instance 分组。
- 对话首条消息才创建任务和会话，不能创建空会话。
- 任务创建后绑定 `employeeId`，员工不可更换。
- `skillIds` 和 `workflowId` 只对当前任务生效。
- 模型列表和可用性由 SEP 返回，用户可在任务内切换模型。
- 工作空间是本机目录，由 main 管理；路径不传给 SEP 平台。
- 任务状态：`queued | running | waiting-approval | completed | failed | cancelled | stopped`
- `stopped` 表示停止当前生成但任务可继续交互；`cancelled` 表示终止任务。

### 通用数据结构

```ts
interface LocalWorkspaceBinding {
  path: string                   // 本机绝对路径
  displayName: string
  accessMode: 'read-only' | 'read-write'
}

interface TaskMessage {
  id: string
  role: 'user' | 'assistant'
  content: string
  createdAt: string              // ISO 8601
  modelId?: string
}

interface TaskArtifact {
  id: string
  name: string
  kind: 'document' | 'code' | 'report'
  summary: string
}

interface TaskSummary {
  taskId: string
  type: 'conversation' | 'workflow'
  title: string
  employeeId: string
  employeeName: string
  modelId: string
  status: TaskStatus
  progress: number               // 0..100
  updatedAt: string
}

type TaskStatus = 'queued' | 'running' | 'waiting-approval' | 'completed' | 'failed' | 'cancelled' | 'stopped'
```

### TASK-CMD-001 创建对话任务（首条消息）

**IPC**: `task:create-conversation`（`invoke`）

```
方向：renderer → main
```

请求：
```ts
interface CreateConversationRequest {
  employeeId: string
  modelId: string
  skillIds?: string[]
  workspace: LocalWorkspaceBinding
  content: string               // 首条消息内容，不能为空
}
```

响应：
```ts
{
  success: boolean
  data?: {
    taskId: string
    title: string               // 从 content 截取
    status: 'queued'
    createdAt: string
    messageId: string           // 用户消息 ID
  }
  error?: { code: string; message: string }
}
```

**main 侧职责**：
1. 校验 `content` 非空
2. 校验 `employeeId` 在授权列表中
3. 校验 `modelId` 在该员工的 `modelOptions` 中
4. 校验 `workspace.path` 存在且有对应权限
5. 创建任务记录，生成 `taskId`
6. 启动 pi session（如尚未启动），发送首条 prompt
7. 通过事件通道推送消息流和状态变更

## 四、事件域

### 事件通道

**IPC**: `task:event`（`send`，main → renderer 推送）

```
方向：main → renderer
```

所有事件统一由此通道推送，通过 `event.type` 区分。

```ts
interface TaskEvent {
  type: TaskEventType
  taskId: string
  runId: string
  sequence: number
  occurredAt: string            // ISO 8601
}

type TaskEventType =
  | 'message.queued'
  | 'message.delta'
  | 'message.completed'
  | 'message.stopped'
  | 'message.failed'
  | 'task.status-changed'
  | 'task.progress'
  | 'tool.started'
  | 'tool.completed'
  | 'approval.requested'
  | 'approval.resolved'
  | 'workflow.log-appended'
  | 'workflow.artifact-created'
```

### 消息事件

**message.queued**
```ts
TaskEvent & { messageId: string }
```

**message.delta**
```ts
TaskEvent & { messageId: string; delta: string }
```
- delta 有序去重，renderer 按 sequence 拼接

**message.completed**
```ts
TaskEvent & { messageId: string; content: string }
```
- 携带完整内容，用于校准丢失或重复的 delta

**message.stopped**
```ts
TaskEvent & { messageId: string }
```

**message.failed**
```ts
TaskEvent & { messageId: string; error: { code: string; message: string } }
```

### 状态事件

**task.status-changed**
```ts
TaskEvent & { status: TaskStatus }
```

**task.progress**
```ts
TaskEvent & { progress: number }  // 0..100，不倒退
```

### 工具事件

**tool.started**
```ts
TaskEvent & { toolName: string; summary: string }
```
- 只提供工具名称和脱敏摘要，不包含敏感参数

**tool.completed**
```ts
TaskEvent & { toolName: string; success: boolean; summary: string }
```

### 审批事件

**approval.requested**
```ts
TaskEvent & {
  approvalId: string
  toolName: string
  risk: string
  description: string
  expiresAt: string            // 60 秒后
}
```
- 工具审批（bash/write/edit）必须经用户确认
- 敏感参数通过专用审批 payload 传输，不写入普通消息

**approval.resolved**
```ts
TaskEvent & { approvalId: string; approved: boolean; reason?: string }
```

### 工作流事件

**workflow.log-appended**
```ts
TaskEvent & { logId: string; entry: string }
```

**workflow.artifact-created**
```ts
TaskEvent & { artifactId: string; name: string; kind: string; summary: string }
```

## 七、通用错误码

```ts
interface IpcError {
  code: string
  message: string
  retryable?: boolean
  details?: Record<string, unknown>
}
```

| 错误码 | 说明 |
|--------|------|
| `INVALID_ARGUMENT` | 参数无效 |
| `INVALID_CREDENTIALS` | 凭据无效 |
| `ACCOUNT_DISABLED` | 账号被禁用 |
| `AUTH_REQUIRED` | 认证失效，需重新登录 |
| `RESOURCE_NOT_AUTHORIZED` | 无权使用该资源 |
| `MODEL_UNAVAILABLE` | 模型不可用 |
| `EMPLOYEE_IMMUTABLE` | 员工不可更换 |
| `TASK_CONFLICT` | 任务冲突（如已有 run 在运行） |
| `TASK_NOT_FOUND` | 任务不存在 |
| `WORKSPACE_NOT_FOUND` | 工作空间目录不存在 |
| `WORKSPACE_ACCESS_DENIED` | 工作空间无权限 |
| `WORKSPACE_READ_ONLY` | 工作空间只读，不允许写入 |
| `APPROVAL_EXPIRED` | 审批已过期 |
| `RATE_LIMITED` | 请求过于频繁 |
| `NETWORK_ERROR` | 网络错误 |
| `SERVICE_UNAVAILABLE` | 服务不可用 |
| `INTERNAL_ERROR` | 内部错误 |

## 八、与 SEP 平台的边界

Electron main 只对 SEP 平台发起以下 HTTP 调用：

| 调用 | 用途 | 频率 |
|------|------|------|
| `POST /client/auth/login` | 用户登录 | 登录时 |
| `GET /client/instances` | 获取授权实例列表 | 登录后、资源刷新时 |
| `POST /client/auth/token` | 换取实例令牌 | 令牌过期时 |
| AI 网关调用 | 实际 AI 推理（通过 pi SDK provider） | 每次对话 |

**SEP 平台不负责**：任务管理、消息持久化、工作流执行、工作空间管理、审批逻辑。这些全部由 Electron main 实现。
