## 六、已有旧接口（待清理/对齐）

以下接口在 `preload.ts` 中已实现，但与新的工作台契约不一致，需要清理或对齐：

| 旧 IPC 通道 | 问题 | 处理方式 |
|------------|------|---------|
| `auth:get-instances` | 直接透传 SEP instance 列表，不做 employee 映射 | 替换为 `resources:list` |
| `pi:start-session` | 按 `employeeId` 启动，但无任务上下文 | 合并到 `task:create-conversation` |
| `pi:send-prompt` | 单独发送 prompt，无任务管理 | 替换为 `task:send-message` |
| `pi:stop-session` | 停止整个 session，非任务级停止 | 替换为 `task:stop` |
| `pi:event` | 原始 pi 事件，未映射为 TaskEvent | 替换为 `task:event` |
| `task:create` / `task:execute` / `task:get` / `task:get-all` | 旧版任务接口，与工作台契约不一致 | 替换为新的 `task:*` 通道 |
| `task:updated` / `task:list-updated` | 旧版事件通道 | 替换为 `task:event` |

## 八、当前缺口总结

- **认证域**：全部已实现，无阻塞。
- **资源域**：全部未实现，P0 阻塞。
- **任务域**：全部未实现，P0 阻塞。
- **事件域**：全部未实现，P0 阻塞。
- **工作空间域**：部分实现，P2 非阻塞。

核心工作聚焦在三个 P0 项：**资源查询 → 创建对话任务 → 消息流事件**。这三个串起来即可打通"选择员工 → 发送首条消息 → 看到 AI 回复"的最小闭环。
