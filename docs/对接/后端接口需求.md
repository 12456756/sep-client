# 后端接口需求（SEP 平台侧）

最后更新：2026-08-18

> 本文档定义 **Electron Main Process → SEP 平台** 的 HTTP 接口需求。
> SEP 平台是客户端的外部依赖，只负责认证和授权资源。任务管理、消息流、工作流执行等核心逻辑由 Electron main 本地实现。
> 客户端前端（React Renderer）不直接访问 SEP 平台。

---

## SEP 平台职责边界

```
Electron Main（客户端后端）          SEP 平台（外部服务）
─────────────────────────          ──────────────────
• 任务状态管理                      • 用户登录认证
• 消息历史持久化                    • 授权实例/员工列表
• pi session 生命周期               • 实例令牌签发
• 工作流执行调度                    • AI 模型网关
• 工具审批逻辑                      • 算力计费
• 工作空间校验                      • 设备管理
• 本地密码加密存储
• 技能本地安装管理
```

## 已有接口（SEP客户端API文档 v1.0）

### 1. 客户端登录

`POST /client/auth/login`

当前可用。需要确认的细节：

- 请求 DTO 是否需要 `fingerprint`/`platform`/`clientVersion` 字段？当前客户端实现中 `fingerprint` 由 Electron main 生成，`platform` 为 `process.platform`
- 错误码细化：当前只返回 HTTP 状态码 + 英文 message，建议增加 `code` 字段区分 `INVALID_CREDENTIALS`、`ACCOUNT_DISABLED`、`RATE_LIMITED`
- 登录成功但账号未关联企业时的正式状态码和错误码
- 邮箱大小写与空白字符的服务端规范（客户端当前会 `trim().toLowerCase()`）

### 2. 获取实例列表

`GET /client/instances`

当前可用。客户端需要此接口返回：

- 当前用户被授权使用的 AI 员工实例
- 每个实例的 `allowedModels`（用于构建前端的 modelOptions）
- 实例状态（ACTIVE / PAUSED / REVOKED）

**数据映射**：客户端将 `instanceId` → `employeeId`，`displayName` 保持不变，`allowedModels` 映射为 `modelOptions`。

### 3. 换取实例令牌

`POST /client/auth/token`

当前可用。用于获取短期实例级 accessToken 以调用 AI 网关。

### 4. AI 模型网关

`POST /gateway/v1/chat/completions`

当前可用。通过 pi-coding-agent SDK 的 provider 机制调用，不直接由客户端代码调用。

## 待确认项

### 登录接口

- 接口是否返回稳定机器错误码（如 `INVALID_CREDENTIALS`、`ACCOUNT_DISABLED`、`RATE_LIMITED`）
- 是否有服务端设备撤销、远程退出能力
- 登录限流的窗口与重试语义
- 登录成功但账号未关联企业时的状态码和错误码

### 实例列表接口

- 实例列表是否已过滤（只返回当前用户有授权且 status=ACTIVE 的实例）
- `allowedModels` 的来源和更新机制
- 资源被撤销后，已有会话应如何处理（继续运行 / 暂停 / 失败）

### 实例令牌

- 令牌过期时间（当前 15 分钟）是否可配置
- 令牌刷新策略建议

## 当前不需要 SEP 平台提供的能力

以下功能由 Electron main 本地实现，**不需要** SEP 平台提供接口：

| 功能 | 实现位置 | 说明 |
|------|---------|------|
| 任务管理（CRUD、列表、筛选） | Electron main | 本地持久化（如 SQLite/JSON 文件） |
| 消息历史 | Electron main | 同上 |
| 消息流事件 | Electron main | pi SDK session 事件 → IPC 推送 |
| 工作流任务执行 | Electron main | pi SDK 执行 + 本地调度 |
| 工具审批 | Electron main | guard.ts 拦截 + IPC 弹窗 |
| 工作空间管理 | Electron main | Node.js fs API |
| 历史账号/记住密码 | Electron main | safeStorage + 本地文件 |
| 技能本地安装 | Electron main | 本地文件管理 |

## 未来可能需要 SEP 平台提供的能力

以下功能当前客户端可本地实现，但若未来需要云端同步或企业级管理，可能需要 SEP 平台支持：

| 功能 | 当前方案 | 云端化需求 |
|------|---------|-----------|
| 任务同步 | 本地存储 | 如需跨设备同步，需 `GET/POST /client/tasks` |
| 技能包下载 | 本地预置 | 如需远程分发，需 `GET /client/skills/{skillId}/download` |
| 工作流模板 | 本地配置 | 如需企业统一管理，需 `GET /client/workflows` |
| 会话历史 | 本地存储 | 如需云端备份，需 `GET /client/conversations` |

## 建议后端改进

1. **统一错误格式**：所有接口返回 `{ code, message, requestId?, retryable?, details? }` 结构
2. **错误码细化**：区分 `INVALID_CREDENTIALS`（密码错误）、`ACCOUNT_DISABLED`（账号禁用）、`DEVICE_REVOKED`（设备吊销）等
3. **实例列表增强**：如果未来支持技能和工作流，在实例列表响应中或通过独立接口返回
