# SEP 客户端对话消息接口说明

> 文档用途：提供给 SEP 平台后端实现客户端对话记录接收接口。
>
> 客户端实现版本：`refactor/backend-structure` 分支，提交 `521b333`。
>
> 接口由客户端在“对话模式”中异步调用，用于保存用户发送给硅基员工的消息，以及 Pi 最终生成的 assistant 消息。

## 1. 接口

```http
PUT /client/employee-conversations/{clientConversationId}/messages/{clientMessageId}
```

客户端会对路径参数进行 URL 编码。平台路由匹配时应按解码后的字符串处理。

### 认证

```http
Authorization: Bearer <accessToken>
Content-Type: application/json
```

使用客户端当前登录用户的 access token。公司和用户身份应从 access token 解析，不由请求体传入。

## 2. 路径参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `clientConversationId` | string | 是 | 客户端对话 ID。当前客户端使用对应任务的 `taskId`。同一对话内保持不变。 |
| `clientMessageId` | string | 是 | 客户端消息 ID。当前客户端生成规则为 `<runId>-user` 或 `<runId>-assistant`，用于幂等去重。 |

路径参数是客户端侧 ID，不要求平台将其当作平台数据库主键。

## 3. 请求体

```json
{
  "subscriptionId": "cmu3wbhhv0004r19ziwonu40e",
  "role": "user",
  "content": "请查看工作目录里有几个文件",
  "runId": "run-01",
  "turnId": "run-01",
  "modelId": "gemini-3.5-flash-high",
  "createdAt": "2026-09-20T08:30:00.000Z"
}
```

### 字段定义

| 字段 | 类型 | 必填 | 约束与说明 |
|---|---|---:|---|
| `subscriptionId` | string | 是 | 公司内硅基员工的订阅 ID。平台需校验该订阅属于当前 access token 对应的公司，并且当前用户有权使用该员工。 |
| `role` | string | 是 | 只能是 `user` 或 `assistant`。`user` 表示用户消息，`assistant` 表示 Pi 的最终文本输出。 |
| `content` | string | 是 | 消息正文。客户端只上传最终用户消息和最终 assistant 输出，不上传流式 delta、工具调用、工具结果、bash 命令、审批记录或推理过程。 |
| `runId` | string | 是 | 客户端本轮执行 ID。用于关联客户端任务运行记录。 |
| `turnId` | string | 是 | 客户端对话轮次 ID。当前实现中与本轮 `runId` 相同，但平台应按独立字段保存。 |
| `modelId` | string | 是 | 本轮使用的模型 ID，例如 `gemini-3.5-flash-high`。 |
| `createdAt` | string | 是 | ISO 8601 时间字符串，客户端生成。建议平台保存原始值，同时记录平台接收时间。 |

## 4. 成功响应

建议首次写入返回 HTTP `200 OK`（或 `201 Created`），响应格式如下：

```json
{
  "data": {
    "conversationId": "conversation-001",
    "messageId": "message-001",
    "clientConversationId": "task-001",
    "clientMessageId": "run-01-user",
    "duplicate": false,
    "storedAt": "2026-09-20T08:30:01.000Z"
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `conversationId` | string | SEP 平台对话记录 ID。 |
| `messageId` | string | SEP 平台消息记录 ID。 |
| `clientConversationId` | string | 原样返回客户端对话 ID。 |
| `clientMessageId` | string | 原样返回客户端消息 ID。 |
| `duplicate` | boolean | 是否命中幂等记录。首次写入为 `false`。 |
| `storedAt` | string | 平台实际保存时间，ISO 8601。可选。 |

如果重复请求能够正常返回，建议返回 HTTP `200 OK`，并设置 `duplicate: true`。客户端也会将 HTTP `409 Conflict` 视为幂等成功，因此平台如果采用 409 表示重复，客户端不会继续无限重试。

## 5. 幂等要求

幂等键至少应为：

```text
(client identity, clientConversationId, clientMessageId)
```

建议数据库建立唯一约束：

```text
enterpriseId + userId + clientConversationId + clientMessageId
```

同一幂等键重复提交时：

1. 不创建第二条消息；
2. 返回第一次写入对应的 `conversationId` 和 `messageId`；
3. 将 `duplicate` 设置为 `true`；
4. 不要因为重复提交修改原消息正文、角色、员工或所属公司。

客户端使用本地 outbox 异步上传，网络超时、应用重启或响应丢失时可能重复提交，因此幂等处理是必需的。

## 6. 权限和数据归属校验

平台应使用 access token 确定：

- 当前用户 `userId`；
- 当前公司 `enterpriseId`。

平台还应校验：

1. `subscriptionId` 存在且属于当前公司；
2. 当前用户对该 `subscriptionId` 具有使用权限；
3. `role`、`content`、`runId`、`turnId`、`modelId`、`createdAt` 类型和长度合法；
4. 同一幂等键不能跨用户或跨公司复用；
5. 不要信任客户端传入的公司 ID、用户 ID 或员工名称，客户端不会发送这些字段。

## 7. 错误响应

客户端按 HTTP 状态码处理：

| 状态码 | 平台含义 | 客户端行为 |
|---:|---|---|
| `400` / `422` | 请求格式或字段校验失败 | 标记为永久失败，不会无限重试。 |
| `401` | access token 无效或过期 | 有限重试，最多 3 次；平台应使用标准认证错误响应。 |
| `403` | 当前用户无权使用该员工 | 标记为永久失败。 |
| `404` | 员工订阅或目标资源不存在 | 标记为永久失败。 |
| `409` | 幂等冲突或重复消息 | 客户端按上传成功处理。 |
| `408` / `429` | 请求超时或限流 | 客户端重试。建议 `429` 返回 `Retry-After`。 |
| `500` / `502` / `503` / `504` | 平台或上游临时故障 | 客户端按退避策略重试。 |

建议错误响应沿用 SEP 现有错误格式，例如：

```json
{
  "statusCode": 403,
  "message": "当前用户无权使用该硅基员工",
  "requestId": "req-001",
  "timestamp": "2026-09-20T08:30:01.000Z",
  "path": "/client/employee-conversations/task-001/messages/run-01-user"
}
```

## 8. 保存模型建议

平台至少需要保存以下信息：

```text
enterpriseId       当前用户所属公司
userId             当前登录用户
subscriptionId     使用的硅基员工
conversationId     平台对话 ID
messageId          平台消息 ID
clientConversationId
clientMessageId
role
content
runId
turnId
modelId
createdAt          客户端消息时间
storedAt           平台保存时间
```

建议对 `content` 设置合理长度限制，并对消息正文进行正常的存储安全处理。不要将 access token 写入数据库或日志。

## 9. 客户端上传时机

客户端不是每个流式片段都调用接口：

- 用户消息：本地对话记录成功写入后进入 outbox；
- assistant 消息：Pi 完成最终输出且本地对话记录成功写入后进入 outbox；
- 上传在后台进行，不阻塞对话执行；
- outbox 文件按登录用户 scope 隔离；
- 应用重启后会继续上传未完成项目。

因此平台接口应允许请求延迟到达，并且不能要求用户界面保持在线等待上传完成。

```bash
curl -X PUT \
  'https://<sep-host>/client/employee-conversations/task-001/messages/run-01-user' \
  -H 'Authorization: Bearer <access-token>' \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "subscriptionId": "cmu3wbhhv0004r19ziwonu40e",
    "role": "user",
    "content": "请查看工作目录里有几个文件",
    "runId": "run-01",

    "modelId": "gemini-3.5-flash-high",
    "createdAt": "2026-09-20T08:30:00.000Z"
  }'
```
