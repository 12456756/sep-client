## 2. 双方负责什么

| 桌面客户端 | SEP 平台 |
| --- | --- |
| 登录并安全持有短期 access token；通过现有认证流程刷新会话 | 验证 JWT，并从登录用户解析有效企业成员和企业身份 |
| 展示知识库、文档状态、失败原因和来源 | 管理知识库、文档及成员授权；每次请求重新检查权限 |
| 管理员在客户端发起上传/替换/重试等操作 | 私有保存原件，解析、切分、生成向量、构建索引和异步处理 |
| 在员工对话/任务中按当前用户权限调用检索，把返回片段作为资料交给客户端运行时 | 返回允许访问的检索片段及版本化来源；不替桌面端生成员工回答 |
| 展示引用来源；在撤权、登出或切换成员时清理本地缓存 | 撤权后阻止后续读取和检索；不保证收回此前已展示或已进入会话历史的内容 |

知识库不绑定硅基员工、员工订阅或部门。平台权限对象是当前企业成员 `memberId`；管理员可管理本企业知识库，普通成员只能读取管理员显式授权的库。

## 3. 地址、认证和请求通用要求

- 当前生产 API 根地址为 `https://longdaosep.cn/api`，例如 `https://longdaosep.cn/api/knowledge-bases`。本次直接核对生产允许的来源仅为 `https://longdaosep.cn`；客户端应由主进程按双方约定发送该受控来源，不能把任意渲染页面传入的 Origin 直接转发。环境切换时配置 API 地址，不要自行添加 `/v1`。
- 请求使用 `Authorization: Bearer <accessToken>`。不要把 access token 放入 URL、日志、React 持久化存储或知识库缓存。
- 桌面客户端应复用现有 DESKTOP 登录/刷新机制。知识库接口不会接受客户端自行提交的 `enterpriseId`、`memberId`、`role` 作为授权依据。
- 使用 `/api/client/auth/login` 或 `/api/client/auth/refresh` 返回的普通 `accessToken`；不要把 refresh token 或 `/api/client/auth/token` 换取的 employment token 用于知识库接口。HTTP 请求与凭证在主进程处理，通过最小 IPC API 向界面返回业务数据。
- 知识库及权限响应带 `Cache-Control: no-store`；客户端若自行缓存，必须按用户/成员隔离，并在登出、切换账号、成员身份变化或权限错误时清理。
- 上传、替换版本、重试及删除文档使用 `Idempotency-Key`。网络超时后重试同一操作时复用原 key；用户重新发起新的操作时生成新 key。
- 当前文档操作的 key 格式为 8–128 位字母、数字、`_` 或 `-`，可使用 UUID。去重键范围为同一用户、同一知识库、同一 key；同一 key 不得跨不同文档或不同操作复用。幂等回放保证不重复执行写入，但返回文档最新状态，不保证逐字重放最初响应。创建知识库当前没有幂等保护，超时后应先刷新列表确认结果，不能盲目重发。
- 版本替换、重试、删除文档须先 GET 文档详情，读取响应 `ETag`，写请求发送 `If-Match: <原样 ETag>`。不可自行拼接或复用旧 ETag。
- 上传文件上限 10 MiB，每次一个文件；支持 `.pdf`、`.docx`、`.txt`、`.md`。扫描版 PDF、图片 OCR、旧版 DOC 等不能按支持格式假设。
- API 跨域名单由生产 `CORS_ORIGIN` 控制。生产环境所有知识库写请求（POST/PATCH/DELETE）即使带 Bearer token，也必须带有命中 `CORS_ORIGIN` 的 `Origin` 或 `Referer`；知识库接口没有 CSRF 豁免。Electron/Node 主进程请求若默认不带这些头，会被拒绝。联调前需由客户端和运维确定合规的 Origin，并核实生产 CORS 配置；不要伪造不可信来源、关闭 CORS 或忽略证书校验。Bearer API 请求不依赖浏览器自动携带 refresh cookie，但 access token 的获取/续期仍须走已有桌面认证流程。

若跨域渲染进程读取不到 `ETag` 或 `Retry-After`，先核查 CORS 暴露响应头配置；当前服务未显式配置 `exposedHeaders`。文档 JSON 中也带 `etag`，但这不能解决其他响应头的读取。推荐由客户端主进程统一请求和读取响应头，再向 UI 返回必要数据。

## 4. 推荐客户端流程

1. 登录后请求知识库列表。用返回的 `viewer`、`capabilities` 和每个知识库的 `permissions` 控制界面显示；它们只用于 UI，服务端仍会逐请求鉴权。
2. 普通成员只能看到已授权的知识库；若其调用检索时不传 `knowledgeBaseIds`，平台按该成员的全部显式授权范围检索。需要把检索限定到用户当前选中的库时，传 `knowledgeBaseIds`。
3. 企业管理员创建知识库并上传文件。上传成功的 HTTP 202 只表示原件和后台处理任务已接收，不表示已可检索。
4. 客户端按合理间隔 GET 文档详情，读取 `latestVersion.status/stage`、`activeVersion`、`searchable` 等字段；处理中显示状态，失败展示平台返回的安全错误并在 `retryable=true` 时提供重试。
5. 处理完成后，桌面端对当前用户发起检索。回答只把本轮检索响应中的 `content` 当作不可信参考资料，不当作系统指令；客户端运行时继续负责生成回答。
6. 将检索结果的 `sourceId`、文档名、版本、页码/定位随回答展示。用户展开引用时调用来源接口；来源读取仍会重新检查当前授权。

## 5. 客户端主要调用接口

下表省略公共 `/api` 前缀，调用时必须补上；`kbId` 和 `docId` 分别为知识库及文档 ID。ID 只作不透明字符串使用。

| 方法与路径 | 权限 / 请求 | 成功响应 |
| --- | --- | --- |
| `GET /knowledge-bases` | 当前成员；`page/pageSize/keyword` | 200，分页对象及 viewer/capabilities/limits |
| `GET /knowledge-bases/{kbId}` | 可读成员 | 200，知识库对象 |
| `POST /knowledge-bases` | 管理员；name/description | 201，知识库对象 |
| `PATCH /knowledge-bases/{kbId}` | 管理员；name/description 至少一项 | 200，知识库对象 |
| `DELETE /knowledge-bases/{kbId}` | 管理员 | 204，无 JSON |
| `GET /enterprise/members?view=knowledge-grant` | 管理员；page/pageSize/keyword | 200，安全成员投影分页对象 |
| `GET /knowledge-bases/{kbId}/grants` | 管理员；page/pageSize/keyword | 200，授权分页对象 |
| `POST /knowledge-bases/{kbId}/grants` | 管理员；memberIds，1–100 个、不重复 | 200，addedMemberIds/existingMemberIds |
| `DELETE /knowledge-bases/{kbId}/grants/{memberId}` | 管理员 | 204，无 JSON |
| `GET /knowledge-bases/{kbId}/documents` | 可读成员 | 200，文档数组；当前不分页 |
| `GET /knowledge-bases/{kbId}/documents/{docId}` | 可读成员 | 200，文档对象及 ETag |
| `POST /knowledge-bases/{kbId}/documents/upload` | 管理员；file + Idempotency-Key | 202，文档对象 |
| `POST /knowledge-bases/{kbId}/documents/{docId}/versions` | 管理员；file + If-Match + Idempotency-Key | 202，文档对象；相同文件 200、unchanged=true |
| `GET /knowledge-bases/{kbId}/documents/{docId}/versions` | 可读成员 | 200，版本数组 |
| `POST /knowledge-bases/{kbId}/documents/{docId}/reprocess` | 管理员；空对象 + If-Match + Idempotency-Key | 202，文档对象 |
| `DELETE /knowledge-bases/{kbId}/documents/{docId}` | 管理员；If-Match + Idempotency-Key | 204，无 JSON |
| `GET /knowledge-bases/{kbId}/documents/{docId}/preview` | 可读成员；page/pageSize/versionId | 200，解析预览分页对象 |
| `POST /knowledge-bases/search` | 当前成员；query/knowledgeBaseIds?/topK? | 200，检索对象 |
| `GET /knowledge-bases/{kbId}/sources/{sourceId}` | 可读成员 | 200，来源对象 |

当前知识库创建/修改/删除不要求 `If-Match`，也没有目标方案所述的完整知识库编辑并发控制；不要按文档操作的 ETag 机制推断所有资源均支持它。JSON 请求为严格 schema，未知业务字段会返回 400。

### 5.1 列表和详情

`GET /api/knowledge-bases?page=1&pageSize=20`

返回 `{ items, page, pageSize, total, viewer, capabilities, limits }`。单条知识库包含 `id/name/description/revision/documentCount/readyDocumentCount/permissions`。管理员可创建；普通成员不能创建、上传或授权。

`GET /api/knowledge-bases/{knowledgeBaseId}/documents`

返回该库文档列表及当前生效版本、最新版本、处理状态和是否可检索。`GET /api/knowledge-bases/{knowledgeBaseId}/documents/{documentId}` 返回文档详情，并通过响应头提供当前 `ETag`。

`status` 为 `PENDING/PROCESSING/READY/FAILED`；阶段包括 `QUEUED/PARSING/CHUNKING/EMBEDDING/PUBLISHING/DONE/RETRY_WAIT/FAILED`。实际可检索与否优先看 `searchable`：最新版本失败时旧生效版本可能仍可用，不要只看顶层 `status` 把整篇文档显示成不可用。`activeVersion/latestVersion` 对旧资料可能为 null。

文档详情接口适合轮询；建议客户端从 2 秒间隔开始，逐渐退避至 10 秒，遇到 429 按 `Retry-After` 等待，并在用户离开页面或超时后停止。不要每秒轮询。状态汇总接口 `GET /api/knowledge-bases/{knowledgeBaseId}/documents/status` 可用于页面概览，不替代单文档详情。

### 5.2 创建、授权和上传（管理员）

创建：`POST /api/knowledge-bases`

```json
{ "name": "员工手册", "description": "公司制度与流程" }
```

上传：`POST /api/knowledge-bases/{knowledgeBaseId}/documents/upload`，`multipart/form-data` 字段名为 `file`，同时发送 `Idempotency-Key`。返回 202，文档处理需随后轮询详情。

成员授权：`POST /api/knowledge-bases/{knowledgeBaseId}/grants`

```json
{ "memberIds": ["<企业成员ID>"] }
```

授权对象必须是本企业有效成员 ID，不是用户 ID、部门 ID 或订阅 ID。授权列表为 `GET .../{knowledgeBaseId}/grants`；撤权为 `DELETE .../{knowledgeBaseId}/grants/{memberId}`。

候选成员通过 `GET /api/enterprise/members?view=knowledge-grant&page=1&pageSize=20` 获取，使用条目中的 `memberId`，不要从账号列表猜测。知识库、成员候选、授权分页的 `pageSize` 最大 100，默认 20。

### 5.3 替换版本、重试和删除（管理员）

- 替换：`POST /api/knowledge-bases/{knowledgeBaseId}/documents/{documentId}/versions`，multipart `file`，发送 `If-Match` 和 `Idempotency-Key`。新版处理期间，原生效版本继续可检索；新版本成功后原子切换。若文件内容与当前生效版完全相同，响应 200 且 `unchanged: true`。
- 重试：`POST .../documents/{documentId}/reprocess`，空 JSON `{}`，发送 `If-Match` 和 `Idempotency-Key`。仅可重试失败且可重试的最新非生效版本；其他情况应提示上传新版本或刷新状态。
- 删除：`DELETE .../documents/{documentId}`，发送 `If-Match` 和 `Idempotency-Key`。返回 204。原件清理可能异步完成，客户端不应把 204 解释成所有备份或已展示内容立刻销毁。

### 5.4 检索和来源

检索：`POST /api/knowledge-bases/search`

```json
{
  "query": "差旅住宿报销标准是什么？",
  "knowledgeBaseIds": ["<当前可访问的知识库ID>"],
  "topK": 5
}
```

`knowledgeBaseIds` 可省略（检索全部当前授权知识库），`topK` 为 1–20，查询最多 1000 字符。不要发送 `subscriptionId`：当前检索契约不使用订阅绑定。

响应主要字段：`status`（`MATCHED`、`NO_MATCH`、`NO_ACCESS`、`NOT_READY`）、`results[]`、`actualStrategy`、`degraded`、`partial`、`durationMs`。每条结果带 `sourceId`、`knowledgeBaseId/name`、`documentId/name`、`versionId`、`content` 和 `location`。检索服务异常是错误，不应伪装成 `NO_MATCH`。

例如下列合成响应（ID 为示意，不能直接用于调用；耗时也不是性能承诺）：

```json
{
  "searchId": "search_example",
  "status": "MATCHED",
  "actualStrategy": "HYBRID",
  "degraded": false,
  "degradationReason": null,
  "durationMs": 250,
  "count": 1,
  "partial": false,
  "results": [{
    "sourceId": "source_example",
    "knowledgeBaseId": "kb_example",
    "knowledgeBaseName": "员工手册",
    "documentId": "doc_example",
    "documentName": "差旅制度.txt",
    "versionId": "version_example",
    "chunkId": "source_example",
    "content": "住宿报销需提交有效发票。",
    "tokenCount": 13,
    "truncated": false,
    "location": { "pageStart": null, "pageEnd": null, "sectionPath": [], "blockStart": 0, "blockEnd": 0 }
  }]
}
```

| 字段或状态 | 界面及运行时处理 |
| --- | --- |
| MATCHED | 有可用片段，允许作为本轮参考资料并展示来源 |
| NO_MATCH | 正常检索无匹配，不能杜撰企业规则 |
| NO_ACCESS | 未指定范围且没有可访问知识库；显示暂无可用知识库 |
| NOT_READY | 当前可访问范围内尚无可检索资料，提示等待处理或补充资料 |
| degraded=true | 查询向量不可用，实际用 LEXICAL 检索；结果可用但需提示能力受限 |
| partial=true | 有部分资料未就绪，命中仅覆盖当前就绪部分 |

显式传入任何不可访问的知识库 ID，整个请求返回 404，不会静默只查剩余库；不要把 404 转成 NO_ACCESS。`knowledgeBaseIds` 最多 100 个且不允许空数组或重复 ID。客户端正式检索不传 `strategy/scoreThreshold/useRerank` 等管理员兼容测试参数。`tokenCount/truncated` 是返回片段的预算信息，客户端仍需给回答和聊天历史预留上下文；平台总片段预算上限为 6000 token。

来源详情：`GET /api/knowledge-bases/{knowledgeBaseId}/sources/{sourceId}`。返回引用片段、文档/版本标识、定位和 `isCurrent`。若返回 404，来源可能已被删除、到期清理或当前用户已失去权限，客户端应移除该来源展示，不绕过权限尝试下载原件。原件下载接口当前已停用（410）。

`isCurrent=false` 时标注“历史版本”，不把旧回答解释成依据当前制度生成。页码为 null 时不要编造页码。预览第一页返回 `versionId`；翻页时带回同一 `versionId`，收到 `DOCUMENT_VERSION_CHANGED` 时从第一页重新打开，避免混合两个版本。预览中的 `chunkId` 是解析块标识，不能当作检索 `sourceId` 使用。

## 6. 错误处理

| HTTP | 客户端处理 |
| --- | --- |
| 401 | 复用桌面端现有刷新流程一次；仍失败则要求重新登录。非幂等请求不得换 key 后盲目重放。 |
| 403 | 当前账号没有企业成员身份或管理员权限；刷新身份/权限状态，不循环重试。 |
| 404 | 资源不存在或对当前成员不可见；清理对应缓存，不探测其他 ID。 |
| 409 | 按响应 `code` 处理，例如处理中冲突、文档未就绪或不可重试；刷新详情后给出明确提示。 |
| 412 / 428 | ETag/前置条件冲突或缺失；重新 GET 详情并由用户确认后再操作。 |
| 413 / 415 | 文件过大或格式不支持；展示服务端限制。 |
| 429 | 按 `Retry-After` 延后请求，提供取消入口，不立即循环。检索/来源读取有独立限流。 |
| 503 | 检索或限流依赖暂不可用；保留用户问题，提示稍后重试，不能当成无匹配。 |

错误响应包含 `statusCode`、`message`、`requestId`、`timestamp`、`path`；适用时包含稳定 `code`。日志上报只记录请求 ID、状态码和错误码，不记录 token、原文、检索 query 或命中内容。

403 还可能来自全局 CSRF 来源检查，此时不能一律提示“没有知识库权限”。先结合 message/requestId 核查请求来源。当前实际业务码包括 `DOCUMENT_PROCESSING`、`DOCUMENT_NOT_RETRYABLE`、`DOCUMENT_NOT_READY`、`IDEMPOTENCY_CONFLICT`、`PRECONDITION_REQUIRED`、`REVISION_CONFLICT`、`KNOWLEDGE_RATE_LIMIT_EXCEEDED`；不要沿用旧目标文档中不同名称的码。

## 7. 联合验收清单

客户端和平台至少共同验证以下场景，生产验证须使用授权的测试企业和合成资料：

- 桌面端登录后，access token 能访问生产 API；未登录返回 401，刷新流程正确，token 不进日志/持久化缓存。
- 管理员能创建知识库、授权成员、上传支持格式；普通成员不能执行管理写操作。
- 真实上传后状态从处理中到完成；通过检索命中内容，返回来源可读取且展示的版本/定位一致。
- 上传新版本时旧版本继续服务，成功后新版本生效；失败时旧版本仍可用。
- 撤权后同一成员下一次检索和来源读取被拒绝；跨企业 ID 不泄漏资源是否存在。
- 429 遵守 `Retry-After`；服务端不可用不显示成“没有相关资料”；登出/切换账号后客户端缓存清理。
- 对一组双方确认的真实企业问题集，人工判定 Top-K 相关性、来源准确率和无答案误命中，并记录通过阈值。仅小型合成语料测试不能作为企业检索质量通过证明。

验收通过的最低标准：以上权限/故障用例无越权；桌面端端到端完成“上传（管理员）→处理完成→成员检索→来源展示→撤权后失效”；企业问题集达到双方事先确认的质量阈值。阈值需在实测前由双方定下，避免事后挑选标准。

## 8. 当前边界和待联调确认

- 桌面端生产 Origin 是否已纳入 `CORS_ORIGIN`、桌面主进程或渲染进程哪一侧请求平台 API，以及写请求能否满足 CSRF 来源校验：需客户端开发环境实测并由运维核对配置。不能仅凭 Web 端通过推断桌面端可连接。若客户端当前请求没有稳定且受控的来源，需先协商认证/来源校验方案，不能把 token 当作绕过条件。
- 当前平台按登录用户最早创建的成员记录解析企业身份，本期不支持多企业切换。若客户端已有多企业切换 UI，接入前须协调平台上下文改造，不能自行传入 `enterpriseId` 切换权限范围。
- 发布时保留的 4 份旧文档和 62 个旧文本块没有重建为当前固定 embedding profile（数量为发布时快照，不代表实时统计）。新上传资料可按当前链路处理；旧资料可由管理员上传新版本进入当前处理链路，向量效果验收建议用新建测试资料。企业手工 reindex 接口已停用，不要调用它重建，也不要直接改旧模型标签。
- 平台接口不支持知识库完全留在本机、原件不上传平台或原件下载；如企业要求数据不离开内网，需要另行设计本地/私有化部署方案。
- 检索结果和来源提供的是可追溯资料，不替客户端生成回答；多员工/自动编排场景下，把一个员工检索到的原文传给另一个员工的规则尚不属于本接口承诺。

## 10. 客户端接手顺序与交付物

1. 先跑桌面登录/刷新、知识库列表、带受控 Origin 的检索，验证 access token 与生产来源校验；此步不通过就先解决联通，不能靠模拟数据宣告接入完成。
2. 接列表/详情/文档状态和来源展示；管理员页面再接成员候选、授权、上传及版本管理。
3. 将检索接入真实员工会话和任务执行，处理追问、取消、重试、切换账号及引用白名单。客户端生成回答后，只接受本轮 results 中的来源 ID，模型生成的任意 URL/ID 不视为可信引用。
4. 按第 7 节跑联合验收，提交客户端版本号、测试环境、用例结果和脱敏 requestId；平台方协助核对错误及权限行为。

客户端应交付：实际可用的页面和运行时接入、权限及故障提示、引用定位展示、联合验收记录。平台方负责处理联调暴露的接口或部署缺陷；真实客户端与企业语料尚未验收前，不把整体功能标为最终交付完成。
