# SEP 客户端与 Web 端联调指南 v1

> 更新时间：2026-09-20
>
> 适用对象：Web 前端、SEP 后端、客户端开发者、联调测试人员。
>
> 当前版本：SEP Client 0.1.0，beta / integration，内部联调用途。
>
> 状态：三个本地安装包已生成且 SHA-256 校验通过；未签名、未公证、未上传；真实安装与端到端业务联调尚待验证。

## 1. 本轮目标与分工

本轮先验证“下载并安装客户端 → 登录与获取订阅 → 本地执行任务 → 上报云端镜像 → Web 展示任务状态”的闭环，不以完成正式签名为前置条件，也不等同于正式发行验收。

| 负责方 | 需要完成的事项 |
|---|---|
| Web 前端 | 三种安装包下载入口、版本/架构/内测提示；接入经后端确认的任务查询接口，展示云端镜像状态与异常 |
| SEP 后端 | 确认任务镜像写接口已部署；提供 Web 查询接口、响应示例、租户权限规则、状态及事件幂等规则；协助关联服务端日志 |
| 客户端 | 提供安装包、校验和、环境信息；发起登录和任务；协助排查上报失败 |
| 测试/发布负责人 | 准备三种系统的测试机、测试企业和账号；分发内测包；记录安装与业务验收证据 |

任务在 Electron 客户端本地执行；Web 读取 SEP 后端的云端镜像。浏览器不直接调用客户端的 `window.electronAPI`，不直接读取本地文件，也不要把已有 Web `/api/tasks` 或 `/api/task-plans` 自动当作客户端任务镜像接口。

本轮不包含 Linux、macOS ZIP、Windows ARM64、自动更新、公开下载发布或 Web 远程控制本地任务。

## 4. 任务监控：以当前客户端实际请求为准

### 4.1 写接口（客户端 → SEP 后端）

以下来自 `electron/common/platform/client-task-api.ts` 和 `electron/runtime/task-cloud-mirror.ts`，不是对服务端可用性的声明。

请求由 Electron 主进程发送，使用客户端 access token：`Authorization: Bearer <accessToken>`、`Content-Type: application/json`。Web 不应获取或复用该令牌，也不要使用 employment token 写任务镜像。

| 方法与完整路径 | 当前请求体 | 当前响应处理 |
|---|---|---|
| `POST /api/client/tasks` | 见下方创建示例 | 直接读取 JSON 顶层 `id`，必须为有效云端任务 ID |
| `PATCH /api/client/tasks/{remoteTaskId}/status` | `{ "status": "RUNNING" }` | 成功需返回有效 JSON 或 HTTP 204 |
| `POST /api/client/tasks/{remoteTaskId}/heartbeat` | `{}` | 成功需返回有效 JSON 或 HTTP 204 |
| `POST /api/client/tasks/{remoteTaskId}/events` | 见下方事件示例 | 成功需返回有效 JSON 或 HTTP 204 |

创建请求示例（ID 为占位符；状态取创建时的本地状态，不保证总从 QUEUED 开始）：

```json
{
  "clientTaskId": "local-task-id",
  "clientRunId": "local-run-id",
  "subscriptionId": "subscription-id",
  "title": "联调测试任务",
  "status": "QUEUED",
  "createdAt": "2026-09-20T07:00:00.000Z"
}
```

创建响应期望为 `{ "id": "remote-task-id" }`，不是 `{ "data": { "id": "..." } }`。`clientRunId`、`subscriptionId` 在类型上允许缺省或 null，后端需确认校验规则；标题当前截取前 200 个字符。

事件请求结构如下；`type` 原样取本地 `TaskExecutionEvent.type`，不在本文虚构一套后端事件枚举：

```text
{
  sequence: number,
  type: string,
  occurredAt: ISO 时间字符串,
  data?: { toolId?, toolName?, success?, attempt?, maxAttempts?, delayMs? }
}
```

`data` 只提取上述字段中的字符串、数字或布尔值。当前不上传完整 prompt、模型响应或本地文件正文；但任务标题及允许字段仍可能带业务信息，必须使用无敏感信息的测试任务。

发行计划中的 `taskType`、`modelId`、`clientVersion`、`progress`、`currentStep`、`activity`、`errorSummary` 等字段目前没有在这些请求中发送，Web 不应要求它们必填或伪造进度。

### 4.2 状态展示

| 客户端本地值 | 上报云端值 | Web 建议文案 |
|---|---|---|
| pending | QUEUED | 等待执行 |
| running | RUNNING | 执行中 |
| waiting_approval | WAITING_APPROVAL | 等待审批 |
| paused | PAUSED | 已暂停 |
| interrupted | CANCELLED | 已取消/中断 |
| completed | COMPLETED | 已完成 |
| failed | FAILED | 执行失败 |

当前 `interrupted` 统一映射为 `CANCELLED`，不能仅凭此值断言是用户主动取消。没有进度百分比时展示状态和更新时间，不显示虚构的 100%。未知状态应有回退文案，不导致页面崩溃。

### 4.3 Web 查询契约：后端必须先补充确认

本次仅核对客户端仓库，未验证后端路由、Swagger 或 Web 实现；这里不指定未经核实的 GET 地址。后端请填写以下内容后，Web 再进行真实接入：

| 待确认项 | 必须提供的信息 |
|---|---|
| 查询路由 | 企业客户端任务列表、详情、事件列表的实际 GET 路径 |
| 身份权限 | Web 自身登录态、企业作用域、管理员/普通成员可见范围、越权返回规则 |
| 响应结构 | 是否包裹 data；云端 id 与 clientTaskId/clientRunId/subscriptionId 的对应关系 |
| 查询参数 | 分页、状态筛选、排序、时间范围和分页响应样例 |
| 更新时间 | 服务端更新时间、最近 heartbeat 时间字段及其时区 |
| 刷新方式 | HTTP 轮询或已存在的推送通道；没有契约时不假设 WebSocket 已支持任务镜像 |
| 幂等规则 | 创建重试、同一任务多次运行，以及 remoteTaskId + sequence 重复事件如何处理 |
| 下线判断 | heartbeat 过期阈值；暂停/审批/终态的在线状态含义 |

建议在后端允许后使用可配置的 3～5 秒列表轮询；这是联调建议而非现有协议。请求失败显示“同步异常/数据可能延迟”，不要把后端不可达直接显示为“任务执行失败”。

## 5. 已知限制与重点风险

以下为代码核对结果，不是已经通过的验收承诺：

- **接口未部署**：403/404 会禁用该本地任务的镜像上报，且会持久化。修复权限或部署接口后，优先新建测试任务；不要反复复用已禁用的任务，也不要直接删除用户数据。
- **有限重试**：网络错误、429 和 5xx 最多尝试 4 次，等待约 0.5/1/2 秒；401 通过认证管理器失效并重新获取 access token 后重试一次。当前镜像请求未显式设置超时。
- **补偿未完成验收**：代码保存映射和部分待发送数据，但没有独立、持续的离线补发调度。镜像创建成功前到达的事件可能被跳过；最终状态补发、重启恢复均必须实测。
- **事件序号风险**：当前序号基于最后成功上报值递增；若上一条未发送成功，下一条可能使用相同序号。断网恢复与幂等测试是重点，不能先宣称无丢失或无重复。
- **heartbeat**：首次在 RUNNING 创建定时器时为 10 秒，WAITING_APPROVAL 时为 15 秒；已有定时器不随状态重新调频，暂停也未单独停用，终态停止逻辑依赖同步成功。Web 不应硬编码每次精确 10 秒或仅据 heartbeat 判定运行状态。
- **作用域与多次运行**：镜像持久化文件位于 userData 下，映射以本地任务 ID 为键；账号/企业切换、同一任务多次运行的归属与隔离需联合验证，未通过前仅用专用测试账号和非敏感数据。
- **流程覆盖**：当前接入点为 TaskManager 任务变化和 TaskRuntime 事件回调；不要据此假设所有会话和工作安排流程都已有对应 Web 镜像。

以上问题应记录到联调缺陷清单，由客户端/后端修复后复测；本指南不修改业务实现。

## 6. 联调步骤与验收记录

每一项初始均为“待测”，执行后填写通过/失败/阻塞和证据。三种系统分别记录安装与启动结果，不能用一台 M 芯片 Mac 代替全部平台验收。

| 编号 | 操作 | 通过标准/证据 |
|---|---|---|
| T01 | 点击三个下载入口并校验 | 平台/架构/文件名正确，SHA-256 一致；未上传则标为阻塞 |
| T02 | 对应系统安装并启动 | 不依赖开发目录；记录系统版本、架构、安装提示和启动截图 |
| T03 | 检查客户端环境栏并登录 | beta/integration/API 地址正确；专用账号登录成功 |
| T04 | 获取员工订阅、加载 runtime | 只看到授权订阅，可进入一个可执行任务；记录 subscriptionId |
| T05 | 新建无敏感信息的任务 | 后端收到创建请求并返回 id；记录 clientTaskId、clientRunId、remoteTaskId |
| T06 | Web 查看任务 | 经确认的查询接口可查到相同 remoteTaskId；企业与用户归属正确 |
| T07 | 完成正常任务 | Web 最终显示 COMPLETED，刷新/重进页面仍一致；记录更新时间 |
| T08 | 审批、暂停、失败、取消 | 对实际支持的入口逐项验证状态；拒绝工具不等于任务必然 FAILED |
| T09 | 观察长任务与终态 | 后端有 heartbeat 证据；终态后观察是否仍上报；记录真实间隔 |
| T10 | 模拟镜像接口断网/429/5xx后恢复 | 镜像故障不直接中断本地执行；核对最终状态和事件完整性，发现缺失即记失败 |
| T11 | 重试创建和事件 | 同一业务任务无重复镜像，事件无误去重/丢失；与后端一起执行可控重放 |
| T12 | 模拟401、403、404 | 验证认证恢复/停止上报与日志；不用真实令牌截图或粘贴工单 |
| T13 | 退出重启与重新运行任务 | 登录恢复、最终状态、事件、运行 ID 映射一致；不能只测界面打开 |
| T14 | 切换账号/企业并用无权限账号查询 | 不泄露另一账号/企业任务；越权由后端拒绝，不只靠前端隐藏 |
| T15 | 卸载/重装 | 记录实际数据保留行为与登录结果；不预先承诺清除或保留全部数据 |

T10 优先只模拟任务镜像接口不可用，保持模型网关可达；整机断网也会影响模型调用，不能将其混同为镜像故障导致任务失败。故障注入只在授权联调环境执行，不影响其他测试者或生产。

第一轮联调至少完成 T01～T07；T08～T15 未通过前，不将可靠补偿、权限隔离和完整发行验收标为完成。建议先由后端开发者与客户端开发者一起跑通 T05/T06，再由 Web 完善状态页面。

## 7. 排查顺序与问题反馈模板

Web 看不到任务时按顺序检查：环境/企业一致 → 客户端是否发出 POST → HTTP 状态和响应顶层 id → 服务端记录 → Web 查询权限/筛选 → 页面刷新。不要首先尝试修改状态映射或使用其他任务接口兜底。

接口 404 优先确认部署与路由；401 检查认证恢复；403 检查企业/订阅授权；2xx 后仍异常需检查响应封装。日志中可检索 `task-cloud-mirror` 和 `cloud task mirror failed; local task continues`，共享前脱敏。

```text
问题编号/标题：
发现时间（含时区）：
安装包文件名 + SHA-256：
操作系统/架构：
客户端版本/通道/构建时间/API 地址：
Web 版本、后端部署版本：
测试企业/账号标识（脱敏，无密码/令牌）：
clientTaskId / clientRunId / remoteTaskId / subscriptionId：
复现步骤、预期、实际：
HTTP 方法/路径/状态码/requestId（如有）：
脱敏响应、客户端日志、后端日志、截图：
是否必现、负责方、复测结果：
```
