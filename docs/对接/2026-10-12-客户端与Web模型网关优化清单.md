# 客户端与 Web 模型网关优化清单

日期：2026-10-12

本文只总结剩余优化项。Web 端指平台模型网关、后端计费与认证、Web 代理和部署链路，不涉及 `/enterprise/skill-versions` 或客户端 `task:retry` 缺节点 ID 的问题。

## 已修复

以下按本次确认的修复状态记录，不再列为待修复问题：

- 后端取消固定 30 秒截断：等待响应头最多 120 秒，连续空闲最多 120 秒，单次请求总时长最多 10 分钟，均可配置。
- 流式转发原样透传上游数据，不再因转发逻辑丢失结束帧、空行或跨块内容。
- Web 代理调整超时并补齐生产镜像配置；异常断流记录日志，不伪造成功结束。

以上是已确认的修复范围，不代表剩余计费、重试和授权问题已经解决。

## 客户端需要优化

| 优先级 | 问题 | 优化方向 |
| --- | --- | --- |
| 高 | 请求归一化删除 `stream_options.include_usage` | 保留 usage 请求参数，与平台约定每轮模型调用的用量返回方式。 |
| 高 | SDK 的 `max_completion_tokens` 被删除，配置的 4096 未成为实际出站上限 | 正确映射平台支持的输出上限字段，按模型能力发送并增加回归测试。 |
| 高 | 429 重试固定等待 2、4、8 秒，不读取 `Retry-After` | 根据服务端等待时间重试，支持取消和等待上限；区分平台限流、上游限流与不可重试错误。 |
| 中 | token 刷新队列缺少有界等待；认证 hook 失败可能被 SDK 吞掉 | 刷新和排队等待可超时、可取消；取得有效雇佣 token 后才能发起模型请求。 |
| 中 | 断流重试后，失败尝试的文本可能拼进成功结果 | 按请求尝试管理输出，重试时移除失败片段，只保存有效结果。 |
| 中 | `finish_reason=length` 被当作普通成功 | 区分完整完成、输出截断、取消和失败，避免把不完整方案标为完成。 |
| 中 | 本地任务与网关请求缺少统一关联标识 | 传递任务、节点、轮次和尝试标识用于追踪；计费幂等必须遵循服务端执行协议，不能整项任务共用一个计费 ID。 |

## Web 平台端需要优化

| 优先级 | 问题 | 优化方向 |
| --- | --- | --- |
| 高 | 计费幂等键使用客户端可控 ID，未绑定认证身份；模型执行本身未去重 | 使用服务端执行 ID，绑定企业、用户和订阅；合法重试同时处理执行去重与计费去重。 |
| 高 | 缺 usage、取消或断流后可能无法记账；后台记账失败仅记录日志 | 保证用量采集，建立持久待结算记录、幂等补偿和 sub2api 对账，不把缺 usage 当作零成本。 |
| 高 | 封禁、退出登录、设备撤销不能立即使旧雇佣 token 失效 | 绑定会话或撤销版本，并检查用户状态；补充撤销后旧 token 不可用的测试。 |
| 高 | 无效 JWT 在身份限流前被拒绝，缺少入口资源防护 | 增加无效认证、连接和请求体防护；不要恢复把所有用户合并到代理 IP 的业务限流。 |
| 中 | 只有请求频率限制，没有并发、token 和企业聚合预算；余额无成本预留 | 根据实际模型续轮和成本设置预算，明确余额预留、释放及欠费边界。 |
| 中 | 网关模型策略未完整执行部门限制、禁止切换和失效模型过滤 | 复用现有有效模型策略，保证客户端列表与实际执行权限一致。 |
| 中 | DTO 对消息、工具结构、上下文和输出上限约束不足 | 在上游调用前完成结构和模型能力校验，返回明确的字段错误。 |
| 中 | 上游 200 响应未校验内容类型；普通 EOF 缺少明确的完成判据 | 避免把 JSON/HTML 当作 SSE；明确有效结束条件，不虚构结束帧。 |
| 中 | 错误响应读取缺少大小上限，部分上游错误缺关联日志 | 有界读取并校验响应；统一记录上下游 Request ID、模型、错误来源和失败阶段。 |
| 中 | 尾斜杠路径可能被 CSRF 错误拒绝 | 统一路由规范化与精确豁免范围，不放宽整个接口前缀。 |
| 中 | 发布和回滚使用固定等待，没有检查活动流是否排空 | 长流结束后再停止旧实例；到达排空上限时明确取消原因并完成计费收尾。 |

## 限流口径

本次审计读取的平台配置为 **60 次 / 60 秒固定窗口**，按 **企业 + 成员 + 员工订阅** 计数。

- 同一身份的不同客户端、任务、模型、工具续轮和重试共享额度。
- 工具调用次数不等于模型请求次数，应以实际模型续轮请求计数。
- 429 应明确返回错误来源、命中规则和恢复时间；客户端按恢复时间等待。
- 上游 sub2api 的 RPM、TPM、并发和额度限制需要另行核实，不能用平台阈值代替。

## 待验收

- 用超过 30 秒的合成流验证修复，覆盖慢首包、连续空闲、总时限、慢客户端和主动取消。
- 检查下游背压暂停读取时，是否被误判为上游空闲超时。
- 验证取消可沿客户端 -> Web 代理 -> 后端 -> sub2api 传播，并完成记账收尾。
- 在发布和回滚期间保持长流，验证活动请求排空。
- 对 429、缺 usage、断流重试、token 撤销和记账失败补充端到端回归测试。

建议顺序：先修客户端请求参数和重试，以及平台计费、令牌撤销；再完善模型策略、资源预算和发布验收。
